# 装饰器

## 闭包（Closure）

闭包是装饰器的基础。闭包由**嵌套函数** + **引用外部变量** + **返回内部函数** 三个条件构成：

```python
# 外部函数 outer 接收参数 x，并将 x 捕获到返回的内部函数中
def outer(x):          # 外部函数
    # 内部函数 inner 引用了外部函数的变量 x，形成闭包
    def inner(y):      # 内部函数，使用了 x
        return x + y
    # 返回 inner 函数对象本身（不加括号），使 outer 的局部变量 x 不随调用结束而销毁
    return inner       # 返回函数对象（不加括号）

# outer(5) 执行后返回 inner 函数，此时 x=5 已被"记住"在闭包环境中
add5 = outer(5)
# 调用 add5(3) 相当于 inner(3)，闭包中保存的 x=5 与传入的 y=3 相加得 8
print(add5(3))         # 8 — x=5 被"记住"了
```

**闭包的作用**：保存外部函数的变量，使其不会随函数调用结束而销毁。

## 装饰器定义

装饰器（Decorator）是一个**可调用对象**（通常是函数），它接收一个函数作为参数，返回一个增强后的新函数。本质是**语法糖**：

```python
# 装饰器本质上是一个高阶函数：接收一个函数，返回一个增强后的新函数
def log(func):
    # wrapper 是包装函数，用 *args, **kwargs 灵活接收任意参数
    def wrapper(*args, **kwargs):
        # 在执行原函数前插入日志行为，实现"增强"效果
        print(f"Calling {func.__name__}")
        # 调用原函数并返回其结果，保持原函数的返回值不变
        return func(*args, **kwargs)
    return wrapper

# @log 是语法糖，等价于 say_hello = log(say_hello)
@log            # 语法糖：等价于 say_hello = log(say_hello)
def say_hello(name):
    print(f"Hello, {name}")

# 调用 say_hello 实际上执行的是 wrapper 函数，内部再调用原函数
say_hello("AI")  # 输出: Calling say_hello \n Hello, AI
```

## 常见装饰器模式

| 模式 | 实现方式 | 用途 |
|------|----------|------|
| **函数装饰器** | 参数为函数，返回包装函数 | 日志、计时、鉴权 |
| **带参装饰器** | 三层嵌套：外层接收参数 | 自定义日志级别、路由路径 |
| **类装饰器** | `__call__` 方法 | 状态管理、配置 |
| ** `@wraps` ** | `functools.wraps(func)` | 保留原函数的元信息（`__name__`、`__doc__`） |

## 带参装饰器

```python
# 带参装饰器：外层函数 repeat 接收参数，返回真正的装饰器
def repeat(n):
    # decorator 是真正的装饰器，接收被装饰的函数 func
    def decorator(func):
        # wrapper 是最终被调用的包装函数
        def wrapper(*args, **kwargs):
            # 循环 n 次执行原函数，实现"重复执行"的效果
            for _ in range(n):
                # 每次调用都保存返回值，最后返回最后一次的结果
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

# @repeat(3) 先执行 repeat(3) 得到 decorator，再等价于 greet = decorator(greet)
@repeat(3)
def greet():
    print("Hello!")

# 实际调用的是 wrapper，内部会执行三次原函数 greet()
greet()  # Hello! 打印三次
```

## 面试追问

**Q1（基础）**：什么是闭包？闭包的形成需要满足哪三个条件？
**回答要点**：

1. 闭包是一种函数式编程的机制，指内部函数能够访问外部函数（外层函数）作用域中的变量，即使外部函数已经执行完毕
2. 闭包形成的三个必要条件：存在函数嵌套（外部函数内部定义内部函数）、内部函数引用外部函数的局部变量、外部函数将内部函数作为返回值返回
3. 闭包的核心作用是保存外部函数的执行环境，使外部函数的局部变量不会随着函数调用结束而被销毁

**Q2（深挖）**：`@wraps` 装饰器的作用是什么？不使用它会导致什么问题？
**回答要点**：

1. `functools.wraps` 是一个装饰器，用于将被装饰函数的元信息（如 `__name__`、`__doc__`、`__module__`、`__annotations__` 等）复制到包装函数上
2. 不使用 `@wraps` 时，包装函数的元信息会覆盖原函数的元信息，例如被装饰后 `func.__name__` 会输出 `wrapper` 而非原函数名
3. 这会影响依赖函数元信息的工具，包括 `help()` 显示错误文档、调试器显示混淆的函数名、自动化文档生成与序列化框架出现混乱

**Q3（实战）**：多层装饰器的执行顺序是怎样的？写出 `@A @B def f()` 的实际等价形式。
**回答要点**：

1. 多层装饰器 `@A @B def f()` 的等价形式为 `f = A(B(f))`，即装饰器的应用顺序由下往上：B 先装饰原函数，A 再装饰 B 返回的结果
2. 调用 `f()` 时的执行顺序由外到内：先执行 A 中在调用原函数前的代码 -> 进入 B 中在调用原函数前的代码 -> 执行原函数 -> 执行 B 中在调用原函数后的代码 -> 执行 A 中在调用原函数后的代码
3. 理解这一"由下往上堆叠、由上往下执行"的顺序对调试复杂装饰器链和使用框架中的多层装饰器（如 Flask 路由与鉴权组合）至关重要

**Q4（边界）**：装饰器在处理类方法或异步函数时有什么需要注意的地方？
**回答要点**：

1. 装饰类方法时，包装函数需要使用 `*args, **kwargs` 来捕获并传递 `self` 参数，确保类方法的实例绑定不受影响
2. 装饰 `async def` 定义的异步函数时，包装函数必须声明为 `async def` 并在内部使用 `await` 调用原函数，否则直接返回协程对象而非实际的执行结果
3. 实现带参装饰器（装饰器工厂）时需注意三层嵌套的正确传参，区分装饰器参数、被装饰函数参数和运行时参数，避免因参数位置错误导致 TypeError
