# 进程与多进程

## 定义

进程（Process）是**操作系统资源分配的最小单位**。每个进程拥有独立的地址空间、文件描述符表、信号处理方式等资源。在 Python 中，`multiprocessing` 模块通过创建子进程实现并行计算，利用多核 CPU 加速 CPU 密集型任务，同时绕过 GIL 的限制。

进程的创建与状态模型：

$$
\begin{aligned}
&\text{创建（fork/spawn）} \rightarrow \text{就绪（ready）} \rightarrow \text{运行（running）} \rightarrow \text{阻塞（blocked）} \\
&\text{运行} \rightarrow \text{就绪（时间片耗尽）} \\
&\text{运行} \rightarrow \text{终止（terminated）}
\end{aligned}
$$

## 核心对比：单进程 vs 多进程

| 对比维度 | 单进程 | 多进程 |
|:--------:|:------|:-------|
| **CPU 利用率** | 单核 100% | 多核 N $\times$ 100%（近似线性） |
| **内存开销** | 低（单个地址空间） | 高（独立地址空间，约 8MB+/进程） |
| **数据隔离** | 天然隔离 | 需要 IPC 机制通信 |
| **编程复杂度** | 低 | 中（需处理同步和通信） |
| **适用场景** | I/O 密集型、轻量任务 | CPU 密集型、并行计算 |

## 直观理解

进程就像多个独立的 Python 解释器同时运行，每个解释器拥有自己完全隔离的内存空间，互不干扰。多进程编程的本质是协调这些独立解释器之间的任务分配和数据交换。

## multiprocessing 核心用法

```python
import multiprocessing as mp

# 1. 基本创建
def worker(n):
    return n * n

p = mp.Process(target=worker, args=(10,))
p.start()
p.join()

# 2. 进程池（自动管理多个进程）
with mp.Pool(processes=4) as pool:
    results = pool.map(worker, range(100))   # 自动分配任务

# 3. 进程间通信 — Queue
q = mp.Queue()
q.put(data)
data = q.get()

# 4. 进程间通信 — Pipe（双向管道）
conn1, conn2 = mp.Pipe()
conn1.send(data)
data = conn2.recv()

# 5. 共享内存
shared_val = mp.Value('i', 0)        # 类型码 + 初始值
shared_arr = mp.Array('d', [1.0, 2.0])

# 6. 同步原语
lock = mp.Lock()
with lock:
    shared_val.value += 1
```

## 进程间通信（IPC）方式对比

| 方法 | 模块/机制 | 速度 | 适用场景 | 注意事项 |
|:----|:---------|:----:|:--------|:---------|
| **Queue** | `multiprocessing.Queue` | 中 | 生产者-消费者模式 | 内部使用 Pipe + 锁，线程/进程安全 |
| **Pipe** | `multiprocessing.Pipe` | 快 | 双向通信，两个端点 | 非线程安全，需自行加锁 |
| **Shared Memory** | `multiprocessing.Value` / `Array` | 最快 | 共享简单数值/同质数组 | 需加锁保护写操作 |
| **Manager** | `multiprocessing.Manager` | 慢 | 共享复杂数据结构（dict/list） | 通过代理实现，开销较大 |
| **文件映射** | `mmap` 模块 | 快 | 大块数据跨进程共享 | 适合大型数组共享，跨平台性有限 |

## ML/DL 应用场景

| 应用场景 | 实现方式 | 说明 |
|:--------:|:--------|:-----|
| **DataLoader 数据加载** | `num_workers > 0` | 子进程预加载+预处理数据，主进程训练不等待 |
| **分布式训练** | `torch.distributed` + NCCL | 每个 GPU 一个进程，多进程协同反向传播 |
| **超参数搜索** | `multiprocessing.Pool.map` | 每个子进程独立训练一组超参数配置 |
| **模型推理批处理** | 多进程负载均衡 | 每个进程加载模型实例，处理独立请求 |
| **特征工程并行** | `Pool.map` / `Pool.starmap` | 并行执行特征提取/转换，聚合结果 |
| **强化学习环境并行** | `multiprocessing.Pipe` 通信 | 每个子进程运行独立环境实例，收集经验 |

## 面试追问

**Q1（基础）**：进程和线程在资源隔离和调度方面有什么区别？Python 中如何创建进程？

**回答要点**：进程是资源分配最小单位，有独立地址空间，调度开销大；线程是 CPU 调度最小单位，共享进程资源，调度开销小；Python 通过 `multiprocessing.Process(target=func).start()` 创建子进程，通过 `multiprocessing.Pool(processes=N).map(func, iterable)` 管理进程池。

**Q2（深挖）**：Python `multiprocessing` 中 `fork` 和 `spawn` 两种启动方式有什么区别？何时选择哪种？

**回答要点**：`fork`（Unix 默认）复制父进程全部内存，启动快但可能死锁，尤其在多线程环境中不安全；`spawn`（Windows 默认，Python 3.8+ 推荐）新启动一个解释器进程，只导入必要模块，安全但启动慢；推荐优先使用 `spawn`（设置 `mp.set_start_method('spawn')`），`fork` 逐渐被 CPython 弃用。

**Q3（实战）**：PyTorch `DataLoader` 中 `num_workers>0` 的实现机制是什么？设置过大会有什么风险？

**回答要点**：`num_workers=m` 启动 m 个子进程，每个子进程独立迭代数据集、执行 `collate_fn` 后将批次放入共享队列；主进程训练时从队列预取下一批数据；设置过大会导致大量内存复制（页面错误颠簸）、数据加载速度反而下降，通常推荐 m = 4--8 倍 GPU 数，不超过主机 CPU 核心数。

**Q4（边界）**：多进程间通信时如何保证数据一致性并避免死锁？共享内存的局限性是什么？

**回答要点**：通过 `multiprocessing.Lock` / `RLock` 保护共享资源写操作，`Queue` 内部已自动加锁；避免死锁需固定加锁顺序，或使用超时 `lock.acquire(timeout=seconds)`；共享内存只能存储 C 基本类型（`Value` / `Array`），不支持 Python 复杂对象（需用 Manager 但性能较差），且跨平台表现不一致（Linux 的 `fork` 共享语义在 Windows `spawn` 中不可用）。
