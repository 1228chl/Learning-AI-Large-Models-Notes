# 深浅拷贝

## 核心前提：可变 vs 不可变

Python 中一切皆对象，按可否修改分为两类：

| 类型 | 类别 | 包含 | 赋值行为 |
|------|------|------|----------|
| **不可变类型** | 创建后不可修改 | `int`, `float`, `str`, `tuple`, `bool` | 修改时创建新对象，原对象不变 |
| **可变类型** | 可在原地修改内容 | `list`, `dict`, `set`, 自定义类实例 | 修改内容时内存地址不变 |

## 三种复制方式

```python
import copy

original = [[1, 2], [3, 4], 5]

# 1. 直接赋值：新引用，指向同一对象
ref = original

# 2. 浅拷贝：新对象，但内层对象是引用
shallow = copy.copy(original)

# 3. 深拷贝：完全独立的新对象
deep = copy.deepcopy(original)
```

| 操作 | 是否创建新对象 | 外层元素 | 内层可变对象 | 适用场景 |
|------|---------------|----------|-------------|----------|
| **直接赋值 `=` ** | 否 | 指向同一对象 | 指向同一对象 | 仅需别名 |
| **浅拷贝 `.copy()` / `[:]` ** | 是 | 独立 | **共享引用** | 一层结构复制 |
| **深拷贝 `deepcopy()` ** | 是 | 独立 | **完全独立** | 嵌套结构完全隔离 |

## 图解理解

```python
原始:      outer → [inner_list, 5]
                        ↓
                     [1, 2]

浅拷贝:    outer' → [inner_list, 5]    ← inner_list 是同一对象
                        ↓
                     [1, 2]            ← 修改 inner_list 影响双方

深拷贝:    outer'' → [inner_list', 5]  ← inner_list 是复制品
                         ↓
                      [1, 2]           ← 完全独立
```

## 实际影响

```python
original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

shallow[0][0] = 99       # 修改内层
print(original[0][0])    # 99 — 被影响了！

deep[0][0] = 0           # 修改内层
print(original[0][0])    # 99 — 不受影响
```

## ML 中的注意事项

| 场景 | 推荐 | 原因 |
|------|------|------|
| **模型参数初始化** | 深拷贝 | 避免多个模型共享同一参数张量 |
| **数据增强 pipeline** | 深拷贝原始数据 | 防止增强操作污染原始数据集 |
| **配置字典复制** | 深拷贝 | 配置通常是嵌套 dict，浅拷贝会导致共享引用 |
| **大数组分片** | 浅拷贝（或视图） | NumPy 切片默认返回视图（类似浅拷贝），性能优先 |

> 在 PyTorch 中，`model.state_dict()` 返回的是参数的独立副本（类似深拷贝），可以安全修改而不影响模型。

## 面试追问

**Q1（基础）**：Python 中直接赋值、浅拷贝和深拷贝三种方式在内存行为上有什么区别？

**回答要点**：直接赋值仅创建引用，新旧变量指向同一对象；浅拷贝创建新对象，但内层可变对象仍共享引用；深拷贝递归复制所有层级，新旧对象完全独立；浅拷贝可用 `copy.copy()`、`.copy()`、`[:]`、`dict.copy()`，深拷贝用 `copy.deepcopy()`。

**Q2（深挖）**：不可变类型（如 `tuple`）浅拷贝后的修改行为是怎样的？`tuple` 中的可变元素会影响吗？

**回答要点**：`tuple` 本身不可变，无法替换其元素，所以浅拷贝后外层看起来"完全独立"；但如果 `tuple` 中包含 `list` 等可变对象，修改该 `list` 的内容会影响所有持有该引用者；这是面试中常见的"不可变对象嵌套可变对象"陷阱。

**Q3（实战）**：在 PyTorch 模型训练中，为什么保存模型配置字典时推荐使用深拷贝？浅拷贝可能导致什么问题？

**回答要点**：模型配置通常是嵌套 `dict`，浅拷贝时内层 `dict` 共享引用，修改一个模型的超参数会意外影响其他共享配置的模型；深拷贝确保每个实验配置完全独立；同样，数据增强管线的原始数据也要深拷贝，防止增强操作污染原始数据集。

**Q4（边界）**：`copy.deepcopy()` 有什么局限性？自定义类如何正确支持深拷贝？

**回答要点**：`deepcopy()` 可能非常慢（递归复制所有对象），占用大量内存，且无法拷贝文件句柄、数据库连接等不可序列化的资源；自定义类支持深拷贝需实现 `__copy__()` 和 `__deepcopy__()` 方法，或确保所有属性可 pickle 序列化。
