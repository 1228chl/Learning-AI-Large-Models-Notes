# Python 异步并发实战

## 定义

在 I/O 密集型任务（如 API 调用、数据库查询、文件读写）中，**异步并发** 通过 `asyncio.gather` 将多个独立的等待操作"重叠"起来，让总耗时约等于最慢的那个任务，而不是所有任务耗时的累加。

### 核心公式

```
总耗时(串行) = Σ(每个任务耗时)
总耗时(并行) ≈ max(每个任务耗时)
```

### 直观理解

> 一去咖啡店点了三杯咖啡。同步做法是"点第一杯→站在那等做完→再点第二杯……"；异步做法是"三杯一起下单→一起等→谁好了拿谁"。异步并没有让"做一杯咖啡"变快，它只是让你在等待时不空耗。

## 四种实战模式

### 模式一：asyncio.gather 并发

用于**多个独立任务并行执行**，等待所有任务完成：

```python
import asyncio

async def fetch(name, seconds):
    print(f"开始 {name}")
    await asyncio.sleep(seconds)  # 模拟网络请求
    print(f"完成 {name}")
    return f"{name} 的结果"

async def main():
    # 三个任务同时开始，一起等
    results = await asyncio.gather(
        fetch("请求A", 2),
        fetch("请求B", 2),
        fetch("请求C", 2),
    )
    print("所有结果：", results)  # 按传入顺序返回

asyncio.run(main())
# 总耗时约 2 秒，不是 6 秒
```

**EduAgent 真实应用**：
- 模型预热：同时加载 BGE-Reranker、MiniLM、BGE-M3 三个本地模型
- 简历审查：六维度并行评分，总耗时 ≈ 一次 LLM 调用
- 试卷批改：三轨并行批改（客观题+编程题+主观题）

### 模式二：run_in_executor 包装同步代码

异步代码中**绝对不能直接调用同步阻塞函数**（会卡死事件循环）。用 `run_in_executor` 丢到线程池：

```python
import asyncio
import time

def heavy_sync_work(n):  # 同步阻塞函数（如本地模型推理）
    time.sleep(2)        # 模拟同步阻塞
    return n * n

async def main():
    loop = asyncio.get_running_loop()
    # 丢到线程池执行，不阻塞事件循环
    result = await loop.run_in_executor(None, heavy_sync_work, 10)
    print("结果：", result)

asyncio.run(main())
```

**固定套路**：
```python
loop = asyncio.get_running_loop()
结果 = await loop.run_in_executor(None, 同步函数, 参数1, 参数2, ...)
```

**EduAgent 真实应用**：
- 本地模型推理（BGE-M3 向量化、BGE-Reranker 精排、MiniLM 分类）
- PDF 解析（PyMuPDF 提取文本）
- 密码校验（bcrypt 是 CPU 密集型）

### 模式三：asynccontextmanager 资源管理

用于管理异步资源的生命周期（启动时加载、关闭时清理）：

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan():
    print("【启动】加载模型 / 建立数据库连接")
    yield                          # yield 之前 = 启动逻辑
    print("【关闭】释放资源 / 清理缓存")

async def main():
    async with lifespan():
        print("应用运行中，处理请求……")
```

**关键理解**：`yield` 上面的代码在"进入"时执行，下面的代码在"退出"时执行。

**EduAgent 真实应用**：FastAPI 的 `lifespan` 函数，`yield` 前自动执行数据库迁移、预热模型，`yield` 后清理缓存。

### 模式四：先创建协程再 gather

```python
# 先创建所有协程（此时还没执行）
tasks = [review_one_dimension(dim) for dim in SIX_DIMENSIONS]

# 再一起执行
dimension_scores = await asyncio.gather(*tasks)
```

## 三个常见坑

| 坑 | 表现 | 正确做法 |
|:---|:-----|:---------|
| **忘记 await** | 拿到协程对象而非结果 | `result = await get_value()` |
| **嵌套 asyncio.run** | 报错：已在事件循环中 | 只用一次 `asyncio.run()` 做入口 |
| **协程里直接阻塞** | 卡死事件循环 | 用 `await asyncio.sleep` 或 `run_in_executor` |

## 面试追问

**Q1（基础）**：asyncio.gather 的作用是什么？串行和并行的耗时差异有多大？
**回答要点**：
1. gather 把多个协程同时启动、一起等待，按传入顺序收集返回值
2. 串行总耗时 = 所有任务耗时相加；并行总耗时 ≈ 最慢的任务
3. 三个 2 秒的任务：串行 6 秒，并行 2 秒

**Q2（深挖）**：为什么协程里不能直接调用同步阻塞函数？run_in_executor 如何解决？
**回答要点**：
1. Python 事件循环是单线程的，同步阻塞函数会霸占线程，不让循环处理其他任务
2. run_in_executor 把同步函数丢进线程池，主事件循环继续处理其他任务
3. 等线程池跑完后，用 await 取回结果

**Q3（实战）**：asynccontextmanager 的 yield 前后代码分别在什么时候执行？
**回答要点**：
1. yield 上面：进入 async with 块时执行（启动逻辑）
2. yield 下面：退出 async with 块时执行（关闭逻辑）
3. 在 EduAgent 中，yield 前加载模型，yield 后清理缓存

**Q4（边界）**：gather 传参时 *tasks 和 tasks 有什么区别？
**回答要点**：
1. `gather(*tasks)` 将列表解包成多个参数传入
2. `gather(tasks)` 把整个列表作为单个参数传入，会导致错误
3. 正确写法：`await asyncio.gather(*tasks)`
