# 上下文管理器

## 定义

上下文管理器（Context Manager）是 Python 中用于**资源管理**的协议，最常见的场景是文件操作、数据库连接、锁获取等——需要"用完记得关闭"的操作。

使用 `with` 语句自动管理资源的**获取**和**释放**：

```python
# 传统写法：手动管理文件的打开和关闭，容易因异常或遗忘导致资源泄漏
f = open("file.txt", "r")
data = f.read()
f.close()

# 上下文管理器：with 语句在进入时自动打开文件，离开时自动关闭文件
# 即使 with 块中发生异常也会正确释放资源，避免资源泄漏
with open("file.txt", "r") as f:
    data = f.read()
```

## 核心协议

上下文管理器通过两个魔术方法实现：

| 方法 | 调用时机 | 返回值 | 典型用途 |
|------|----------|--------|----------|
| `__enter__` | `with` 块开始时 | 赋值给 `as` 后的变量 | 获取资源 |
| `__exit__` | `with` 块结束时（无论是否异常） | `True` =阻止异常传播 | 释放资源 |

```python
class FileManager:
    # 构造方法：记录要打开的文件名和打开模式
    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode

    # __enter__ 在 with 块开始时调用：负责获取资源（打开文件）
    def __enter__(self):
        self.file = open(self.filename, self.mode)
        # 返回值赋值给 as 后的变量，让用户在 with 块中操作文件
        return self.file        # 赋值给 as 后的变量

    # __exit__ 在 with 块结束时自动调用：负责释放资源（关闭文件）
    # exc_type/exc_val/exc_tb 分别记录异常类型、值和回溯信息，无异常时均为 None
    def __exit__(self, exc_type, exc_val, exc_tb):
        # 无论 with 块中是否发生异常，都会执行文件关闭操作
        self.file.close()       # 无论如何都会执行
        # 返回 False 表示不阻止异常，让异常继续向外传播
        return False            # False = 让异常继续传播
```

## `contextlib` 模块

使用标准库 `contextlib` 可以更简洁地创建上下文管理器：

| 工具 | 用途 | 示例 |
|------|------|------|
| `@contextmanager` | 用生成器语法定义 | `yield` 前是 `__enter__`，后是 `__exit__` |
| `closing()` | 调用对象的 `close()` 方法 | `closing(urllib.urlopen(...))` |
| `suppress()` | 忽略指定异常 | `suppress(FileNotFoundError)` |
| `redirect_stdout` | 临时重定向输出 | 捕获 `print` 输出 |

```python
from contextlib import contextmanager

# @contextmanager 装饰器将生成器函数变为上下文管理器，比定义类更简洁
@contextmanager
def managed_file(filename, mode):
    # yield 之前的代码相当于 __enter__：获取资源（打开文件）
    f = open(filename, mode)
    try:
        # yield 的值将被 with as 语句接收，相当于 __enter__ 的返回值
        yield f                 # __enter__ 返回的值
    finally:
        # finally 确保无论 with 块是否异常都会执行清理，相当于 __exit__
        f.close()              # __exit__ 中执行
```

## 面试追问

**Q1（基础）**：上下文管理器的 `__enter__` 和 `__exit__` 分别在什么时候被调用？`__exit__` 的参数是什么含义？

**回答要点**：`__enter__` 在进入 `with` 块时调用，返回值赋给 `as` 后的变量；`__exit__` 在离开 `with` 块时（无论是否发生异常）调用；参数 `exc_type`、`exc_val`、`exc_tb` 分别表示异常类型、异常值和回溯信息，无异常时均为 `None`。

**Q2（深挖）**：`__exit__` 返回 `True` 和 `False` 分别有什么影响？什么场景会返回 `True`？

**回答要点**：返回 `False`（默认）让异常继续向外传播；返回 `True` 则吞掉异常，`with` 块像什么都没发生一样继续；场景如 `contextlib.suppress()` 实现——希望忽略某些特定异常时返回 `True`。

**Q3（实战）**：使用 `@contextmanager` 装饰器定义上下文管理器时，`yield` 前后的代码分别对应什么？为什么通常需要 `try/finally`？

**回答要点**：`yield` 前的代码对应 `__enter__`，`yield` 的值赋给 `as` 变量；`yield` 后的代码对应 `__exit__`；必须用 `try/finally` 包裹 `yield`，确保即使 `with` 块内抛出异常，清理代码（如关闭文件）也能执行。

**Q4（边界）**：`with` 语句能否同时管理多个上下文管理器？什么情况会导致上下文管理器失效？

**回答要点**：可以，如 `with A() as a, B() as b:`（Python 3.10+ 也支持括号分组）；上下文管理器失效的情况包括：`__enter__` 中发生异常导致 `__exit__` 未执行、`@contextmanager` 装饰的生成器中只 `yield` 一次但仍需处理多个资源、或忘记正确处理异常导致资源泄漏。
