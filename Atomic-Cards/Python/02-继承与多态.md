# 继承与多态

Python 面向对象三大特性——封装、继承、多态——的概览，详细内容见各独立卡片：

| **继承** | 子类复用父类代码，MRO 解决多继承查找顺序 | [12-继承与MRO](./12-继承与MRO.md) |

## 封装 (Encapsulation)

数据+方法绑定，对外隐藏实现细节。Python 通过命名约定（`_name` 受保护、`__name` 私有）和 `@property` 实现可控访问。 → [11-封装(Encapsulation)](./11-封装(Encapsulation).md)

## 继承与 MRO

子类复用父类代码，支持单/多/多层继承。C3 线性化算法解决多继承的方法查找顺序（`__mro__`）。 → [12-继承与MRO](./12-继承与MRO.md)

## 多态与鸭子类型

同一接口不同实现，Python 不检查类型只检查方法存在性。"如果它像鸭子一样叫，那它就是鸭子。" → [13-多态与鸭子类型](./13-多态与鸭子类型.md)

## ML 中的继承与多态

| 应用场景 | 体现 | 说明 |
|----------|------|------|
| **模型家族** | `BERT(nn.Module)`、`GPT2(nn.Module)` | 不同模型共享 `nn.Module` 接口，统一训练流程 |
| **多种优化器** | `SGD`、`Adam`、`AdamW` 都继承 `Optimizer` | PyTorch 统一优化器接口 |
| **数据集加载** | `ImageFolder(Dataset)`、`TensorDataset(Dataset)` | 不同数据格式统一为 Dataset 协议 |
| **Hook 机制** | `register_forward_hook` | 不修改类定义即可扩展功能（装饰器模式） |

## 面试追问

**Q1（基础）**：Python 中如何实现封装？`_name` 和 `__name` 有什么区别？
**回答要点**：

1. `_name` 表示受保护属性，是约定俗成的命名规范，外部仍可访问，提示开发者"请谨慎使用"
2. `__name` 触发名称修饰（Name Mangling），自动重命名为 `_ClassName__name`，用于避免子类意外覆盖
3. `@property` 装饰器将方法伪装成属性，实现可控的 getter/setter 访问

**Q2（深挖）**：Python 多继承中如何解决命名冲突？MRO 的查找顺序是什么？
**回答要点**：

1. Python 使用 C3 线性化算法计算 MRO（方法解析顺序），存储在类的 `__mro__` 属性中
2. MRO 遵循"子类优先、深度优先、单调性"原则，保证每个父类在 MRO 中只出现一次
3. `super()` 遵循 MRO 链调用下一个类的方法，而非简单地调用父类

**Q3（实战）**：在 PyTorch 框架中如何体现继承与多态？举例说明。
**回答要点**：

1. 自定义模型继承 `nn.Module`，必须实现 `forward()` 方法，这是模板方法模式的体现
2. 不同优化器（`SGD`、`Adam`）继承 `Optimizer` 基类，通过 `step()` 统一接口实现多态
3. 数据集类继承 `Dataset` 并实现 `__len__` 和 `__getitem__`，DataLoader 统一遍历

**Q4（边界）**：`__name` 的命名修饰机制有哪些边界情况需要注意？
**回答要点**：

1. 名称修饰只在类定义内部发生，外部直接访问 `__name` 会触发 AttributeError
2. 以双下划线开头且结尾的"魔法方法"（如 `__init__`）不会被修饰
3. 超过连续两个下划线的命名不会被修饰，只有恰好以 `__` 开头且不以 `__` 结尾的才触发
