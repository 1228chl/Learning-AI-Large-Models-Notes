# 注意力机制

## 定义

注意力机制（Attention Mechanism）让模型在生成每个输出时**动态关注输入序列的特定位置**，打破了 Seq2Seq 模型中固定长度上下文向量的"信息瓶颈"。

设 $d_k$ 为键向量的维度。

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

注意力本质是一个**加权求和**——模型根据查询 $Q$ 与键 $K$ 的相似度，对值 $V$ 进行加权组合。

## 直观理解

### 注意力机制的查询-键-值结构

将注意力机制类比为数据库查询操作：

| 注意力组件 | 类比 | 说明 |
|:----------|:-----|:------|
| $Q$（查询） | 你的搜索词 | 你想要找什么 |
| $K$（键） | 数据库中每条记录的标题 | 每条信息的"标签"或"索引" |
| $V$（值） | 数据库中的完整内容 | 实际的信息内容 |
| $QK^T$ | 搜索词与标题的匹配度打分 | 查询与键的相似度 |
| $\text{softmax}$ | 排序并归一化为百分比 | 将分数转化为概率分布 |
| $\text{softmax}(...)V$ | 按匹配度加权获取内容 | 最匹配的内容贡献最大 |

### 为什么除以 $\sqrt{d_k}$？

点积 $QK^T$ 的方差随维度 $d_k$ 线性增长——每个维度独立同分布时，$d_k$ 维点积的方差为 $d_k$。方差越大，$\text{softmax}$ 输出的分布越极端（接近 one-hot），梯度在饱和区趋近于零。除以 $\sqrt{d_k}$ 将方差归一化到 1，使 softmax 的梯度更加温和稳定。这可以理解为"给注意力分数做温度控制"：$d_k$ 越大，温度越高，需要更强的缩放冷却。

### 注意力的几何本质

在向量空间中，注意力的每一步都有清晰的几何含义：
1. $QK^T$：计算查询向量与所有键向量的**点积**——即查询在键方向上的投影长度
2. $\text{softmax}$：将投影长度归一化为概率分布，数值大的方向获得更多权重
3. $(\text{softmax分数}) \times V$：在值向量空间中做**加权平均**，最终输出落在值向量张成的子空间内，位置由注意力权重决定

## 注意力计算方式

```python
import torch
import torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V):          # 缩放点积注意力：Q 为查询矩阵，K 为键矩阵，V 为值矩阵
    """缩放点积注意力"""

    scores = Q @ K.transpose(-2, -1) / (K.size(-1) ** 0.5)  # 计算 Q 与 K 的点积相似度，除以 sqrt(d_k) 防止梯度消失

    weights = F.softmax(scores, dim=-1)                      # 对最后一个维度做 softmax，得到每个位置的注意力权重
    return weights @ V                                        # 用注意力权重对 V 进行加权求和，得到上下文向量
```

| 注意力类型 | 公式 | 复杂度 | 特点 |
|:---------:|:----:|:------:|------|
| **加性（Additive/Bahdanau）** | $v^T \tanh(W_1 Q + W_2 K)$ | $O(n^2 \cdot d)$ | 早期 RNN 注意力 |
| **点积（Dot-Product/Luong）** | $Q^T K$ | $O(n^2)$ | 简单快速 |
| **缩放点积（Scaled Dot-Product）** | $\frac{Q^T K}{\sqrt{d_k}}$ | $O(n^2)$ | **默认首选**，梯度稳定 |

其中：
- $v$：可学习的注意力向量
- $W_1, W_2$：可学习的权重矩阵

## Bahdanau Attention vs Luong Attention

| 对比 | Bahdanau（加性，2014） | Luong（点积，2015） |
|:----:|:---------------------:|:------------------:|
| **计算方式** | 加性 $v^T \tanh(W[q; h])$ | 点积 $q^T h$ |
| **Decoder 对齐** | 上一时间步隐状态计算 | 当前时间步隐状态计算 |
| **计算量** | 大（需训练 $W$ 和 $v$ ） | 小 |
| **RNN 匹配度** | 天然适合 | 需更多 Trick |

其中：
- $v$：可学习的注意力向量
- $W$：可学习的权重矩阵
- $q$：解码器隐状态（查询向量）
- $h$：编码器隐状态

## 注意力的核心作用

```python
不带注意力：       "I love cats" → [固定向量 C] → "我 爱 猫"
带注意力：         "I love cats"
                     ↑  ↑  ↑
                    [0.1, 0.8, 0.1]  ← 当前步对各输入词的关注权重
                       ↓
                    "爱" ← 当前步输出
```

| 作用 | 说明 |
|:----|------|
| **对齐（Alignment）** | 找到输入中与当前输出最相关的部分 |
| **信息选择** | 从输入中提取相关信息，忽略无关信息 |
| **可解释性** | 注意力权重可视化展示模型关注点 |

## ML 中的注意力

| 应用场景 | 注意力形式 | 说明 |
|:--------:|:---------:|------|
| **机器翻译（Seq2Seq+Attn）** | Encoder-Decoder Attention | 翻译时关注原句对应位置 |
| **Transformer** | 自注意力 + 交叉注意力 | 编码器自注意，解码器交叉注意 |
| **图像 Captioning** | 图像区域注意力 | 生成每个词时关注不同图像区域 |
| **视觉问答（VQA）** | 问题和图像的双向注意力 | 根据问题关注图像相关区域 |
| **推荐系统** | 用户行为序列注意力 | 关注历史行为中重要的交互 |

## 面试追问

**Q1（基础）**：注意力机制解决了 Seq2Seq 中的什么核心问题？请简述它的工作原理。
**回答要点**：

1. 解决了固定上下文向量的信息瓶颈问题
2. 解码每个输出时，动态计算对编码器所有位置的加权和
3. 权重由查询 $Q$ 与键 $K$ 的相似度通过 softmax 归一化得到

**Q2（深挖）**：Bahdanau（加性）注意力和 Luong（点积）注意力有哪些关键区别？各自在什么场景下更适用？
**回答要点**：

1. Bahdanau 使用加性注意力 $v^T\tanh(W[q;h])$，参数量大但表达力强；Luong 使用点积注意力 $q^T h$，计算简单快速
2. Bahdanau 在计算 decoder 对齐时使用上一时间步的隐状态，天然适合 RNN 架构
3. Luong 使用当前时间步的隐状态计算对齐，更接近后来的缩放点积注意力

**Q3（实战）**：你在项目中观察过注意力权重的可视化结果吗？如果发现注意力分布太分散（没有聚焦到关键位置），你会如何排查和改进？
**回答要点**：

1. 可能是模型容量不够或训练不充分
2. 尝试增加注意力头数、调整缩放温度参数、增加 dropout 防止过拟合
3. 检查数据是否存在对齐噪声

**Q4（边界）**：注意力机制在什么时候会失效或效果变差？有何改进方案？
**回答要点**：

1. 长序列时 $O(n^2)$ 内存/计算代价过高
2. 某些任务中软对齐不存在（如精确匹配场景），注意力可能被虚假相关性误导
3. 改进方案包括稀疏注意力、线性注意力、Flash Attention
