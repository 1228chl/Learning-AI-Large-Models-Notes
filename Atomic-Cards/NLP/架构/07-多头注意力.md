# 多头注意力

## 定义

设 $Q$ 为查询矩阵，$K$ 为键矩阵，$V$ 为值矩阵。

多头注意力（Multi-Head Attention）将 $Q, K, V$ 投影到 $h$ 个不同的子空间，在每个子空间独立计算注意力，然后将结果拼接并投影回原始维度。

## 直观理解

### 多头注意力 = "多个专家从不同角度观察"

单头注意力的局限：所有注意力都集中在同一个表示空间中，模型只能学到"一种"关注模式。多头注意力让模型同时从 $h$ 个不同的角度观察序列——每个头关注不同类型的关系。

类比：同样一段文本，一个头关注语法关系（主语-谓语），另一个头关注语义关系（实体-属性），另一个头关注位置关系（远近程度）。将多个头的输出拼接起来，模型就同时获得了多个视角的信息。

### 为什么多头有效？

每个注意力头在不同的子空间中计算，这意味着它们学到的是互补的注意力模式。如果所有头都学到相同的模式，则多头没有意义——但实践中不同头确实关注不同的语言现象（如某些头关注句法依赖，某些头关注共指关系）。$h$ 通常取 8 或 16。

$$
\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \dots, \text{head}_h) W^O
$$

- $W^O$：输出投影矩阵

$$
\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)
$$

- $W_i^Q$：第 $i$ 个头的查询投影矩阵
- $W_i^K$：第 $i$ 个头的键投影矩阵
- $W_i^V$：第 $i$ 个头的值投影矩阵

```python
import torch.nn as nn

# PyTorch 多头注意力
# 创建多头注意力层实例：将总维度拆分为多个子空间并行计算，捕捉不同类型的关系
mha = nn.MultiheadAttention(

    embed_dim=512,     # 模型总维度

    num_heads=8,       # 注意力头数（512 / 8 = 64 每头）

    batch_first=True   # 输入输出形状为 (batch, seq_len, embed_dim)，便于批处理
)

# 输入形状: (batch_size, seq_len, embed_dim)
# 前向传播：传入 Q(query)、K(key)、V(value)，输出注意力加权后的特征和权重矩阵
output, weights = mha(query, key, value)
# output: (N, L, 512), weights: (N, 8, L, L)
```

## 为什么需要多头？

```python
单头注意力：所有信息混合在一个注意力模式中
           "这只猫在追那只狗，它跑得很快"
                               ↑
                         "它"关注了 "猫"？还是"狗"？
                         → 只能聚焦一个关系

多头注意力：8个独立的注意力模式
           头1: 语法关系（动词-主语）
           头2: 语义关系（代词-指代）
           头3: 位置关系（远近）
           ...
           → 每个头学习不同类型的关系
```

| 特性 | 单头注意力 | 多头注意力 |
|:----:|:---------:|:----------:|
| 表达能力 | 一种关系模式 | $h$ 种不同关系模式 |
| 并行性 | 单个注意力 | 每个头独立计算，可并行 |
| 参数 | 少 | $h$ 组 $W^Q, W^K, W^V$ |
| 可解释性 | — | 可分析每个头关注什么 |

## 注意力头的角色

通过分析预训练模型（如 BERT）的各注意力头，发现不同头学习不同的语言模式：

| 注意力头类型 | 关注模式 | 示例 |
|:-----------:|:--------:|:----:|
| **语法头** | 词性依赖 | 动词 → 主语、形容词 → 名词 |
| **位置头** | 相邻词 | 关注左右邻词 |
| **语义头** | 远距离指代 | 代词 → 其指代的名词 |
| **特殊头** | [CLS] / [SEP] | 关注特殊标记 |

## ML 中的多头注意力

其中 $d_{head}$ 为每头维度。

| 模型 | 注意力配置 | 说明 |
|:----:|:---------:|------|
| **BERT-base** | 12 层 × 12 头 | $d_{head} = 768 / 12 = 64$ |
| **BERT-large** | 24 层 × 16 头 | $d_{head} = 1024 / 16 = 64$ |
| **GPT-3** | 96 层 × 96 头 | $d_{head} = 12288 / 96 = 128$ |
| **LLaMA** | 32 层 × 32 头 | 使用分组查询注意力（GQA） |

## 面试追问

**Q1（基础）**：为什么单头注意力不足以表达复杂的语言关系？多头注意力如何弥补这一不足？
**回答要点**：

1. 单头注意力只能产生一个注意力分布，只能聚焦一种关系模式
2. 多头注意力将 Q、K、V 投影到 h 个不同子空间，每个头并行学习不同类型的关系（语法、语义、位置）
3. 将所有头的输出拼接并投影回原始维度，融合多种关系信息

**Q2（深挖）**：多头注意力的参数如何计算？embed_dim、num_heads 和 d_head 之间是什么关系？
**回答要点**：

1. d_head = embed_dim / num_heads，通常设为 64
2. 每组需要 $W^Q_i, W^K_i, W^V_i$ 三个投影矩阵，总参数量与单头相同
3. 加上最后的输出投影 $W^O$，标准配置中每头维度保持 64

**Q3（实战）**：在 BERT 的可解释性分析中，各注意力头实际学到了什么不同类型的模式？这对你调试模型有什么启发？
**回答要点**：

1. 语法头关注词性依赖（动词-主语），位置头关注相邻词，语义头关注远距离指代（代词-名词）
2. 分析注意力头分布可以帮助诊断模型是否学到了合理的语言模式
3. 如果某些头全部关注 [SEP] 或均匀分布，可能说明训练不充分或模型退化

**Q4（边界）**：为什么 LLaMA 等最新大模型改用分组查询注意力（GQA）而不是标准多头注意力？GQA 解决了什么问题？
**回答要点**：

1. 标准多头注意力在推理时需要缓存所有头的 K、V 矩阵（KV cache），内存消耗大
2. GQA 减少 K、V 头的数量（如 Q 有 32 头，K、V 只有 8 头），大幅降低缓存大小
3. 在保持模型质量的同时提升推理吞吐量，适合大规模部署
