# 自注意力与 Transformer

## 定义

**自注意力（Self-Attention）** 是 Transformer 的核心：序列中每个位置都**关注所有其他位置**，直接建模所有位置间的依赖关系，不受距离限制。

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

- 在自注意力中： $Q = K = V = XW$ （同一序列通过不同线性变换得到）
- $QK^T$ ：计算每对位置的相关性得分
- $\sqrt{d_k}$ ：缩放因子，防止内积过大导致 softmax 梯度饱和
- Softmax：归一化为注意力权重
- $V$ 加权求和：得到每个位置的输出

## 直观理解

### 自注意力的全连接信息交换

自注意力的核心操作可以理解为**"全连接信息交换"**：序列中的每个 token 将自己的信息广播给所有其他 token，同时从所有其他 token 收集信息，并根据相关性加权融合。

几何上，自注意力层执行的是**"在 token 空间中的软性重排列"**：输入序列 $X$ 的每个位置向量经过自注意力后，变成了所有位置向量的加权组合。组合权重是动态的（由 $QK^T$ 实时计算），而非固定的卷积核。

### 自注意力与 RNN 的本质差异

| 特性 | RNN | Transformer 自注意力 |
|:----|:----|:--------------------|
| 信息传递路径 | 沿时间步逐步传递（$O(n)$ 步） | 一步直达（$O(1)$ 路径长度） |
| 并行度 | 串行（等前一步算完才能算下一步） | 完全并行（所有位置同时计算） |
| 远程依赖 | $n$ 步后信息衰减严重 | 任意距离直接连接，无衰减 |

RNN 的信息传递路径长度为 $O(n)$，意味着远距离 token 的信息需要经过所有中间 token 的"传话"才能到达，每次传话都有信息损失。自注意力为每对 token 建立直接连接，路径长度恒为 $O(1)$，不存在"信息传话衰减"问题。

### Transformer 的编码器-解码器分工

编码器通过自注意力充分理解输入序列的语义结构（双向上下文），解码器通过掩码自注意力确保自回归生成（只能看左边已生成的内容），再通过交叉注意力连接编码器的输出。整个架构遵循"理解-生成"的分工范式。

## Transformer 完整架构

```python
输出 → Linear → Softmax
         ↑
    Add & Norm
         ↑
    Feed Forward
         ↑
    Add & Norm
         ↑
    Multi-Head Self-Attention
         ↑
  [位置编码 + 输入嵌入]
         ↑
     输入序列
```

```python
import torch.nn as nn

# PyTorch 内置 Transformer
# 实例化完整的 Transformer 模型，包含编码器和解码器，用于序列到序列建模
transformer = nn.Transformer(

    d_model=512,                    # 模型维度

    nhead=8,                        # 注意力头数

    num_encoder_layers=6,           # 编码器层数

    num_decoder_layers=6,           # 解码器层数

    dim_feedforward=2048           # FFN 中间维度
)
```

| 组件 | 作用 | 说明 |
|:----:|:----|------|
| **自注意力** | 序列内部所有位置的关系建模 | 解决长距离依赖 |
| **多头注意力** | 多个子空间同时学习不同类型的关系 | $8$ 或 $16$ 个注意力头 |
| **FFN**（前馈网络） | 每个位置的独立非线性变换 | $\text{ReLU}(xW_1 + b_1)W_2 + b_2$，其中 $x$ 为输入向量，$W_1,W_2$ 为权重矩阵，$b_1,b_2$ 为偏置项 |
| **残差连接** | $x + \text{Sublayer}(x)$ | 解决深层梯度消失 |
| **Layer Norm** | 对每个位置的特征做归一化 | 稳定训练 |
| **位置编码** | 注入序列位置信息 | 弥补注意力无位置概念 |

## 编码器 vs 解码器

| 组件 | 编码器 | 解码器 |
|:----:|:------|:------|
| 输入 | 完整的源序列 | 已生成的目标序列 |
| 注意力 | 自注意力（双向，能看到前后） | **掩码自注意力**（只能看左侧）+ 交叉注意力 |
| 掩码 | 无 | 未来位置的注意力掩码为 $-\infty$ |
| 角色 | 提取输入表示 | 根据输入表示和已生成内容预测下一个词 |

## Transformer 的核心优势

| 对比 | RNN | Transformer |
|:----:|:---:|:-----------:|
| 并行计算 | ❌ 串行 | ✅ **完全并行** |
| 长距离依赖 | ❌ 难 | ✅ 自注意力直接建模 |
| 最大序列长度 | ~100 | ~512（相对位置编码可扩展） |
| 计算复杂度 | $O(n)$ 步 | $O(n^2)$ 每层（自注意力的计算量） |
| 参数量 | 少 | 大（需大数据预训练） |

> Transformer 架构是 NLP 领域的分水岭，几乎所有现代大模型（BERT、GPT、T5、LLaMA）都基于此架构。

## 面试追问

**Q1（基础）**：自注意力（Self-Attention）与普通注意力（Cross-Attention）有什么区别？Transformer 为什么需要自注意力？
**回答要点**：

1. 自注意力中 Q、K、V 来自同一序列，而普通注意力中 Q 来自一个序列（如解码器），K、V 来自另一个序列（如编码器）
2. 自注意力让每个位置关注序列中所有其他位置，直接建模全局依赖，不受距离限制
3. 自注意力是 Transformer 解决 RNN 长距离依赖问题的核心机制，同时支持完全并行计算

**Q2（深挖）**：Transformer 是如何解决 RNN 的序列依赖和长距离遗忘问题的？它的计算复杂度代价是什么？
**回答要点**：

1. 自注意力一步到位计算所有位置对的相关性，不存在 RNN 的长期遗忘问题
2. 完全并行化计算，训练效率远高于 RNN 的串行计算方式
3. 代价是 $O(n^2)$ 复杂度和更大的参数量，需要更多数据和计算资源

**Q3（实战）**：你在训练 Transformer 时遇到不收敛或训练震荡的问题，会检查哪些超参数或技巧？
**回答要点**：

1. 使用 learning rate warmup + 衰减策略，避免训练初期梯度爆炸
2. 标签平滑（label smoothing）防止过自信，检查梯度范数是否异常
3. 调整 dropout 比例，验证 Pre-LN 还是 Post-LN 结构，确保序列长度 padding 效率

**Q4（边界）**：自注意力 $O(n^2)$ 的计算复杂度是 Transformer 的公认瓶颈。目前有哪些主流方案来解决长序列问题？
**回答要点**：

1. 稀疏注意力（Longformer、BigBird）使用滑动窗口 + 全局 token，降低计算范围
2. 线性注意力（Performer）用核方法近似标准注意力，将复杂度降至 $O(n)$
3. Flash Attention 通过 IO-aware 算法优化访存效率，Mistral 采用滑动窗口注意力在实际应用中提速
