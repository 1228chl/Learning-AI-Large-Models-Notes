# 分词算法

## 定义

分词（Tokenization）是将文本切分为**最小语义单元**（Token）的过程，是 NLP 所有任务的第一步。不同语言和场景采用不同的分词策略。

## 三大类分词

| 方法 | 原理 | 代表 | 语言 |
|------|------|------|:----:|
| **词级分词** | 按词或词组切分 | jieba（中文）、空格分词（英文） | 中、英 |
| **字符级分词** | 按单个字符切分 | 中文字符级 | 中文 |
| **子词分词** | 在词和字符之间平衡 | BPE、WordPiece、SentencePiece | 通用 |

## BPE（Byte-Pair Encoding）

最流行的子词分词算法，通过**迭代合并最频繁的字符对**来构建词表：

```python
# 1. 初始化：每个字符作为独立 token
# 2. 统计相邻字符对的频次
# 3. 合并频次最高的字符对为新的 token
# 4. 重复 2-3 直到达到目标词表大小
```

**优势**：可以处理 OOV（未登录词）问题，任何词都可以分解为已知子词。

```python
from transformers import AutoTokenizer

# BERT 使用 WordPiece（类似 BPE）
tokenizer = AutoTokenizer.from_pretrained("bert-base-chinese")  # 加载预训练的 BERT 中文分词器

tokens = tokenizer.tokenize("我爱自然语言处理")                 # 将句子切分为 WordPiece 子词 token 列表
print(tokens)            # ['我', '爱', '自', '然', '语', '言', '处', '理']
print(tokenizer.encode("我爱自然语言处理"))                     # 将句子转为 token ID 序列，含 [CLS] 和 [SEP]
# [101, 2769, 4263, 572, 5085, 6443, 4086, 4495, 6895, 102]
```

## 主流分词器对比

| 分词器 | 算法 | 词表大小 | 代表模型 |
|:------:|:----:|:--------:|----------|
| **BPE** | 字节对编码 | 50K | GPT 系列、RoBERTa |
| **WordPiece** | 似然最大化合并 | 30K | BERT |
| **Unigram LM** | 基于语言模型概率剪枝 | — | XLNet、ALBERT |
| **SentencePiece** | 将原始文本（含空格）视为字符流 | — | T5、LLaMA |
| **jieba** | 基于词典和 HMM | — | 中文分词（独立使用） |

## ML 中的分词

| 应用场景 | 分词器 | 说明 |
|----------|:------:|------|
| **BERT 文本分类** | WordPiece | 将句子转为 token IDs + attention mask |
| **GPT 文本生成** | BPE | 自回归逐个 token 生成 |
| **LLaMA 推理** | SentencePiece (BPE) | 处理多语言 |
| **中文 NLP** | jieba 分词 | 中文预处理（推荐先分词再训练） |

```python
# jieba 中文分词示例
import jieba


text = "自然语言处理是人工智能的一个重要分支"   # 待分词的中文输入文本

words = jieba.lcut(text)                       # 精确模式：jieba 精确切分，不产生冗余词
# ['自然语言', '处理', '是', '人工智能', '的', '一个', '重要', '分支']
```

## 面试追问

**Q1（基础）**：词级分词、字符级分词和子词分词各有什么优缺点？在什么场景下选择哪种？
**回答要点**：

1. 词级分词词表大但语义保留好，适合语义理解任务和传统 NLP 流程
2. 字符级分词无 OOV 但序列变长且丢失词义，适合低资源语言或拼写敏感的场景
3. 子词分词在词和字符间取得平衡，覆盖率和效率兼顾，是现代 LLM 的主流选择

**Q2（深挖）**：BPE 算法的核心步骤是什么？它为什么能处理未登录词（OOV）问题？
**回答要点**：

1. 从字符级初始化开始，迭代统计相邻字符对频次并合并最高频次对，直至达到目标词表大小
2. 任何词都能分解为已有的子词片段，因此不存在严格意义上的未登录词
3. 词表大小可控，在覆盖率和编码效率之间取得平衡，兼顾压缩率和泛化能力

**Q3（实战）**：在一个中文 NLP 项目中，你对输入文本会先用 jieba 分词还是直接用 BERT 的 WordPiece？分享你的经验和理由。
**回答要点**：

1. BERT 的 WordPiece 已在字符级别处理中文，直接使用模型内置 tokenizer 通常效果更好且省去预处理环节
2. jieba 分词在传统机器学习或特征工程场景下更有用，可提取有意义的词级特征用于分类或检索
3. 深度学习任务中优先使用模型内置 tokenizer，确保训练和推理时分词一致性，避免数据泄露风险

**Q4（边界）**：BPE 分词有哪些已知的局限性？在什么场景下它的效果会变差？
**回答要点**：

1. 纯统计方法，无语言学动机，可能切分语义完整的词，影响下游任务的语义理解
2. 跨语言时同一词的切分不一致，对形态丰富的语言（如土耳其语）会产生超长序列
3. 无法感知词法边界，在拼写错误或噪声文本上容易产生不可预测的切分结果
