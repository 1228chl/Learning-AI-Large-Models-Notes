# 自然语言处理概述

## 定义

自然语言处理（Natural Language Processing，简称 NLP）是计算机科学、人工智能与语言学交叉的核心研究领域，根本目标是让计算机能够**理解、解释和生成人类语言**。

从数学视角看，NLU 是从文本序列到语义空间的映射 $f: \mathcal{X} \rightarrow \mathcal{Y}$，NLG 是给定表示生成目标序列 $P(\mathbf{y} \mid \mathbf{z})$。

NLP 的两大核心子领域：

| 子领域 | 全称 | 核心任务 | 典型应用 |
|:-------|:-----|:---------|:---------|
| **自然语言理解（NLU）** | Natural Language Understanding | 词义消歧、句法分析、语义角色标注、意图识别、情感分析、实体抽取 | 问答系统、智能客服、搜索引擎查询理解 |
| **自然语言生成（NLG）** | Natural Language Generation | 根据结构化数据或语义表示生成自然语言文本 | 机器翻译、对话系统回复生成、报告自动撰写 |

## NLP 面临的核心挑战

人类语言的歧义性和上下文依赖性是 NLP 困难的根本原因：

| 挑战类型 | 说明 | 示例 |
|:---------|:-----|:------|
| **歧义性** | 词汇、句法、语义层面均存在多种解释 | "他吃了一个苹果公司的香蕉" — 苹果公司 vs 水果 |
| **上下文依赖** | 一词多义需靠上下文消解 | "我去银行取钱" vs "河边的银行" |
| **指代消解** | 代词或别名需指向真实实体 | "小明说他没有吃饭" — "他"指小明 |
| **常识推理** | 需要世界知识和因果推断 | "她淋雨后感冒了" — 隐含因果关系 |
| **语言多样性** | 同一意思可用无数种不同句式表达 | "快一点" vs "加速" vs "搞快点" |
| **低资源语言** | 缺乏标注数据的语言难以训练模型 | 许多少数民族语言、方言 |

## 发展简史（四大阶段）

NLP 的发展经历了四个主要范式：

| 阶段 | 时间 | 核心方法 | 代表成果 | 局限性 |
|:-----|:----|:---------|:---------|:-------|
| **规则驱动** | 1950s-1980s | 手写语法规则、基于词典 | 基于规则的机器翻译（Georgetown实验） | 规则覆盖不全，难以处理歧义 |
| **统计学习** | 1990s-2000s | HMM、最大熵、朴素贝叶斯、SVM | 统计机器翻译（IBM Model）、N-gram语言模型 | 需要大量特征工程，无法捕捉深层语义 |
| **深度学习** | 2010s | LSTM、CNN、Attention、Word2Vec | Seq2Seq + Attention 机器翻译 | 需大量标注数据，训练成本高 |
| **预训练大模型** | 2018-至今 | Transformer、BERT、GPT、LLaMA | GPT-4、Claude、BERT 微调范式 | 算力需求巨大，推理成本高，可解释性差 |

### 关键里程碑

- **2013**：Word2Vec（Mikolov）— 词向量的分布式表示，开启表示学习时代
- **2014**：Seq2Seq + Attention（Bahdanau）— 注意力机制解决长序列问题
- **2017**：Transformer（Vaswani）— "Attention is All You Need"，自注意力彻底取代 RNN
- **2018**：BERT（Devlin）— 双向编码 + MLM 预训练，开启微调范式
- **2020**：GPT-3（Brown）— 1750 亿参数，In-Context Learning 和 Few-shot 能力涌现
- **2022-2025**：ChatGPT / Claude — 指令微调 + RLHF，对话式 AI 全面落地

## 典型应用场景

| 应用 | 涉及的 NLP 技术 | 输入 | 输出 |
|:-----|:----------------|:-----|:-----|
| **语音助手** | ASR + NLU + 对话管理 + TTS | 语音 | 语音/动作 |
| **机器翻译** | 编码器-解码器 + 注意力 | 源语言文本 | 目标语言文本 |
| **搜索引擎** | 查询理解 + 实体链接 + 排序 | 查询词 | 相关文档列表 |
| **智能客服** | 意图识别 + 槽位填充 + NLG | 用户问题 | 回复文本 |
| **情感分析** | 文本分类 | 评论文本 | 情感标签 |
| **命名实体识别** | 序列标注 | 原始文本 | 实体+类型 |
| **文本摘要** | 抽取式/生成式摘要模型 | 长文档 | 简短摘要 |

## ML/DL 应用场景

| 应用场景 | 数学形式 | 说明 |
|:---------|:---------|:------|
| 文本分类 | $\hat{y} = \arg\max_{c} P(c \mid \mathbf{x})$ | 将文档映射到预定义类别，是 NLP 最基础的任务之一 |
| 序列标注 | $\hat{\mathbf{y}} = \arg\max_{\mathbf{y}} P(\mathbf{y} \mid \mathbf{x})$ | 为每个 token 预测标签，用于 NER、词性标注 |
| 机器翻译 | $\hat{\mathbf{y}} = \arg\max_{\mathbf{y}} P(\mathbf{y} \mid \mathbf{x};\theta)$ | 条件语言模型，生成目标语言序列 |
| 句法分析 | $\hat{T} = \arg\max_{T} P(T \mid S)$ | 生成句子的依存树或成分树，揭示语法结构 |
| 指代消解 | 判断 $\text{mention}_i$ 与 $\text{mention}_j$ 是否共指同一实体 | 解决代词"他/她/它"的指代问题 |

## 面试追问

**Q1（基础）**：NLU 和 NLG 有什么区别？举例说明它们在同一个系统中如何配合工作。

**回答要点**：

1. NLU 是从语言输入中提取结构和意义（理解），NLG 是根据结构化表示生成自然语言文本（生成），二者是理解与表达的关系。
2. 在智能客服系统中：首先用 NLU 解析用户问题"我要退订会员"，识别意图为"取消订阅"，提取槽位"会员类型"；然后根据业务逻辑决定回复策略；最后用 NLG 生成回复"请提供您的会员订单号"。
3. 数学视角：NLU 是 $f: \mathcal{X} \rightarrow \mathcal{Z}$（文本→语义表示），NLG 是 $g: \mathcal{Z} \rightarrow \mathcal{Y}$（语义表示→文本）。

**Q2（深挖）**：为什么深度学习之前的 NLP 方法难以处理语言歧义？Transformer 的出现解决了哪些根本问题？

**回答要点**：

1. 规则和统计方法受限于特征工程——人工设计的特征难以覆盖语言中所有的歧义模式；N-gram 模型只能捕捉局部上下文，无法利用远距离信息消歧。
2. Transformer 的自注意力机制允许每个 token 直接关注序列中所有其他 token，能捕捉长距离依赖关系，从根本上解决了上下文建模问题。
3. 预训练范式（BERT/GPT）让模型在海量无标注语料上学习通用语言知识，微调时只需少量标注数据即可适配下游任务，大幅降低了标注成本。

**Q3（实战）**：如果你要为某个特定领域（如医疗、法律）构建 NLP 应用，你会如何选择技术方案？预训练模型还是传统方法？

**回答要点**：

1. 首选预训练模型 + 领域微调：选一个通用预训练模型（如 BERT-base），用领域语料做继续预训练（Domain-adaptive Pretraining），再在标注数据上微调。这是当前工业界的主流方案。
2. 若标注数据极少（< 100 条）：用 LLM 的 Few-shot / In-Context Learning 能力做零样本推理，或使用提示词模板配合 GPT-4/Claude 等大模型做知识蒸馏。
3. 若对推理速度有极高要求（毫秒级响应）：考虑蒸馏模型（如 DistilBERT）或 ONNX 量化部署，牺牲少量精度换取速度和成本优势。

**Q4（边界）**：NLP 中的"理解"是真正的理解吗？当前大语言模型的能力是否存在天花板？

**回答要点**：

1. 当前 NLP 系统的"理解"本质上是模式匹配和概率预测——模型根据训练数据中的统计规律预测最可能的输出，并非人类式的语义理解。最有力的证据是模型在面对对抗样本或反事实推理时容易出错。
2. 大模型的天花板包括：幻觉问题（生成看似合理但实际错误的内容）、缺乏真正的因果推理能力、上下文窗口限制（长文本中信息丢失）、知识更新依赖训练数据截止日期。
3. 当前研究前沿试图通过工具调用（搜索、计算器）、检索增强生成（RAG）、思维链推理（CoT）等方式弥补这些不足，但这些仍是外围增强，未改变核心的统计预测本质。
