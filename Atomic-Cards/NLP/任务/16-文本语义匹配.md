# 文本语义匹配

## 定义

文本语义匹配（Text Semantic Matching）是 NLP 的基础任务之一：给定两个文本片段 A 和 B，判断它们的语义是否相似或匹配。该任务广泛应用于问答系统、信息检索、语义搜索、复述识别等场景。

核心直觉：**语义相似的句子即使字面不同，也应被判定为匹配**；反之，字面相近但语义不同的句子应被判定为不匹配。

### 余弦相似度公式

基于嵌入的匹配方法通常使用**余弦相似度**衡量两个向量之间的语义距离：

$$
\cos(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{\|\mathbf{a}\| \|\mathbf{b}\|} = \frac{\sum_{i=1}^{n} a_i b_i}{\sqrt{\sum_{i=1}^{n} a_i^2} \sqrt{\sum_{i=1}^{n} b_i^2}}
$$

其中：
- $\mathbf{a}, \mathbf{b}$ 分别为句子 A 和句子 B 的嵌入向量
- $a_i, b_i$ 为向量在第 $i$ 维的分量
- $n$ 为嵌入向量的维度
- $\cos(\mathbf{a}, \mathbf{b}) \in [-1, 1]$，值越接近 1 表示语义越相似

## 核心方法

### 基于 Prompt 的 LLM 方法

使用大语言模型直接判断句子对的语义相似性，核心在于设计清晰的 prompt 指令：

```text
现在你需要帮助我完成文本匹配任务，当我给你两个句子时，
你需要回答我这两句话语义是否相似。
句子一: ...
句子二: ...
你只能回答"是"或者"不是"，不能回答别的内容。
```

**优点**：无需训练数据，零样本即可推理，适合冷启动场景。
**缺点**：推理成本高，响应延迟大，对长文本或复杂语义的稳定性较差。

### 基于嵌入的方法

将两个文本分别通过嵌入模型（如 Sentence-BERT、text2vec）转化为固定长度的向量，然后用余弦相似度打分：

```python
import numpy as np

def cosine_similarity(vec_a, vec_b):
    dot = np.dot(vec_a, vec_b)
    norm_a = np.linalg.norm(vec_a)
    norm_b = np.linalg.norm(vec_b)
    return dot / (norm_a * norm_b)

# 假设已通过嵌入模型得到向量
# vec_a = embed("股票市场今日大涨")
# vec_b = embed("持续上涨的市场让投资者感到满意")
# score = cosine_similarity(vec_a, vec_b)  # 接近 1
```

**优点**：速度快，可预计算和缓存向量，适合大规模候选集检索。
**缺点**：无法捕捉句子对之间的交互信息，对细粒度语义差异区分能力有限。

### 基于 BERT 的方法

将句子对拼接后输入 BERT，使用 [CLS] 位置的输出向量接分类层做二分类：

```text
输入: [CLS] 句子A [SEP] 句子B [SEP]
                        ↓
                    BERT 编码器
                        ↓
              [CLS] 向量 → Linear → Softmax
                        ↓
                   相似/不相似
```

```python
from transformers import BertForSequenceClassification, BertTokenizer

model = BertForSequenceClassification.from_pretrained(
    'bert-base-chinese', num_labels=2
)
tokenizer = BertTokenizer.from_pretrained('bert-base-chinese')

def predict(text_a, text_b):
    inputs = tokenizer(
        text_a, text_b,
        return_tensors='pt',
        truncation=True, padding=True
    )
    outputs = model(**inputs)
    logits = outputs.logits
    return logits.argmax().item()  # 0: 不相似, 1: 相似
```

**优点**：通过注意力机制捕捉句子对间的交互信息，精度通常最高。
**缺点**：需要标注数据微调，推理时需同时编码两个句子，无法预计算。

## ML/DL 应用场景

| 应用场景 | 数学形式 | 说明 |
|:---------|:---------|:-----|
| 问答匹配 | $\text{sim}(q, a) = \cos(e_q, e_a) \quad \text{或} \quad P(\text{match} \mid [\text{CLS}])$ | 判断用户问题与候选答案是否语义匹配，用于 FAQ 检索和问答系统 |
| 语义搜索 | $\text{score}(q, d) = \cos(E_q, E_d)$ | 将查询和文档编码为嵌入向量后计算余弦相似度，实现语义级别的文档检索 |
| 信息检索精排 | $P(\text{rel} \mid q, d) = \text{softmax}(W \cdot h_{[\text{CLS}]})$ | 对粗召回结果使用 Cross-Encoder 做精细排序，提升搜索相关性 |
| 复述识别 | $P(\text{para} \mid s_1, s_2) = \sigma(W \cdot [h_1; h_2])$ | 判断两个句子是否互为同义改写，用于文本去重和数据清洗 |
| 自然语言推理 | $P(y \mid p, h) = \text{softmax}(W \cdot h_{[\text{CLS}]}) \quad y \in \{\text{蕴含, 矛盾, 中立}\}$ | 判断前提与假设之间的逻辑关系，用于事实验证和一致性检测 |

## 方法对比

| 方法 | 是否需要标注数据 | 推理速度 | 精度上限 | 典型场景 |
|:----:|:----------------:|:--------:|:--------:|:--------|
| Prompt-LLM | 否（零样本） | 慢 | 中 | 冷启动、快速验证 |
| 嵌入 + 余弦相似度 | 否（可用预训练嵌入） | 快 | 中低 | 大规模候选检索 |
| BERT 拼接分类 | 是（需微调） | 中 | 高 | 精排、高精度匹配 |

## 应用场景

| 场景 | 说明 | 典型方法 |
|:----|:----|:--------|
| **问答匹配** | 判断用户问题与候选答案是否匹配 | BERT 拼接 + 分类 |
| **信息检索** | 检索 query 与文档的相关性排序 | 嵌入检索 + BERT 精排 |
| **语义搜索** | 理解用户搜索意图，匹配语义相似文档 | 嵌入向量 + 余弦相似度 |
| **复述识别** | 判断两个句子是否为同义改写 | BERT 拼接 + 分类 |
| **对话系统** | 匹配用户意图与知识库中的标准问 | 嵌入 + 相似度排序 |
| **文本去重** | 检测大规模语料中的语义重复文本 | 嵌入向量 + 聚类/相似度 |
| **自然语言推理** | 判断前提与假设的蕴含/矛盾/中立关系 | BERT 拼接 + 多分类 |

## 面试追问

**Q1（基础）**：文本语义匹配和文本分类有什么本质区别？为什么文本匹配通常需要特殊的模型架构？
**回答要点**：

1. 文本分类是单输入 → 单标签，模型只需理解单个文本的语义即可做出判断；文本匹配是双输入 → 关系标签，模型需要理解两个文本之间的语义关系。
2. 文本匹配需要捕捉句子对之间的交互信息（如对齐、对比、推理），简单的单塔分类模型无法处理这种交互。
3. 因此文本匹配通常使用 Siamese 网络（双塔结构，共享权重的嵌入模型）或 Cross-Encoder（拼接 BERT 结构）。

**Q2（深挖）**：基于嵌入的方法（双塔）和基于 BERT 拼接的方法（单塔/Cross-Encoder）各自的优缺点是什么？在实际项目中如何选择？
**回答要点**：

1. 双塔（嵌入 + 余弦相似度）：速度快，可预计算向量，适合大规模候选检索（如百万级），但双塔之间缺乏交互，精度较低。
2. 单塔（BERT 拼接）：精度高，通过注意力机制充分交互，但推理时必须同时编码两个句子，无法预计算，适合精排阶段（如几十到几百个候选）。
3. 实际项目通常采用**召回 + 精排**的两阶段架构：先用双塔做粗召回（海量候选 → 几百个），再用单塔做精排（几百个 → 排序结果）。

**Q3（实战）**：你在使用基于 BERT 的文本匹配模型时，训练数据的正负样本比例如何设计？有什么经验技巧？
**回答要点**：

1. 正负样本比例建议 1:1 到 1:3，过高的负样本比例会导致模型偏向负类；过低的负样本比例会导致模型对不匹配的区分能力差。
2. 负样本要注重**难负样本挖掘**：选择那些字面相似但语义不匹配的句子对作为负样本，而不是随机采样，这样可以显著提升模型区分能力。
3. 可使用 In-batch Negative 策略：在一个 batch 内，将其他句对的正样本作为当前句对的负样本，在不增加额外计算量的情况下扩充负样本数量。

**Q4（边界）**：文本匹配中的"匹配"和 NLI（自然语言推理）中的"蕴含"有什么区别？为什么需要区分这两个概念？
**回答要点**：

1. 文本匹配要求两个句子语义**相似**（等价关系），即它们表达的意思基本一致；NLI 中的蕴含要求一个句子**推理出**另一个句子（单向关系），二者不一定语义等价。
2. 例如："小明养了一只猫" 蕴含 "小明养了一只宠物"，但这两句话并不语义相似（匹配为"不相似"）。
3. 在实际应用中需要根据任务目标选择合适的关系定义：搜索场景需要匹配/相似，知识推理场景需要蕴含关系。
