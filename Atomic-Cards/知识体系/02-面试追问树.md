# 面试追问树

## 定义

面试追问树从核心知识点出发，沿**深度和广度**展开追问链路，帮助构建完整的知识体系并应对面试中的层层深入提问。

## RNN 追问树

```python
RNN 是什么？
  ├─ 为什么 RNN 适合序列数据？
  │   └─ 参数共享、循环连接
  ├─ RNN 有什么局限？
  │   ├─ 梯度消失 → 为什么？(连乘 < 1)
  │   │   └─ 如何解决？→ LSTM（门控机制）
  │   └─ 梯度爆炸 → 如何解决？→ 梯度裁剪
  ├─ LSTM 比 RNN 好在哪里？
  │   ├─ 遗忘/输入/输出门
  │   └─ 细胞状态（加法梯度流）
  ├─ GRU 和 LSTM 的区别？
  │   └─ 参数更少，效果相当
  └─ 现在为什么不用 RNN 了？
      └─ Transformer 并行 + 长距离
```

## Transformer 追问树

```python
Transformer 的核心创新？
  ├─ 自注意力是什么？
  │   ├─ Q, K, V 分别是啥？
  │   ├─ 为什么要除以 √dₖ？→ 防止 softmax 饱和
  │   └─ 多头注意力的作用？→ 多种关系模式
  ├─ 为什么需要位置编码？
  │   ├─ 自注意力是排列不变的
  │   └─ Sinusoidal vs RoPE 的区别？
  ├─ 为什么用 LayerNorm 不用 BatchNorm？
  │   └─ 序列变长、不依赖 batch
  ├─ 残差连接的作用？
  │   └─ 梯度直通、深层训练
  └─ Transformer 计算复杂度？
      └─ O(n²·d) → 长序列怎么优化？→ Flash Attention / 稀疏注意力
```

## BERT vs GPT 追问树

```python
BERT 和 GPT 的区别？
  ├─ 架构：编码器 vs 解码器
  ├─ 注意力：双向 vs 掩码自注意力
  ├─ 训练任务：MLM vs 下一个词预测
  ├─ 适合：理解 vs 生成
  ├─ 为什么 GPT 能 zero-shot？→ 自回归 = 语言模型
  └─ 为什么 BERT 微调效果好？→ 双向编码 = 更丰富表示
```

## ML 基础追问树

```python
过拟合是什么？如何解决？
  ├─ 原因：模型太复杂 / 数据太少 / 噪声
  ├─ 诊断：训练误差低，验证误差高
  ├─ 解决：
  │   ├─ 增加数据 / 数据增强
  │   ├─ 降低模型复杂度
  │   ├─ 正则化（L1/L2/Dropout）
  │   └─ 早停（Early Stopping）
  └─ 欠拟合是什么？→ 模型太简单
```

## 面试追问

**Q1（基础）**：面试追问树的结构是什么样的？它和普通的面试题集有什么本质区别？

**回答要点**：①以核心知识点为根节点，沿深度（原理追问）和广度（横向对比）两个维度展开分支；②普通题集是平铺罗列，追问树是层次化、链路式的——每个分支代表一条可能被面试官深挖的追问路径；③核心价值在于训练「被打断后接回主线」的能力，而非死记硬背答案。

**Q2（深挖）**：对比 BERT 和 GPT 的追问树——为什么 BERT 适合理解任务而 GPT 适合生成任务？能否从注意力机制和训练目标两个角度解释？

**回答要点**：①注意力机制：BERT 使用双向自注意力（编码器），每个 token 能看到上下文全部信息，适合做「填空/分类」式理解；GPT 使用掩码自注意力（解码器），每个 token 只能看到左侧内容，天然适合「从左到右」的生成。②训练目标：BERT 用 MLM（掩码语言模型）随机遮住 token 让其预测，强调上下文表征；GPT 用自回归下一个词预测，强调序列生成的连贯性。③引申：这也是为什么 BERT 微调效果好（双向编码提供丰富表征），而 GPT 能 zero-shot（自回归即语言模型本身）。

**Q3（实战）**：面试官追问「为什么现在不用 RNN 了」，你应该按什么逻辑组织回答？请用追问树的分支结构模拟你的应答路线。

**回答要点**：①第一层：直接指出 RNN 的核心痛点——梯度消失/梯度爆炸（连乘效应）；②第二层：沿解决路径展开——梯度裁剪解决爆炸，LSTM/GRU 的门控机制和细胞状态（加法梯度流）缓解消失；③第三层：终极答案——Transformer 的自注意力机制实现了并行计算 + 长距离依赖捕获，从根本上替代了 RNN 的循环结构；④加分项：提及 Mamba / RWKV 等状态空间模型作为 RNN 思想在 Transformer 时代的新变体。

**Q4（边界）**：追问树作为面试准备工具，存在哪些固有局限？过度依赖追问树可能带来什么风险？

**回答要点**：①局限性：追问树是静态的，而技术领域（尤其是大模型方向）更新极快，树上的分支可能半年后就过时了（如 LLM 追问树需要不断补充 Mamba、MoE、Multi-Query Attention 等新内容）；②风险：过分依赖树的固定分支可能导致思维僵化，实际面试中面试官可能从树之外的交叉领域提问（如「Transformer 的 KV Cache 如何影响后端部署的资源规划」是跨层级问题）；③补充建议：追问树应搭配项目经验复盘和系统设计练习使用，不能作为唯一的准备手段。
