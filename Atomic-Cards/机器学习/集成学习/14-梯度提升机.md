# 梯度提升机（GBDT / XGBoost / LightGBM）

## 定义

梯度提升（Gradient Boosting）是 Boosting 流派中最成功的方法。它**串行**训练决策树，每棵新树学习**前一棵树的残差**（实际值 - 预测值），逐步降低整体偏差。

## 直观理解

### 梯度提升的残差拟合机制

梯度提升的直觉：第一个模型做出预测后，计算预测值与真实值之间的**残差**（即错误）。第二个模型专门学习这个残差，试图修正第一个模型的错误。第三个模型学习第二个模型修正后的残差……如此串行推进，每一步都在减少整体误差。

在 GBDT 中，"学习残差"等价于**拟合损失函数的负梯度方向**——这正是"梯度提升"名称的来源：每棵树都在做函数空间的梯度下降。

### XGBoost vs LightGBM vs 原生 GBDT

- **原生 GBDT**：基础实现，逐层分裂，速度较慢
- **XGBoost**：加入正则化（限制树复杂度）、二阶泰勒展开近似损失、列采样、并行化——Kaggle 竞赛之王
- **LightGBM**：单边梯度采样（GOSS）+ 互斥特征捆绑（EFB），训练速度比 XGBoost 快数倍，适合大数据

### 超参数敏感性

梯度提升对超参数敏感：树的数量（n_estimators）过多容易过拟合，学习率（learning_rate）过低需要更多树，过高会导致跳过最优解。一般调参策略：小学习率 + 适量树，配合早停。

```python
# GBDT（sklearn 原生）：梯度提升决策树分类器
from sklearn.ensemble import GradientBoostingClassifier


gbdt = GradientBoostingClassifier(

    n_estimators=100,   # 串行训练的决策树数量，树越多越容易过拟合

    max_depth=3,        # 每棵树深度较浅（弱学习器），防止单棵树过拟合

    learning_rate=0.1   # 每棵树对最终预测的贡献幅度，越小需要越多树来补偿
)
gbdt.fit(X_train, y_train)  # 串行训练：每棵新树拟合前一棵树的残差
```

## 核心思想

$$
\text{第 t 步:} \quad F_t(x) = F_{t-1}(x) + \eta \cdot h_t(x)
$$

其中 $h_t(x)$ 是拟合**负梯度**（残差方向）的新树， $\eta$ 是学习率。

```python
# 手动理解 GBDT 的串行逻辑：每棵新树学习前一轮的残差
from sklearn.tree import DecisionTreeRegressor

# 第一棵树：直接拟合原始目标值
tree1 = DecisionTreeRegressor(max_depth=3)
tree1.fit(X, y)

residual1 = y - tree1.predict(X)    # 计算残差 = 真实值 - 预测值，下一棵树将学习这个差值

# 第二棵树：拟合残差（即前一棵树的错误部分）
tree2 = DecisionTreeRegressor(max_depth=3)
tree2.fit(X, residual1)

residual2 = residual1 - tree2.predict(X)  # 更新残差，依次递推

# 集成预测 = tree1 + lr * tree2 + lr * tree3 + ... 每棵树乘以学习率逐步逼近真实值
```

## XGBoost — 工业级实现

XGBoost 在原始 GBDT 基础上做了大量优化：

```python
import xgboost as xgb


model = xgb.XGBClassifier(

    n_estimators=200,       # 树的数量，配合早停使用，实际训练可能在达到此值前停止

    max_depth=6,            # 树深度，比GBDT的默认深度大一些，因为XGBoost有正则化控制

    learning_rate=0.1,      # 学习率，每棵树的贡献步长

    subsample=0.8,          # 行采样比例（每棵树只用80%的训练样本），防止过拟合

    colsample_bytree=0.8,   # 列采样比例（每棵树只用80%的特征），类似随机森林增加多样性

    reg_alpha=0.1,          # L1 正则化系数，产生稀疏解

    reg_lambda=1.0,         # L2 正则化系数，控制权重大小防止过拟合

    eval_metric='logloss',  # 评估指标为对数损失，用于监控早停

    early_stopping_rounds=20,  # 验证集指标连续20轮不提升则提前停止训练

    use_label_encoder=False # 不使用旧版标签编码器（新版sklearn兼容）
)

model.fit(
    X_train, y_train,

    eval_set=[(X_val, y_val)],  # 提供验证集用于早停和评估监控

    verbose=False               # 不输出每次迭代的训练日志
)
```

## LightGBM — 更快更强

```python
import lightgbm as lgb


lgb_model = lgb.LGBMClassifier(

    n_estimators=200,       # 最大迭代次数

    num_leaves=31,          # 叶子数（控制树的复杂度），比XGBoost的max_depth更直接控制过拟合

    max_depth=-1,           # 不限制树深度，由num_leaves控制复杂度

    learning_rate=0.1,      # 学习率，越小模型越稳健

    subsample=0.8,          # 行采样比例

    colsample_bytree=0.8,   # 列采样比例

    reg_alpha=0.1,          # L1正则化

    reg_lambda=1.0          # L2正则化
)

lgb_model.fit(
    X_train, y_train,

    eval_set=[(X_val, y_val)],                      # 提供验证集用于监控过拟合

    callbacks=[lgb.early_stopping(20)]              # 回调函数：20轮不提升则早停
)
```

## 三种主流实现对比

| 特性 | GBDT（sklearn） | XGBoost | LightGBM |
|------|:--------------:|:-------:|:--------:|
| **分裂策略** | 逐层分裂（Level-wise） | 逐层分裂 | 逐叶分裂（Leaf-wise） |
| **训练速度** | 慢 | 中 | **最快** |
| **内存占用** | 高 | 中 | **最低** |
| **分类特征** | ❌ 需编码 | ❌ 需编码 | ✅ **原生支持** |
| **缺失值处理** | ❌ 需填充 | ✅ 自动学习分裂方向 | ✅ 自动处理 |
| **GPU 加速** | ❌ | ✅ | ✅ |
| **分布式** | ❌ | ✅ | ✅ |
| **精度** | 基准 | 略高 | 与 XGBoost 相当 |

## 超参数速查

| 参数 | 控制 | 调高 | 调低 |
|------|------|:----:|:----:|
| `n_estimators` | 树的数量 | 过拟合 | 欠拟合 |
| `learning_rate` | 每棵树贡献 | 过拟合 | 欠拟合 |
| `max_depth` / `num_leaves` | 树的复杂度 | 过拟合 | 欠拟合 |
| `subsample` | 行采样比例 | 过拟合 | 欠拟合 |
| `reg_alpha` / `reg_lambda` | 正则化强度 | 欠拟合 | 过拟合 |

> **Kaggle 结构化数据比赛的霸主**。绝大多数表格数据竞赛冠军方案都基于 XGBoost / LightGBM。

## 面试追问

**Q1（基础）**：梯度提升（Gradient Boosting）的核心思想是什么？每棵新树学的是什么？
**回答要点**：

1. 串行训练决策树，每棵新树拟合前一棵树的残差（实际值 - 预测值）的负梯度方向
2. 最终预测是所有树的加权求和 Fₜ(x)=Fₜ₋₁(x)+η·hₜ(x)
3. 通过逐步降低偏差来提升整体性能，每棵树只贡献一小部分（由学习率 η 控制）

**Q2（深挖）**：XGBoost 相比传统 GBDT 做了哪些关键优化？
**回答要点**：

1. 加入正则化项（L1+L2）防止过拟合，并支持列采样增加多样性
2. 对损失函数做二阶泰勒展开，使用梯度和 Hessian 矩阵，收敛更快
3. 支持自动处理缺失值、特征维度并行化、早停机制等工程优化

**Q3（实战）**：LightGBM 的"逐叶分裂"（Leaf-wise）相比 XGBoost 的"逐层分裂"（Level-wise）有什么优势和风险？
**回答要点**：

1. Leaf-wise 每次只分裂增益最大的叶子，能更快降低损失，训练速度更快、内存占用更低
2. 容易长出深度不平衡的树，更容易过拟合，需通过 num_leaves 和 max_depth 限制来防止
3. Level-wise 逐层分裂更保守但更稳定

**Q4（边界）**：梯度提升模型对异常值敏感吗？在什么数据结构下表现不佳？
**回答要点**：

1. 对异常值比随机森林更敏感，异常值产生极大残差，后续树拟合这些噪声导致过拟合
2. 对高维稀疏数据（如文本）不如线性模型加 L1 正则化
3. 分类特征多时 LightGBM 原生支持更好但 XGBoost 需手动编码
