# 文本处理三剑客

## grep — 文本搜索

根据模式搜索文件内容，返回匹配的行：

```bash
grep [选项] "模式" 文件

# 常用用法
grep "error" train.log              # 搜索包含 error 的行
grep -i "warning" train.log         # 忽略大小写
grep -r "import torch" ./src/       # 递归搜索目录
grep -n "accuracy" train.log        # 显示行号
grep -c "epoch" train.log           # 统计匹配次数
grep -A 3 -B 2 "loss:" train.log    # 显示匹配行前后 N 行
grep -v "DEBUG" train.log           # 反向匹配（排除）
```

## sed — 流编辑器

对文本进行替换、删除、插入等操作，常用于批处理：

```bash
sed 's/旧/新/g' file.txt              # 全局替换
sed -i 's/learning_rate: 0.01/learning_rate: 0.001/g' config.yaml  # 原地替换
sed -n '10,20p' train.log            # 打印 10-20 行
sed '/^$/d' file.txt                 # 删除空行
```

## awk — 文本分析工具

按列处理结构化文本，默认按空格/Tab 分割：

```bash
awk '{print $1, $NF}' file.txt        # 打印第一列和最后一列
awk '$3 > 90 {print $1, $3}' score.txt # 条件过滤
awk '{sum+=$1} END {print sum/NR}'   # 计算第一列平均值

# ML 日志分析：提取每个 epoch 的 loss
grep "Epoch" train.log | awk '{print $3, $7}'
```

## ML 中的黄金组合

```bash
# 1. 提取 loss 曲线数据（接 TensorBoard 或 matplotlib）
grep "Train Loss:" train.log | awk '{print $NF}' > train_loss.txt

# 2. 统计错误类型
grep "Error:" train.log | awk '{print $2}' | sort | uniq -c | sort -nr

# 3. 过滤训练日志中的关键指标
grep -E "(Epoch|Test Acc|Best)" train.log

# 4. 批量替换配置文件参数
find configs/ -name "*.yaml" -exec sed -i 's/batch_size: 32/batch_size: 64/g' {} +

# 5. 查看最大的 checkpoint 文件
ls -lh checkpoints/*.pt | awk '{print $5, $NF}' | sort -h

# 6. 从 tensorboard 日志提取标量数据
grep "step_value" events.out.tfevents.* | awk '{print $2, $4}'
```

> 文本三剑客 + `xargs` 是 Linux 命令行数据处理的核心技能，在 ML 日志分析、数据预处理、配置管理中高频使用。

## 面试追问

**Q1（基础）**：grep、sed、awk 三剑客分别适用于什么场景？给出一个最简的使用示例。

**回答要点**：1）grep 用于文本搜索过滤—— `grep "error" train.log` 查找含 error 的行；2）sed 用于流式文本编辑—— `sed 's/old/new/g' file` 执行全局替换；3）awk 用于按列处理结构化文本—— `awk '{print $1, $NF}' file` 打印首列和末列。

**Q2（深挖）**：三剑客在数据处理能力上有什么本质区别？何时应该选择 awk 而非 grep？

**回答要点**：1）grep 擅长行匹配（返回整行），但不支持列处理和算术运算；2）sed 擅长替换/删除/插入操作，状态功能弱；3）awk 是完整的模式扫描语言，支持列分割、算术运算（`$3 > 90`）、内置变量（NR/NF）、数组、循环——当需要按列过滤（第 3 列大于阈值）、跨行聚合（计算平均值）、多条件组合时，awk 无可替代；4）awk 比 grep 慢，但比写 Python 脚本快得多。

**Q3（实战）**：在 ML 训练中如何用三剑客组合分析日志文件？请描述一个完整的处理流程。

**回答要点**：1）实时过滤关键指标：`tail -f train.log | grep -E "(Epoch|Loss|Acc)"`；2）提取 loss 数值画图：`grep "Train Loss" train.log | awk '{print $NF}' > train_loss.txt`；3）统计错误类型频率：`grep "Error:" train.log | awk '{print $2}' | sort | uniq -c | sort -nr`；4）批量修改配置文件：`find configs/ -name "*.yaml" -exec sed -i 's/lr: 0.01/lr: 0.001/g' {} +`；5）提取特定 epoch 区间日志：`sed -n '/Epoch 10/,/Epoch 20/p' train.log`。

**Q4（边界）**：三剑客在处理 GB 级大文件时有什么性能瓶颈？什么情况下应该换用其他工具？

**回答要点**：1）grep/sed/awk 都是单线程处理，对大文件（>10GB）速度有限；2）sed -i 原地修改会创建临时文件，磁盘不足时失败；3）awk 的关联数组在大数据量下占内存较多；4）替代方案：大文件可用 rg（ripgrep，多线程并行更快）；复杂日志解析推荐 Python/pandas 或 PySpark；需要快速预览推荐 less 或 head/tail 分块查看。
