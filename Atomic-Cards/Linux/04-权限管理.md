# 权限管理

## 文件权限表示

Linux 中每个文件都有三组权限（读 r、写 w、执行 x），分别针对三种角色：

```bash
$ ls -l
-rwxr-xr-- 1 user group 1024 Jul 1 10:00 script.sh
^ ^^^^^^^^   ^    ^
| + 权限     用户  组
+
文件类型: -普通文件  d目录  l链接
```

| 权限位 | 含义 | 数值 |
|--------|------|------|
| `r` | 读取文件内容 / 列出目录 | 4 |
| `w` | 修改文件 / 在目录中创建删除文件 | 2 |
| `x` | 执行文件 / 进入目录 | 1 |
| `-` | 无此权限 | 0 |

## chmod — 修改权限

```bash
# 符号模式
chmod u+x script.sh         # 给用户加执行权限
chmod g-w file.txt          # 移除用户组写权限
chmod o+r file.txt          # 给其他人加读权限
chmod a+x script.sh         # 所有人加执行权限

# 数值模式（最常用）
chmod 755 script.sh         # 用户:rwx, 组:r-x, 其他:r-x
chmod 644 data.txt          # 用户:rw-, 组:r--, 其他:r--
chmod 600 id_rsa            # 用户:rw-, 组:---, 其他:---（私钥）

# 递归修改目录
chmod -R 755 /path/to/dir/
```

权限数值计算：`rwx` = 4+2+1 = 7，`r-x` = 4+0+1 = 5，`r--` = 4+0+0 = 4

## chown — 修改所有者

```bash
chown user:group file.txt     # 同时修改用户和组
chown -R user:group /data/    # 递归修改
chown user file.txt           # 只修改用户
```

## ML 中的权限实践

| 场景 | 建议权限 | 说明 |
|------|----------|------|
| **SSH 私钥** | `600`（`-rw-------`） | 私钥必须仅自己可读，否则 SSH 拒绝连接 |
| **脚本文件**（`.sh`） | `755`（`-rwxr-xr-x`） | 可执行，其他人可读 |
| **配置文件**（`.yaml`、`.json`） | `644`（`-rw-r--r--`） | 所有者写，其他人只读 |
| **数据集 / 模型权重** | `644` 或 `755` | 根据是否需要写权限 |
| **共享目录**（多用户协作） | `775`（`-rwxrwxr-x`） | 同组用户可读写 |

```bash
# 典型 AI 训练服务器权限配置
chmod 600 ~/.ssh/id_rsa                 # SSH 安全
chmod 700 ~/.ssh                         # .ssh 目录
chmod 755 /data/datasets/                # 数据集共享
chown -R user:group /data/experiments/   # 实验目录归属
```

## 面试追问

**Q1（基础）**：Linux 文件权限中的 rwx 三组权限位分别代表什么？如何用数值表示和计算？

**回答要点**：1）三组分别对应 owner/group/others，每组包含读(4)、写(2)、执行(1) 三个权限位；2）数值计算为位的加权和：rwx=4+2+1=7，r-x=4+0+1=5，r--=4+0+0=4，---=0；3）典型值：755（rwxr-xr-x，常见可执行文件）、644（rw-r--r--，普通文档）、600（rw-------，SSH 私钥）。

**Q2（深挖）**：chmod 的符号模式（u/g/o/a + -/=）与数值模式（755/644）各自在什么情况下更有优势？

**回答要点**：1）符号模式擅长增量修改—— `chmod u+x script.sh` 只需加一个权限，不影响已有设置；`chmod go-w file` 能批量去掉多个角色的写权限，无需计算新数值；2）数值模式适合精确设置—— `chmod 600 key.pem` 一次到位，确定性高，适合脚本中使用；3）实际中：日常微调用符号模式，安全设置和脚本中用数值模式更可靠。

**Q3（实战）**：在 ML 训练服务器的多用户协作场景中，你会如何规划权限策略？

**回答要点**：1）SSH 私钥必须 600、.ssh 目录必须 700 否则 SSH 拒绝连接；2）共享数据集目录设为 755（owner 写，同组和其他只读），保证所有人都能读取数据；3）实验输出目录设为 775 使同组用户可读写，便于协作调试；4）使用 `chown -R user:group /data/experiments/` 确保归属正确；5）Python 脚本文件设为 755 可执行，配置文件设为 644。

**Q4（边界）**：除了 rwx 基础权限，Linux 还有哪些高级权限机制？分别在什么场景下使用？

**回答要点**：1）SUID（chmod u+s）——当普通用户执行文件时临时获得 owner 权限，如 /usr/bin/passwd 需要写入 /etc/shadow；2）SGID（chmod g+s）——在目录上设置后，子文件继承目录的组，适用于共享协作目录（如 /data/team/）；3）Sticky Bit（chmod +t）——/tmp 目录的典型设置，用户只能删除自己的文件，防止互相误删；4）ACL（setfacl）——提供比 rwx 更细粒度的控制，可为特定用户单独设置权限。
