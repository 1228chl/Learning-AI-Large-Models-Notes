# 文件查看与编辑

## 快速查看

| 命令 | 作用 | 适用场景 |
|------|------|----------|
| `cat` | 一次性输出整个文件 | 小文件、管道传递 |
| `tac` | 反向输出（从尾到头） | 逆序查看 |
| `nl` | 带行号输出 | 查看代码、配置文件 |
| `rev` | 反转每行字符 | 特殊处理需求 |

## 分页查看

```bash
less train.log          # 分页查看（推荐！）
    # 快捷键：空格=下一页, b=上一页, /=搜索, q=退出

more train.log          # 基础分页（功能较少，推荐用 less）
```

## 首尾查看

```bash
head -n 20 train.log    # 查看前 20 行（默认 10 行）
tail -n 20 train.log    # 查看后 20 行
tail -f train.log       # 实时跟踪文件新增内容（Ctrl+C 退出）
tail -n 100 -f train.log  # 从最后 100 行开始跟踪
```

## 统计与比较

```bash
wc -l train.log         # 统计行数
wc -w train.log         # 统计单词数
wc -c train.log         # 统计字节数

diff file1 file2        # 比较两个文件差异
sort file.txt           # 排序
uniq file.txt           # 去重（需先 sort）
```

## ML 中的文件查看场景

```bash
# 1. 实时监控训练日志（最常用）
tail -f logs/train.log | grep -E "(Epoch|Loss|Acc)"

# 2. 查看配置文件
less configs/model.yaml
cat configs/model.yaml | grep -A 5 "model:"  # 查看某段配置

# 3. 快速查看数据集样本数
cat labels.csv | wc -l

# 4. 查看训练结束时的最终结果
tail -n 30 train.log

# 5. 合并多个日志文件
cat logs/run_{1,2,3}.log > all_logs.txt

# 6. 在日志中搜索并显示上下文
grep -n -C 3 "NaN" train.log     # 找到 NaN 出现的位置和周围内容
```

## 面试追问

**Q1（基础）**：cat、less、head、tail 分别适用于什么文件查看场景？各自使用哪个快捷键？
回答要点：1）cat 一次性输出整个文件，适合小文件和管道传递（`cat file | grep pattern`）；2）less 分页查看大文件，支持上下翻页（空格=下一页、b=上一页、/=搜索、q=退出）；3）head -n 20 看文件开头，适合预览首部内容；4）tail -n 20 看文件结尾，tail -f 实时跟踪追加内容（Ctrl+C 退出），是监控日志最常用的命令。

**Q2（深挖）**：less 和 more 有什么关键区别？为什么 less 被推荐为日常使用工具？
回答要点：1）less 支持双向浏览（more 只能向前翻页，less 支持 PageUp/PageDown 上下翻页）；2）less 支持 vi 风格键绑定（j/k 上下移动、G 跳到底部、gg 跳到顶部）；3）less 支持模式搜索（/向下搜索、?向上搜索）、显示行号（-N）、实时跟踪（Shift+F，类似 tail -f）；4）less 启动更快，只读取文件需要的部分而非全部加载到内存，适合大文件；5）基本取代了 more。

**Q3（实战）**：在 ML 训练中如何组合 tail 和其他命令实现高效的日志监控？
回答要点：1）`tail -f train.log | grep -E "(Epoch|Loss|Acc)"`——实时过滤只显示关键指标；2）`tail -f train.log | grep -A 5 "Error"`——出现错误时显示上下文；3）`tail -n 100 -f train.log`——从最后 100 行开始跟踪，避免遗漏近期日志；4）`tail -f train.log | awk '/Epoch/ {print $NF}'`——实时提取 loss 数值；5）配合 `tee` 可同时写入文件和屏幕显示：`tail -f train.log | tee latest.log | grep "Loss"`。

**Q4（边界）**：查看 GB 级超大日志文件时，cat 或 less 会遇到什么问题？有什么替代方案？
回答要点：1）cat 会将整个文件载入终端缓冲区，导致卡死或耗尽内存，应避免使用；2）less 对大文件虽可工作但搜索和翻页会明显变慢；3）替代方案：head/tail 只读取首尾部分；grep 按需搜索，比 cat 后管道更高效；split 分割文件：`split -l 100000 large.log chunk_`；快速查看文件行数用 `wc -l` 预估大小；更快的查看工具如 lnav（增强版 less，支持 SQL 查询日志）。
