# 网络与系统监控

## 远程连接与文件传输

```bash
# SSH 远程登录
ssh user@192.168.1.100               # 基本登录
ssh -p 2222 user@host                # 指定端口
ssh -i ~/.ssh/id_rsa user@host       # 密钥登录
ssh -L 8888:localhost:8888 user@host # 端口转发（远程 Jupyter）

# SCP 文件传输
scp file.txt user@host:/remote/path/           # 本地→远程
scp user@host:/remote/path/file.txt ./         # 远程→本地
scp -r data_dir/ user@host:/remote/dir/        # 递归传输目录

# rsync（增量同步，大型数据传输推荐）
rsync -avz data/ user@host:/remote/data/       # 只传输差异部分
rsync -avz --progress data/ user@host:/data/   # 显示进度
```


## 磁盘与内存监控

```bash
# 磁盘
df -h                   # 查看磁盘分区使用情况（人类可读格式）
du -sh /data/           # 查看目录总大小
du -h --max-depth=1 .   # 查看当前目录下一级子目录大小

# 内存
free -h                 # 查看内存使用情况（-h 人类可读）
free -m                 # 以 MB 为单位

# 系统负载
uptime                  # 查看系统运行时间和平均负载
```

## GPU 监控

```bash
# 最常用：查看 GPU 状态
nvidia-smi              # GPU 型号、显存、温度、进程
watch -n 1 nvidia-smi   # 每秒刷新（Ctrl+C 退出）

# 进阶监控工具（需安装）
gpustat                 # 更友好的 GPU 状态查看
nvtop                   # GPU 版的 htop
nvitop                  # 更全面的 GPU 进程管理
```

## ML 运维常用组合

```bash
# 1. 检查训练环境
nvidia-smi && python -c "import torch; print(torch.cuda.is_available())"

# 2. 空间不足时快速清理
du -sh /tmp/* | sort -hr | head -10     # 找到最大的临时文件
find . -name "*.pt" -size +1G           # 找到大于 1G 的 checkpoint

# 3. 后台训练 + 资源监控
nohup python train.py > train.log 2>&1 &
watch -n 30 nvidia-smi                  # 每 30 秒检查 GPU 状态
tail -f train.log                       # 同时查看日志

# 4. 端口冲突排查
lsof -i :8888                           # 查看端口占用
kill -9 $(lsof -ti :8888)               # 杀掉占用端口的进程

# 5. 多 GPU 训练设置
export CUDA_VISIBLE_DEVICES=0,1,2,3     # 指定可见 GPU
python -m torch.distributed.launch --nproc_per_node=4 train.py
```

## 面试追问

**Q1（基础）**：SSH 远程连接服务器有哪几种常用方式？各自的应用场景是什么？
回答要点：1）密码登录：`ssh user@host`，简单但不安全，不适合自动化；2）密钥登录：`ssh -i ~/.ssh/id_rsa user@host`，使用公钥认证更安全，适合自动化脚本和日常连接；3）指定端口：`ssh -p 2222 user@host`，应对非默认端口配置；4）端口转发：`ssh -L 8888:localhost:8888 user@host`，远程地 Jupyter Notebook 映射到本地浏览器；5）跳板机：`ssh -J jump_user@jump_host user@target_host`，通过堡垒机连接内网服务器。

**Q2（深挖）**：scp 和 rsync 在文件传输场景下有什么本质区别？何时应该选择 rsync？
回答要点：1）scp 是全量复制——每次传输整个文件，适合一次性小文件传输，命令简单直接；2）rsync 是增量同步——只传输差异部分，支持断点续传、压缩传输（-z）、保留权限和时间戳（-a）；3）选择 rsync 的场景：大数据量目录（数据集传输）、需要定期同步（cron 定时 rsync）、网络不稳定（支持断点续传）、需要确认传输进度（--progress）；4）scp 适合：快速传输单个小文件、简单的临时拷贝行为。

**Q3（实战）**：在 ML 训练环境中你如何进行完整的 GPU 状态监控和训练环境检查？
回答要点：1）`nvidia-smi` 查看 GPU 型号、显存占用、温度、功耗和运行中的进程；2）`watch -n 1 nvidia-smi` 每隔 1 秒刷新查看 GPU 实时动态；3）`nvidia-smi | grep python | awk '{print $5}'` 提取占用 GPU 的进程 PID；4）`python -c "import torch; print(torch.cuda.is_available())"` 验证 PyTorch 是否可用 CUDA；5）`gpustat` 提供更简洁的 GPU 状态一览；6）`df -h` 和 `free -h` 检查磁盘空间和内存，防止训练中途因资源不足失败。

**Q4（边界）**：使用 SSH 密钥登录时有哪些常见的安全风险？如何防范？
回答要点：1）私钥泄露：id_rsa 被窃取——必须设 600 权限（否则 SSH 拒绝），建议加 passphrase 保护密钥文件；2）私钥遗失：更换密钥时需在所有服务器上更新 authorized_keys；3）SSH 暴力破解：建议禁用密码登录（只允许密钥）、更换非默认端口（22 改为高端口）、使用 fail2ban 封禁攻击 IP；4）转发风险：启用 SSH Agent Forwarding 时，跳板机被攻破会暴露本地私钥——用 -J 跳板机模式或 ProxyJump 替代；5）审计建议：定期轮换密钥、使用 SSH CA 签名证书统一管理。
