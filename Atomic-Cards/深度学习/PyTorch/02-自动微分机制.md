# 自动微分机制

## 定义

自动微分（Automatic Differentiation, AD）是 PyTorch 的核心功能。它通过**记录所有张量操作**构建**有向无环图（DAG）**，当调用 `.backward()` 时沿着计算图反向传播，自动计算每个张量的梯度。

## 直观理解

### 自动微分的计算图机制

自动微分的核心直觉：**前向传播时记录下所有运算步骤，反向传播时遍历这些步骤自动应用链式法则**。

具体来说，PyTorch 在每次对张量做运算时（如加法、乘法、矩阵乘法），都会在后台构建一个计算图——节点是张量和操作，边是数据流向。当你调用 `loss.backward()` 时，PyTorch 从 loss 节点开始，沿着计算图反向遍历，每到一节点就计算该操作的局部梯度并乘以上游传来的梯度，最终得到每个参数的梯度 $\partial L / \partial \theta$。

### 自动微分 vs 数值微分 vs 符号微分

- **数值微分**：$(f(x+h)-f(x))/h$，近似求导，计算慢且精度低
- **符号微分**：手动推导公式，然后编译成代码，适合小规模
- **自动微分（AD）**：将函数分解为基本操作，在运行时组合这些操作的导数——精确且高效，是深度学习框架的标准方式

```python
import torch

# 核心用法
x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)  # 创建张量并开启梯度追踪，PyTorch将记录所有涉及该张量的运算以构建计算图

y = (x ** 2).sum()              # 前向传播：对x逐元素平方后求和，同时自动构建计算图记录操作链路
y.backward()                    # 反向传播：从y出发沿计算图反向求导，自动计算各叶子节点的梯度

print(x.grad)                   # tensor([2., 4., 6.])  — 输出dy/dx = 2*x 在x=[1,2,3]处的梯度值
```

## 计算图（DAG）

```python
# 计算图结构：x经过平方运算（Pow）得到中间结果，再求和（Sum）得到最终输出y
输入 x → 平方 → 求和 → 输出 y
          ↑       ↑

    grad_fn=<PowBackward>  grad_fn=<SumBackward>  # 每个运算节点自动关联反向传播函数，用于后续链式求导
```

| 组件 | 作用 | 说明 |
|------|------|------|
| **叶子节点** | 用户创建的张量（`required_grad=True`） | 其 `.grad` 存放梯度 |
| **中间节点** | 由运算产生的张量 | 不保留梯度（释放内存） |
| ** `grad_fn` ** | 记录创建该张量的运算 | 反向传播时用于计算梯度 |
| **计算图** | 所有操作构成的 DAG | 动态构建，每次前向重新创建 |

## 关键 API

```python
# 1. 启用/禁用梯度
with torch.no_grad():               # 在推理/评估阶段禁用梯度计算，减少显存占用并加速前向传播

    y_pred = model(X_val)           # 执行模型推理，此过程中不会构建计算图，也不记录grad_fn

# 2. 清零梯度（每轮训练必须）
optimizer.zero_grad()               # 清空优化器中所有参数累积的梯度，防止上一轮的梯度与当前batch累加

# 3. 仅部分参数需要梯度
for param in model.parameters():    # 遍历模型所有参数

    param.requires_grad = False     # 关闭参数的梯度计算，用于迁移学习中冻结预训练层（微调时只更新顶层）

# 4. 梯度累积（模拟大 batch）
loss.backward()                     # 反向传播计算当前小批量的梯度，累加到参数的.grad属性中

if step % accumulation_steps == 0:  # 当累积的小批量步数达到指定值时，才执行一次参数更新
    optimizer.step()                # 使用累积的梯度更新模型参数，等效于更大的batch_size
    optimizer.zero_grad()           # 更新后清空梯度，为下一轮累积做准备
```

## ML 中的自动微分

| 应用场景 | 使用方法 | 说明 |
|----------|----------|------|
| **模型训练** | `loss.backward()` + `optimizer.step()` | 标准训练循环 |
| **推理/评估** | `with torch.no_grad():` | 禁用梯度构建，节省显存 |
| **梯度累积** | 多次 `backward()` 后一次 `step()` | 模拟大批量训练 |
| **梯度裁剪** | `clip_grad_norm_()` 在 `backward()` 之后 | 防止梯度爆炸 |
| **对抗攻击** | 保留计算图生成对抗样本 | `data.grad` 计算扰动 |

## 面试追问

**Q1（基础）**：PyTorch 的自动微分是如何记录计算图的？调用 .backward() 时发生了什么？
**回答要点**：

1. 每次对 requires_grad=True 的张量执行运算时，自动构建一个记录操作的 DAG（有向无环图）
2. 每个节点记录运算类型（grad_fn），边表示数据流向
3. .backward() 从输出节点开始，沿 DAG 反向遍历，链式求导并累加到叶子节点的 .grad 属性

**Q2（深挖）**：为什么推理时要用 torch.no_grad()？它从哪些方面节省资源？
**回答要点**：

1. 禁用计算图构建，不再记录每个操作的 grad_fn，节省显存（中间节点的激活值不再保留供反向使用）
2. 加速推理（省去图构建开销）
3. 推理不需要梯度，no_grad() 是安全且高效的最佳实践

**Q3（实战）**：梯度累积多次 backward() 后一次 step()，需要特别注意什么？
**回答要点**：

1. 每次 backward() 梯度会累加到 .grad，需在累积开始时 zero_grad()
2. 注意 loss 的缩放——梯度累积时每个 micro-batch 的 loss 应除以 accumulation_steps
3. BN 层的统计量在 micro-batch 上更新可能不准确，需调整 momentum 或使用 SyncBN

**Q4（边界）**：PyTorch 的动态图相比 TensorFlow 的静态图有什么优劣？
**回答要点**：

1. 动态图（Define-by-Run）每步重新构建，调试方便，控制流直接用 Python 代码
2. 静态图（Define-and-Run）先建图后执行，可全局优化且部署高效
3. PyTorch 2.0 的 torch.compile 通过 JIT 编译融合两者优势，动态图开发体验 + 静态图执行效率
