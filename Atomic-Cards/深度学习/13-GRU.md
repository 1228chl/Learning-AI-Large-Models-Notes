# GRU

## 定义

门控循环单元（GRU, Gated Recurrent Unit）是 LSTM 的简化变体，由 Cho 等人于 2014 年提出。它将 LSTM 的三个门**合并为两个门**，去掉独立的细胞状态 $C$ ，参数量更少，计算更快，效果与 LSTM 相当。

$$
z_t = \sigma(W_z \cdot [h_{t-1}, x_t]) \quad \text{更新门}
$$

$$
r_t = \sigma(W_r \cdot [h_{t-1}, x_t]) \quad \text{重置门}
$$

$$
\tilde{h}_t = \tanh(W_h \cdot [r_t \odot h_{t-1}, x_t]) \quad \text{候选状态}
$$

$$
h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t \quad \text{最终状态}
$$

```python
import torch.nn as nn

gru = nn.GRU(input_size=100, hidden_size=256, num_layers=2, batch_first=True)
output, h_n = gru(x)

# 与 LSTM 的对比
lstm = nn.LSTM(100, 256)     # params = 4 × (100×256 + 256×256 + 256) ≈ 365K
gru = nn.GRU(100, 256)       # params = 3 × (100×256 + 256×256 + 256) ≈ 274K
```

## GRU vs LSTM

| 对比 | LSTM | GRU |
|:----:|:----:|:----:|
| **门数量** | 3（遗忘/输入/输出） | **2**（更新/重置） |
| **细胞状态** | 有 $C_t$ | **无**（仅 $h_t$ ） |
| **参数量** | 多（4 组权重） | **少**（3 组权重） |
| **计算速度** | 慢 | **快** |
| **过拟合** | 易过拟合 | **鲁棒** |
| **数据量要求** | 大数据集 | **小数据集友好** |

## 更新门 vs 重置门

| 门 | 公式 | 当值为 0 | 当值为 1 |
|:--:|:----:|:---------:|:---------:|
| **更新门 $z_t$ ** | $\sigma(W_z[h_{t-1}, x_t])$ | 完全忽略新信息（保持旧状态） | 完全使用新信息 |
| **重置门 $r_t$ ** | $\sigma(W_r[h_{t-1}, x_t])$ | 完全忽略过去状态 | 完全考虑过去状态 |

**直观理解**：

- **更新门**：决定过去状态保留多少，新信息加入多少（LSTM 的遗忘门 + 输入门）
- **重置门**：决定如何将过去状态与当前输入结合

## 三种 RNN 选择指南

```python
# 数据量小时：GRU（参数少，不易过拟合）
# 数据量大且需要长程记忆：LSTM
# 简单序列任务：普通 RNN（但需控制层数）
```

| 场景 | 推荐 | 原因 |
|:----:|:----:|------|
| **小数据集** | GRU | 参数少，鲁棒 |
| **大数据集、长序列** | LSTM | 更强的长期记忆 |
| **计算资源受限** | GRU | 更快，更省显存 |
| **需要可解释性** | GRU | 结构更简单 |
| **简单序列任务** | RNN | 够用且快 |

## ML 中的 GRU

| 应用场景 | 说明 |
|----------|------|

## 面试追问

**Q1（基础）**：GRU 相比 LSTM 做了哪些简化？这带来了什么优缺点？

**回答要点**：将遗忘门和输入门合并为更新门，去掉独立的细胞状态 C_t，仅保留隐藏状态 h_t；参数量从 4 组降为 3 组，计算更快更省显存；缺点是表达能力在理论上略弱于 LSTM，超长序列任务中可能不如 LSTM。

**Q2（深挖）**：GRU 的更新门如何等价实现 LSTM 中遗忘门和输入门的功能？

**回答要点**：更新门 z_t 同时控制遗忘旧信息和新信息融入：h_t = (1-z_t)⊙h_{t-1} + z_t⊙h̃_t；当 z_t 接近 0 时相当于遗忘门关闭、保留旧状态；当 z_t 接近 1 时相当于输入门打开、完全使用新信息；两者互补，无需独立控制。

**Q3（实战）**：什么业务场景下你会优先选择 GRU 而不是 LSTM？

**回答要点**：数据量较小时 GRU 参数更少不易过拟合；计算资源受限（移动端/边缘设备）GRU 推理更快；中等长度序列任务（文本情感分类、短文本编码）GRU 效果与 LSTM 相当；快速迭代实验中 GRU 训练速度优势明显。

**Q4（边界）**：GRU 在超长序列（200+ 时间步）上与 LSTM 相比有什么不足？

**回答要点**：缺少独立的细胞状态 C_t，梯度只能通过 h_t 传播，长程记忆能力弱于 LSTM；LSTM 的细胞状态 C_t 提供了更稳定的梯度高速公路；实践中在处理长文档、音频等长序列时 LSTM 仍略优于 GRU。
