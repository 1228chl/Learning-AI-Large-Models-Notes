# 分布式训练

## 定义

分布式训练是将模型训练任务拆分到**多个 GPU/多台机器**上并行执行的技术，用于解决单卡显存不足和训练时间过长的问题。核心思想是**并行计算梯度**，然后**同步或异步更新参数**。

## 为什么需要分布式训练

| 场景 | 模型规模 | 单卡显存需求 | 方案 |
|:-----|:---------|:------------|:------|
| BERT-base 微调 | 1.1 亿参数 | ~16 GB（FP32） | 单卡可训 |
| LLaMA-7B 微调 | 70 亿参数 | ~56 GB（FP16） | 单卡不够 |
| LLaMA-65B 微调 | 650 亿参数 | ~520 GB | 多卡必须 |
| GPT-3 训练 | 1750 亿参数 | ~数 TB | 上千卡集群 |

## 三大并行策略

### 数据并行（Data Parallelism）

每张卡持有完整模型副本，将数据切分到各卡独立计算梯度，然后同步梯度：

```
Batch 0 → 卡0 → 前向+反向 → 梯度 g0 ─┐
Batch 1 → 卡1 → 前向+反向 → 梯度 g1 ─┤
Batch 2 → 卡2 → 前向+反向 → 梯度 g2 ─┤ → AllReduce(平均梯度) → 各卡同步更新
Batch 3 → 卡3 → 前向+反向 → 梯度 g3 ─┘
```

**DDP（Distributed Data Parallel）**：PyTorch 官方推荐的数据并行方案，每卡一个独立进程，通过 NCCL 通信库做梯度 AllReduce。

```python
import torch
import torch.distributed as dist
import torch.nn as nn
from torch.nn.parallel import DistributedDataParallel
from torch.utils.data.distributed import DistributedSampler

# 初始化分布式环境（每个 GPU 进程独立运行）
dist.init_process_group(backend='nccl')          # NCCL 是 GPU 通信的最佳后端
local_rank = dist.get_rank()                      # 当前进程的 GPU 编号
torch.cuda.set_device(local_rank)                 # 每个进程绑定到指定 GPU

# 模型包装为 DDP
model = nn.Linear(100, 10).cuda()
model = DistributedDataParallel(model, device_ids=[local_rank])

# 数据加载器：每个进程只取一部分数据
sampler = DistributedSampler(train_dataset)       # 自动将数据切分到各进程
dataloader = DataLoader(train_dataset, sampler=sampler, batch_size=32)

# 训练循环（与单卡几乎相同）
for epoch in range(10):
    sampler.set_epoch(epoch)                       # 每个 epoch 打乱数据
    for x, y in dataloader:
        loss = model(x).sum()
        loss.backward()                            # DDP 自动梯度同步
        optimizer.step()
```

### 模型并行（Model Parallelism）

将模型的不同层放置在不同 GPU 上，数据依次通过各卡：

```
GPU 0: 层 1-3 → GPU 1: 层 4-6 → GPU 2: 层 7-9 → GPU 3: 层 10-12
         (前向: 卡0→卡1→卡2→卡3)
         (反向: 卡3→卡2→卡1→卡0)
```

**流水线并行（Pipeline Parallelism）**：将 batch 进一步切分为 micro-batch，让各卡同时在处理不同 micro-batch，减少空闲等待时间（GPipe / PipeDream）。

### 张量并行（Tensor Parallelism）

将单个层的计算（如矩阵乘法）拆分到多个 GPU 上并行计算：

$$
\text{FFN}(x) = \underbrace{W_1}_{\text{GPU 0+1}} \cdot \underbrace{\text{ReLU}(W_2 \cdot x)}_{\text{GPU 0+1}}
$$

## 混合精度训练（AMP）

| 精度 | 存储格式 | 显存节省 | 计算速度 | 适用场景 |
|:-----|:---------|:--------:|:--------:|:---------|
| FP32 | 32-bit 单精度 | 基准 | 基准 | 权重更新累加 |
| FP16 | 16-bit 半精度 | 约 50% | 2~8 倍 | 前向/反向计算 |
| BF16 | 16-bit 脑浮点 | 约 50% | 2~8 倍 | 比 FP16 更稳定 |
| INT8 | 8-bit 整型 | 约 75% | — | 推理量化 |

```python
from torch.cuda.amp import autocast, GradScaler

# 混合精度训练：FP16 计算 + FP32 主权重
scaler = GradScaler()                              # 梯度缩放：防止 FP16 下精度丢失

for x, y in dataloader:
    optimizer.zero_grad()

    with autocast():                                # 自动混合精度上下文
        loss = criterion(model(x), y)               # 内部自动选择 FP16/FP32

    scaler.scale(loss).backward()                   # 缩放后的反向传播
    scaler.step(optimizer)                          # 反缩放 + 参数更新
    scaler.update()                                 # 更新缩放因子
```

## ZeRO / FSDP（零冗余优化器）

ZeRO（Zero Redundancy Optimizer）的核心思想是**各卡不再持有完整的优化器状态**，而是分片存储：

| ZeRO 阶段 | 优化器状态 | 梯度 | 模型参数 | 显存节省 |
|:----------|:----------:|:----:|:--------:|:--------:|
| ZeRO-1 | 分片 | 完整 | 完整 | 4 倍 |
| ZeRO-2 | 分片 | 分片 | 完整 | 8 倍 |
| ZeRO-3 (FSDP) | 分片 | 分片 | 分片 | 线性 |

**FSDP（Fully Sharded Data Parallel）**：PyTorch 对 ZeRO-3 的实现，将模型参数、梯度、优化器状态全部切分到各卡，仅在需要时 AllGather 恢复。

## 面试追问

**Q1（基础）**：DataParallel（DP）和 DistributedDataParallel（DDP）的区别是什么？
**回答要点**：

1. DP 是单进程多线程（GIL 限制，主线程成为瓶颈），DDP 是多进程（每个 GPU 独立进程，无 GIL 问题）。
2. DP 每次反向传播后主卡收集所有梯度并更新，通信开销大；DDP 的每个进程独立计算梯度，通过 AllReduce 在通信上更高效。
3. DDP 是官方推荐方案，DP 仅适用于单机小规模实验。

**Q2（深挖）**：混合精度训练中梯度缩放（GradScaler）的作用是什么？为什么 FP16 训练需要它？
**回答要点**：

1. FP16 的数值范围比 FP32 小得多，梯度在反向传播中可能下溢（小于 FP16 可表示的最小正数，变为 0）。
2. GradScaler 在反向传播前将 loss 乘以一个缩放因子，使梯度放大到 FP16 可表示的范围，更新参数时再除以缩放因子恢复。
3. 缩放因子动态调整：如果出现梯度溢出（inf/nan），跳过该步更新并减小缩放因子；如果连续多步正常，增大缩放因子。

**Q3（实战）**：你如何判断一个模型训练任务是否需要分布式训练？8 卡 DDP 的加速比大概是怎样的？
**回答要点**：

1. 判断标准：单卡显存不足（模型参数 + 优化器状态 + batch 数据 > 显存）或训练时间过长（数天以上）。
2. 加速比：DDP 的理论加速比接近线性，实际受通信开销影响。8 卡通常达到 6~7 倍加速（75%~87% 效率），通信占比较小的模型加速比更高。
3. 通信瓶颈：模型越小、batch 越小，通信占比越大，加速比越差。梯度 AllReduce 的通信量 = 参数量 × 4 bytes（FP32）。

**Q4（边界）**：FSDP（ZeRO-3）相比 DDP 在显存节省上的原理是什么？FSDP 的通信开销问题如何缓解？
**回答要点**：

1. FSDP 将模型参数、梯度、优化器状态全部切分到各卡，每卡只存 1/N 的模型状态。但前向/反向时需要 AllGather 恢复完整参数，增加了通信量。可以在前向传播完就释放参数，而不是等整个前向结束。
2. FSDP 的通信量是 DDP 的约 N 倍（N 为卡数），但显存节省是线性的。
3. 缓解策略：设置 `forward_prefetch=True` 预取下一层的参数；对计算量大的层不分片（`wrap_policy` 控制）；使用混合精度配合 FSDP 减少通信数据量。
