# 早停与学习率调度

## 定义

早停（Early Stopping）是一种防止过拟合的正则化技术：**在训练过程中监控验证集性能，当验证集指标不再提升时提前终止训练，在模型泛化能力最佳的时刻保存模型参数**。

形式化定义：令 $f(t)$ 为第 $t$ 个 epoch 后的验证集损失，早停条件为：

$$
\text{stop at } t = \arg\min_{t} f(t), \quad \text{if } f(t) \text{ 连续 } \text{patience} \text{ 轮未更新}
$$

其中 $\text{patience}$ 为容忍轮数，即验证集损失连续多少轮未降低时才触发早停，以抵抗训练过程中的正常波动。

## 早停的直观理解

**训练误差总在下降，但验证误差先降后升**——这就是早停的时机：

```
验证误差
  ↑
  │         ╱╲
  │   ╱╲  ╱  ╲
  │ ╱  ╲╱    ╲  ← 早停点（验证误差最低）
  │╱            ╲
  │              ╲
  ╰──────────────────→ 训练轮数
       ↑          ↑
   欠拟合区间   过拟合区间
```

### 早停参数

| 参数 | 含义 | 推荐值 | 说明 |
|:-----|:-----|:------:|:-----|
| **patience** | 容忍轮数 | 5~20 | 验证损失连续不下降的轮数阈值 |
| **min_delta** | 最小改善量 | 1e-4~1e-3 | 验证损失至少下降多少才算"改善" |
| **restore_best_weights** | 恢复最优权重 | True | 训练结束后是否恢复到验证损失最低的权重 |

```python
import torch

# 早停的简单实现
class EarlyStopping:
    """监控验证损失，在连续 patience 轮未下降时停止训练"""
    def __init__(self, patience=7, min_delta=0.001):
        self.patience = patience          # 最大容忍轮数
        self.min_delta = min_delta        # 最小改善阈值
        self.counter = 0                  # 连续未改善计数
        self.best_loss = float('inf')     # 最佳验证损失
        self.best_state = None            # 最佳模型参数

    def __call__(self, val_loss, model):
        if val_loss < self.best_loss - self.min_delta:
            # 验证损失显著下降，保存当前最佳模型参数
            self.best_loss = val_loss
            self.best_state = {k: v.clone() for k, v in model.state_dict().items()}
            self.counter = 0
        else:
            # 验证损失未改善，计数器加一
            self.counter += 1
            if self.counter >= self.patience:
                # 超过容忍轮数，加载最佳权重并停止训练
                model.load_state_dict(self.best_state)
                return True  # 触发早停
        return False
```

## 学习率调度

### 为什么需要学习率调度

训练初期需要较大的学习率快速收敛，后期需要较小的学习率精细微调，避免在最优解附近震荡。

### 常用调度策略

| 策略 | 更新方式 | 适用场景 | 特点 |
|:-----|:---------|:---------|:-----|
| **Step Decay** | 每 N 轮乘以衰减因子 $\eta_{\text{new}} = \eta \times \gamma$ | 常规训练 | 简单直接，需手动设定衰减点 |
| **Cosine Annealing** | $\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})(1 + \cos(\frac{t}{T}\pi))$ | 对比学习、SGD 训练 | 平滑下降，无需手动设衰减点 |
| **ReduceLROnPlateau** | 验证损失停滞时衰减 | 实际项目首选 | 自适应，根据验证集指标调整 |
| **Warmup** | 前若干步从 0 线性增加到 $\eta$ | 大模型/Transformer | 防止训练初期梯度爆炸 |
| **OneCycleLR** | 先增后减的周期性调度 | 快速训练 | 用更大学习率加速收敛 |

```python
from torch.optim.lr_scheduler import ReduceLROnPlateau, CosineAnnealingLR

optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

# 方案一：自适应调度（推荐，适合大多数项目）
scheduler = ReduceLROnPlateau(
    optimizer,
    mode='min',            # 监控指标越小越好（如验证损失）
    factor=0.5,            # 触发时学习率减半
    patience=3,            # 连续 3 轮未改善时触发衰减
    min_lr=1e-6            # 学习率下限
)

# 训练循环中使用
for epoch in range(100):
    train_loss = train_one_epoch()           # 一轮训练
    val_loss = validate()                     # 验证集评估
    scheduler.step(val_loss)                  # 根据验证损失调整学习率
    current_lr = optimizer.param_groups[0]['lr']
    print(f'Epoch {epoch}: val_loss={val_loss:.4f}, lr={current_lr:.2e}')
```

## 早停 + 学习率调度的联合使用

早停和学习率调度是互补的——前者决定何时停止，后者决定如何优化：

```
for epoch in range(max_epochs):
    train_loss = train_one_epoch()
    val_loss = validate()
    
    scheduler.step(val_loss)         # 学习率自适应调整
    
    if early_stopper(val_loss, model):  # 检查早停条件
        print(f"Early stopping at epoch {epoch}")
        break
```

## ML/DL 应用场景

| 应用场景 | 使用方式 | 说明 |
|:---------|:---------|:------|
| 全监督模型训练 | 监控验证损失，patience=10 | 防止过拟合，节省训练时间 |
| 预训练模型微调 | 监控验证准确率，patience=3~5 | 微调收敛快，早停容忍度更小 |
| Transformer 大模型 | Warmup + Cosine Annealing | 训练初期 warmup 防止梯度爆炸 |
| 对比学习训练 | Cosine Annealing + 早停 | 对比学习需要大量 epoch，早停节约资源 |

## 面试追问

**Q1（基础）**：早停为什么能防止过拟合？它和正则化有什么关系？
**回答要点**：

1. 训练过程是"从简单到复杂"的——模型先学到通用规律（泛化能力提升），后来开始记忆噪声（泛化下降）。早停在验证误差最低点截断，恰好阻止了过拟合阶段。
2. 从优化角度看，早停限制了参数在损失函数平面上移动的"步数"，等效于限制了参数范数的大小，在效果上类似于 L2 正则化。
3. 早停不需要修改损失函数或网络结构，是一种零开销的正则化方法（只需在训练循环中额外做一次验证评估）。

**Q2（深挖）**：ReduceLROnPlateau 和 Cosine Annealing 各有什么优缺点？如何选择？
**回答要点**：

1. ReduceLROnPlateau 自适应强：根据验证集实际表现调整，适合不确定训练动态的场景；但可能因验证集噪声提前触发。
2. Cosine Annealing 无需监控验证集：学习率按余弦曲线平滑下降，适合对比学习等需要大量 epoch 的场景；但需要预设总轮数，训练提前终止时学习率可能未降至最低。
3. 实际项目推荐：常规训练用 ReduceLROnPlateau + 早停，大模型/对比学习用 Warmup + Cosine Annealing + 早停。

**Q3（实战）**：你在训练一个分类模型时，验证损失在第 10 轮开始上升但训练损失还在下降，你会怎么做？
**回答要点**：

1. 这是典型的过拟合信号。首先确认验证损失是否确实在上升（排除验证集噪声），可以增加验证频率或观察 2-3 轮趋势。
2. 触发早停（patience=3~5），加载第 10 轮的模型参数作为最终模型。同时检查学习率是否过大导致震荡。
3. 后续优化：增加 Dropout 或数据增强，降低模型复杂度，或增加验证集数据量。避免在问题阶段的模型上继续训练。

**Q4（边界）**：早停在什么场景下可能失效？如何改进？
**回答要点**：

1. 验证集分布与测试集不一致时，早停选出的模型可能过拟合验证集而非真正泛化——需要确保验证集能代表真实数据分布。
2. 训练过程中验证损失存在多个局部极小值时，早停可能过早停在第一个局部极小而非全局最优——可以尝试增大 patience 或使用模型快照集成（Snapshot Ensembling）。
3. 训练数据本身存在错误标签（噪声）时，验证损失曲线可能不呈现"先降后升"的典型形态——需要先清洗数据或使用标签平滑。
