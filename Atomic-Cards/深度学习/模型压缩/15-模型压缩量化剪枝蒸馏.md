# 模型压缩（量化 / 剪枝 / 蒸馏）

## 定义

模型压缩将大型模型"瘦身"为适合部署的小模型，在尽量保持精度的前提下减小模型大小、降低推理延迟。三种主流技术分别从**数值精度**（量化）、**结构稀疏性**（剪枝）和**模型架构**（蒸馏）三个维度实现压缩。

## 三大技术对比

| 技术 | 原理 | 压缩比 | 精度损失 | 适用阶段 | 详细卡片 |
|:----:|:----|:------:|:--------:|:--------:|:--------|
| **量化** | 降低参数精度（FP32→INT8） | 4x | 小（<1\%） | 训练后 | [19-模型量化(Quantization)](./19-模型量化%28Quantization%29.md) |
| **剪枝** | 移除不重要连接或通道 | 2-10x | 中 | 训练后/训练中 | [20-模型剪枝(Pruning)](./20-模型剪枝%28Pruning%29.md) |
| **蒸馏** | 小模型模仿大模型输出 | 取决于学生模型 | 小 | 训练时 | [21-知识蒸馏(Distillation)](./21-知识蒸馏%28Distillation%29.md) |

## 组合策略

三种技术可按流水线组合以获得最佳部署效果：

1. **蒸馏** — 先用大模型训练小模型（改变架构）
2. **剪枝** — 移除小模型中的冗余参数（改变结构）
3. **量化** — 降低参数精度（压缩每个参数）

前一步的结果决定后一步的上限，顺序一般建议：先蒸馏，再剪枝，最后量化。

## 代码示例：压缩组合流程（PyTorch 风格）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import torch.nn.utils.prune as prune

# 1. 知识蒸馏（KD Loss 示意）
teacher_logits = teacher_model(batch)         # 教师前向
student_logits = student_model(batch)         # 学生前向
kd_loss = nn.KLDivLoss(reduction="batchmean")(
    F.log_softmax(student_logits / T, dim=-1),
    F.softmax(teacher_logits / T, dim=-1)
) * (T ** 2)                                  # 软标签损失 × T² 平衡梯度
ce_loss = nn.CrossEntropyLoss()(student_logits, labels)
loss = alpha * kd_loss + (1 - alpha) * ce_loss

# 2. 通道结构化剪枝
for name, module in student_model.named_modules():
    if isinstance(module, nn.Conv2d):
        prune.l1_unstructured(module, name="weight", amount=0.3)
        prune.remove(module, "weight")

# 3. 训练后动态量化（INT8）
quantized_model = torch.quantization.quantize_dynamic(
    student_model, {nn.Linear}, dtype=torch.qint8
)
```

## 面试追问

**Q1（基础）**：量化和剪枝在减小模型尺寸的原理上有什么本质区别？
**回答要点**：

1. 量化降低每个参数的数值精度（FP32→INT8 减少 4 倍存储），不改变网络结构，对所有参数等比例压缩
2. 剪枝直接移除部分参数（置零），改变网络稀疏度，选择性移除"不重要"的连接或通道
3. 量化可在训练后直接应用无需重训练，剪枝后通常需要微调恢复精度

**Q2（深挖）**：为什么非结构化剪枝在通用 GPU 上难以获得实际加速？
**回答要点**：

1. 非结构化剪枝产生稀疏权重矩阵，但 GPU 的并行计算基于密集矩阵乘法优化，无法直接利用稀疏性
2. 稀疏矩阵需要特殊硬件或库的支持（如 NVIDIA 稀疏张量核心），通用 GPU 无此能力
3. 结构化剪枝（通道/层级别）保持权重为密集矩阵形态，可直接利用 GPU 并行计算获得实际加速

**Q3（实战）**：要将 BERT 模型部署到移动端，你会如何组合三种压缩技术？
**回答要点**：

1. 先用蒸馏将 BERT-large/base 压缩为 TinyBERT 等小模型，大幅减少参数量并保留核心能力
2. 再用训练后动态量化将 FP32 转为 INT8，兼容性好且无需重训练
3. 若仍需减小体积，用结构化剪枝移除不重要的注意力头；推荐顺序为蒸馏→剪枝→量化，前一步的结果决定后一步的上限

**Q4（边界）**：4-bit 量化对 LLM 的生成质量影响有多大？哪些任务损失最明显？
**回答要点**：

1. 4-bit 量化通常保持 90\%+ 的原始质量，但数学推理、代码生成等需要精确数值计算的任务下降明显
2. 量化误差在低比特下逐层累积，长文本生成中可能产生更多幻觉或逻辑断裂
3. 不同量化方法（GPTQ vs AWQ vs GGML）效果差异显著，需针对具体任务评测后选择合适方法
