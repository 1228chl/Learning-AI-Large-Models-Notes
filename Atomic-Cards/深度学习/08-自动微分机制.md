# 自动微分机制

## 定义

自动微分（Automatic Differentiation, AD）是 PyTorch 的核心功能。它通过**记录所有张量操作**构建**有向无环图（DAG）**，当调用 `.backward()` 时沿着计算图反向传播，自动计算每个张量的梯度。

```python
import torch

# 核心用法
x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y = (x ** 2).sum()              # 前向传播：构建计算图
y.backward()                    # 反向传播：自动求梯度
print(x.grad)                   # tensor([2., 4., 6.])
```

## 计算图（DAG）

```python
输入 x → 平方 → 求和 → 输出 y
          ↑       ↑
    grad_fn=<PowBackward>  grad_fn=<SumBackward>
```

| 组件 | 作用 | 说明 |
|------|------|------|
| **叶子节点** | 用户创建的张量（`required_grad=True`） | 其 `.grad` 存放梯度 |
| **中间节点** | 由运算产生的张量 | 不保留梯度（释放内存） |
| ** `grad_fn` ** | 记录创建该张量的运算 | 反向传播时用于计算梯度 |
| **计算图** | 所有操作构成的 DAG | 动态构建，每次前向重新创建 |

## 关键 API

```python
# 1. 启用/禁用梯度
with torch.no_grad():               # 推理时禁用（省显存/加速）
    y_pred = model(X_val)

# 2. 清零梯度（每轮训练必须）
optimizer.zero_grad()               # 或 model.zero_grad()

# 3. 仅部分参数需要梯度
for param in model.parameters():
    param.requires_grad = False     # 冻结参数（微调）

# 4. 梯度累积（模拟大 batch）
loss.backward()                     # 梯度累加到 .grad
if step % accumulation_steps == 0:
    optimizer.step()                # 累积 N 步后更新
    optimizer.zero_grad()
```

## ML 中的自动微分

| 应用场景 | 使用方法 | 说明 |
|----------|----------|------|
| **模型训练** | `loss.backward()` + `optimizer.step()` | 标准训练循环 |
| **推理/评估** | `with torch.no_grad():` | 禁用梯度构建，节省显存 |
| **梯度累积** | 多次 `backward()` 后一次 `step()` | 模拟大批量训练 |
| **梯度裁剪** | `clip_grad_norm_()` 在 `backward()` 之后 | 防止梯度爆炸 |
| **对抗攻击** | 保留计算图生成对抗样本 | `data.grad` 计算扰动 |

## 面试追问

**Q1（基础）**：PyTorch 的自动微分是如何记录计算图的？调用 .backward() 时发生了什么？

**回答要点**：每次对 requires_grad=True 的张量执行运算时，自动构建一个记录操作的 DAG（有向无环图）；每个节点记录运算类型（grad_fn），边表示数据流向；.backward() 从输出节点开始，沿 DAG 反向遍历，链式求导并累加到叶子节点的 .grad 属性。

**Q2（深挖）**：为什么推理时要用 torch.no_grad()？它从哪些方面节省资源？

**回答要点**：禁用计算图构建，不再记录每个操作的 grad_fn；节省显存（中间节点的激活值不再保留供反向使用）；加速推理（省去图构建开销）；推理不需要梯度，no_grad() 是安全且高效的最佳实践。

**Q3（实战）**：梯度累积多次 backward() 后一次 step()，需要特别注意什么？

**回答要点**：每次 backward() 梯度会累加到 .grad，需在累积开始时 zero_grad()；注意 loss 的缩放——梯度累积时每个 micro-batch 的 loss 应除以 accumulation_steps；BN 层的统计量在 micro-batch 上更新可能不准确，需调整 momentum 或使用 SyncBN。

**Q4（边界）**：PyTorch 的动态图相比 TensorFlow 的静态图有什么优劣？

**回答要点**：动态图（Define-by-Run）每步重新构建，调试方便，控制流直接用 Python 代码；静态图（Define-and-Run）先建图后执行，可全局优化且部署高效；PyTorch 2.0 的 torch.compile 通过 JIT 编译融合两者优势，动态图开发体验 + 静态图执行效率。
