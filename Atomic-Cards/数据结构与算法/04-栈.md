# 栈

## 定义

栈（Stack）是一种**后进先出（LIFO, Last In First Out）** 的线性数据结构。只允许在同一端（栈顶）进行插入（push）和删除（pop）操作。

类比：一摞盘子——最后放上去的盘子最先被拿走。

## 核心操作复杂度

| 操作 | 描述 | 时间复杂度 |
|------|------|:----------:|
| `push(x)` | 将元素 x 压入栈顶 | $O(1)$ |
| `pop()` | 弹出栈顶元素 | $O(1)$ |
| `top()` / `peek()` | 查看栈顶元素（不弹出） | $O(1)$ |
| `is_empty()` | 判断栈是否为空 | $O(1)$ |
| `size()` | 返回栈中元素个数 | $O(1)$ |

```python
# Python 中用 list 模拟栈
stack = []

stack.append(1)         # push
stack.append(2)
stack.append(3)
top = stack.pop()       # pop → 3
peek = stack[-1]        # peek → 2
```

## 应用场景

| 场景 | 原理 | 示例 |
|------|------|------|
| **函数调用栈** | 每次函数调用压入栈帧，返回时弹出 | 递归调用的底层实现 |
| **括号匹配** | 左括号入栈，右括号匹配时弹出 | `{[()]}` 合法性检查 |
| **表达式求值** | 操作数栈 + 运算符栈 | 逆波兰表达式计算 |
| **撤销操作（Undo）** | 每次操作入栈，撤销时出栈 | Ctrl+Z |
| **深度优先搜索（DFS）** | 节点入栈，探索到底后回溯 | 迷宫求解、拓扑排序 |
| **回溯算法** | 递归天然使用栈保存状态 | 八皇后、全排列 |

## 栈与递归

递归函数的底层实现就是栈。每次递归调用创建一个新的栈帧（stack frame），保存局部变量和返回地址。递归过深会导致**栈溢出**（Stack Overflow）。

```python
# 递归本质是隐式栈
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

# 手动用栈模拟递归（DFS）
def dfs_iterative(root):
    stack = [root]
    while stack:
        node = stack.pop()
        if node:
            print(node.val)
            stack.append(node.right)   # 注意顺序
            stack.append(node.left)
```


## 面试追问

**Q1（基础）**：栈的 LIFO 特性决定了它适合解决哪类问题？为什么括号匹配用栈而不用队列？
回答要点：栈适合解决需要"最近匹配"或"撤销最近操作"的问题，如括号匹配、函数调用、表达式求值。括号匹配中，最后遇到的左括号必须匹配第一个遇到的右括号（后进先出），而队列的 FIFO 特性是先匹配最老的括号，不符合嵌套规则。

**Q2（深挖）**：递归函数本质上是如何利用栈的？递归过深导致"栈溢出"的内部机制是什么？
回答要点：每次递归调用在调用栈上压入一个新的栈帧，保存局部变量、参数和返回地址；递归返回时弹出栈帧。栈空间是有限的（通常 1-8MB），递归深度太大时栈帧累计超出限制，触发 Segmentation Fault 或 RecursionError。非递归改写（迭代 + 显式栈）可以避免此问题。

**Q3（实战）**：如何用栈实现浏览器的"前进/后退"功能？两个栈如何协同工作？
回答要点：用两个栈——后退栈 A 和前进栈 B。访问新页面时压入 A 并清空 B；点击"后退"时将 A 的栈顶弹出压入 B；点击"前进"时将 B 的栈顶弹出压入 A。两个栈配合可同时支持后退和前进，且访问新页面时清空前进栈符合用户预期（新页面后无法再"前进"到旧页面）。

**Q4（边界）**：用栈模拟递归一定能解决栈溢出问题吗？显式栈 vs 隐式栈各有什么优缺点？
回答要点：显式栈将函数调用栈替换为堆上的数据结构（如 Python list），不受系统栈大小限制；但手动管理状态更复杂（需维护局部变量的等效结构），代码可读性下降。且显式栈的 push/pop 仍有堆内存分配开销，极端情况下递归嵌套极深的 DFS 仍可能耗光系统内存。
