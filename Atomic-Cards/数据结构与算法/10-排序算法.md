# 排序算法

## 常见排序对比

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|------|:----:|:----:|:----:|:----:|------|
| **冒泡排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ | 相邻比较交换 |
| **选择排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ❌ | 每轮选最小 |
| **插入排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ | 小规模+近乎有序时快 |
| **归并排序** | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | ✅ | 分治，稳定 |
| **快速排序** | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ | ❌ | 实际最快 |
| **堆排序** | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | ❌ | 利用堆结构 |
| **计数排序** | $O(n+k)$ | $O(n+k)$ | $O(k)$ | ✅ | 非比较，整数 |
| **基数排序** | $O(dn)$ | $O(dn)$ | $O(n)$ | ✅ | 按位排序 |

## 核心实现

```python
# 快速排序（最常用）
def quick_sort(nums):
    if len(nums) <= 1:
        return nums
    pivot = nums[len(nums) // 2]
    left = [x for x in nums if x < pivot]
    mid = [x for x in nums if x == pivot]
    right = [x for x in nums if x > pivot]
    return quick_sort(left) + mid + quick_sort(right)

# 归并排序
def merge_sort(nums):
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])
    return merge(left, right)

def merge(a, b):
    i = j = 0
    res = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            res.append(a[i]); i += 1
        else:
            res.append(b[j]); j += 1
    return res + a[i:] + b[j:]
```

## 如何选择

```python
# Python 内置排序（Timsort = 归并 + 插入）
sorted(nums)                # 稳定，O(n log n)
nums.sort()                 # 原地排序
```

| 数据特征 | 推荐算法 |
|----------|----------|
| 数据量小（< 50） | 插入排序 |
| 近乎有序 | 插入排序（快速） |
| 数据量大（通用） | 快速排序 / Timsort |
| 要求稳定排序 | 归并排序 / 插入排序 |
| 整数值且范围小 | 计数排序 |
| 链表排序 | 归并排序 |
| 内存极有限 | 堆排序 |

## 面试追问

**Q1（基础）**：快速排序的核心思想是什么？如何选择 pivot？pivot 的选择对性能有什么影响？

**回答要点**：快排核心是分治——选一个 pivot，将数组分为小于 pivot 和大于 pivot 两部分，递归排序左右部分。pivot 选得好（中位数附近）使左右规模均衡，复杂度 $O(n\log n)$ ；每轮选到极端值（最小/最大）导致分区极不平衡，退化为 $O(n^2)$ 。常用策略有：固定选中间/首尾、随机选择、三数取中（首+中+尾取中值）。

**Q2（深挖）**：归并排序和快速排序的稳定性、空间复杂度和最坏情况分别有什么不同？为什么实际工程中快排通常比归并快？

**回答要点**：归并排序稳定、 $O(n)$ 额外空间、最坏 $O(n\log n)$ ；快排不稳定、 $O(\log n)$ 额外空间（递归栈）、最坏 $O(n^2)$ 。快排通常更快是因为：数据局部性好（从两端向中间扫描），缓存命中率高；归并需开辟额外数组做 merge，有大量内存拷贝开销。

**Q3（实战）**：Python 的 Timsort 如何结合插入排序和归并排序的优点？为什么被称为"自适应"排序算法？

**回答要点**：Timsort 将数组分成若干已有序片段（run），每个 run 长度不足时用插入排序（利用其对小规模和部分有序数据高效的特点），再用归并排序合并所有 run。它检测数据中已有有序性（自然 run），对于近乎有序的数据接近 $O(n)$ ，因此称为自适应排序。这是 Python 和 Java 默认排序算法的原因。

**Q4（边界）**：比较排序的时间复杂度下界为什么是 $O(n\log n)$ ？非比较排序（计数排序、基数排序）如何突破这一下界？它们有什么限制？

**回答要点**：基于比较的排序每次比较有 2 种结果， $n$ 个元素的排列有 $n!$ 种可能，因此至少需要 $\log_2(n!) = O(n\log n)$ 次比较。非比较排序利用数据本身的数值特性（如计数排序用桶、基数排序按位处理）绕过比较，可以达到 $O(n)$ 。但限制也很明确：计数排序要求数据范围小且为整数；基数排序适用于固定长度（如定长字符串、整数），且需要额外的辅助空间。
