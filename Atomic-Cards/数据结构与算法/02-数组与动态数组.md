# 数组与动态数组

## 定义

数组（Array）是一种线性数据结构，将相同类型的元素存储在**连续的内存空间**中。通过**索引**（Index）可以在 $O(1)$ 时间内随机访问任意元素。

**动态数组**（如 Python 的 `list`、C++ 的 `vector`）在底层仍是连续数组，但在容量不足时自动**扩容**（通常倍增）。

## 核心操作复杂度

| 操作 | 数组 | 动态数组（均摊） | 说明 |
|------|:----:|:----------------:|------|
| **随机访问** | $O(1)$ | $O(1)$ | 连续内存 + 索引计算 |
| **插入（末尾）** | — | $O(1)$ | 通常 $O(1)$ ，扩容时 $O(n)$ |
| **插入（中间/头部）** | $O(n)$ | $O(n)$ | 后续元素需要后移 |
| **删除（末尾）** | — | $O(1)$ | 直接减少 size |
| **删除（中间/头部）** | $O(n)$ | $O(n)$ | 后续元素需要前移 |
| **查找** | $O(n)$ | $O(n)$ | 线性扫描（无序时） |

## Python 示例

```python
# 静态数组（初始化固定长度）
arr = [0] * 5                          # [0, 0, 0, 0, 0]

# 动态数组（自动扩容）
nums = [1, 2, 3]
nums.append(4)                         # 末尾 O(1)
nums.insert(0, 0)                      # 头部 O(n)
nums.pop()                             # 末尾删除 O(1)
nums.pop(0)                            # 头部删除 O(n)

# 随机访问 O(1)
x = nums[2]
```

## 数组 vs 链表

| 对比 | 数组 | 链表 |
|------|:----:|:----:|
| 内存 | **连续** | 分散 |
| 随机访问 | $O(1)$ | $O(n)$ |
| 插入/删除 | $O(n)$ | $O(1)$ （已知位置） |
| 缓存友好 | ✅ 高（空间局部性） | ❌ 低 |
| 内存开销 | 低 | 高（额外指针） |

## ML 中的数组

| 场景 | 形式 |
|------|------|
| **特征矩阵** | `X.shape = (n_samples, n_features)` — 二维数组 |
| **图像张量** | `img.shape = (H, W, C)` — 三维数组 |
| **权重参数** | `W.shape = (d_in, d_out)` — 矩阵连续存储 |
| **批量数据** | `DataLoader` 返回的 tensor 基于连续内存 |
| **GPU 加速** | GPU 对连续内存访问有极致优化（合并访问） |

> NumPy 的 `ndarray` 和 PyTorch 的 `Tensor` 底层都是连续数组，配合 SIMD 和 GPU 实现高性能计算。

## 面试追问

**Q1（基础）**：数组为什么能在 $O(1)$ 时间内随机访问任意元素？这个时间复杂度是如何保证的？

**回答要点**：数组元素存储在连续内存中，每个元素大小固定，通过基地址 + 索引 × 元素大小直接计算出内存地址，无需遍历。这个寻址操作是常数时间的，与数组长度无关。

**Q2（深挖）**：动态数组在容量不足时如何扩容？为什么说"均摊 $O(1)$ "的插入是合理的？扩容因子（如 1.5 倍 vs 2 倍）对性能有何影响？

**回答要点**：动态数组（如 Python list）在容量满时申请新内存（通常 1.5-2 倍大小），复制旧元素到新地址，释放旧内存。虽然单次扩容是 $O(n)$ ，但扩容次数随 n 增长呈对数级减少，均摊到每次插入上近似 $O(1)$ 。扩容因子过小（如 1.25）会导致频繁扩容；过大（如 2）会浪费更多内存。

**Q3（实战）**：在 PyTorch / NumPy 中，为什么操作连续内存的张量比非连续视图更快？实际编码中如何避免"内存不连续"的坑？

**回答要点**：连续张量在底层是一整块连续内存，CPU/GPU 可利用空间局部性和缓存预取加速；非连续视图（如转置、切片）访问时需要跳跃式寻址，降低带宽利用率。使用 `.contiguous()` 确保连续性，避免在循环中频繁做非连续切片操作。

**Q4（边界）**：数组的连续存储特性在哪些场景下会成为缺点？有没有比数组更合适的选择？

**回答要点**：中间插入/删除频繁时数组需要大量移动元素， $O(n)$ 的开销过高；存储稀疏数据时连续内存浪费严重（大量空位）；不确定最大容量时扩容带来性能抖动。此时链表、哈希表或稀疏矩阵格式（如 CSR/CSC）可能是更好的选择。
