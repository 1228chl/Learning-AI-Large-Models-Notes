# 链表

## 定义

链表（Linked List）是一种线性数据结构，元素存储在**分散的内存节点**中，每个节点包含**数据**和指向下一节点的**指针**。通过指针将节点串联起来，链表的长度可以动态变化。

## 三种类型

```python
# 单向链表节点
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val                   # 节点存储的数据值
        self.next = next                 # 指向下一个节点的指针，末尾节点为None

# 双向链表节点
class DoublyListNode:
    def __init__(self, val=0, prev=None, next=None):
        self.val = val                   # 节点存储的数据值
        self.prev = prev                 # 指向前一个节点的指针，支持反向遍历
        self.next = next                 # 指向下一个节点的指针
```

| 类型 | 指针方向 | 特点 |
|------|----------|------|
| **单向链表** | 每个节点指向下一个 | 最简结构，只能单向遍历 |
| **双向链表** | 每个节点指向前后 | 可双向遍历，删除更灵活 |
| **循环链表** | 尾节点指向头节点 | 环形结构，适合轮询 |

## 核心操作复杂度

| 操作 | 数组 | 单向链表 |
|------|:----:|:--------:|
| **随机访问** | $O(1)$ | $O(n)$ |
| **头部插入** | $O(n)$ | $O(1)$ |
| **头部删除** | $O(n)$ | $O(1)$ |
| **尾部插入（有尾指针）** | $O(1)$ | $O(1)$ |
| **已知节点后插入** | $O(n)$ | $O(1)$ |
| **查找值** | $O(n)$ | $O(n)$ |

```python
# 构建链表 1 → 2 → 3
node3 = ListNode(3)                      # 先创建尾节点，next默认为None
node2 = ListNode(2, node3)               # 中间节点指向尾节点
head = ListNode(1, node2)                # 头节点指向中间节点，形成完整链表

# 头插 O(1)
new_head = ListNode(0, head)             # 创建新节点指向原头节点，新节点成为新头，无需移动任何元素

# 遍历 O(n)
cur = head                               # 从头节点开始遍历
while cur:                               # 遍历直到末尾（cur为None时结束）
    print(cur.val)                       # 打印当前节点的值
    cur = cur.next                       # 通过指针移动到下一个节点
```

## 链表的变体应用

| 变体 | 结构 | 典型用途 |
|------|------|----------|
| **跳表（Skip List）** | 多层链表索引 | Redis Sorted Set 底层实现 |
| **LRU 缓存** | 双向链表 + 哈希表 | 最近最少使用淘汰策略 |
| **邻接表** | 数组 + 链表 | 图的稀疏存储 |

## ML 中的链表

原生 ML 计算（矩阵乘法、卷积）中链表使用较少（因内存不连续不利 GPU 计算），但在以下场景发挥作用：

| 场景 | 使用方式 |
|------|----------|
| **稀疏矩阵** | 每个节点的非零元素链接起来 |
| **计算图（Graph）** | 节点间的前驱/后继关系 |
| **Transformer 中间变量** | 计算图中的梯度传播路径 |
| **数据流水线** | 生产者-消费者队列结构 |

## 面试追问

**Q1（基础）**：链表节点为什么需要指针（引用）来连接？头指针的作用是什么？

**回答要点**：链表节点在内存中分散存储，无法通过索引计算地址，必须通过每个节点中存储的 next 指针找到下一个节点。头指针是链表的入口，丢失头指针意味着整个链表不可达；删除/插入链表头时需要更新头指针。

**Q2（深挖）**：单向链表的"已知节点后插入"为什么是 $O(1)$ ，而"已知节点前插入"却需要 $O(n)$ 时间？双向链表如何解决这个问题？

**回答要点**：单向链表只知道当前节点和 next，前插入需要找到前驱节点，必须从头遍历 $O(n)$ ；双向链表每个节点有 prev 指针，已知节点可直接访问前驱，前插入也是 $O(1)$ 。因此需要频繁前插时优先用双向链表。

**Q3（实战）**：LRU 缓存为什么使用"双向链表 + 哈希表"的组合？能否只用哈希表实现？

**回答要点**：哈希表提供 $O(1)$ 查找，但无法维护"最近使用"的顺序；双向链表能以 $O(1)$ 时间将访问的节点移到头部（表示最近使用）。两者组合实现 get/put 均为 $O(1)。纯哈希表无法高效维护访问顺序，需要额外数据结构如 OrderedDict（底层也是双向链表 + 哈希表）。

**Q4（边界）**：在 GPU 计算场景中链表几乎不被使用，原因是什么？链表在哪些现代场景中正在被替代？

**回答要点**：GPU 依赖连续内存合并访问（coalesced access）来最大化带宽，链表的分散存储导致大量非合并访存，严重降低吞吐量。在存储领域，B 树/B+ 树（利用连续页和分支因子）在大规模索引中逐步替代链表；在并发编程中，无锁数据结构往往使用 CAS + 数组而非链表来避免指针悬挂问题。
