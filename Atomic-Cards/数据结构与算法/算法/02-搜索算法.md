# 搜索算法

## 二分查找（Binary Search）

在**有序数组**中查找目标值，每次将搜索范围缩小一半：

```python
def binary_search(nums, target):
    # 二分查找：在有序数组中通过不断折半缩小搜索范围

    left, right = 0, len(nums) - 1       # 初始化左右指针，采用闭区间[left, right]搜索

    while left <= right:                 # 区间非空时持续二分

        mid = left + (right - left) // 2 # 计算中间索引，差值法避免left+right过大导致溢出

        if nums[mid] == target:          # 找到目标值，直接返回索引
            return mid
        elif nums[mid] < target:         # 中间值小于目标，目标只可能在右半区间

            left = mid + 1               # 收缩左边界，排除左半部分
        else:                            # 中间值大于目标，目标只可能在左半区间

            right = mid - 1              # 收缩右边界，排除右半部分
    return -1                            # 循环结束未找到，返回-1表示不存在
```

| 性质 | 值 |
|------|:--:|
| 时间复杂度 | $O(\log n)$ |
| 空间复杂度（迭代） | $O(1)$ |
| 空间复杂度（递归） | $O(\log n)$ |
| 前提条件 | 数组必须有序 |

**变种**：查找左边界、右边界、最接近目标值的元素。

## 线性搜索（Linear Search）

```python
def linear_search(nums, target):
    for i, v in enumerate(nums):         # 遍历数组，同时获取索引和元素值

        if v == target:                  # 找到与目标值相等的元素
            return i                     # 返回第一个匹配元素的索引
    return -1                            # 遍历完所有元素仍未找到，返回-1
```

时间复杂度： $O(n)$ ，空间复杂度： $O(1)$ 。适用于**无序数据**或**小规模数据**。

## 搜索算法对比

| 算法 | 前提 | 时间复杂度 | 空间复杂度 | 应用 |
|------|------|:----------:|:----------:|------|
| **线性搜索** | 无 | $O(n)$ | $O(1)$ | 无序小数据集 |
| **二分搜索** | 有序数组 | $O(\log n)$ | $O(1)$ | 有序数据查找 |
| **哈希查找** | 键的映射 | $O(1)$ | $O(n)$ | 精确等值查询 |
| **二叉搜索树** | 有序树 | $O(\log n)$ | $O(n)$ | 动态数据查找 |
| **跳表查找** | 有序多层索引 | $O(\log n)$ | $O(n\log n)$ | Redis Sorted Set |

## 面试追问

**Q1（基础）**：二分查找的前提条件是什么？为什么用 `mid = left + (right - left) // 2` 而不是 `mid = (left + right) // 2`？
**回答要点**：

1. 前提是数组必须有序，否则二分查找无法正确缩小搜索范围
2. `(left + right) // 2` 在 left 和 right 都很大时可能整数溢出（如 Java/C++ 中 int 相加超过最大值）
3. `left + (right - left) // 2` 通过先算差值避免溢出，是语言无关的最佳实践

**Q2（深挖）**：二分查找的变种——查找左边界、右边界、最接近目标值的元素——各用于什么场景？区间开闭怎么写最不容易出错？
**回答要点**：

1. 左边界用于查找第一个等于 target 的位置（重复元素场景）；右边界用于最后一个等于 target 的位置；最接近值用于 target 不一定存在时找最近匹配
2. 推荐使用左闭右闭 `[left, right]`，搜索条件 `while left <= right`，收缩时 `left = mid + 1` / `right = mid - 1`
3. 查找左边界时当 `nums[mid] == target` 不返回，而是收缩右边界继续向左搜索

**Q3（实战）**：在向量检索（ANN）中，HNSW 如何借鉴二分/多分思想实现近似最近邻搜索？为什么不用精确二分？
**回答要点**：

1. HNSW 构建多层图结构——顶层稀疏（长距离跳跃），底层稠密（精细搜索）；从顶层开始搜索，类似二分查找每一层找最近节点再跳到下层细化
2. 高维向量空间无天然序关系，无法排序，因此不能用精确二分
3. 精确最近邻在百万级高维数据上计算量过大（"维度灾难"），需用近似方法换取可接受的召回率

**Q4（边界）**：二分查找要求数据有序，但维护有序数组的插入/删除成本是 $O(n)$ 。如何在大规模动态数据上实现高效搜索？
**回答要点**：

1. 可用平衡 BST（ $O(\log n)$ 插入/查找/删除）、跳表（Redis Sorted Set 底层， $O(\log n)$ 插入/查找且实现简单）、或 B+ 树（数据库索引）
2. 哈希表提供 $O(1)$ 等值查找但不支持有序遍历和范围查询
3. 如果数据有天然局部性（时间序列），分块索引加布隆过滤器预过滤也是常见工程方案
