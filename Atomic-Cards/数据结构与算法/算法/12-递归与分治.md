# 递归与分治

## 递归三要素

递归（Recursion）是函数调用自身来解决问题的编程范式。三个必要条件：

| 要素 | 含义 | 示例（阶乘） |
|------|------|-------------|
| **终止条件**（Base Case） | 最小子问题的直接解 | `n <= 1 → return 1` |
| **递推关系**（Recurrence） | 将大问题转化为规模更小的子问题 | `fact(n) = n * fact(n-1)` |
| **递归调用** | 按递推关系调用自身，逼近终止条件 | `return n * fact(n-1)` |

```python
def factorial(n):

    if n <= 1:                       # 终止条件：0和1的阶乘为1，防止无限递归
        return 1

    return n * factorial(n - 1)      # 递推关系：n! = n * (n-1)!，递归调用逐步逼近终止条件
```

## 分治算法（Divide and Conquer）

分治是递归最经典的应用：**分（Divide）→ 治（Conquer）→ 合（Combine）**

| 步骤 | 动作 | 示例（归并排序） |
|------|------|-----------------|
| **Divide** | 将大问题分解为独立的子问题 | 将数组从中间切分为两半 |
| **Conquer** | 递归求解子问题 | 递归对两半分别排序 |
| **Combine** | 将子问题的解合并为原问题的解 | 合并两个有序数组 |

```python
def fib_naive(n):                        # 朴素递归版：大量重复计算，时间复杂度O(2^n)

    if n <= 1: return n                  # 终止条件：fib(0)=0, fib(1)=1
    return fib_naive(n-1) + fib_naive(n-2)  # 递归分裂为两个子问题，调用树呈指数增长


def fib_memo(n, memo={}):                # 记忆化递归版：用缓存避免重复计算，时间复杂度O(n)
    if n in memo: return memo[n]         # 已计算过则直接返回缓存结果，避免重复递归

    if n <= 1: return n                  # 终止条件

    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)  # 计算并存入缓存后再返回
    return memo[n]
```

## 递归 vs 迭代

| 对比 | 递归 | 迭代 |
|------|:----:|:----:|
| 代码可读性 | ⭐⭐⭐ 更接近问题描述 | ⭐⭐ 有时复杂 |
| 性能 | 有函数调用开销 | 通常更快 |
| 栈溢出风险 | ❌ 递归深度大时可能溢出 | ✅ 无此问题 |
| 空间复杂度 | 隐式栈（调用深度） | 通常 $O(1)$ |

**尾递归优化**：如果递归调用是函数的最后一个操作，某些语言（如 Scheme）可优化为迭代。Python **不支持**尾递归优化。

## 经典分治应用

| 算法 | 分治策略 | 复杂度 |
|------|----------|:------:|
| **归并排序** | 数组切半，分别排序后合并 | $O(n\log n)$ |
| **快速排序** | 选 pivot，分区后递归排序 | $O(n\log n)$ |
| **二分查找** | 每次排除一半区间 | $O(\log n)$ |
| **最大子数组** | 跨中点、左侧、右侧三部分 | $O(n\log n)$ |
| **Strassen 矩阵乘** | 矩阵分块 | $O(n^{2.807})$ |
| **FFT（快速傅里叶变换）** | 奇偶分解 | $O(n\log n)$ |

## ML 中的递归思想

| 场景 | 递归/分治体现 |
|------|--------------|
| **决策树** | 递归划分特征空间，每个节点是子问题 |
| **反向传播** | 链式法则逐层计算梯度（递归地应用） |
| **Transformer 层数** | 多层堆叠：每层输出是下层的输入 |
| **RNN 时间展开** | 每个时间步递归地处理序列 |
| **HuggingFace `from_pretrained` ** | 递归加载子模块权重 |

## 面试追问

**Q1（基础）**：递归函数的三个必要条件是什么？请用阶乘函数说明每个条件的具体作用。
**回答要点**：

1. 终止条件（Base Case）：当 n ≤ 1 时直接返回 1，作为最小子问题的直接解，防止无限递归
2. 递推关系（Recurrence）：fact(n) = n × fact(n-1)，将规模为 n 的大问题转化为规模更小的子问题
3. 递归调用：函数按递推关系调用自身，每次调用都向终止条件逐步逼近

**Q2（深挖）**：Python 为什么不支持尾递归优化？递归转迭代的一般方法是什么？
**回答要点**：

1. Python 设计哲学注重保持调用栈的完整性以方便调试和异常回溯，尾递归优化会改变栈帧的表现形式
2. 递归转迭代的通用方法是显式使用栈（list）保存状态，将递归参数封装为栈帧
3. 用 while 循环模拟递归调用和返回过程，手动执行压栈和弹栈操作

**Q3（实战）**：归并排序和快速排序都用了分治思想，它们在"分"和"合"两个阶段的做法有什么本质不同？这导致了什么性能差异？
**回答要点**：

1. 归并排序分阶段简单（从中间直接切分），合阶段复杂（需 O(n) merge 操作合并有序数组，需 O(n) 额外空间，稳定排序）
2. 快速排序分阶段复杂（选 pivot 并原址分区），合阶段无需额外操作，原址操作不需额外空间，但不稳定
3. 归并排序最坏始终 O(n log n)，快速排序最坏 O(n²)；快排平均性能更优且常数更小

**Q4（边界）**：递归深度过大导致栈溢出时，是否所有递归都能改写成迭代？改写后的代码可能存在哪些新问题？
**回答要点**：

1. 所有递归都可以改写成迭代，因为递归底层依赖的调用栈完全可以用显式栈来模拟
2. 改写后代码复杂度显著增加，需要手动管理状态和返回地址，逻辑容易出错
3. 复杂递归（如树形递归、多路分支）的显式栈需维护更多辅助状态，且仍有 OOM 风险（从栈溢出转为堆耗尽），实践中若深度可预估应优先保留递归版本
