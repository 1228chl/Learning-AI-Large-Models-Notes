# 排序算法

## 常见排序对比

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|------|:----:|:----:|:----:|:----:|------|
| **冒泡排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ | 相邻比较交换 |
| **选择排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ❌ | 每轮选最小 |
| **插入排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ | 小规模+近乎有序时快 |
| **归并排序** | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | ✅ | 分治，稳定 |
| **快速排序** | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ | ❌ | 实际最快 |
| **堆排序** | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | ❌ | 利用堆结构 |
| **计数排序** | $O(n+k)$ | $O(n+k)$ | $O(k)$ | ✅ | 非比较，整数（$k$ 为数据范围） |
| **基数排序** | $O(dn)$ | $O(dn)$ | $O(n)$ | ✅ | 按位排序（$d$ 为位数） |

## 核心实现

```python
# 快速排序（最常用）：选取基准值，将数组分割为小于和大于基准的两部分，递归排序
def quick_sort(nums):

    if len(nums) <= 1:                   # 空数组或单元素数组已有序，直接返回
        return nums

    pivot = nums[len(nums) // 2]         # 选择中间元素作为基准值，避免极端输入下的性能退化

    left = [x for x in nums if x < pivot]    # 小于基准的放入左列表

    mid = [x for x in nums if x == pivot]    # 等于基准的放入中间列表

    right = [x for x in nums if x > pivot]   # 大于基准的放入右列表
    return quick_sort(left) + mid + quick_sort(right)  # 递归排序左右部分后合并为完整有序数组

# 归并排序：分治思想，先分割到最小单元，再两两合并有序数组
def merge_sort(nums):

    if len(nums) <= 1:                   # 递归终止条件：单个元素天然有序
        return nums

    mid = len(nums) // 2                 # 从中间切分，将规模减半

    left = merge_sort(nums[:mid])        # 递归排序左半部分

    right = merge_sort(nums[mid:])       # 递归排序右半部分
    return merge(left, right)            # 合并两个有序数组为完整有序数组

def merge(a, b):                         # 合并两个已排序的数组，归并排序的核心操作

    i = j = 0                            # 双指针分别指向两个数组的起始位置

    res = []                             # 存放合并后的有序结果
    while i < len(a) and j < len(b):     # 两数组都未遍历完时持续比较

        if a[i] <= b[j]:                 # 取较小的元素加入结果，保持排序稳定性

            res.append(a[i]); i += 1
        else:

            res.append(b[j]); j += 1
    return res + a[i:] + b[j:]           # 将剩余未遍历的元素直接追加到结果末尾
```

## 如何选择

```python
# Python 内置排序（Timsort = 归并 + 插入，自适应排序）
sorted(nums)                             # 返回新排序列表，原数组不变，稳定O(n log n)
nums.sort()                              # 原地排序，不创建新列表，节省内存
```

| 数据特征 | 推荐算法 |
|----------|----------|
| 数据量小（< 50） | 插入排序 |
| 近乎有序 | 插入排序（快速） |
| 数据量大（通用） | 快速排序 / Timsort |
| 要求稳定排序 | 归并排序 / 插入排序 |
| 整数值且范围小 | 计数排序 |
| 链表排序 | 归并排序 |
| 内存极有限 | 堆排序 |

## ML/DL 应用场景

| 应用场景 | 排序算法 | 说明 |
|----------|----------|------|
| **特征重要性排序** | 快速排序 / 归并排序 | 训练完成后对特征重要性分数（如树模型的 feature_importances_）降序排列，筛选关键特征 |
| **推荐系统排序** | Timsort / 堆排序 | 对候选 item 的预测得分批量排序，选取 Top-N 推荐给用户 |
| **评估指标计算** | 归并排序（稳定） | 计算 NDCG、MAP 等排序指标时，需要对预测得分排序并与真实排序对比 |
| **非极大值抑制（NMS）** | 按置信度排序 | 目标检测中对检测框按置信度降序排列，优先保留高置信度框再剔除重叠框 |
| **近似最近邻搜索** | 部分排序 / Top-K 堆排序 | 在海量向量中检索 Top-K 最相似向量，用堆的部分排序特性避免全量排序 |

## 面试追问

**Q1（基础）**：快速排序的核心思想是什么？如何选择 pivot？pivot 的选择对性能有什么影响？
**回答要点**：

1. 快速排序核心是分治思想：选一个基准值（pivot），将数组分为小于和大于 pivot 两部分，递归排序左右部分
2. pivot 选得好（中位数附近）使分区均衡，复杂度 $O(n\log n)$；选到极端值导致分区不平衡，退化为 $O(n^2)$
3. 常用 pivot 选择策略：固定选中间/首尾、随机选择、三数取中（首+中+尾取中值）

**Q2（深挖）**：归并排序和快速排序的稳定性、空间复杂度和最坏情况分别有什么不同？为什么实际工程中快排通常比归并快？
**回答要点**：

1. 归并排序：稳定、$O(n)$ 额外空间、最坏 $O(n\log n)$；快速排序：不稳定、$O(\log n)$ 额外空间（递归栈）、最坏 $O(n^2)$
2. 快排通常更快是因为数据局部性好（从两端向中间扫描），缓存命中率高
3. 归并排序需开辟额外数组做 merge，有大量内存拷贝开销

**Q3（实战）**：Python 的 Timsort 如何结合插入排序和归并排序的优点？为什么被称为"自适应"排序算法？
**回答要点**：

1. Timsort 将数组分成若干已有序片段（run），长度不足时用插入排序补齐，再用归并排序合并所有 run
2. 它检测数据中已有的有序性（自然 run），对近乎有序的数据接近 $O(n)$，因此称为自适应排序
3. 综合了插入排序（小规模高效）和归并排序（稳定合并）的优点，是 Python 和 Java 默认排序算法

**Q4（边界）**：比较排序的时间复杂度下界为什么是 $O(n\log n)$？非比较排序（计数排序、基数排序）如何突破这一下界？它们有什么限制？
**回答要点**：

1. 比较排序每次比较有 2 种结果，n 个元素排列有 n! 种可能，至少需要 $\log_2(n!) = O(n\log n)$ 次比较
2. 非比较排序利用数据本身的数值特性（计数排序用桶、基数排序按位处理）绕过比较，可达到 $O(n)$
3. 限制：计数排序要求数据范围小且为整数；基数排序适用于固定长度（如定长字符串、整数），需额外辅助空间
