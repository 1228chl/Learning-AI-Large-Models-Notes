# 队列

## 定义

队列（Queue）是一种**先进先出（FIFO, First In First Out）** 的线性数据结构。元素从一端（队尾）加入，从另一端（队首）移除。

类比：排队买票——先到的人先服务。

## 核心操作复杂度

| 操作 | 描述 | 时间复杂度 |
|------|------|:----------:|
| `enqueue(x)` | 从队尾加入元素 | $O(1)$ |
| `dequeue()` | 从队首移除元素 | $O(1)$ |
| `front()` | 查看队首元素 | $O(1)$ |
| `rear()` / `back()` | 查看队尾元素 | $O(1)$ |
| `is_empty()` | 判断队列是否为空 | $O(1)$ |

```python
# Python 中用 collections.deque（双端队列，O(1) 两端操作）
from collections import deque

q = deque()
q.append(1)             # enqueue → [1]
q.append(2)             # → [1, 2]
q.append(3)             # → [1, 2, 3]
first = q.popleft()     # dequeue → 1, 队列为 [2, 3]
```

## 循环队列

避免数组实现时"假溢出"（队尾满了但队首有空位），通过模运算重用空间：

```python
class CircularQueue:
    def __init__(self, k):
        self.q = [None] * k
        self.head = self.tail = self.size = 0
        self.cap = k

    def enqueue(self, val):
        if self.size == self.cap:
            return False
        self.q[self.tail] = val
        self.tail = (self.tail + 1) % self.cap
        self.size += 1
        return True

    def dequeue(self):
        if self.size == 0:
            return None
        val = self.q[self.head]
        self.head = (self.head + 1) % self.cap
        self.size -= 1
        return val
```

## 双端队列（Deque）

两端都可以进行插入和删除，兼具栈和队列的能力：

```python
dq = deque()
dq.append(1)              # 尾部入队 → [1]
dq.appendleft(0)          # 头部入队 → [0, 1]
dq.pop()                  # 尾部出队 → 1
dq.popleft()              # 头部出队 → 0
```

## 应用场景

| 场景 | 原理 | 示例 |
|------|------|------|
| **广度优先搜索（BFS）** | 逐层访问，先入先出 | 最短路径、层序遍历 |
| **任务调度** | 按到达顺序执行 | 打印机队列、CPU 调度 |
| **生产者-消费者** | 缓冲解耦 | DataLoader 多进程加载 |
| **滑动窗口** | 双端队列维护窗口极值 | 滑动窗口最大值 |
| **消息队列** | 异步解耦 | Redis List / Kafka |

## ML 中的队列

| 场景 | 使用方式 |
|------|----------|
| **PyTorch DataLoader** | 多进程队列预加载数据，减少 GPU 等待 |
| **滑动窗口特征** | 维护固定窗口大小的历史数据 |
| **经验回放（Replay Buffer）** | 强化学习中存储过往经验，随机采样 |
| **流式数据处理** | 实时数据 pipeline 中的缓冲队列 |

## 面试追问

**Q1（基础）**：队列的 FIFO 特性对应现实生活中的什么场景？为什么 BFS 要用队列而不用栈？

**回答要点**：FIFO 对应排队的先到先服务，先进入的元素先被处理。BFS 逐层遍历时，要求先访问的节点（同层或更早层）的邻居必须先被处理，队列的 FIFO 保证按发现顺序依次出队，实现"层层推进"；若用栈（LIFO）则变成 DFS 的深入到底再回溯。

**Q2（深挖）**：循环队列如何解决"假溢出"问题？为什么需要牺牲一个存储单元来区分队空和队满？

**回答要点**：数组实现队列时，出队操作使队首指针后移导致前面有空位但队尾已到末尾，无法入队——即假溢出。循环队列用模运算将队尾指针回绕到数组开头，复用空闲位置。队空条件 `head == tail`，队满条件 `(tail + 1) % cap == head`，因此需要牺牲一个单元区分两者。也可用 size 字段计数来免去牺牲单元。

**Q3（实战）**：PyTorch DataLoader 的多进程数据加载如何利用队列来减少 GPU 等待？队列大小设置不当会导致什么问题？

**回答要点**：DataLoader 使用生产者-消费者模式，worker 进程预加载数据放入队列，主进程从队列取数据送给 GPU。队列起到了缓冲解耦作用，使数据准备和模型计算可以流水线并行。队列太小会导致 GPU 频繁等待数据（饥饿）；太大则占用过多内存，且数据可能过时（epoch 切换时的 stale 数据）。

**Q4（边界）**：在什么场景下普通队列的 FIFO 特性不再是最优策略？优先队列和双端队列分别解决了什么问题？

**回答要点**：任务有不同优先级时 FIFO 不公平（如紧急任务需优先处理），需用优先队列；需要两端操作时（如滑动窗口最大值、回文检查），普通队列只能操作一端效率低，需用双端队列。此外超大数据量或分布式场景下，内存队列可能成为瓶颈，需使用消息队列（如 Kafka、Redis List）来解耦和持久化。
