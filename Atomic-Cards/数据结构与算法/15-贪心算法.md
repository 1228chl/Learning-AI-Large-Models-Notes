# 贪心算法

## 定义

贪心算法（Greedy Algorithm）在每一步都做出**当前看来最优的选择**（局部最优），期望通过一系列局部最优选择达到全局最优。

参考：[Hello 算法 第15章](https://www.hello-algo.com/chapter_greedy/)

## 适用条件

| 条件 | 说明 | 反例 |
|------|------|------|
| **贪心选择性质** | 局部最优选择能推导出全局最优 | 零钱兑换（某些硬币面额） |
| **最优子结构** | 原问题最优解包含子问题最优解 | 与 DP 相同，但贪心不回头 |

**与动态规划的核心区别**：贪心**不重新考虑过去的决策**，一路向前；DP 依赖前面所有的决策。

## 区间调度——选择最多不重叠区间

按**结束时间最早**贪心，每次选择与已选区间不重叠的、结束最早的任务：

```python
def interval_scheduling(intervals):
    """贪心：选择最多的不重叠区间"""
    if not intervals:
        return 0
    intervals.sort(key=lambda x: x[1])       # 按结束时间升序
    count = 1
    last_end = intervals[0][1]               # 已选区间的结束时间
    for i in range(1, len(intervals)):
        start, end = intervals[i]
        if start >= last_end:                # 不重叠
            count += 1
            last_end = end
    return count

# 示例
intervals = [(1,4), (3,5), (0,6), (5,7), (8,11)]
print(interval_scheduling(intervals))        # 3 → (1,4), (5,7), (8,11)
```

## 零钱兑换——贪心的局限性

```python
def coin_change_greedy(coins, amt):
    """贪心：每次选不超过剩余金额的最大面值"""
    coins.sort()
    i = len(coins) - 1
    count = 0
    while amt > 0:
        while i > 0 and coins[i] > amt:
            i -= 1
        amt -= coins[i]
        count += 1
    return count if amt == 0 else -1

# 正例：coins = [1, 5, 10, 20, 50, 100], amt=60 → 贪心得 3 枚（50+10）
# 反例：coins = [1, 20, 50], amt=60 → 贪心得 11 枚（50+1×10），最优 3 枚（20+20+20）
```

| 场景 | 贪心是否最优 |
|------|:-----------:|
| 标准货币面额（1,5,10,20,50,100） | ✅ 最优 |
| 自定义面额（1,20,50） | ❌ 可能失败 |
| 自定义面额（1,49,50） | ❌ 可能失败 |

> 零钱兑换需要**动态规划**来保证全局最优解。

## 背包问题——贪心 vs DP

| 问题类型 | 贪心 | 动态规划 |
|----------|:----:|:--------:|
| **分数背包**（物品可分割） | ✅ 按价值/重量比贪心 | 不需要 |
| **0-1 背包**（物品不可分割） | ❌ 可能失败 | ✅ |
| **完全背包**（物品无限） | ❌ 可能失败 | ✅ |

```python
# 分数背包（贪心可解）
def fractional_knapsack(w, v, capacity):
    items = sorted(zip(w, v), key=lambda x: x[1]/x[0], reverse=True)
    total_value = 0
    for weight, value in items:
        if capacity >= weight:
            total_value += value
            capacity -= weight
        else:
            total_value += value * capacity / weight
            break
    return total_value
```

## 常见贪心应用

| 问题 | 贪心策略 |
|------|----------|
| **Huffman 编码** | 每次合并频率最小的两棵树 |
| **Dijkstra 最短路径** | 每次选当前 dist 最小的未处理节点 |
| **最小生成树（Prim / Kruskal）** | 每次选权重最小且不产生环的边 |
| **任务调度** | 按截止时间或处理时间排序 |
| **加油站问题** | 每次在当前站加足够到下一站的油 |
| **跳跃游戏** | 维护能跳到的最远位置 |

## ML 中的贪心思想

| 场景 | 贪心体现 |
|------|----------|
| **决策树分裂** | 每步选信息增益/基尼系数最大的特征 |
| **特征选择（前向）** | 每步加一个使模型提升最大的特征 |
| **Greedy LM 解码** | 每步取概率最大的 token（贪心解码） |
| **MCTS（蒙特卡洛树搜索）** | 结合贪心和随机模拟 |


## 面试追问

**Q1（基础）**：贪心算法的"贪心选择性质"和"最优子结构"分别指什么？为什么缺一不可？
**回答要点**：贪心选择性质指局部最优选择能导向全局最优解——每步决定后不回头重新考虑；最优子结构指问题的最优解包含子问题的最优解——子问题可独立求解。缺贪心选择性质则局部最优无法保证全局最优；缺最优子结构则子问题间相互纠缠，无法分步决策。两者同时成立才能保证贪心的正确性。

**Q2（深挖）**：为何某些面额的零钱兑换问题贪心有效（如 [1,5,10,20,50,100]），而另一些不行（如 [1,20,50]）？数学上如何判断贪心是否成立？
**回答要点**：标准货币面额满足"每个面额是前一个的倍数"或更一般的"规范币制"（canonical coin system）条件——贪心策略对集合中的所有金额都能得到最优解。[1,20,50] 不满足，因为 60 的最优解是 20+20+20（3 枚），但贪心取 50+1×10（11 枚）。数学上可验证：如果一个面额小于相邻两倍且最优解中该面额的使用次数有上界，则可能破坏贪心正确性，需要用 DP 验证。

**Q3（实战）**：区间调度"按结束时间最早贪心"为什么是最优的？如何证明这个贪心策略的正确性？
**回答要点**：按结束时间最早选择，给后续任务留下最大剩余时间，可容纳更多区间。交换论证法证明：设贪心解为 G，最优解为 OPT，贪心选择的是结束最早的区间 g1。若 OPT 中第一个区间不是 g1，可用 g1 替换它——g1 结束不晚于它，剩余时间不减少，替换后仍是合法解且区间数不变。依次替换所有位置，贪心解数 ⩾ 最优解数，因此贪心最优。

**Q4（边界）**：贪心算法在图像分割、推荐排序等 ML 场景中常用，但它"只看眼前"的特性会导致什么典型问题？如何引入"前瞻"机制弥补？
**回答要点**：贪心解码（每步取概率最高的 token）在文本生成中容易陷入重复、缺乏多样性，且无法纠正早期错误（一步错步步错）。弥补方案：Beam Search（每步保留 top-K 路径，引入有限前瞻）；MCTS（通过模拟多步后回传评估，将前瞻信息融入当前决策）；或先训练一个全局评估函数（Critic）来指导贪心方向。
