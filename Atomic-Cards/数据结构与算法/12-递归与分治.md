# 递归与分治

## 递归三要素

递归（Recursion）是函数调用自身来解决问题的编程范式。三个必要条件：

| 要素 | 含义 | 示例（阶乘） |
|------|------|-------------|
| **终止条件**（Base Case） | 最小子问题的直接解 | `n <= 1 → return 1` |
| **递推关系**（Recurrence） | 将大问题转化为规模更小的子问题 | `fact(n) = n * fact(n-1)` |
| **递归调用** | 按递推关系调用自身，逼近终止条件 | `return n * fact(n-1)` |

```python
def factorial(n):
    if n <= 1:          # 终止条件
        return 1
    return n * factorial(n - 1)  # 递推 + 调用
```

## 分治算法（Divide and Conquer）

分治是递归最经典的应用：**分（Divide）→ 治（Conquer）→ 合（Combine）**

| 步骤 | 动作 | 示例（归并排序） |
|------|------|-----------------|
| **Divide** | 将大问题分解为独立的子问题 | 将数组从中间切分为两半 |
| **Conquer** | 递归求解子问题 | 递归对两半分别排序 |
| **Combine** | 将子问题的解合并为原问题的解 | 合并两个有序数组 |

```python
def fib_naive(n):           # 递归版—O(2^n)
    if n <= 1: return n
    return fib_naive(n-1) + fib_naive(n-2)

def fib_memo(n, memo={}):   # 记忆化—O(n)
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)
    return memo[n]
```

## 递归 vs 迭代

| 对比 | 递归 | 迭代 |
|------|:----:|:----:|
| 代码可读性 | ⭐⭐⭐ 更接近问题描述 | ⭐⭐ 有时复杂 |
| 性能 | 有函数调用开销 | 通常更快 |
| 栈溢出风险 | ❌ 递归深度大时可能溢出 | ✅ 无此问题 |
| 空间复杂度 | 隐式栈（调用深度） | 通常 $O(1)$ |

**尾递归优化**：如果递归调用是函数的最后一个操作，某些语言（如 Scheme）可优化为迭代。Python **不支持**尾递归优化。

## 经典分治应用

| 算法 | 分治策略 | 复杂度 |
|------|----------|:------:|
| **归并排序** | 数组切半，分别排序后合并 | $O(n\log n)$ |
| **快速排序** | 选 pivot，分区后递归排序 | $O(n\log n)$ |
| **二分查找** | 每次排除一半区间 | $O(\log n)$ |
| **最大子数组** | 跨中点、左侧、右侧三部分 | $O(n\log n)$ |
| **Strassen 矩阵乘** | 矩阵分块 | $O(n^{2.807})$ |
| **FFT（快速傅里叶变换）** | 奇偶分解 | $O(n\log n)$ |

## ML 中的递归思想

| 场景 | 递归/分治体现 |
|------|--------------|
| **决策树** | 递归划分特征空间，每个节点是子问题 |
| **反向传播** | 链式法则逐层计算梯度（递归地应用） |
| **Transformer 层数** | 多层堆叠：每层输出是下层的输入 |
| **RNN 时间展开** | 每个时间步递归地处理序列 |
| **HuggingFace `from_pretrained` ** | 递归加载子模块权重 |

## 面试追问

**Q1（基础）**：递归函数的三个必要条件是什么？请用阶乘函数说明每个条件的具体作用。

**回答要点**：终止条件（base case）——n ≤ 1 时返回 1，防止无限递归；递推关系—— $fact(n) = n \times fact(n-1)$ ，将大问题转化为规模更小的子问题；递归调用——函数调用自身并逐步逼近终止条件。缺任意一个都会导致递归不终止或不正确。

**Q2（深挖）**：Python 为什么不支持尾递归优化？递归转迭代的一般方法是什么？

**回答要点**：Python 的设计哲学是保持调用栈的完整性（便于调试和异常回溯），且尾递归优化会改变栈帧表现。递归转迭代的通用方法是显式使用栈（list）保存状态：将递归参数封装为栈帧，用 while 循环模拟递归调用和返回过程，手动压栈/弹栈。

**Q3（实战）**：归并排序和快速排序都用了分治思想，它们在"分"和"合"两个阶段的做法有什么本质不同？这导致了什么性能差异？

**回答要点**：归并排序从中间切分（简单分，难合），"合"的阶段需要 $O(n)$ 的 merge 操作合并两个有序数组；快速排序选 pivot 分区（难分，易合），"合"的阶段不需要额外操作。归并的 merge 需要 $O(n)$ 额外空间且稳定；快排的原址分区无需额外空间但不稳定。归并最坏始终 $O(n\log n)$ ，快排最坏 $O(n^2)$ 。

**Q4（边界）**：递归深度过大导致栈溢出时，是否所有递归都能改写成迭代？改写后的代码可能存在哪些新问题？

**回答要点**：所有递归都可以改写成迭代（因为递归底层就是栈），利用显式栈模拟调用过程。但改写后的问题：代码复杂度显著增加（需手动管理状态和返回地址），容易出错；对于复杂递归（如树形递归、多路分支），显式栈需要维护更多辅助状态；且堆上分配显式栈仍有 OOM 风险（只是从栈溢出变成堆内存耗尽）。实践中除非深度可预估且安全，优先保留可读性好的递归版本。
