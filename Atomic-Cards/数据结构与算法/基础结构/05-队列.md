# 队列

## 定义

队列（Queue）是一种**先进先出（FIFO, First In First Out）** 的线性数据结构。元素从一端（队尾）加入，从另一端（队首）移除。

## 直观理解

### 队列的先进先出特性

队列的 FIFO 特性精确对应现实中的排队：先到的人先被服务，后到的人排在队尾等待。在算法中，队列天然适合**广度优先搜索（BFS）**——先发现的节点先被探索，像水波一样从起点向外逐层扩散。

### 队列 vs 栈

| 特性 | 队列（FIFO） | 栈（LIFO） |
|:-----|:------------|:-----------|
| 顺序 | 先进先出 | 后进先出 |
| 适用搜索 | BFS（逐层扩散） | DFS（深入回溯） |
| 现实类比 | 排队 | 一摞盘子 |
| 在 ML 中 | 数据流水线、任务队列 | 反向传播、计算图

## 核心操作复杂度

| 操作 | 描述 | 时间复杂度 |
|------|------|:----------:|
| `enqueue(x)` | 从队尾加入元素 | $O(1)$ |
| `dequeue()` | 从队首移除元素 | $O(1)$ |
| `front()` | 查看队首元素 | $O(1)$ |
| `rear()` / `back()` | 查看队尾元素 | $O(1)$ |
| `is_empty()` | 判断队列是否为空 | $O(1)$ |

```python
# Python 中用 collections.deque（双端队列，O(1) 两端操作）
from collections import deque


q = deque()                              # 创建空的双端队列，作为FIFO队列使用
q.append(1)                              # enqueue：从队尾加入元素1，O(1)
q.append(2)                              # 队尾加入元素2
q.append(3)                              # 队尾加入元素3

first = q.popleft()                      # dequeue：从队首移除元素1，先进先出，O(1)
```

## 循环队列

避免数组实现时"假溢出"（队尾满了但队首有空位），通过模运算重用空间：

```python
class CircularQueue:
    def __init__(self, k):

        self.q = [None] * k              # 底层用固定长度数组存储，避免动态扩容开销

        self.head = self.tail = self.size = 0  # head指向队首，tail指向队尾空位，size记录元素个数

        self.cap = k                     # 队列最大容量

    def enqueue(self, val):

        if self.size == self.cap:        # 队满时无法入队，防止覆盖未读取数据
            return False

        self.q[self.tail] = val          # 在队尾位置写入新元素

        self.tail = (self.tail + 1) % self.cap  # 队尾指针模运算循环后移，复用已出队空位

        self.size += 1
        return True

    def dequeue(self):

        if self.size == 0:               # 队空时无元素可出队
            return None

        val = self.q[self.head]          # 读取队首元素

        self.head = (self.head + 1) % self.cap  # 队首指针模运算后移，逻辑删除该元素

        self.size -= 1
        return val                       # 返回出队的元素值
```

## 双端队列（Deque）

两端都可以进行插入和删除，兼具栈和队列的能力：

```python

dq = deque()
dq.append(1)                           # 从尾部添加元素，相当于栈的push操作
dq.appendleft(0)                       # 从头部添加元素，拓展了普通队列的能力
dq.pop()                               # 从尾部移除并返回元素，相当于栈的pop
dq.popleft()                           # 从头部移除并返回元素，相当于队列的dequeue
```

## 应用场景

| 场景 | 原理 | 示例 |
|------|------|------|
| **广度优先搜索（BFS）** | 逐层访问，先入先出 | 最短路径、层序遍历 |
| **任务调度** | 按到达顺序执行 | 打印机队列、CPU 调度 |
| **生产者-消费者** | 缓冲解耦 | DataLoader 多进程加载 |
| **滑动窗口** | 双端队列维护窗口极值 | 滑动窗口最大值 |
| **消息队列** | 异步解耦 | Redis List / Kafka |

## ML 中的队列

| 场景 | 使用方式 |
|------|----------|
| **PyTorch DataLoader** | 多进程队列预加载数据，减少 GPU 等待 |
| **滑动窗口特征** | 维护固定窗口大小的历史数据 |
| **经验回放（Replay Buffer）** | 强化学习中存储过往经验，随机采样 |
| **流式数据处理** | 实时数据 pipeline 中的缓冲队列 |

## 面试追问

**Q1（基础）**：队列的 FIFO 特性对应现实生活中的什么场景？为什么 BFS 要用队列而不用栈？
**回答要点**：

1. FIFO 对应排队的先到先服务，先进入的元素先被处理，体现了公平的线性顺序
2. BFS 逐层遍历时，队列的 FIFO 保证先访问节点的邻居先被处理，实现"层层推进"的访问顺序
3. 若用栈（LIFO）则变成 DFS 的深入到底再回溯，无法保证按层遍历

**Q2（深挖）**：循环队列如何解决"假溢出"问题？为什么需要牺牲一个存储单元来区分队空和队满？
**回答要点**：

1. 数组实现队列时，出队操作使队首指针后移导致前面有空位但队尾已到末尾而无法入队，即"假溢出"
2. 循环队列用模运算将队尾指针回绕到数组开头，复用已出队的空闲位置来解决假溢出
3. 队空条件 `head == tail`，队满条件 `(tail + 1) % cap == head`，牺牲一个单元区分两者；也可用 size 字段计数免去牺牲

**Q3（实战）**：PyTorch DataLoader 的多进程数据加载如何利用队列来减少 GPU 等待？队列大小设置不当会导致什么问题？
**回答要点**：

1. 使用生产者-消费者模式，worker 进程预加载数据放入队列，主进程从队列取数据送给 GPU，使数据准备与模型计算流水线并行
2. 队列太小会导致 GPU 频繁等待数据而饥饿，降低训练吞吐量
3. 队列太大则占用过多内存，且 epoch 切换时可能产生 stale 数据

**Q4（边界）**：在什么场景下普通队列的 FIFO 特性不再是最优策略？优先队列和双端队列分别解决了什么问题？
**回答要点**：

1. 任务有不同优先级时 FIFO 不公平，需用优先队列让高优先级任务优先出队
2. 需要两端操作时（如滑动窗口最大值），普通队列仅操作一端效率低，需用双端队列
3. 超大数据量或分布式场景下，内存队列可能成为瓶颈，需使用消息队列（如 Kafka）来解耦和持久化
