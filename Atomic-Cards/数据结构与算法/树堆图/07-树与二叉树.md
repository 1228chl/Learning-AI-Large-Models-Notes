# 树与二叉树

## 定义

树（Tree）是一种**非线性**数据结构，由节点（Node）和边（Edge）组成。每个节点有零个或多个**子节点**，有且只有一个**根节点**。二叉树（Binary Tree）是每个节点最多有两个子节点（左孩子、右孩子）的树。

## 直观理解

### 树 = 分层结构

树与线性结构（数组、链表）的本质区别：**线性结构是"一对一"的前后关系，树是"一对多"的层级关系**。树天然适合表示具有层级结构的数据：文件系统目录、公司组织架构、HTML 文档的 DOM 树、编译器中的抽象语法树（AST）。

二叉树的"二分"特性使其成为算法设计的基础：二叉搜索树的查找 $O(\log n)$、堆的优先级管理 $O(\log n)$、决策树的递归划分——都利用了二叉树的分治结构。

### 树的遍历方式

树的遍历有两种基本方式，对应不同的访问顺序：
- **深度优先（DFS）**：沿一条路径走到最深处，再回溯——用栈实现（递归或显式栈）
- **广度优先（BFS）**：逐层从左到右访问——用队列实现

前序、中序、后序遍历是 DFS 的三种变体，区别在于访问根节点的时机（前、中、后）。

## 二叉树遍历

```python
class TreeNode:

    def __init__(self, val=0, left=None, right=None):

        self.val = val                   # 节点存储的数据值

        self.left = left                 # 指向左子节点的指针

        self.right = right               # 指向右子节点的指针

# 深度优先遍历（DFS）— 用递归或栈深入到底再回溯
def inorder(root):                       # 中序：先遍历左子树，再访问根节点，最后遍历右子树
    if not root: return                  # 空节点直接返回，递归终止条件
    inorder(root.left)                   # 递归遍历左子树，将左子树全部处理完
    print(root.val)                      # 访问当前根节点
    inorder(root.right)                  # 递归遍历右子树

def preorder(root):                      # 前序：先访问根节点，再遍历左子树，最后遍历右子树
    if not root: return
    print(root.val)                      # 先处理当前节点
    preorder(root.left)                  # 再递归处理左子树
    preorder(root.right)                 # 最后递归处理右子树

def postorder(root):                     # 后序：先遍历左子树，再遍历右子树，最后访问根节点
    if not root: return
    postorder(root.left)                 # 先递归处理左子树
    postorder(root.right)                # 再递归处理右子树
    print(root.val)                      # 左右子树都处理完后才访问根节点

# 广度优先遍历（BFS）— 用队列逐层推进
from collections import deque
def level_order(root):
    if not root: return                  # 空树直接返回

    q = deque([root])                    # 根节点入队，作为层序遍历的起点
    while q:                             # 队列不为空时持续遍历

        node = q.popleft()               # 取出队首节点（同一层从左到右处理）
        print(node.val)                  # 访问当前节点
        if node.left: q.append(node.left)    # 左子节点入队，下一层按顺序处理
        if node.right: q.append(node.right)  # 右子节点入队
```

## 二叉搜索树（BST）

对任意节点，**左子树所有值 < 节点值 < 右子树所有值**：

| 操作 | 平均 | 最坏（退化为链表） |
|------|:----:|:------------------:|
| 查找 | $O(\log n)$ | $O(n)$ |
| 插入 | $O(\log n)$ | $O(n)$ |
| 删除 | $O(\log n)$ | $O(n)$ |

BST 的不平衡问题由平衡树解决：**AVL 树**（严格平衡，四种旋转维护高度差 ≤ 1）和**红黑树**（近似平衡，旋转次数少，插入/删除性能更优，Java TreeMap、C++ map 的底层）。

### BST vs B+ 树

传统二叉树（如 BST）在内存中工作良好，但数据量超出单机内存需要磁盘 I/O 时，二叉树每个节点只存一个键值导致树高过大，磁盘 I/O 次数过多。B+ 树每个节点存储数百个键值，将树高控制在 3-4 层，每次 I/O 读取整个节点（一页数据），因此数据库和文件系统的索引底层普遍使用 B+ 树而非二叉树。

## 二叉树分类

| 类型 | 定义 | 用途 |
|------|------|------|
| **满二叉树** | 所有层节点数达到最大 | 理论分析 |
| **完全二叉树** | 除最后一层外都满，且最后一层靠左 | **堆**的底层存储 |
| **二叉搜索树（BST）** | 左小右大 | 有序数据存储 |
| **平衡二叉树（AVL）** | 任意节点左右子树高度差 ≤ 1 | 严格平衡的 BST |
| **红黑树** | 近似平衡，旋转少 | 工程最常用（Map 底层） |
| **线段树** | 区间查询和更新 | 区间最值、区间和 |
| **Trie（前缀树）** | 字符串前缀匹配 | 自动补全、词典 |

## 面试追问

**Q1（基础）**：二叉树的三种深度优先遍历（前序、中序、后序）分别是什么顺序？如何理解"递归序"这个概念？
**回答要点**：

1. 前序遍历顺序为根→左→右；中序遍历为左→根→右；后序遍历为左→右→根
2. 递归遍历时每个节点会被访问三次：第一次到达时对应前序位置、左子树返回时对应中序位置、右子树返回时对应后序位置
3. 在不同时机打印/处理节点即得到不同的遍历顺序，这就是"递归序"的核心思想

**Q2（深挖）**：二叉搜索树（BST）在什么情况下会退化为链表？如何避免？AVL 树和红黑树各采用什么策略维持平衡？
**回答要点**：

1. 按升序或降序顺序插入数据时 BST 退化为链表，查找时间复杂度退化为 O(n)
2. AVL 树通过严格维护左右子树高度差不超过 1（四种旋转操作），保证严格 O(log n) 的查找性能
3. 红黑树通过颜色约束（红节点不能连续、根节点为黑、叶子节点为黑等）维持近似平衡，旋转次数少，插入/删除性能更优

**Q3（实战）**：XGBoost / LightGBM 中的决策树是如何利用二叉树结构做特征分裂的？分裂点如何选择？
**回答要点**：

1. 每棵树从根节点开始递归地选择最优特征和最优分裂点，将样本划分到左右子树
2. XGBoost 使用预排序加加权分位数近似寻找分裂点；LightGBM 使用直方图算法将连续特征离散化，减少分裂点候选数
3. 每个叶子节点的输出值是落到该节点的样本的梯度统计聚合值

**Q4（边界）**：当数据量超出单机内存时，传统二叉树索引面临什么问题？B+ 树如何解决？
**回答要点**：

1. 二叉树每个节点只存储一个键值，导致树高较大，磁盘 I/O 次数过多
2. B+ 树每个节点可以存储数百个键值，将树高控制在 3 到 4 层，每次 I/O 读取整个节点（一页）的数据，充分利用磁盘块读取效率
3. 叶子节点用链表串联，支持高效的范围查询，因此数据库和文件系统的索引底层普遍使用 B+ 树而非二叉树
