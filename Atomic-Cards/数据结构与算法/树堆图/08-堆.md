# 堆

## 定义

堆（Heap）是一种**完全二叉树**结构，且任意父节点的值总是大于等于（**最大堆**）或小于等于（**最小堆**）其子节点的值。

## 直观理解

### 堆的优先队列机制

堆的核心直觉：**堆是一种能快速获取最大值（或最小值）的数据结构**。获取堆顶元素是 $O(1)$，插入和删除堆顶都是 $O(\log n)$。

堆与排序数组的对比：
- 排序数组找最大值：$O(1)$（取末尾），但插入 $O(n)$
- 堆找最大值：$O(1)$（取堆顶），插入 $O(\log n)$

堆的"偏序"特性：堆只保证父节点大于子节点（最大堆），不保证兄弟节点之间的大小关系。这意味着堆是"部分有序"的——排序程度不如二叉搜索树，但插入和删除的效率更高。

### 堆的应用场景

堆（优先队列）是许多算法的核心组件：Dijkstra 最短路径、Huffman 编码、Top-K 问题、任务调度。

## 核心操作复杂度

| 操作 | 时间复杂度 | 说明 |
|------|:----------:|------|
| `push(x)` | $O(\log n)$ | 插入到末尾，上浮（sift up） |
| `pop()` | $O(\log n)$ | 弹出堆顶，末尾元素放到堆顶，下沉（sift down） |
| `peek()` | $O(1)$ | 查看堆顶（根节点） |
| `build()` | $O(n)$ | 从无序数组建堆（Floyd 算法） |
| `heapify` | $O(\log n)$ | 单个节点下沉调整 |

```python
import heapq

# Python 默认是最小堆
heap = []                               # 空列表作为堆的底层存储，heapq用数组实现完全二叉树
heapq.heappush(heap, 5)                 # 插入元素5，自动上浮到适当位置保持堆性质，O(log n)
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)

smallest = heapq.heappop(heap)          # 弹出堆顶最小值1，末尾元素移到堆顶后下沉调整，O(log n)

# 最大堆：取负数
max_heap = []                           # heapq只支持最小堆，通过存负值将最大问题转化为最小问题
heapq.heappush(max_heap, -5)            # 存入-5，原值5越大则-5越小，越靠近堆顶
heapq.heappush(max_heap, -1)

largest = -heapq.heappop(max_heap)      # 弹出最小值-5，取负还原为原始最大值5

# 建堆 O(n)
nums = [3, 1, 4, 1, 5, 9]              # 无序原始数组
heapq.heapify(nums)                     # 原地建堆，从最后一个非叶子节点开始下沉，时间复杂度O(n)

# Top-K 问题
top_k = heapq.nlargest(3, nums)          # 用堆找出最大的3个元素，适合海量数据中筛选Top-K
```

## 堆排序

```python
def heap_sort(nums):
    heapq.heapify(nums)                          # 将无序数组原地建为最小堆，O(n)
    return [heapq.heappop(nums) for _ in range(len(nums))]  # 依次弹出堆顶最小值，得到升序结果，O(n log n)
```

堆排序时间复杂度 $O(n\log n)$ ，空间复杂度 $O(1)$ （原地排序），但不稳定。

## 堆 vs 二叉搜索树

| 对比 | 堆 | BST |
|------|:--:|:---:|
| 结构约束 | 父 ≥ 子（或 ≤） | 左 < 根 < 右 |
| 查找 | $O(n)$ （略无序） | $O(\log n)$ |
| 取最值 | $O(1)$ 堆顶 | $O(\log n)$ 最左/右 |
| 插入 | $O(\log n)$ | $O(\log n)$ |
| 主用途 | **优先队列** | **有序数据** |

## 应用场景

| 场景 | 原理 | 示例 |
|------|------|------|
| **优先队列** | 按优先级出队 | 任务调度、Dijkstra 最短路径 |
| **Top-K 问题** | 固定大小堆 | 前 K 大/小元素 |
| **中位数查找** | 最大堆 + 最小堆 | 数据流中位数 |
| **合并 K 个有序序列** | 最小堆存每个序列的头 | 外部排序 |
| **定时任务** | 按时间排序的最小堆 | 定时器调度 |

## ML/DL 应用场景

| 应用场景 | 堆的使用方式 | 说明 |
|----------|-------------|------|
| **Beam Search** | 最大堆维护 Top-K 候选序列 | 序列生成（机器翻译、文本生成）中每步保留得分最高的 K 个路径，避免指数级搜索 |
| **KNN 检索** | 最小堆筛选最近邻 | 遍历数据集时维护大小为 K 的最小堆，堆顶为当前第 K 近的距离值，快速判断新样本是否进入 Top-K |
| **训练任务调度** | 优先队列（堆）决定任务执行顺序 | 按优先级（如最紧迫时间、最大梯度范数）调度训练子任务，确保关键任务优先完成 |
| **损失函数 Top-K 筛选** | 堆选取 Top-K 困难样本 | 在 Contrastive Loss / Triplet Loss 中用堆选出最难区分的样本对，加速模型收敛 |
| **Dijkstra 最短路径** | 最小堆加速最短距离节点选取 | 图神经网络和路径规划中，堆每次弹出当前距离最小的节点，保证 $O((V+E)\log V)$ 复杂度 |

## 面试追问

**Q1（基础）**：堆的"完全二叉树"性质是什么意思？为什么堆可以用数组存储而无需指针？
**回答要点**：

1. 完全二叉树指除最后一层外，每层节点数达到最大值，最后一层节点全部靠左排列的二叉树结构。
2. 堆利用数组的索引映射关系存储：节点 $i$ 的左子节点索引为 $2i+1$，右子节点为 $2i+2$，父节点为 $\lfloor (i-1)/2 \rfloor$，无需显式指针即可完成父子节点导航。
3. 这种无指针的紧凑存储方式不仅节省了指针的内存开销，还能利用数组的连续内存特性提升缓存命中率。

**Q2（深挖）**：建堆操作（heapify）的时间复杂度为什么是 $O(n)$ 而不是 $O(n\log n)$？请从下沉次数角度解释。
**回答要点**：

1. 建堆从最后一个非叶子节点开始，依次向前对每个节点执行下沉（sift down）操作，而非从根节点开始上浮。
2. 高度为 $h$ 的节点最多下沉 $h$ 次，所有节点下沉次数总和为 $\frac{n}{4}\cdot1 + \frac{n}{8}\cdot2 + \frac{n}{16}\cdot3 + \cdots$，该级数收敛于 $O(n)$。
3. 若采用逐个插入建堆的方式（每个节点执行上浮），总复杂度为 $O(n\log n)$，因此 Floyd 建堆算法更优。

**Q3（实战）**：用堆解决 Top-K 问题（如从 100 亿个整数中找最大的 100 个）的内存优势是什么？具体如何操作？
**回答要点**：

1. 维护一个大小为 $K$ 的最小堆，遍历数据时若当前元素大于堆顶，则弹出堆顶并将当前元素压入堆中，然后执行下沉调整。
2. 只需 $O(K)$ 的额外内存（$K=100$），远小于全排序所需的 $O(N)$ 内存，适合处理海量数据。
3. 使用最小堆而非最大堆的原因是：最小堆的堆顶恰好是当前 Top-K 的门槛值，新元素只需与门槛比较即可判断是否入选，而最大堆无法区分新元素是否进入 Top-K。

**Q4（边界）**：堆的"只保证堆顶最值，不保证内部有序"这一特性在哪些场景下是缺点？如何补救？
**回答要点**：

1. 需要查找任意元素（非堆顶）时，堆需要 $O(n)$ 遍历扫描。补救方案：使用索引堆，借助哈希表辅助索引实现 $O(1)$ 查找和 $O(\log n)$ 更新。
2. 需要合并两个堆时，普通二叉堆的合并操作为 $O(n)$。补救方案：使用可并堆（如左偏堆、二项堆、斐波那契堆）将合并操作降为 $O(\log n)$。
3. 需要完整有序的输出序列时，堆本身不能直接提供。补救方案：先进行堆排序（$O(n\log n)$）再输出结果，或改用平衡二叉搜索树。
