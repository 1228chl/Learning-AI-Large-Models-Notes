# 图

## 定义

图（Graph）由**顶点（Vertex）** 和**边（Edge）** 组成 $G = (V, E)$。图是最灵活的数据结构，树、链表都是图的特例。

| 分类 | 定义 | 示例 |
|------|------|------|
| **有向图 vs 无向图** | 边是否有方向 | 单向关注 / 好友关系 |
| **有权图 vs 无权图** | 边是否有权重 | 距离 / 社交连接 |
| **连通图 vs 非连通图** | 是否任意两点可达 | 网络图 / 孤立聚类 |
| **稀疏图 vs 稠密图** | 边数远小于/接近完全图 | 社交网络 / 电路图 |

## 存储方式

```python
# 1. 邻接矩阵（适合稠密图）
graph = [[0, 1, 1],
         [1, 0, 0],
         [1, 0, 0]]
# 查询边：O(1)，空间：O(V²)

# 2. 邻接表（适合稀疏图，更常用）
graph = {
    'A': ['B', 'C'],
    'B': ['A'],
    'C': ['A'],
}
# 查询边：O(度)，空间：O(V + E)
```

| 对比 | 邻接矩阵 | 邻接表 |
|------|:--------:|:------:|
| 查询边 | $O(1)$ | $O(\deg(v))$ |
| 遍历所有邻边 | $O(V)$ | $O(\deg(v))$ |
| 空间 | $O(V^2)$ | $O(V+E)$ |
| 适用 | 稠密图 | 稀疏图（实际更常见） |

## 图的遍历

```python
# DFS（栈/递归）— 深入到底再回溯
def dfs(graph, node, visited=set()):
    if node in visited: return
    visited.add(node)
    print(node)
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited)

# BFS（队列）— 层层推进
from collections import deque
def bfs(graph, start):
    visited = {start}
    q = deque([start])
    while q:
        node = q.popleft()
        print(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                q.append(neighbor)
```

## 最短路径算法

| 算法 | 适用 | 时间复杂度 | 说明 |
|------|------|:----------:|------|
| **Dijkstra** | 非负权图 | $O((V+E)\log V)$ | 单源最短路径（堆优化） |
| **Bellman-Ford** | 任意权图（可检测负环） | $O(VE)$ | DP 思想 |
| **Floyd-Warshall** | 所有点对 | $O(V^3)$ | DP 动态规划 |
| **A\*** | 有启发信息 | 优于 Dijkstra | 地图导航 |

## 面试追问

**Q1（基础）**：邻接矩阵和邻接表两种存储方式各自的空间复杂度是多少？如何根据图的特点选择合适的存储方式？
回答要点：邻接矩阵 $O(V^2)$，邻接表 $O(V+E)$。稠密图（边数接近 $V^2$）用邻接矩阵更简单且有 $O(1)$ 的边查询；稀疏图（边数远小于 $V^2$）用邻接表节省大量空间。实际工程中绝大多数图是稀疏的（社交网络、网络拓扑），邻接表更常用。

**Q2（深挖）**：Dijkstra 算法为什么不能处理负权边？Bellman-Ford 如何解决负权问题？如何检测负环？
回答要点：Dijkstra 基于贪心——每次从已确定最短距离的节点中选最小的向外扩展，一旦处理过的节点不会重新松弛，负权边可能导致后续更短路径被忽略。Bellman-Ford 对所有边做 V-1 轮松弛，保证找到最短路径；再做一轮若仍有边可松弛则说明存在负环。

**Q3（实战）**：推荐系统中的用户-物品二部图如何建模？如何用图算法做推荐？
回答要点：用户和物品作为两类节点，交互行为（点击、购买）作为边构建二部图。可通过随机游走（Personalized PageRank）计算用户对物品的相关性分数；或通过 Node2Vec / GNN 学习节点 embedding，用向量相似度推荐。图神经网络（如 LightGCN）通过聚合邻居信息得到节点表示，是当前主流方法。

**Q4（边界）**：当图规模达到数十亿节点（如全网社交关系）时，传统单机图算法面临什么挑战？分布式图计算框架如何解决？
回答要点：单机内存无法容纳整图，邻接表遍历引发大量随机磁盘 I/O。分布式图框架（如 Pregel、GraphX、Spark GraphFrames）采用"以顶点为中心"的 BSP 模型——每轮所有节点并行处理消息，通过消息传递实现跨机通信。但跨网络通信开销大且需要处理数据倾斜（超级节点如大 V 用户）。存储上常用 CSR/CSC 压缩格式降低内存占用。
