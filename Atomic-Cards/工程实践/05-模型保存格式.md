# 模型保存格式

## 定义

训练好的 ML 模型需要保存到磁盘以便后续部署。不同框架和场景使用不同的保存格式，各有优劣。

## 主流格式对比

| 格式 | 框架 | 用途 | 安全性 | 跨语言 |
|:----:|:----:|:----|:----:|:-----:|
| **`.pkl`（Pickle）** | scikit-learn、通用 Python | 小型模型、原型开发 | ⚠️ 低 | ❌ |
| **`.joblib`** | **scikit-learn（推荐）** | 大型 sklearn 模型、Pipeline | ⚠️ 中 | ❌ |
| **`.pt` / `.pth`** | **PyTorch** | 深度学习模型、checkpoint | ✅ 安全 | ❌（需 ONNX）|
| **`.h5` / `.hdf5`** | **TensorFlow/Keras** | 深度学习模型 | ✅ | ❌ |
| **`.onnx`** | **跨框架** | 模型互转和部署 | ✅ | ✅ |
| **`.bin`** | **HuggingFace** | Transformers 预训练模型 | ✅ | ⚠️ 部分 |

## 各框架保存方法

```python
# === scikit-learn ===
import joblib
# 保存（compress 压缩级别 0-9）
joblib.dump(model, 'model.joblib', compress=3)
# 加载
model = joblib.load('model.joblib')

# === PyTorch ===
import torch
# 仅保存参数（推荐）
torch.save(model.state_dict(), 'model.pt')
model.load_state_dict(torch.load('model.pt', map_location='cpu'))

# 保存完整模型（包含架构）
torch.save(model, 'model_full.pth')
model = torch.load('model_full.pth')

# 保存 checkpoint（包含优化器状态）
torch.save({
    'epoch': epoch,
    'model_state_dict': model.state_dict(),
    'optimizer_state_dict': optimizer.state_dict(),
    'loss': loss,
}, 'checkpoint.pt')

# === HuggingFace ===
from transformers import AutoModel
model.save_pretrained('./my_model/')   # 保存 config.json + pytorch_model.bin
tokenizer.save_pretrained('./my_model/')
model = AutoModel.from_pretrained('./my_model/')
```

## 模型格式选择指南

```python
# 选择建议
if framework == "scikit-learn":
    format = ".joblib"     # 比 pickle 更快、更小、更安全
elif framework == "PyTorch":
    format = ".pt"         # 保存 state_dict，不保存架构
elif need_cross_platform:
    format = ".onnx"       # 跨框架、跨语言部署
elif framework == "HuggingFace":
    format = "save_pretrained()"  # 自动保存模型 + 配置 + tokenizer
```

## ONNX 转换

```python
# PyTorch → ONNX（跨平台部署）
import torch.onnx

dummy_input = torch.randn(1, 3, 224, 224)
torch.onnx.export(
    model, dummy_input, "model.onnx",
    input_names=['input'], output_names=['output'],
    dynamic_axes={'input': {0: 'batch_size'}}
)
```

## ML 中的模型保存

| 应用场景 | 推荐格式 | 原因 |
|:--------:|:--------|:----|
| **本地实验** | `.joblib` / `.pt` | 简单快速 |
| **生产部署** | `.onnx` / `save_pretrained` | 跨平台、版本兼容 |
| **模型分发** | `.onnx` | 接收方可用任意框架 |
| **继续训练** | `.pt` checkpoint | 保存优化器状态、epoch |
| **移动端/边缘** | `.onnx` / TFLite | 轻量推理 |


## 面试追问

**Q1（基础）**：PyTorch 中 `model.state_dict()` 和直接 `torch.save(model)` 两种保存方式有何区别？推荐哪种？
**回答要点**：`state_dict` 只保存参数（轻量、框架耦合低），`torch.save(model)` 保存完整模型（含架构，重、跨版本易出错）；推荐保存 `state_dict`，配合模型类定义文件实现可复现加载。

**Q2（深挖）**：ONNX 格式为什么能实现跨框架部署？它的工作原理是什么？
**回答要点**：ONNX 定义标准化的计算图中间表示（IR）；将 PyTorch/TF 模型的计算图导出为 ONNX 格式，再由目标框架（ONNX Runtime）解释执行；支持动态轴（dynamic axes）处理可变 batch size。

**Q3（实战）**：在生产环境切换模型格式时，如何保证转换前后推理结果一致？
**回答要点**：对比转换前后模型输出误差（设定允许阈值如 1e-4）；注意算子兼容性（PyTorch→ONNX 部分算子不支持或行为不同）；使用 ONNX Runtime 验证精度，必要时 fallback 到原始框架。

**Q4（边界）**：Pickle 格式加载模型存在哪些安全风险？如何避免？
**回答要点**：Pickle 反序列化时会执行任意 Python 代码（`__reduce__` 方法），存在远程代码执行风险；`joblib` 也是基于 Pickle，同样不安全；安全方案：生产环境用 ONNX/TensorRT/SavedModel 等非 Pickle 格式；来源不可信的 `.pkl` 文件绝不加载。
