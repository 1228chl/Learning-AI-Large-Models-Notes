# 向量数据库概述

## 定义

向量数据库（Vector Database）是一种专门用于存储、索引和检索**高维向量**的数据库系统。它将数据（文本、图像、音频等）通过嵌入模型转换为向量，然后提供高效的**相似度搜索**能力——即找出与查询向量最相似的 Top-K 个向量。

## 关系型数据库 vs 向量数据库

| 对比维度 | 关系型数据库（MySQL） | 向量数据库（Milvus） |
|----------|---------------------|---------------------|
| **数据模型** | 行列表格（结构化） | 向量 + 标量字段 |
| **查询方式** | SQL 精确匹配、范围查询 | ANN（近似最近邻）搜索 |
| **索引** | B+ 树、哈希索引 | IVF、HNSW、磁盘索引 |
| **排序依据** | 数值大小、字典序 | 向量距离/相似度 |
| **适用场景** | 事务处理、精确查询 | 语义搜索、相似度匹配 |
| **典型延迟** | 毫秒级 | 毫秒级（百万级数据） |

## 主流向量数据库对比

| 产品 | 类型 | 特点 | 适用场景 |
|------|------|------|----------|
| **Milvus** | 分布式向量数据库 | 云原生、水平扩展、丰富索引类型 | 生产级 RAG、大规模检索 |
| **FAISS** | 向量检索库（非数据库） | Meta 开源，纯 Python/C++ 库 | 本地/离线检索、原型验证 |
| **Chroma** | 轻量级向量数据库 | 易上手、Python 原生、无需部署 | 小规模项目、学习原型 |
| **Pinecone** | 托管云服务 | 免运维、开箱即用、收费 | 快速上线的商业项目 |
| **Qdrant** | 向量数据库（Rust 实现） | 高性能、支持过滤、WAL 持久化 | 生产级替代方案 |

## 核心流程

```python
# 向量数据库的工作流程
# 1. 索引阶段：文档 → 分块 → 嵌入 → 存入向量库
# 2. 检索阶段：查询 → 嵌入 → 相似度搜索 → 返回 TOP-K
# 3. 生成阶段：查询 + 检索结果 → LLM 生成答案
```

## 与 Redis 的定位区别

| 维度 | Redis | 向量数据库（Milvus） |
|------|-------|---------------------|
| 核心能力 | 内存键值缓存 | 高效的向量相似度搜索 |
| 数据规模 | GB 级（受内存限制） | 百亿级（分布式） |
| 索引方式 | 哈希表 | IVF / HNSW / DiskANN |
| 检索类型 | 精确键查找 | 近似最近邻（ANN） |
| 在 RAG 中的角色 | BM25 结果缓存 | 语义向量存储与检索 |

> **面试追问**
>
> Q1（基础）：什么是向量数据库？它和传统关系型数据库（如MySQL）的核心区别是什么？
> 回答要点：① 向量数据库专门用于存储和检索高维向量，通过ANN近似最近邻搜索找出语义最相似的Top-K个向量。② MySQL用SQL精确匹配和范围查询，排序依据是数值大小；向量数据库按向量距离（余弦/欧氏/内积）排序。③ 向量数据库的索引（IVF/HNSW）针对高维向量设计，不同于MySQL的B+树索引。
>
> Q2（深挖）：Milvus、FAISS和Chroma三者的定位和适用场景有何不同？如何选型？
> 回答要点：① Milvus是分布式向量数据库，支持水平扩展、丰富索引类型和云原生部署，适合生产级RAG和大规模检索。② FAISS是Meta开源的向量检索纯Python/C++库，非独立数据库，适合本地/离线检索和原型验证。③ Chroma是轻量级嵌入式向量数据库，易上手无需部署，适合小规模项目和学习原型。④ 选型：生产环境用Milvus，快速原型用Chroma，定制化算法研究用FAISS。
>
> Q3（实战）：请描述RAG系统中向量数据库的完整工作流程（索引阶段→检索阶段→生成阶段）。
> 回答要点：① 索引阶段：原始文档→文本分块（Chunk）→嵌入模型生成向量→存入向量数据库。② 检索阶段：用户查询→同一嵌入模型生成查询向量→向量数据库相似度搜索→返回Top-K相关文档块。③ 生成阶段：用户原始查询+检索到的相关文档块→拼接到Prompt→输入LLM生成带引用的回答。④ 关键设计：分块策略直接影响检索质量，向量维度与嵌入模型需匹配。
>
> Q4（边界）：哪些类型的查询不适合用向量数据库处理？分别在什么场景下应回归传统数据库？
> 回答要点：① 精确匹配查询（如用户ID=1001查找用户名）用Hash索引毫秒级返回，向量数据库反而慢。② 范围查询、数值比较和事务操作（如年龄>18、转账）是关系型数据库的强项。③ 结构化数据的分组聚合统计（SUM、AVG、GROUP BY）不支持。④ 最佳实践：向量数据库做语义检索层，关系型数据库做精确数据存储，两者互补而非替代。
