# 稠密向量与稀疏向量（Dense vs Sparse Vectors）

## 定义

**稠密向量（Dense Vector）** 和 **稀疏向量（Sparse Vector）** 是两种文本向量化表示方式，分别通过神经网络嵌入和词频统计生成，在 RAG 系统中协同使用以实现最佳检索效果。

### 稠密向量

稠密向量是 Embedding 模型（如 BGE、text2vec）将文本映射为的**低维稠密浮点数组**，每个维度都有非零值，维度通常在 256 ~ 1024 之间：

$$
\mathbf{v}_{\text{dense}} = \text{Encoder}(t) \in \mathbb{R}^d
$$

- $\text{Encoder}$：神经编码器（如 BERT、BGE），将文本映射到语义空间
- $t$：输入文本
- $\mathbb{R}^d$：$d$ 维实数向量空间，其中 $d$ 为向量维度（如 768、1024）
- $\mathbf{v}_{\text{dense}}$：稠密向量，每一维取值通常为 $[-1, 1]$ 或 $[0, 1]$ 区间的浮点数

### 稀疏向量

稀疏向量是基于词频统计的**高维稀疏表示**，每个维度对应词汇表中的一个词，维度数等于词汇表大小（通常是数万到数十万），但非零维度极少（仅文本中出现过的词）：

$$
\mathbf{v}_{\text{sparse}} = \{(i_1, w_1), (i_2, w_2), \dots, (i_k, w_k)\} \in \mathbb{R}^{|V|}
$$

- $i_j$：词汇表中第 $j$ 个命中词的索引
- $w_j$：该词的权重值，通常由 BM25 或 TF-IDF 计算得出
- $|V|$：词汇表大小（通常在 5 万 ~ 50 万之间）
- $k$：非零维度数，通常 $k \ll |V|$，如一篇短文可能只有 10-30 个非零维度
- $\mathbf{v}_{\text{sparse}}$：稀疏向量，非零维度不到总维度的 0.1%

## 核心对比

| 对比维度 | 稠密向量 | 稀疏向量 |
|:--------:|:--------:|:--------:|
| **维度数** | 256~1024 | 50000~500000 |
| **非零率** | 100%（全部维度非零） | < 0.1%（只有出现过的词非零） |
| **生成方式** | 神经网络编码（语义理解） | 词频统计（精确匹配） |
| **语义能力** | 强：理解同义词、近义表达 | 弱：仅精确匹配词汇 |
| **匹配原理** | "汽车" 和 "车辆" 语义相近可匹配 | "汽车" 和 "车辆" 是不同的词，无法匹配 |
| **OOV 问题** | 无（Subword 分词可处理未登录词） | 有（不在词汇表中的词无法表示） |
| **检索特性** | 语义检索，召回率高 | 关键词匹配，精确率（Precision）高 |
| **存储方式** | 连续数组（float32 × d） | 索引-值对数组（仅存非零项） |
| **典型模型** | BGE, text2vec, OpenAI Ada | BM25, TF-IDF, SPLADE |

## 混合检索原理

稠密和稀疏向量结合使用，通过加权融合排序实现最佳检索效果：

$$
\text{Score}(q, d) = \alpha \cdot \text{sim}_{\text{dense}}(\mathbf{q}_{\text{dense}}, \mathbf{d}_{\text{dense}}) + (1 - \alpha) \cdot \text{sim}_{\text{sparse}}(\mathbf{q}_{\text{sparse}}, \mathbf{d}_{\text{sparse}})
$$

- $\alpha$：稠密检索权重，通常取 0.3~0.7，需根据具体数据集调优
- $\mathbf{q}_{\text{dense}}$：查询的稠密向量
- $\mathbf{q}_{\text{sparse}}$：查询的稀疏向量
- $\text{sim}_{\text{dense}}$：余弦相似度或内积，计算稠密向量的语义相关性
- $\text{sim}_{\text{sparse}}$：通常用 BM25 分数，计算稀疏向量的关键词匹配度
- $\mathbf{d}_{\text{dense}}, \mathbf{d}_{\text{sparse}}$：文档的稠密和稀疏向量

### 直观理解

> 稠密向量 = "知道你在说什么"（语义理解），稀疏向量 = "听见你说的是什么词"（精确匹配）。两者结合，一个负责"宽泛召回"（高召回），一个负责"精确筛选"（高精确率）。

## ML/DL 应用场景

| 应用场景 | 稠密向量作用 | 稀疏向量作用 |
|:--------|:------------|:------------|
| **RAG 问答系统** | 理解用户问题的语义，召回同义概念 | 精确匹配专业术语、编号、专有名词 |
| **文档搜索引擎** | 理解查询意图，跨语言检索 | 关键词高亮、精确匹配文档ID/日期 |
| **混合检索** | 语义召回扩大候选集 | 用关键词精排提升准确率 |
| **重复检测** | 检测语义相似但措辞不同的文本 | 精确匹配完全相同的文本片段 |
| **电商搜索** | "红色连衣裙"可以召回"红色裙子" | "iPhone 15" 必须精确匹配型号 |

## 面试追问

**Q1（基础）**：稠密向量和稀疏向量在生成方式上有何本质区别？
**回答要点**：

1. 稠密向量由神经网络编码器生成，通过自注意力/Transformer 理解文本语义，所有维度都有非零值
2. 稀疏向量由词频统计算法（BM25/TF-IDF）生成，仅文本中出现过的词对应的维度有非零值
3. 稠密向量维度固定（如 768 维），稀疏向量维度 = 词汇表大小（数万至数十万维）

**Q2（深挖）**：既然稠密向量能理解语义，为什么 RAG 系统还需要稀疏向量？
**回答要点**：

1. 稠密向量对精确匹配（专有名词、编号、日期、代码）效果差，"GPT-4"和"GPT-3"语义相似度高但含义不同
2. 稀疏向量天然擅长精确匹配，当用户输入精确术语时优先召回正确文档
3. 两者互补：稠密向量高召回（recall），稀疏向量高精确率（precision），混合检索通常取加权融合

**Q3（实战）**：在 Milvus 中如何同时存储和检索稠密向量与稀疏向量？
**回答要点**：

1. 在 Collection 中定义两个字段：`dense_vector`（FLOAT_VECTOR, dim=768）和 `sparse_vector`（SPARSE_FLOAT_VECTOR）
2. `dense_vector` 建 IVF_FLAT/HNSW 索引，`sparse_vector` 自动支持倒排索引
3. 检索时使用 `hybrid_search()` 或两次 `search()` 后加权融合（RRF/加权平均），无需手动分别查两次
4. 使用 BGE-M3 模型可同时输出稠密向量和稀疏向量，一次调用生成两种表示

**Q4（边界）**：稀疏向量在大规模 RAG 系统中有哪些实际局限？
**回答要点**：

1. 词汇表固定后无法处理新出现的领域术语或跨语言查询（需要频繁更新词表）
2. 稀疏向量无法理解同义词，用户说"车辆"但文档只写"汽车"时无法匹配
3. 存储优化：虽然非零项少，但索引结构（倒排索引）在文档量极大时内存消耗不容忽视
4. 当前最佳实践是稠密+稀疏混合，而非仅用任何一种
