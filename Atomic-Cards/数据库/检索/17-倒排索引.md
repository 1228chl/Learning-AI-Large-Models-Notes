# 倒排索引（Inverted Index）

## 定义

倒排索引（Inverted Index）是全文检索系统的核心数据结构，它记录**每个词项出现在哪些文档中**（以及出现的位置和频率），从而实现从关键词到文档的快速定位。与正向索引（文档→词项）相反，倒排索引是**词项→文档**的映射。

### 正向索引 vs 倒排索引

**正向索引（Forward Index）**：以文档为主键，记录文档中包含哪些词。

$$
\text{Doc}_1: \{w_1, w_3, w_5\}, \quad \text{Doc}_2: \{w_2, w_3, w_4\}
$$

**倒排索引（Inverted Index）**：以词项为主键，记录词项出现在哪些文档中。

$$
\text{Inverted Index} = \{ (t_j, \{(d_i, \text{freq}_{ij}, \text{positions}_{ij})\}) \}
$$

- $t_j$：词汇表中第 $j$ 个词项（term）
- $d_i$：包含词项 $t_j$ 的第 $i$ 篇文档
- $\text{freq}_{ij}$：词项 $t_j$ 在文档 $d_i$ 中出现的词频（Term Frequency）
- $\text{positions}_{ij}$：词项 $t_j$ 在文档 $d_i$ 中出现的位置列表（用于短语查询和邻近搜索）

### 检索匹配机制

给定查询 $q = [t_1, t_2, \dots, t_k]$，检索过程为：

$$
\text{Result}(q) = \bigcap_{j=1}^k \text{PostingList}(t_j)
$$

- $\text{PostingList}(t_j)$：词项 $t_j$ 的倒排列表（包含该词的所有文档集合）
- $\bigcap$：取各词项倒排列表的交集（AND 查询）或并集（OR 查询）

## 倒排索引构建过程

### 1. 文档集合示例

```
Doc1: "全文检索技术是信息检索领域的重要研究方向"
Doc2: "倒排索引是全文检索系统的核心数据结构"
Doc3: "中文分词是全文检索中非常关键的一步"
```

### 2. 分词与倒排表

| 词项 | 包含该词的文档 | 词频 | 位置 |
|:-----|:-------------|:----|:-----|
| 全文检索 | Doc1, Doc2, Doc3 | 1:2, 2:1, 3:1 | 1:[0,5], 2:[0], 3:[0] |
| 倒排索引 | Doc2 | 2:1 | 2:[1] |
| 检索 | Doc1, Doc2 | 1:1, 2:3 | 1:[3], 2:[2] |
| 分词 | Doc3 | 3:2 | 3:[0,4] |
| 数据结构 | Doc2 | 2:1 | 2:[4] |

### 3. 代码示例

```python
from collections import defaultdict

class InvertedIndex:
    """
    简单的倒排索引实现：支持索引构建、检索和 TF-IDF 排序。
    """
    def __init__(self):
        self.index = defaultdict(dict)     # 倒排表: {词项: {文档ID: 词频}}
        self.doc_lengths = {}              # 文档长度: {文档ID: 总词数}
        self.doc_count = 0                 # 文档总数

    def add_document(self, doc_id: int, tokens: list[str]):
        """
        将分词后的文档加入倒排索引。

        Args:
            doc_id: 文档唯一标识
            tokens: 分词后的词项列表
        """
        self.doc_count += 1
        self.doc_lengths[doc_id] = len(tokens)

        # 统计每个词项在当前文档中的词频
        term_freq = defaultdict(int)
        for token in tokens:
            term_freq[token] += 1

        # 写入倒排表
        for term, freq in term_freq.items():
            self.index[term][doc_id] = freq

    def search(self, query_tokens: list[str], top_k: int = 5) -> list[tuple[int, float]]:
        """
        检索：找出包含所有查询词项的文档，按 TF-IDF 排序。

        Args:
            query_tokens: 查询的分词结果
            top_k: 返回 top-k 结果

        Returns:
            list[(doc_id, score)]: 按相关性得分降序排列
        """
        # 找出包含所有查询词项的文档（AND 查询）
        result_docs = None
        for term in query_tokens:
            if term not in self.index:
                return []                  # 任一查询词不在索引中，返回空
            doc_set = set(self.index[term].keys())
            if result_docs is None:
                result_docs = doc_set
            else:
                result_docs &= doc_set     # AND 取交集

        if not result_docs:
            return []

        # 计算每个候选文档的相关性得分（简化 TF-IDF）
        scores = []
        for doc_id in result_docs:
            score = 0.0
            for term in query_tokens:
                tf = self.index[term].get(doc_id, 0)
                # TF-IDF 简化公式
                idf = self.doc_count / max(len(self.index[term]), 1)
                score += tf * (idf ** 0.5)  # sqrt(IDF) 防止长文档主导
            scores.append((doc_id, score))

        # 按得分降序排列
        scores.sort(key=lambda x: -x[1])
        return scores[:top_k]


# ========== 使用示例 ==========
index = InvertedIndex()

# 构建索引
index.add_document(1, ["全文检索", "技术", "信息", "检索"])
index.add_document(2, ["倒排索引", "全文检索", "系统", "核心"])
index.add_document(3, ["中文", "分词", "全文检索", "关键"])

# 检索
results = index.search(["全文检索", "核心"])
for doc_id, score in results:
    print(f"文档 {doc_id}: 得分 {score:.4f}")
```

## 倒排索引在检索系统中的地位

```
用户查询 → 分词 → 倒排索引导航 → 得分排序 → 返回结果
                  ↓
          词项 → PostingList
                  ↓
          快速定位候选文档（毫秒级）
                  ↓
          避免了全文档顺序扫描
```

## 直观理解

> 倒排索引好比书的"索引页"：你想找"Transformer"这个词，不用翻完整本书，只需查索引页找到"Transformer: 第45, 78, 123页"——倒排索引就是这种"词→位置"的映射表。

## 性能分析

倒排索引的检索时间复杂度为 $O(k)$（$k$ 为查询词项数），而顺序扫描需要 $O(N \times L)$（$N$ 文档数，$L$ 平均长度）。百万级文档集上，倒排索引可在 10ms 内返回结果，顺序扫描需数秒到数分钟。但这种优势的代价是**存储开销**——倒排表随文档量线性增长，亿级文档需数百 GB 内存，需通过分片（sharding）将索引分布到多台机器。

## ML/DL 应用场景

| 应用场景 | 倒排索引的作用 | 说明 |
|:--------|:--------------|:-----|
| **搜索引擎** | 关键词快速定位文档 | 百度/Google 的核心检索结构 |
| **RAG 稀疏检索** | 配合 BM25/TF-IDF 实现关键词匹配 | 与稠密向量检索互补，提升准确率 |
| **拼写纠错** | 为每个词的编辑距离变体建索引 | 用户输入"transformer"时匹配到"transformer" |
| **短语查询** | 利用位置信息精确匹配短语 | 搜索"深度学习"时过滤掉"深度"和"学习"不连续的情况 |

## 面试追问

**Q1（基础）**：倒排索引相比顺序扫描在全文档搜索中有什么性能优势？
**回答要点**：

1. 顺序扫描需要遍历每个文档的每个词，时间复杂度 $O(N \times L)$（$N$ 文档数，$L$ 平均长度）
2. 倒排索引直接从词项定位文档，时间复杂度 $O(k)$（$k$ 为查询词项数），常为毫秒级
3. 对百万级文档集，顺序扫描需要数秒到数分钟，倒排索引可在 10ms 内返回结果

**Q2（深挖）**：倒排索引中除了文档 ID 和词频，为什么还要记录位置信息？
**回答要点**：

1. 位置信息支持短语查询（phrase query）：检索 "机器学习" 时确保两词相邻且顺序正确
2. 支持邻近搜索（proximity search）：检索 "深度学习...框架" 时限定两词间隔不超过 N 个词
3. 支持高亮显示：在搜索结果中标记关键词出现的位置
4. 存储位置有额外开销，可根据应用需求选择是否保留位置信息

**Q3（实战）**：在 RAG 系统的混合检索中，倒排索引（稀疏检索）和向量检索（稠密检索）如何协同工作？
**回答要点**：

1. 倒排索引实现关键词精确匹配：用户输入精确定义或术语时优先命中
2. 向量检索实现语义匹配：同义词、近义表达也能命中
3. 两者通过 RRF（倒数排序融合）或加权融合（WeightedRanker）合并得分
4. 实际效果：倒排查找补全向量检索对精确术语的遗漏，提升整体召回率

**Q4（边界）**：倒排索引在大规模系统中面临哪些挑战？如何优化？
**回答要点**：

1. 内存占用：倒排表随文档量线性增长，亿级文档需数百 GB 内存 → 使用分片（sharding）将索引分布到多台机器
2. 更新延迟：新增文档需更新倒排表，频繁更新导致 I/O 瓶颈 → 采用增量索引 + 合并策略（LSM-Tree 思想）
3. 跳跃指针（skip pointers）：在倒排列表中插入跳跃指针，加速 AND 查询时多个倒排表的合并操作
4. 压缩编码：使用变长编码（如 Varint、Gamma 编码）压缩倒排列表中的整数序列，减少存储和 I/O
