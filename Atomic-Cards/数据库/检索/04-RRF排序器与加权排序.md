# RRF 排序器与加权排序

## 问题背景

混合检索从多个检索器（稠密检索、稀疏检索等）返回不同的结果列表，需要**排序器**（Ranker）将这些异构结果融合为一个统一的排序列表。排序器负责"粗排序"，从多路召回中筛选出候选集；而**重排序器**（Reranker）在粗排序基础上做"精排序"，使用交叉编码器对少量候选文档进行精细打分。

```
用户查询
    │
    ├──→ 稠密检索（语义匹配）──→ 结果列表 A
    ├──→ 稀疏检索（关键词匹配）──→ 结果列表 B   ← 多路召回，各自独立打分
    └──→ 其他检索器 ──────────→ 结果列表 C
                                        │
                                        ↓
                              排序器（Ranker）融合排序       ← 粗排序阶段
                                        │
                                        ↓
                              重排序器（Reranker）精排       ← 精排序阶段
                                        │
                                        ↓
                                  最终 Top-K 结果
```

## 加权排序器

加权排序器对不同检索器的分数进行加权求和，是最直观的融合策略：

$$
score(d) = \sum_{i=1}^{N} w_i \times s_i
$$

- $score(d)$：文档 $d$ 的最终融合得分
- $N$：检索器（检索路径）的数量
- $w_i$：第 $i$ 个检索器的权重，满足 $\sum w_i = 1$
- $s_i$：第 $i$ 个检索器对文档 $d$ 输出的原始相似度分数

### 分数归一化的必要性

不同检索器使用的距离度量取值范围不同，必须归一化到同一尺度后才能加权求和：

| 距离度量 | 取值范围 | 归一化方法 |
|:---------|:--------:|:-----------|
| 欧氏距离（L2） | $[0, +\infty)$ | 通过指数变换或 Min-Max 归一化映射到 $[0,1]$ |
| 内积（IP） | $(-\infty, +\infty)$ | 先对向量做 L2 归一化，内积退化为余弦相似度 |
| 余弦相似度 | $[-1, 1]$ | 线性映射到 $[0,1]$：$(s + 1) / 2$ |

> 归一化方法的选择直接影响融合效果，不当的归一化可能导致某个检索器的分数主导整个结果。

## RRF（倒数排序融合）

RRF（Reciprocal Rank Fusion，倒数排序融合）是一种**基于排名位置**而非原始分数的融合策略，避免了分数归一化的难题：

$$
score(d) = \sum_{i=1}^{N} \frac{1}{k + rank_i(d) + 1}
$$

- $d$：待评分的文档
- $N$：检索路径（检索器）的数量
- $rank_i(d)$：文档 $d$ 在第 $i$ 个检索器返回列表中的排名位置（从 0 开始计数）
- $k$：平滑参数，默认值 60，控制排名贡献的衰减速度
  - $k$ 值越小，前几名之间的分数差距越大
  - $k$ 值越大，各排名之间的分数越平滑

### 计算示例

假设有 3 个检索器返回的结果列表，文档 A、B、C 在不同列表中的排名如下：

| 文档 | 稠密检索排名 | 稀疏检索排名 | 语义检索排名 | RRF 得分（k=60） | 计算过程 |
|:----|:----------:|:----------:|:----------:|:--------------:|:---------|
| 文档 A | 0 | 5 | — | 0.0316 | $1/(60+0+1) + 1/(60+5+1)$ |
| 文档 B | 2 | 1 | 3 | 0.0459 | $1/(60+2+1) + 1/(60+1+1) + 1/(60+3+1)$ |
| 文档 C | — | — | 0 | 0.0164 | $1/(60+0+1)$ |

> "—" 表示该文档未出现在对应检索器的结果列表中（视为排名无限大，贡献为 0）。
>
> **文档 B** 虽然没有任何第 1 名的单项排名，但同时在 3 个列表中出现且排名都靠前，RRF 累积得分最高，排在最终结果的首位。

### 排名贡献曲线

| 排名位置 | 贡献分数（k=60） | 贡献分数（k=10） |
|:--------:|:---------------:|:---------------:|
| 0（第 1 名） | 0.01639 | 0.09091 |
| 5 | 0.01515 | 0.06250 |
| 10 | 0.01408 | 0.04762 |
| 50 | 0.00901 | 0.01639 |
| 100 | 0.00621 | 0.00901 |

> k 值越小，排名越靠前的文档获得的分数优势越明显；k 值越大，不同排名之间的分数差距越平缓。

## 加权排序 vs RRF 对比

| 对比维度 | 加权排序（Weighted Ranker） | RRF（倒数排序融合） |
|:---------|:---------------------------|:-------------------|
| **输入类型** | 原始相似度分数 | 排名位置（序号） |
| **归一化需求** | 需要分数归一化 | 不需要（天然对齐） |
| **权重控制** | 显式权重（可调节各检索器重要性） | 隐式（所有检索器等权） |
| **异构兼容性** | 较差（不同分数尺度难融合） | 较好（排名天然可比） |
| **计算开销** | 低 | 低 |
| **适用场景** | 同构检索器、分数尺度一致 | 异构检索器、分数尺度差异大 |

## ML/DL 应用场景

| 应用场景 | 数学形式 | 说明 |
|:---------|:---------|:-----|
| RAG 混合检索 | $score = w_1 \cdot s_{\text{dense}} + w_2 \cdot s_{\text{sparse}}$ | 稠密检索 + 稀疏检索的加权融合，兼顾语义和关键词匹配 |
| 多路召回融合 | $score(d) = \sum \frac{1}{k + rank_i(d) + 1}$ | 多路召回（如 BM25、向量检索、知识图谱检索）的 RRF 融合 |
| 搜索引擎排序 | $score = \sum w_i \cdot f_i(q, d)$ | 综合多种排序信号（文本相关性、PageRank、时效性等） |
| 集成检索系统 | $score_{\text{RRF}} = \sum \frac{1}{k + rank_i}$ | 多种异构检索模型输出的排名融合，避免分数归一化难题 |

## 面试追问

**Q1（基础）**：加权排序器和 RRF 排序器的核心区别是什么？各有什么优缺点？
**回答要点**：

1. 加权排序器直接对原始相似度分数加权求和，需要分数归一化（因为不同距离度量取值不同），权重可显式调节各检索器的重要性。
2. RRF 基于排名位置计算得分，不需要归一化，天然兼容异构检索器（稠密、稀疏等分数尺度不同的检索器）。
3. 加权排序优点：权重可解释、可调节；缺点：归一化方式选择影响结果、异构检索器融合困难。
4. RRF 优点：无需归一化、异构兼容性好、计算简单；缺点：丢失分数信息（仅用排名不考虑差距大小）、k 值需要调参。

**Q2（深挖）**：为什么 RRF 公式的分母中需要使用 $(k + rank_i + 1)$ 而不是 $(k + rank_i)$？加 1 的作用是什么？
**回答要点**：

1. $rank_i(d)$ 从 0 开始计数（第 1 名 rank=0），分母加 1 确保排名为 0 时的贡献为 $1/(k+1)$ 而不是 $1/k$。
2. 避免排名 0 造成分母过小导致贡献分数过高，保持与排名 1、2... 的平滑过渡。
3. 如果不加 1，k 取默认值 60 时第 1 名的贡献为 $1/60 \approx 0.0167$，加 1 后为 $1/61 \approx 0.0164$，差距不大但数学上更规范。

**Q3（实战）**：在 RAG 系统中，RRF 排序器如何与重排序器（Reranker）配合使用？两阶段各自处理多少候选？
**回答要点**：

1. 第一阶段 RRF：对多路召回的结果做粗排序融合，通常保留 100-200 个候选文档。RRF 负责将稠密检索和稀疏检索等异构结果合并为一个统一的排名列表。
2. 第二阶段重排序：对 RRF 输出的 Top-X（如 50-100 个候选）用交叉编码器 Reranker 做精细分数计算，输出最终 Top-5 或 Top-10。
3. 这种两阶段设计的原因：RRF 计算开销极低（仅需排名序号），适合处理大量候选；Reranker 计算开销高（交叉注意力），只适合少量候选的精排。

**Q4（边界）**：RRF 排序器在什么场景下效果会变差？如何改进？
**回答要点**：

1. 当某个检索器的召回质量明显低于其他检索器时，RRF 等权融合会引入噪声，拉低整体排序质量。此时可考虑加权 RRF（给各检索器的倒数排名项乘以不同的权重）。
2. 排名位置丢失了分数差距信息（如排名 0 的文档与排名 1 的文档可能得分差距很小，也可能差距巨大），RRF 无法区分。可考虑将 RRF 与分数阈值结合使用。
3. k 值的默认值 60 并非万能，k 值过大则排名差异被平滑殆尽（所有文档得分趋同），k 值过小则前几名过分突出。需要通过验证集调优 k 值，或使用动态 k 值策略（根据检索结果数量调整）。
4. 长尾分布的数据集上，RRF 可能过度偏向出现在多个检索器结果中的"温热门"文档，忽视仅在单一检索器中高排名的"冷门但精确"文档。
