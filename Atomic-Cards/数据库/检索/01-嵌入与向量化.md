# 嵌入与向量化

## 定义

嵌入（Embedding）是将非结构化数据（文本、图像、音频）映射到**高维稠密向量空间**的过程，使得语义相似的内容在向量空间中距离相近。嵌入模型是实现这一映射的神经网络。

$$
f_{\text{embed}}: \text{text} \to \mathbb{R}^d
$$

## 稠密向量 vs 稀疏向量

| 对比维度 | 稠密向量（Dense） | 稀疏向量（Sparse） |
|----------|-------------------|-------------------|
| **维度** | 固定低维（256~768） | 词表大小（数万~百万） |
| **表示** | 非零元素占多数 | 绝大多数位置为 0 |
| **语义能力** | 捕捉深层语义（同义词、近义） | 精确词匹配（关键词、术语） |
| **典型模型** | BERT、E5、BGE | BM25、SPLADE |
| **优势** | 语义泛化能力强 | 精确命中、可解释性好 |
| **劣势** | 罕见词处理弱 | 语义泛化差、维度爆炸 |

## BGE-M3 多向量模型

BGE-M3（BAAI General Embedding - Multilingual, Multi-function, Multi-granularity）支持同时输出稠密向量和稀疏向量：

- **稠密向量**：捕捉语义相似度
- **稀疏向量**：捕捉关键词匹配（类似 BM25）
- **多语言**：支持中文、英文等 100+ 语言
- **多粒度**：支持短文本到长文档

```python
from sentence_transformers import SentenceTransformer

# 加载 BGE-M3 多向量模型，它同时支持稠密向量和稀疏向量输出，适用于多语言场景
model = SentenceTransformer("BAAI/bge-m3")

# 生成稠密向量：将文本映射到 1024 维连续向量空间，
# 语义相似的文本在该空间中距离更近（余弦相似度可衡量）
dense_vec = model.encode("什么是向量数据库")

# 生成稀疏向量（lexical 权重）：返回每个词在词表上的权重分布，
# 用于精确匹配关键词，与 BM25 的 TF-IDF 思路类似；
# return_sparse=True 指示模型输出 Token 级别的权重而非连续向量
sparse_vec = model.encode("向量数据库", return_sparse=True)
```

## 嵌入在 RAG 中的角色

```python
# ========== 文档索引阶段：将知识库文本转为可检索的向量 ==========
#
# 原始文档 → 文本分块(Chunk) → 嵌入模型 → [向量1, 向量2, ...]
#  ① 先按段落或滑动窗口将长文档切分成语义完整的 Chunk
#  ② 每个 Chunk 通过嵌入模型转为稠密向量（语义浓缩）
#  ③ 将所有向量写入向量数据库（如 Milvus），构建近似最近邻索引
#                                                      ↓
#                                              向量数据库(Milvus)
#
# ========== 查询检索阶段：将用户问题转化为向量并搜索 ==========
#
# 用户查询 → 嵌入模型(同一模型) → 查询向量
#  ① 用户问题必须使用与索引阶段相同的嵌入模型进行编码
#  ② 因为不同模型输出的向量位于不同语义空间，无法直接比较
#                                      ↓
#                              向量数据库相似度搜索
#  ③ 计算查询向量与库中所有向量的余弦距离或欧氏距离
#                                      ↓
#                             返回 TOP-K 相关文档块
#  ④ 将得分最高的 K 个文档块返回给 RAG 系统的生成模块
```

## 常见嵌入模型对比

| 模型 | 维度 | 最大长度 | 特点 | 适用场景 |
|------|:----:|:--------:|------|----------|
| **BGE-M3** | 1024 | 8192 | 多语言、稠密+稀疏双输出 | 生产 RAG（推荐） |
| **BGE-large-zh** | 1024 | 512 | 中文优化 | 中文文本检索 |
| **E5-large** | 1024 | 512 | 英文指令跟随 | 英文检索 |
| **text-embedding-3** | 1536 | 8192 | OpenAI 出品 | 通用英文 |

## 面试追问

**Q1（基础）**：什么是嵌入（Embedding）？稠密向量和稀疏向量的核心区别是什么？
**回答要点**：

1. 嵌入是将非结构化数据（文本、图像）映射到高维向量空间的过程，语义相似的内容在向量空间中距离相近。
2. 稠密向量维度固定（256-1024 维），绝大多数元素非零，捕捉深层语义（同义词、近义词）。
3. 稀疏向量维度为词表大小（数万到百万维），绝大多数位置为 0，精确匹配关键词，可解释性好。

**Q2（深挖）**：BGE-M3 为什么能同时输出稠密向量和稀疏向量？这种多向量输出的优势是什么？
**回答要点**：

1. BGE-M3 采用多功能架构：稠密向量通过 Transformer 编码器+池化层生成，捕捉语义相似度；稀疏向量通过词级别的 lexical 权重输出，类似 BM25 的关键词匹配。
2. 优势：同时拥有语义泛化能力和精确关键词命中能力，不需要部署两套独立的嵌入模型。
3. 支持 100+语言和 8192 Token 的长文本，适合多语言 RAG 场景。

**Q3（实战）**：在 RAG 系统中，嵌入模型在索引阶段和检索阶段分别如何工作？两者必须用同一个模型吗？
**回答要点**：

1. 索引阶段：文档分块后通过嵌入模型转为向量存入数据库。
2. 检索阶段：用户查询用同一嵌入模型转为查询向量，在向量库中做相似度搜索找到 Top-K 相关块。
3. 索引和检索阶段必须使用同一个嵌入模型（或具有兼容向量空间的模型），否则两个向量不在同一语义空间中，相似度比较无意义。

**Q4（边界）**：嵌入质量会受到哪些因素影响？如何提升嵌入质量以改善 RAG 效果？
**回答要点**：

1. 分块策略不当（过大导致语义混杂，过小导致上下文不完整）直接降低嵌入质量。
2. 嵌入模型的领域适配性和最大 Token 长度限制影响效果。
3. 提升方法：选择领域匹配的嵌入模型（中文用 BGE-large-zh）、优化分块策略（滑动窗口/语义分块）、必要时用大模型生成的合成数据进行微调。
4. 罕见词、专有名词在处理时容易丢失语义信息，可结合稀疏向量补偿。
