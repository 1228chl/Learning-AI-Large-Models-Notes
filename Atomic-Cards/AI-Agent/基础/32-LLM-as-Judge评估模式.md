# LLM-as-Judge 评估模式

## 定义

LLM-as-Judge 是一种用大模型作为"评判者"来评估另一个模型输出的评估范式。它不依赖精确字符串匹配或人工标注的"标准答案"，而是让一个评判 LLM 根据评估标准和行为锚点（behavioral anchors）对输出进行**语义级别**的打分和判断。核心公式：

$$ \text{评估结果} = \text{LLM}(\text{评估标准} + \text{行为锚点} + \text{待评估内容}) $$

与传统自动化指标（如 BLEU、ROUGE）相比，LLM-as-Judge 能捕捉语义等价（"明天要下雨"和"预计明日有降水"得分相同），但代价是评判结果有一定随机性，需要人工抽样交叉验证。

## 核心设计要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 评估维度 | 独立正交的打分角度 | 具体性、可操作性、完整性 |
| 行为锚点 | 每个分数对应的具体行为描述 | 5 分="每条建议都有具体操作步骤"；1 分="只有空洞的鼓励" |
| 评分量表 | 建议 1-5 或 1-10 分制 | 奇数分制允许中间值，避免过度细化 |
| 评判 Prompt | 包含角色设定 + 评估维度 + 锚点 + 输出格式 | "你是一位严格的面试官..." |

## 直观理解

> 让一位资深教师（评判 LLM）去批改另一位老师（被评估 LLM）学生的主观题答案——不是看"每个字是否和标准答案一模一样"，而是根据评分标准（行为锚点）判断"学生的回答是否理解了核心概念"。为了确保这位资深教师没有偏心或走神，每隔一段时间让真人老师抽查一批试卷（人工交叉验证），对比两者的打分。如果偏差大了，就重新培训（调整评定锚点）。

## 评判 Prompt 设计模板

```python
JUDGE_PROMPT = """你是一位严格的{role}。请根据以下标准评估内容质量。

## 评估维度
{dimensions_with_anchors}

## 待评估内容
{content_to_evaluate}

## 输出格式
{output_schema}

请逐维度打分，并给出打分理由。"""

# 行为锚点是评判一致性的关键——不给 LLM 锚点，打分方差极高
# 示例：锚点 vs 无锚点
# 无锚点："请对回答质量打分（1-5）" → LLM 的"3分"和"4分"边界模糊
# 有锚点："5分=给出了完整代码且能运行；3分=伪代码逻辑正确；1分=方向完全错误"
```

## 人工抽样交叉验证

LLM 评判与人工评判的一致性需要定期校准：

```python
# 交叉验证流程
def calibrate_judge(evaluations, sample_size=50):
    """每期抽样 50 条，对比 LLM 评分与人工评分的一致性"""
    samples = random.sample(evaluations, sample_size)
    for eval in samples:
        human_score = get_human_score(eval.id)   # 人工独立打分
        llm_score   = eval.judge_score            # LLM 评判打分
        record(eval.id, human_score, llm_score)   # 记录偏差

    # 计算一致性指标
    mae = mean_absolute_error(human_scores, llm_scores)
    if mae > 1.5:                                  # 阈值：平均偏差 > 1.5 分
        print("警告：LLM 评判与人工打分偏差过大，需调整评定锚点")
```

## 三种评估方法对比

| 维度 | 自动化指标 | LLM-as-Judge | 人工基线 |
|------|-----------|-------------|---------|
| 准确性 | 精确但语义盲区大 | 语义感知强，有一定随机性 | 金标准 |
| 成本 | 极低 | 中等（每次评判一次 LLM 调用） | 极高 |
| 可重复性 | 100% | ~85-95% | 依赖标注者一致性 |
| 适用场景 | 有标准答案的客观任务 | 开放域生成质量评估 | 主观性最强的任务 |
| 规模化 | 轻松百万级 | 千-万级 | 百-千级 |

## AI/ML 工程应用场景

| 应用场景 | 评判维度 | 锚点设计要点 |
|---------|---------|------------|
| RAG 回答正确性评估 | 事实准确性 + 完整性 | 与 ground truth 关键要点逐一比对 |
| 模拟面试报告质量 | 具体性 + 可操作性 + 完整性 | 每条建议是否给出可执行的操作步骤 |
| 简历评分一致性 | 六维度锚点评分 | 与人工专家评分偏差 MAE < 4 |
| 代码生成质量 | 正确性 + 可读性 + 效率 | 是否通过测试用例 + 命名规范 + 时间复杂度 |

## 面试追问

**Q1（基础）**：什么是 LLM-as-Judge？它与 BLEU/ROUGE 等传统指标的核心区别？

**回答要点**：

1. LLM-as-Judge：用一个 LLM 作为评判者，根据评估标准对另一个模型的输出进行语义级打分
2. 传统指标（BLEU/ROUGE）：基于 n-gram 重叠的精确字符串匹配——"明天要下雨"和"预计明日有降水"得分为零
3. LLM-as-Judge 是"语义匹配"——能识别表述不同但含义相同的输出，更接近人类评判
4. 代价：评判结果有随机性（同一输入多次评判可能不同），需要交叉验证

**Q2（深挖）**：行为锚点（behavioral anchors）为什么是 LLM-as-Judge 的关键？没有锚点会怎样？

**回答要点**：

1. 锚点给每个分数附上具体行为描述——LLM 不再是模糊地"觉得好"而是对照标准判断
2. 没有锚点的后果：同一输出两次评判可能差 2-3 分（评分方差大）；不同人设计的评判 Prompt 结果不可比
3. 好锚点的特征：描述可观察的、具体的行为（"给出了完整可运行代码"），而非主观评价（"回答很好"）
4. 锚点设计原则：5 分和 1 分必须极端明确（两端定标），3 分描述"及格线"

**Q3（实战）**：人工抽样交叉验证的频率和样本量怎么定？发现 LLM 评判偏差过大怎么办？

**回答要点**：

1. 首次上线：全量抽样 100-200 条建立基准一致性
2. 常规运行：每周抽样 30-50 条，或在 Prompt/模型变更后全量复检
3. 偏差过大（MAE > 1.5 分）：优先检查锚点是否模糊——增加更具体的行为描述
4. 若锚点已经足够具体：检查评判 LLM 是否需要更强的模型（如从 DeepSeek-V3 切换到更强模型）

**Q4（边界）**：LLM-as-Judge 能否评判它自己生成的输出？评判 LLM 和被评判 LLM 是同一个模型会怎样？

**回答要点**：

1. 自我评判存在严重偏差——LLM 倾向于给自己的输出打更高分（自我偏好偏差）
2. 强烈建议：评判 LLM 与被评判 LLM 使用不同模型（如被评判用 DeepSeek，评判用 Claude）
3. 若必须用同一模型：设置不同的 system prompt 角色，且降低评判结果的权重
4. 论文实践：多数 LLM-as-Judge 研究使用 GPT-4 评判其他模型的输出，避免自我评判
