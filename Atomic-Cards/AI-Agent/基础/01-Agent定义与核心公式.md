# Agent 定义与核心公式

## 定义

AI Agent（智能体）是以**大语言模型（LLM）为"大脑"**，结合**记忆、规划和工具调用**能力，能自主感知环境、制定计划、执行动作并完成复杂任务的软件实体。

**核心公式**：

$$
\text{Agent} = \text{LLM} + \text{记忆} + \text{规划} + \text{工具使用}
$$

```python
# Agent 的简化循环
def agent_loop(query):  # 定义 Agent 主循环函数，接收用户的原始查询作为输入
    # 1. 感知：理解用户输入
    # 2. 规划：拆解任务步骤
    # 3. 行动：调用工具获取信息
    # 4. 观察：分析工具返回结果
    # 5. 循环：根据观察决定下一步
    pass
```

## 传统 LLM vs Agent

| 对比 | 传统 LLM | Agent |
|:----:|:--------|:------|
| **交互模式** | 一问一答，被动响应 | 自主规划，主动执行 |
| **单次/多步** | 单轮生成 | 多步推理 + 行动循环 |
| **记忆** | 无（或有限上下文） | 短期（对话）+ 长期（向量库） |
| **工具调用** | ❌ 不能 | ✅ 可调用 API、数据库、代码执行 |
| **类比** | 百科全书 | 全能助理 |

## Agent 的能力层次

```python
┌──────────────────────┐
│  规划（Planning）     │  任务分解、反思、思维链
├──────────────────────┤
│  记忆（Memory）       │  短期上下文 + 长期知识库
├──────────────────────┤
│  工具（Tools）        │  调用 API、搜索、代码执行
├──────────────────────┤
│  LLM 大脑             │  理解、推理、生成
└──────────────────────┘
```

| 能力 | 说明 | 技术实现 |
|:----|:----|:--------|
| **规划** | 将复杂任务拆解为可执行的子步骤 | ReAct、Plan-and-Solve、思维链 |
| **记忆** | 短期（当前对话）& 长期（向量数据库） | Chat History、RAG |
| **工具** | 扩展 LLM 能力边界 | Function Calling、API 集成 |
| **行动** | 执行具体操作并观察结果 | Code Interpreter、浏览器操作 |

## Agent 的应用场景

| 场景 | Agent 行为 | 示例 |
|:----|:---------|:----|
| **客服系统** | 理解问题 → 查知识库 → 生成回复 | 电商售前咨询 |
| **代码开发** | 理解需求 → 搜索代码 → 生成/修改代码 | GitHub Copilot Chat |
| **数据分析** | 理解问题 → 写 SQL → 执行查询 → 分析结果 | Text-to-SQL |
| **自动化办公** | 解析邮件 → 查日历 → 回复/安排会议 | 个人助理 Agent |

## 面试追问

**Q1（基础）**：什么是 AI Agent？请用核心公式说明它与传统 LLM 的主要区别。
**回答要点**：

1. Agent 核心公式为 Agent = LLM + 记忆 + 规划 + 工具使用，以 LLM 为"大脑"驱动整体运行
2. Agent 具备自主感知环境、制定计划、执行动作并完成复杂任务的能力
3. 与传统 LLM 的被动问答单轮交互不同，Agent 能进行多步推理和主动执行

**Q2（深挖）**：Agent 的四种核心能力层次中，"规划"和"工具"各自解决了传统 LLM 的哪些局限？
**回答要点**：

1. 规划能力通过 ReAct、思维链等方法将复杂任务分解为可执行的子步骤，解决传统 LLM 无法进行多步推理的问题
2. 工具能力通过 Function Calling 和 API 集成突破 LLM 的知识截止日期和操作边界
3. 两者结合使 Agent 能访问外部数据并执行动作，完成传统 LLM 无法独立处理的复杂任务

**Q3（实战）**：在客服场景中，如何基于 Agent 公式设计一个电商客服 Agent 的工作循环？
**回答要点**：

1. 感知阶段：理解用户意图（退货、查物流等），明确任务目标和所需信息
2. 规划与行动：将任务拆解为查订单→查规则→生成回复等子步骤，调用订单 API 和知识库获取信息
3. 观察与循环：分析工具返回结果，判断信息是否充足，决定继续循环或生成最终回复

**Q4（边界）**：AI Agent 在什么场景下可能表现不佳或失败？如何改进？
**回答要点**：

1. 多步规划容易累积错误（错误传播），需设置最大步数和熔断机制防止无限循环
2. 工具调用失败时缺乏优雅降级策略，应设计备选降级回复方案保障可用性
3. 缺乏可靠的长程记忆可能在复杂任务中"遗忘"早期目标，需配合显式记忆模块或外部存储
