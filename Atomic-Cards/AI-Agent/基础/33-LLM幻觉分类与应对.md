# LLM 幻觉分类与应对

## 定义

LLM 幻觉（Hallucination）指大语言模型生成看似合理但实际错误或无根据的内容。根据问题来源，幻觉可分为**事实性幻觉**（Factuality Hallucination）和**忠实性幻觉**（Faithfulness Hallucination），分别对应"知识错了"和"不听话了"。

## 幻觉分类

### 事实性幻觉（Factuality Hallucination）

模型生成的内容与**客观事实**不符，包括：

| 类型 | 表现 | 示例 |
|:----|:-----|:-----|
| **事实不一致** | 混淆概念、张冠李戴 | "Adam 优化器使用动量的概念来自 Yann LeCun"（实际来自 Polyak） |
| **凭空捏造** | 编造不存在的信息 | 编造论文标题、虚构 API 参数、杜撰历史事件 |
| **数据偏差** | 训练数据中的偏见被放大 | 性别/种族刻板印象、地域偏见 |

### 忠实性幻觉（Faithfulness Hallucination）

模型生成的内容与**用户指令**或**提供的上下文**不一致，包括：

| 类型 | 表现 | 示例 |
|:----|:-----|:-----|
| **指令偏离** | 不遵守用户约束 | 要求"100 字以内"回复 500 字 |
| **上下文忽略** | 忽略提供的文档内容 | 给定 PDF 后仍凭空回答 |
| **逻辑矛盾** | 前后文自相矛盾 | 前面说 A 正确，后面又说 B 正确 |

## 幻觉产生原因

| 原因 | 说明 | 影响 |
|:-----|:------|:-----|
| **知识过时** | 训练数据截止日期后的事件 | 事实性幻觉 |
| **训练数据偏差** | 数据中错误/偏见被模型学到 | 事实性幻觉 |
| **数据稀疏** | 长尾知识在训练数据中出现次数少 | 事实性幻觉 |
| **解码随机性** | Temperature 等参数引入的随机性 | 忠实性幻觉 |
| **指令理解偏差** | 模型对复杂指令理解不到位 | 忠实性幻觉 |

## 四大 LLM 开发方案对比

| 方案 | 原理 | 对抗幻觉的优势 | 对抗幻觉的局限 |
|:----|:-----|:--------------|:--------------|
| **提示词工程** | 精妙指令约束模型行为 | 零成本、快速见效 | 对事实性幻觉无效，无法"教"模型新知识 |
| **模型微调** | 用领域数据调整模型参数 | 从根本上减少领域内幻觉 | 成本高、可能过拟合、无法更新知识 |
| **RAG（检索增强生成）** | 外部知识库 + 检索 + 生成 | 事实性幻觉的利器，知识可更新 | 检索质量依赖索引和分块策略 |
| **AI Agent** | 工具调用 + 多步推理 + 验证 | 可通过工具验证结果、自我修正 | 架构复杂、延迟高、成本高 |

### 幻觉应对方案选择

```python
def choose_anti_hallucination_strategy(scenario: str) -> str:
    """根据场景选择对抗幻觉的方案"""
    if scenario == "知识更新":
        return "RAG（外部知识库）"
    elif scenario == "输出格式":
        return "提示词工程（结构化约束）"
    elif scenario == "领域专业":
        return "微调（领域数据）"
    elif scenario == "验证纠错":
        return "Agent（工具调用 + 自我验证）"
    else:
        return "组合方案：RAG + 提示词工程"
```

## 面试追问

**Q1（基础）**：LLM 幻觉有哪两种主要类型？区别是什么？
**回答要点**：
1. 事实性幻觉：内容与客观事实不符，属于"知识错了"
2. 忠实性幻觉：内容与用户指令或上下文不符，属于"不听话了"
3. 区别：前者是模型"不知道"（知识问题），后者是模型"不照做"（指令遵循问题）

**Q2（深挖）**：为什么 RAG 被认为是扼杀事实性幻觉的利器？
**回答要点**：
1. RAG 将模型与外部知识源连接，从根本上解决了模型的"知识更新"和"私有知识"问题
2. 模型不再依赖训练数据中的记忆，而是基于检索到的证据生成答案
3. 检索到的文档可作为引用来源，让用户验证答案的正确性
4. 但 RAG 不能解决忠实性幻觉——模型仍可能忽略检索到的文档

**Q3（实战）**：生产环境中如何系统性地检测和减少幻觉？
**回答要点**：
1. 检测层：LLM-as-Judge 对输出做事实性检查（标注引用来源）
2. 验证层：对关键数据（如数字、日期、API 参数）做规则校验
3. 反馈层：用户反馈 + 人工标注，构建评估数据集
4. 改进层：根据反馈优化 Prompt / 更新 RAG 知识库 / 微调模型

**Q4（边界）**：Temperature 参数如何影响幻觉？Temperature = 0 能完全消除幻觉吗？
**回答要点**：
1. Temperature 控制输出随机性：T 越高，越倾向于生成低概率 token，增加忠实性幻觉风险
2. T = 0 采用贪心解码（每次都选概率最高的 token），可减少忠实性幻觉
3. 但 T = 0 不能消除事实性幻觉——模型仍然"不知道"它没学过的知识
4. 即使 T = 0，模型仍可能因重复 token 抑制（repetition penalty）等其他机制产生不一致输出
