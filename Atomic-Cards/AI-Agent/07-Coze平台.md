# Coze 平台

## 定义

Coze（扣子）是字节跳动推出的**低代码 AI Agent 开发平台**，以 SaaS 方式提供服务，让非技术人员也能搭建智能体应用。

| 版本 | 网址 | 说明 |
|:----:|:----|:----|
| **国内版** | www.coze.cn | 适配国内大模型（豆包等） |
| **国际版** | www.coze.com | 适配 GPT、Claude 等 |
| **开源版** | Coze Studio | 可私有化部署 |

## 核心功能

```python
# Coze Agent的核心构成公式：大模型+知识库+插件+工作流+对话记忆
Agent = LLM + 知识库 + 插件 + 工作流 + 对话记忆
```

| 功能 | 说明 | 技术实现 |
|:----|:----|:--------|
| **LLM 配置** | 选择底层大模型 | 豆包、GPT、Claude、MiniMax |
| **知识库** | 上传私有文档让 Agent 学习 | RAG + 向量数据库 |
| **插件** | 扩展 Agent 能力 | 搜索、日历、邮件、代码执行 |
| **工作流** | 拖拽式编排多步骤任务 | 条件分支、循环、并行 |
| **对话记忆** | 跨轮上下文保持 | 短期 + 长期记忆 |
| **发布渠道** | 嵌入到各平台使用 | 飞书、微信、网页嵌入 |

## Agent 构建流程

```yaml
1. 设定角色: "你是电商客服助手"
2. 配置 LLM: 选择模型、设置温度
3. 添加知识库: 上传产品手册、FAQ
4. 配置插件: 查询物流、查询库存
5. 发布测试: 在预览窗口测试对话
6. 部署上线: 发布到飞书/微信等渠道
```

## 面试追问

**Q1（基础）**：Coze 平台构建 Agent 的核心功能模块有哪些？低代码具体体现在哪些环节？
**回答要点**：

1. LLM 配置、知识库、插件、工作流、对话记忆、多渠道发布六个核心模块
2. 低代码体现在拖拽式工作流编排、可视化知识库文件管理、插件市场一键集成
3. 无需编程即可发布到飞书、微信等渠道

**Q2（深挖）**：Coze 国内版和国际版在底层模型选择和生态兼容性上的主要差异是什么？
**回答要点**：

1. 国内版适配豆包、MiniMax 等国产生态，国际版适配 GPT、Claude 等海外模型
2. 国际版工作流节点类型和高级功能更丰富；数据存储区域不同，国内版数据在境内合规、国际版在海外
3. 国内版集成了飞书、抖音等字节生态，国际版集成 Slack、Discord 等

**Q3（实战）**：用 Coze 搭建一个电商售前咨询 Agent，需要配置哪些资源？工作流如何设计？
**回答要点**：

1. 设定角色 Prompt 为"专业电商顾问"；选择豆包或 GPT 作为底层 LLM；上传产品手册和价格表到知识库
2. 配置商品查询、库存检查、优惠计算等插件；设计工作流：用户提问 -> 知识库检索 -> 判断是否需要查库存 -> 调用库存插件 -> 组装回答
3. 发布到飞书或网页嵌入

**Q4（边界）**：使用 Coze 低代码平台搭建 Agent 的主要局限性有哪些？什么情况下应转向代码开发？
**回答要点**：

1. 插件生态有限，无法实现任意自定义功能——涉及私有系统集成时需用代码开发
2. 工作流节点执行逻辑固定，无法实现精细的条件判断和循环控制；SaaS 模式下存在数据隐私风险
3. 平台有调用频率和知识库容量限制——高并发或大数据量场景受限；需要私有化部署或使用冷门模型时推荐 LangChain 或 Dify 自部署
