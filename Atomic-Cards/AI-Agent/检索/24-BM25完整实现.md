# BM25 完整实现（带缓存）

## 定义

BM25 完整实现提供了从基础 BM25 检索到生产级缓存搜索引擎的完整代码示例，涵盖中文分词（jieba）、Softmax 得分归一化、阈值过滤以及 Redis 缓存加速等关键环节。本节帮助开发者掌握 BM25 在实际项目中的部署与优化方法。

## 基础 BM25

```python
from rank_bm25 import BM25Okapi
import jieba
import numpy as np

# 1. 准备文档
documents = [
    "北京大学创办于1898年",
    "清华大学是中国著名高等学府",
    "人工智能是计算机科学的分支",
]
# 使用jieba对每个文档进行中文分词，得到分词后的文档列表供BM25构建索引
tokenized_docs = [list(jieba.cut(doc)) for doc in documents]

# 2. 创建 BM25 索引
# 传入分词后的文档列表，构建BM25统计模型（包含词频、逆文档频率等统计量）
bm25 = BM25Okapi(tokenized_docs)

# 3. 检索
query = "北京大学什么时候成立的"
# 对用户查询进行中文分词，使查询与文档在相同的词空间上计算相似度
query_tokens = list(jieba.cut(query))
# 计算查询与每个文档的BM25相关性得分，得分越高表示文档与查询越相关
scores = bm25.get_scores(query_tokens)

# 4. Softmax 归一化（分数映射到 0-1 范围）
def softmax(scores):
    # 减去最大值防止指数运算溢出，同时保持分数的相对大小关系
    exp_scores = np.exp(scores - np.max(scores))
    # 除以归一化常数，将任意范围的得分转换为总和为1的概率分布
    return exp_scores / exp_scores.sum()

# 对BM25原始得分进行Softmax归一化，使不同查询的得分可以在统一尺度下比较
normalized_scores = softmax(scores)

# 5. 阈值过滤
threshold = 0.85  # 设置置信度阈值，仅当最高得分超过此值时才认为匹配成功

best_idx = np.argmax(normalized_scores)  # 找到归一化后得分最高的文档索引
if normalized_scores[best_idx] > threshold:
    print(f"匹配到: {documents[best_idx]}")
else:
    print("未找到高匹配度的答案")
```

## 生产级 BM25 + Redis 缓存

```python
import hashlib
import json

class BM25Search:
    """带 Redis 缓存的 BM25 搜索引擎"""

    def __init__(self, redis_client, mysql_client):

        self.redis_client = redis_client  # Redis客户端实例，用于缓存加速

        self.mysql_client = mysql_client  # MySQL客户端实例，用于持久化存储FAQ数据

        self.bm25 = None  # BM25模型对象，初始化后由_load_data创建

        self.questions = []  # 存储分词后的问题列表，供BM25索引使用

        self.original_questions = []  # 存储原始问题文本，用于返回匹配的原始问题
        self._load_data()

    def _load_data(self):
        """从 Redis（缓存）或 MySQL 加载问题数据"""
        # 先从 Redis 获取缓存
        original_key = "qa_original_questions"

        tokenized_key = "qa_tokenized_questions"

        # 尝试从Redis缓存中获取原始问题和分词后的问题列表
        self.original_questions = self.redis_client.get_data(original_key)

        tokenized_questions = self.redis_client.get_data(tokenized_key)

        if not self.original_questions or not tokenized_questions:
            # Redis无缓存或缓存失效，回退到MySQL加载全量数据
            self.original_questions = self.mysql_client.fetch_questions()
            # 对从MySQL加载的每个问题逐一进行中文分词
            tokenized_questions = [
                self._tokenize(q[0]) for q in self.original_questions
            ]
            # 将原始问题和分词结果写入Redis缓存，下次启动避免重复加载和分词
            self.redis_client.set_data(original_key, self.original_questions)
            self.redis_client.set_data(tokenized_key, tokenized_questions)


        self.questions = tokenized_questions
        # 基于分词后的问题列表构建BM25索引，用于后续查询相似度计算
        self.bm25 = BM25Okapi(self.questions)

    def _tokenize(self, text):
        """中文分词"""
        import jieba
        # 使用jieba精确模式进行中文分词，返回词语列表
        return list(jieba.cut(text))

    def _softmax(self, scores):
        """归一化 BM25 分数到 0~1"""
        # 减去最大值防止指数运算溢出，同时保持分数排序不变
        exp_scores = np.exp(scores - np.max(scores))
        # 归一化为概率分布，使所有文档得分之和为1，便于统一阈值判断
        return exp_scores / exp_scores.sum()


    def search(self, query, threshold=0.85):
        """检索并返回答案"""
        # 对空查询或非字符串输入直接返回失败，避免无效计算
        if not query or not isinstance(query, str):
            return None, False

        # 检查查询缓存，相同问题有缓存答案时直接返回，避免重复BM25计算
        cached = self.redis_client.get_answer(query)
        if cached:
            return cached, False

        # BM25检索：对查询分词后计算与所有问题的相关性得分
        query_tokens = self._tokenize(query)

        scores = self.bm25.get_scores(query_tokens)
        # 对原始得分进行softmax归一化，便于跨查询使用统一阈值
        normalized = self._softmax(scores)


        best_idx = np.argmax(normalized)  # 找到得分最高的文档索引

        best_score = normalized[best_idx]  # 获取对应的最高归一化得分

        # 仅当最高得分超过阈值时才认为找到了可靠匹配
        if best_score > threshold:
            return best_idx, True
        return None, False
```

## 文本预处理（中文）

```python
import jieba
import re

def preprocess_text(text):
    """中文文本预处理：分词 + 去停用词"""
    # 去除非中文和非英文字符（标点、数字、特殊符号等），仅保留有语义的文本
    text = re.sub(r'[^一-龥a-zA-Z]', ' ', text)
    # 使用jieba精确模式对清洗后的文本进行中文分词
    words = jieba.lcut(text)
    # 过滤掉单字词和常见停用词，保留长度大于1且有实际语义的词汇，提升检索质量
    stop_words = {'的', '了', '在', '是', '我', '有', '和', '就', '不', '人', '都', '一', '一个', '上', '也', '很', '到', '说', '要', '去', '你', '会', '着', '没有', '看', '好', '自己', '这'}
    return [w for w in words if len(w) > 1 and w not in stop_words]
```

## 面试追问

**Q1（基础）**：为什么生产级 BM25 搜索需要对原始分数做 Softmax 归一化和阈值过滤？阈值 0.85 的含义是什么？
**回答要点**：

1. 原始 BM25 分数范围不固定（依赖文档长度、词频等），无法跨查询统一比较
2. Softmax 将分数映射到 (0,1) 概率分布，使阈值设定有统一的语义含义
3. 0.85 表示只有归一化置信度超过 85% 的匹配才被采纳——高阈值保证精度但可能降低召回

**Q2（深挖）**：BM25Search 中 Redis 缓存为什么设计了问题数据缓存和查询缓存两层？各自的失效策略是什么？
**回答要点**：

1. 问题数据缓存存储分词后的问题列表和 BM25 索引，避免每次搜索都从 MySQL 加载全量数据重建索引，在知识库更新时主动清空重建
2. 查询缓存存储相同问题的搜索结果，避免重复计算，可设置 TTL 过期保证时效性
3. 两层缓存分别解决"建索引慢"和"查索引慢"两个不同瓶颈，失效策略各有侧重

**Q3（实战）**：BM25Search 从 MySQL 加载数万条 FAQ 构建 BM25 索引时耗时较长，你会如何优化启动性能？
**回答要点**：

1. 利用 Redis 序列化缓存 BM25 对象或分词后的问题列表，下次启动直接加载缓存避免全量重建
2. 增量更新——只从 MySQL 拉取新增或修改的问题而非全量同步
3. 异步构建——启动时先加载旧缓存快速可用，后台异步刷新索引

**Q4（边界）**：内存版 BM25（rank_bm25）和 ElasticSearch BM25 在架构和适用场景上有什么本质区别？
**回答要点**：

1. rank_bm25 轻量级 Python 库全内存运算——部署简单、延迟极低，适合万级以内的小型系统，但不支持分布式、持久化和高级过滤
2. ES BM25 基于 Lucene——支持海量数据分布式部署、全文检索+过滤+排序+聚合，但部署运维成本高
3. 数据量<10 万且需求简单时 rank_bm25 更高效，>10 万或需要高级检索功能时选择 ES
