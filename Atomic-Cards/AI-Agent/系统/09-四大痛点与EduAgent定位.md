# 四大痛点与 EduAgent 系统定位

## 定义

**EduAgent** 是一个面向 IT 教育培训机构的 AI 原生教学辅助系统，通过融合私有知识（RAG）、内置业务流程（LangGraph）和工程化容错机制，解决通用大模型在教育培训场景中的"幻觉、无状态、不可靠"三大局限。

### 教育培训四大痛点

| 痛点 | 核心矛盾 | 对应 Agent 模块 |
|------|---------|----------------|
| 学员答疑 | 老师精力有限 vs 重复问题多 | QA（智能问答 Agent） |
| 试卷批改 | 工作量大 vs 评分一致性要求高 | Exam（试卷批改 Agent） |
| 简历审查 | 简历数量多 vs 没时间逐份精读 | Resume（简历审查 Agent） |
| 模拟面试 | 需要专业陪练 vs 缺少面试官资源 | Interview（模拟面试 Agent） |

### 通用大模型不够用的三个原因

1. **缺少企业私有知识** → 幻觉：模型不知道机构的课程大纲、教材案例、学员常见错误，回答内容无法基于机构真实教学材料
2. **缺少业务流程** → 多步骤有状态：试卷批改需要多步流转（提交→AI批改→教师确认→发布），模拟面试是天生的多阶段状态机，而通用大模型每次调用都是无状态的单次对话
3. **缺少工程化可靠性** → 无 retry/降级/超时/熔断：生产环境网络抖动、LLM API 超时、数据库连接闪断是常态，通用模型不提供任何容错保障

### EduAgent 三大核心能力

$$
\text{EduAgent} = \text{私有知识(RAG)} + \text{业务流程(LangGraph)} + \text{工程容错}
$$

- **私有知识融合**：RAG 技术将机构课程大纲、教材讲义、常见错误 QA 注入知识库，LLM 回答时检索最相关片段作为上下文，从根本上解决幻觉问题
- **内置业务流程**：LangGraph 图模型将教学流程建模为状态图，每个步骤有明确的输入输出和状态管理，支持多步流转、暂停恢复、分支路由
- **容错机制**：内置自动重试（网络抖动恢复）、降级（LLM 不可用时返回友好提示）、超时保护（30s 熔断）、异常分类（可重试/不可重试），确保系统稳定运行

### 直观理解

> EduAgent 不是"给大模型套个壳子"，而是为教育培训场景量身定制的 AI 操作系统——它知道机构的教材、能走完完整的教学流程、并且在网络抖动时不会崩溃。

## 应用场景

| 应用场景 | 涉及模块 | 说明 |
|----------|---------|------|
| 学员在线答疑 | QA Agent + RAG 知识库 | 学员提问→检索课程讲义→LLM 生成回答，标注来源 |
| 期末试卷批改 | Exam Agent + HitL | 学生提交 Word 试卷→AI 三轨并行批改→教师确认→发布成绩 |
| 简历初筛 | Resume Agent | 学员上传 PDF 简历→六维度并行评分→问题诊断→评价报告 |
| 模拟面试陪练 | Interview Agent + 状态机 | 热身→技术问答→项目深挖→反问收尾→五维度评估报告 |

## 面试追问

**Q1（基础）**：EduAgent 解决了教育培训机构的哪四个痛点？
**回答要点**：

1. 学员答疑（老师精力有限 vs 重复问题多）
2. 试卷批改（工作量大 vs 评分一致性要求高）
3. 简历审查（简历数量多 vs 没时间逐份精读）
4. 模拟面试（需要专业陪练 vs 缺少面试官资源）

**Q2（深挖）**：通用大模型在教育培训场景中不够用的三个原因及其对应的解决方案？
**回答要点**：

1. 缺少企业私有知识→幻觉→RAG 技术注入私有知识库，提供课程讲义、教材案例作为上下文
2. 缺少业务流程→多步骤有状态→LangGraph 图模型将教学流程建模为状态图，支持多步流转和状态管理
3. 缺少工程化可靠性→无容错机制→内置重试/降级/超时/熔断/异常分类

**Q3（实战）**：EduAgent 三大核心能力在你的项目中如何体现？请举例说明。
**回答要点**：

1. 私有知识融合：通过 RAG 将公司内部文档（产品手册、FAQ、技术规范）向量化存入 Milvus，Agent 回答时自动检索相关内容
2. 内置业务流程：用 LangGraph 定义请假审批流程（申请→主管审批→HR 确认→归档），interrupt 等待主管操作
3. 工程容错：@with_retry 装饰器覆盖所有 LLM 调用，LLM API 超时自动重试 2 次，仍失败则走降级路径

**Q4（边界）**：EduAgent 的架构设计在什么场景下会失效？如何优化？
**回答要点**：

1. 极低延迟场景失效：RAG 检索（向量库 30ms + Reranker 200ms）增加了端到端延迟，不可用于实时对话（如客服实时语音）
2. 超大规模失效：单进程内嵌 3 个本地模型（BGE-M3 / Reranker / MiniLM）在 1000+ QPS 下内存不足，需拆分为独立微服务独立扩缩容
3. 知识库冷启动失效：新机构没有历史课程材料和问答数据，RAG 检索为空，需先人工灌入基础语料或使用 LLM 生成种子数据
