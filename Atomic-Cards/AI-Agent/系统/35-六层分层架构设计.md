# 六层分层架构设计

## 定义

**六层分层架构** 是 EduAgent 系统的整体架构设计，从上到下依次为：**API 层、编排层、Agent 层、公共层、MCP 层、数据层**。每层各司其职，上层依赖下层，下层不感知上层。

### 架构总览

```
┌─────────────────────────────────────────────┐
│           API 层（FastAPI）                   │
│   REST 接口 / SSE 流式接口 / WebSocket       │
├─────────────────────────────────────────────┤
│       编排层 Orchestrator                    │
│   意图识别 → Agent路由 / 多Agent串联         │
├─────────────────────────────────────────────┤
│              Agent 层                        │
│   QA Agent │ Exam Agent │ Resume Agent │ Interview Agent │
├─────────────────────────────────────────────┤
│              公共层 Common                   │
│   嵌入模型 │ 重排序模型 │ 意图分类 │ 工具函数 │
├─────────────────────────────────────────────┤
│               MCP 层                         │
│   模型调用协议 │ 统一LLM接口 │ 模型切换 │ 重试降级 │
├─────────────────────────────────────────────┤
│              数据层 Data                     │
│   Milvus │ PostgreSQL │ 文件存储 │ 缓存 │ 消息队列 │
└─────────────────────────────────────────────┘
```

## 每层详解

### 第一层：API 层

**职责**：对外暴露的接口层，负责接收请求和返回响应。

**关键角色**：
- REST 接口：常规请求-响应，如简历上传、试卷提交
- SSE 流式接口：模拟面试的流式输出
- WebSocket：可选，双向实时通信

**设计要点**：
- API 层不做业务逻辑，只做参数校验、身份认证、请求转发
- 使用 FastAPI 依赖注入管理全局资源
- 统一的错误处理和响应格式

### 第二层：编排层 Orchestrator

**职责**：系统的"大脑"，负责理解用户意图并将请求路由到正确的 Agent。

**关键角色**：
- 意图识别器：对用户输入进行意图分类
- 单 Agent 路由：明确请求直接路由到对应 Agent
- 多 Agent 串联：复杂场景串联多个 Agent

**设计要点**：
- Orchestrator 本身不执行业务逻辑，只负责调度
- 意图识别附带置信度，低于阈值时请求用户确认

### 第三层：Agent 层

**职责**：业务逻辑的执行层，每个 Agent 封装完整的业务流程。

**四个核心 Agent**：
- QA Agent：RAG 检索增强问答
- Exam Agent：三轨并行试卷批改
- Resume Agent：结构化简历评估
- Interview Agent：状态机模拟面试

**设计要点**：
- 每个 Agent 独立部署在自己的 LangGraph 图中
- Agent 之间不直接通信，通过 Orchestrator 协调
- 每个 Agent 有自己的状态管理、错误处理和降级策略

### 第四层：公共层 Common

**职责**：提供所有 Agent 共享的基础能力。

**关键角色**：
- 嵌入模型服务（BGE-M3）
- 重排序服务（BGE-Reranker）
- 意图分类服务（MiniLM）
- 工具函数（文本切分、格式转换等）

**设计要点**：
- 公共层组件是无状态的，可被多个 Agent 共享
- 模型加载由公共层管理，避免每个 Agent 重复加载
- 接口设计为纯函数，便于测试和替换

### 第五层：MCP 层

**职责**：统一的大模型调用接口，负责所有与 LLM 的通信。

**关键角色**：
- 统一 LLM 接口：封装不同 API 差异
- 模型切换：支持 DeepSeek、GPT-4 等切换
- 重试降级：自动重试、降级策略
- 流式处理：统一流式接口

**设计要点**：
- 屏蔽不同 LLM 的 API 差异
- 重试采用指数退避算法
- 降级策略包括：切换备用模型、返回缓存结果、友好提示

### 第六层：数据层 Data

**职责**：数据存储和管理的底层基础设施。

**关键角色**：
- Milvus：向量存储和检索
- PostgreSQL：关系数据存储
- 文件存储：简历 PDF、试卷等
- 缓存：Redis 或内存缓存
- 消息队列：可选，异步任务处理

**设计要点**：
- 通过 Repository 模式提供统一访问接口
- 向量数据库和关系数据库各司其职
- 数据访问层实现连接池管理

## 面试追问

**Q1（基础）**：EduAgent 的六层分层架构是哪六层？每层的核心职责是什么？
**回答要点**：
1. API 层：对外暴露接口，接收请求返回响应
2. 编排层：意图识别和 Agent 路由
3. Agent 层：执行业务逻辑
4. 公共层：共享基础能力（模型、工具）
5. MCP 层：统一大模型调用接口
6. 数据层：数据存储管理

**Q2（深挖）**：为什么编排层不放在 Agent 层内部？这样分层有什么好处？
**回答要点**：
1. 职责分离：编排层只负责路由，Agent 层只负责执行
2. 可扩展性：新增 Agent 只需修改编排层的路由表，Agent 层不动
3. 容错隔离：编排层故障不影响已在运行的 Agent，Agent 层故障不影响路由

**Q3（实战）**：MCP 层的作用是什么？统一 LLM 接口解决了什么问题？
**回答要点**：
1. 屏蔽不同 LLM 的 API 差异，上层代码不需要关心用哪个模型
2. 统一管理重试、降级、切换，避免每个 Agent 重复实现
3. 切换模型只需改 MCP 层配置，业务代码完全不动

**Q4（边界）**：如果公共层的一个模型加载失败，哪些层会受影响？
**回答要点**：
1. 公共层模型加载失败 → 依赖该模型的 Agent 层受影响
2. 但 API 层、编排层、数据层不受影响
3. 这种分层隔离正是六层架构的优势——故障不会跨层扩散
