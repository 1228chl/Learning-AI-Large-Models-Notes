# 策略选择与多路径RAG检索

## 定义

策略选择（Strategy Selection）是 RAG 系统在检索阶段根据用户查询类型动态选择最优检索路径的决策机制。不同于单一固定检索流程，多路径检索根据查询意图从**直接检索**、**假设问题检索**、**子问题检索**和**回溯问题检索**四种策略中选择最合适的一种，以提升复杂查询的检索命中率。

### 形式化定义

策略选择可形式化为一个策略函数 $\pi$，输入为查询 $q$ 和可选的对话历史 $H$，输出最优检索策略 $s^*$：

$$
s^* = \pi(q, H) = \arg\max_{s \in \mathcal{S}} \text{score}(q, s)
$$

其中 $\mathcal{S}$ 为策略集合，$\text{score}(q, s)$ 由 LLM 或分类模型评估查询 $q$ 与策略 $s$ 的匹配度：

$$
\text{score}(q, s) = P_{\text{LLM}}(s \mid q, H, \text{instructions})
$$

- $q$：用户输入的原始查询
- $H$：多轮对话历史，用于消解指代
- $\mathcal{S}$：四种策略集合 $\{\text{Direct}, \text{HyDE}, \text{SubQuery}, \text{StepBack}\}$
- $\text{score}(q, s)$：查询 $q$ 适合策略 $s$ 的置信度分数
- $P_{\text{LLM}}$：LLM 在指令引导下对策略的打分概率分布

## 四种检索策略详解

| 策略 | 原理 | 适用查询类型 | 改写方式 | 示例 |
|:----|:-----|:-----------|:--------|:-----|
| **直接检索**（Direct） | 不改写 query，直接使用原始查询检索向量库 | 简单事实类、关键词明确 | 无改写 | "什么是梯度消失" |
| **假设问题检索**（HyDE） | 让 LLM 先生成一个假设性答案，以答案代替 query 去检索 | 复杂概念、需要推理 | 伪答案生成 | "解释 Transformer 的自注意力机制" → 先生成伪答案 |
| **子问题检索**（SubQuery） | 将复杂查询拆分为多个子问题，分别检索后合并 | 多角度、对比类 | 子查询分解 | "LSTM 和 GRU 有什么区别" → ["LSTM 原理", "GRU 原理", "二者对比"] |
| **回溯问题检索**（StepBack） | 从具体问题回溯到更抽象的高层概念，先检索抽象概念再回答具体问题 | 需要前置知识的深度问题 | 去噪回溯 | "为什么 Transformer 不用 RNN" → "RNN 的序列处理原理是什么" |

### 1. 直接检索

直接检索是最基础的 RAG 策略，将用户原始查询直接送入向量检索。适用于简单的事实性问答，无需任何改写。

$$
\text{Result} = \text{Retrieve}(q)
$$

### 2. 假设问题检索（HyDE）

HyDE（Hypothetical Document Embedding）先生成一个"假设性答案"，用该答案的嵌入向量去检索相似文档。

$$
\hat{a} = \text{LLM}(q), \quad \text{Result} = \text{Retrieve}(\hat{a})
$$

- $\hat{a}$：LLM 根据查询 $q$ 生成的假设答案
- $\text{Retrieve}(\hat{a})$：用假设答案的嵌入向量检索向量库

### 3. 子问题检索（SubQuery）

将复杂查询拆分为多个独立子问题，分别检索后合并结果去重。

$$
\mathcal{Q}_{\text{sub}} = \text{LLM}_{\text{decompose}}(q) = \{q_1, q_2, \dots, q_k\}, \quad \text{Result} = \bigcup_{i=1}^k \text{Retrieve}(q_i)
$$

- $\mathcal{Q}_{\text{sub}}$：LLM 拆分得到的子问题集合
- $k$：子问题数量，通常为 2-4 个

### 4. 回溯问题检索（StepBack）

先回溯到更高层的抽象概念去检索，再结合原始查询做精化检索。

$$
q_{\text{back}} = \text{LLM}_{\text{stepback}}(q), \quad \text{Result} = \text{ReRank}(\text{Retrieve}(q_{\text{back}}) \cup \text{Retrieve}(q))
$$

- $q_{\text{back}}$：回溯后的抽象问题
- $\text{ReRank}$：对两次检索结果合并后做重排序

## 策略选择决策流程

```python
def select_strategy(query: str, history: list = None) -> str:
    """
    使用 LLM 判断最适合当前查询的检索策略。
    """
    prompt = f"""
    判断以下查询最适合哪种 RAG 检索策略，仅返回策略名称。

    可选策略：
    - direct: 事实性、关键词明确的简单查询
    - hyde: 需要详细解释的复杂概念查询
    - subquery: 多角度、对比类、需要分解的查询
    - stepback: 需要前置知识或背景的深度查询

    查询：{query}

    策略："""
    strategy = llm.invoke(prompt).strip().lower()
    return strategy if strategy in ("direct", "hyde", "subquery", "stepback") else "direct"
```

## 四种策略对比总结

| 对比维度 | Direct | HyDE | SubQuery | StepBack |
|:--------|:------:|:----:|:--------:|:--------:|
| **检索次数** | 1 | 1 | k（子问题数） | 2 |
| **改写开销** | 无 | 一次 LLM 调用 | 一次拆分+多次检索 | 两次检索+重排序 |
| **召回率** | 低（复杂查询） | 高 | 最高 | 高 |
| **精确率** | 高 | 中 | 中 | 中 |
| **适用查询复杂度** | 低 | 中-高 | 高 | 中-高 |
| **典型延迟** | 低 | 中 | 高 | 中-高 |

## ML/DL 应用场景

| 应用场景 | 默认策略 | 何时切换 |
|:--------|:--------|:---------|
| **FAQ 问答** | Direct | 问题过长或含比较时切 SubQuery |
| **知识库深度问答** | HyDE | 需要前置知识时切 StepBack |
| **多文档对比** | SubQuery | / |
| **教育问答系统** | StepBack | 基础概念题切 Direct |

## 面试追问

**Q1（基础）**：RAG 系统中为什么需要多种检索策略而不是只用直接检索？
**回答要点**：

1. 不同查询类型对检索方式有不同需求：事实问答需精确匹配，复杂概念需语义扩展，对比问题需多角度覆盖
2. 单一策略无法兼顾所有场景——直接检索对复杂问题召回率低，HyDE 对简单问题浪费 token
3. 动态策略选择可以在检索精度和系统开销之间取得最佳平衡

**Q2（深挖）**：HyDE 策略中假设答案的生成质量对检索效果有什么影响？
**回答要点**：

1. 假设答案越接近真实文档的语义分布，检索效果越好
2. 关键因素：LLM 的推理能力、假设答案长度（过短缺乏语义、过长引入噪声）
3. 控制方法：限制假设答案长度（100-200 tokens）、使用更可靠的 LLM 生成、结合指令约束格式

**Q3（实战）**：在教育问答系统中如何设计策略选择的决策逻辑？
**回答要点**：

1. 用 BERT 微调模型做快速意图分类，区分 FAQ/知识库/闲聊三大类
2. 知识库类查询再使用 LLM 从 4 种策略中做精细选择
3. 设置 fallback 策略：策略选择不明确时默认使用 HyDE + 直接检索的混合

**Q4（边界）**：多策略检索在实际系统中会增加多少延迟？如何优化？
**回答要点**：

1. 直接检索延迟最低（一次向量查询），SubQuery 延迟最高（多次检索需合并）
2. 策略选择本身也有延迟（一次 LLM 调用约 0.5-2 秒）
3. 优化方案：子问题并行检索（多线程并发）、策略选择用轻量分类模型替代 LLM、结果缓存命中时跳过策略选择
