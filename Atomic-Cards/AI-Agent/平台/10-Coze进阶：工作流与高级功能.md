# Coze 进阶：工作流与高级功能

## 定义

Coze（扣子）不仅提供基础的 Agent 搭建能力，还支持**工作流编排**、**数据库操作**、**多模态处理**等高级功能。这些功能使 Coze Agent 能够处理复杂的业务逻辑，而不仅仅是简单的问答。

## 工作流节点

Coze 的工作流以 **DAG（有向无环图）** 形式组织，支持以下节点类型：

| 节点类型 | 功能 | 适用场景 |
|:---------|:-----|:---------|
| **代码节点** | 执行自定义 Python/JS 代码 | 数据转换、逻辑判断、API 调用 |
| **变量聚合** | 合并多条分支的结果 | 并行处理后汇总 |
| **批处理** | 批量处理列表数据 | 批量翻译、批量审核 |
| **条件分支** | 按条件分流 | 意图路由、阈值判断 |
| **循环** | 重复执行子流程 | 迭代优化、多轮处理 |

### 代码节点示例

```python
# Coze 代码节点：对输入数据进行格式化
def main(input_data: dict) -> dict:
    texts = input_data.get("texts", [])
    result = [t.strip() for t in texts if t.strip()]
    return {"cleaned": result, "count": len(result)}
```

## 数据库操作（NL2SQL）

Coze 内置了知识库和数据库能力，支持通过自然语言操作数据库：

| 操作 | SQL 对应 | 说明 |
|:----|:---------|:-----|
| **NL2SQL 查询** | `SELECT` | 自然语言描述查询条件，自动生成 SQL |
| **数据插入** | `INSERT` | 将用户输入写入数据库表 |
| **数据更新** | `UPDATE` | 更新已有记录 |
| **自定义 SQL** | 任意 SQL | 高级用户可手写 SQL，绕过 NL2SQL 限制 |

### 数据库设计模式

- **频道共享模式**：多个 Bot 共享同一张表，通过 channel_id 字段隔离数据
- **逻辑删除**：表设计包含 `is_delete` 字段，不直接物理删除数据
- **字段权限**：可控制哪些字段对用户可见，哪些字段仅内部使用

## 多模态节点

| 节点 | 功能 | 说明 |
|:-----|:-----|:------|
| **文生图** | 根据文本生成图片 | 基于 Stable Diffusion 或类似模型 |
| **图片增强** | 图片清晰度提升、去水印 | 预处理用户上传的图片 |
| **ASR（语音识别）** | 语音转文字 | 语音输入转文本，后续节点处理 |

## Coze Studio（开源版）

Coze Studio 是 Coze 的开源版本，支持**私有化部署**，适用于对数据安全有要求的企业场景。

| 特性 | Coze Cloud | Coze Studio |
|:----|:-----------|:------------|
| **部署方式** | SaaS | Docker 自托管 |
| **数据存储** | 字节跳动云端 | 企业自有服务器 |
| **模型接入** | 豆包/GPT/Claude 等 | 可接入企业私有模型 |
| **适用场景** | 快速原型、小团队 | 企业级生产环境 |

## Coze Bot vs Application

Coze 中有两个核心概念：

- **Bot**：独立 AI 助手，配置知识库、插件、工作流，面向最终用户
- **Application**：Bot 的容器，管理 Bot 的发布渠道、访问权限、用量统计

**区别**：Bot 是"AI 大脑"，Application 是"运行环境"。

## 发布渠道

| 渠道 | 说明 | 适用场景 |
|:----|:-----|:---------|
| **微信** | 通过微信公众号/小程序接入 | 国内 C 端用户 |
| **飞书** | 飞书 Bot 接入 | 企业内部使用 |
| **Discord** | Discord Bot 接入 | 海外用户 |

## ML/DL 应用场景

| 应用场景 | 数学形式 | 说明 |
|:--------|:---------|:-----|
| 客服 Bot 多轮对话 | 工作流条件分支 + 循环节点 | 意图识别、分流处理、多轮对话状态管理 |
| 批量数据处理 | 批处理节点 + 代码节点 | 批量翻译、批量审核，并行处理再聚合 |

## 面试追问

**Q1（基础）**：Coze 工作流中的代码节点和变量聚合节点分别有什么作用？
**回答要点**：
1. 代码节点执行自定义脚本，用于数据转换、逻辑判断、API 调用等
2. 变量聚合节点合并多条并行分支的结果，用于汇总处理
3. 两者结合可以实现复杂的业务逻辑，如先并行处理再汇总

**Q2（深挖）**：Coze 的 NL2SQL 功能是如何实现的？有什么局限？
**回答要点**：
1. LLM 将用户的自然语言描述转换为 SQL 查询语句
2. 局限：复杂查询（多表 JOIN、子查询）可能转换错误
3. 局限：对数据库表结构敏感，字段命名不清晰时效果差
4. 解决方案：使用自定义 SQL 节点绕过 NL2SQL，手写精确查询

**Q3（实战）**：多 Bot 共享同一张数据库表时，如何做数据隔离？
**回答要点**：
1. 使用频道共享模式，表中加 channel_id 字段
2. 每个 Bot 的 Application 配置不同的 channel_id
3. 查询时自动附加 channel_id 过滤条件，确保数据隔离

**Q4（边界）**：什么场景下应该选择 Coze Studio 而非 Coze Cloud？
**回答要点**：
1. 数据安全要求高：涉及敏感数据不能出企业内网
2. 需要自定义模型：接入企业自有的私有模型
3. 高并发场景：Coze Cloud 有 API 调用频率限制
4. 成本控制：大规模使用时 Studio 自托管可能更经济
