# Coze 参数调优指南

## 定义

Coze 平台为 Agent 的 LLM 配置提供了 **Temperature、TopP、TopK** 三个核心解码参数，控制模型输出的随机性和多样性。合理调参是在"稳定性"和"创造性"之间找到平衡，不同任务场景需要不同的参数组合。

## 核心参数

| 参数 | 范围 | 作用 | 低值效果 | 高值效果 |
|:----|:----|:-----|:---------|:---------|
| **Temperature** | 0 ~ 2 | 控制输出概率分布的平滑度 | 确定性高、保守 | 创造性高、发散 |
| **TopP** | 0 ~ 1 | 累积概率阈值，只从概率和达标的 token 中采样 | 候选 token 少 | 候选 token 多 |
| **TopK** | 1 ~ 100 | 只从概率最高的 K 个 token 中采样 | 候选 token 少 | 候选 token 多 |

## Temperature 概率分布对比

| T 值 | 概率分布特点 | 输出效果 | 适用场景 |
|:----|:------------|:---------|:---------|
| **0** | 贪心解码，选概率最高的 token | 完全确定，重复性高 | 事实问答、代码生成 |
| **0.4** | 轻微平滑，保留高概率 token | 稳定但略有变化 | 客服回复、知识问答 |
| **0.8** | 明显平滑，中低概率 token 有机会 | 有创意但可控 | 创意写作、文案生成 |
| **1.5** | 接近均匀分布 | 发散、不可预测 | 头脑风暴、诗歌生成 |

## 场景化调参指南

| 任务类型 | Temperature | TopP | TopK | 说明 |
|:---------|:----------:|:----:|:----:|:------|
| **精确问答** | 0 | 0.1 | 1 | 事实性答案，确定性最高 |
| **客服回复** | 0.3 ~ 0.5 | 0.5 | 20 | 标准回复略有变化，避免机械感 |
| **代码生成** | 0.1 ~ 0.3 | 0.3 | 10 | 需要稳定输出，但允许变量名变化 |
| **文案写作** | 0.7 ~ 0.9 | 0.8 | 40 | 有创意但保持主题 |
| **创意写作** | 0.8 ~ 1.2 | 0.9 | 50 | 充分发挥创造力 |
| **头脑风暴** | 1.2 ~ 1.5 | 1.0 | 100 | 最大多样性，生成多维度想法 |

## 调参决策流程

```python
def select_params(task_type: str) -> dict:
    """根据任务类型选择最佳参数组合"""
    params = {
        "精确问答": {"temperature": 0, "top_p": 0.1, "top_k": 1},
        "客服回复": {"temperature": 0.4, "top_p": 0.5, "top_k": 20},
        "代码生成": {"temperature": 0.2, "top_p": 0.3, "top_k": 10},
        "文案写作": {"temperature": 0.8, "top_p": 0.8, "top_k": 40},
        "创意写作": {"temperature": 1.0, "top_p": 0.9, "top_k": 50},
        "头脑风暴": {"temperature": 1.4, "top_p": 1.0, "top_k": 100},
    }
    return params.get(task_type, {"temperature": 0.7, "top_p": 0.8, "top_k": 40})
```

## 参数协同效应

**Temperature + TopP 联动**：两者都控制随机性，但机制不同。通常建议固定一个值，调另一个：

- **固定 Temperature，调 TopP**：先确定"发散程度"，再用 TopP 裁剪低概率 token
- **固定 TopP，调 Temperature**：先确定"候选池大小"，再用 Temperature 控制分布平滑度
- **经验法则**：不要同时大幅调整两个参数，最多调一个，另一个用默认值

**TopK 与 TopP 的关系**：
- TopK 是"硬截断"——只保留概率最高的 K 个 token
- TopP 是"软截断"——保留累积概率达到 P 的 token 集合
- 两者可同时使用：先取 TopK 截断，再在剩余 token 中按 TopP 筛选

## ML/DL 应用场景

| 应用场景 | 数学形式 | 说明 |
|:--------|:---------|:-----|
| 精确问答参数配置 | $T=0$, $\text{TopP}=0.1$, $\text{TopK}=1$ | 确定性最高，适用于事实性问答和代码生成 |
| 创意写作参数配置 | $T=0.8$, $\text{TopP}=0.8$, $\text{TopK}=40$ | 平衡创造性和可控性，适合文案和创意内容 |

## 面试追问

**Q1（基础）**：Temperature = 0 时模型输出是完全确定的吗？为什么？
**回答要点**：
1. Temperature = 0 使用贪心解码，每次都选概率最高的 token
2. 给定相同输入，输出是确定的（无随机性）
3. 但注意：模型本身有浮点精度问题，在不同硬件上可能略有差异

**Q2（深挖）**：为什么精确问答任务推荐 Temperature = 0 而创意写作推荐 T = 0.8-1.2？
**回答要点**：
1. 精确问答需要事实准确，高 Temperature 可能导致模型选择低概率 token 而编造事实
2. 创意写作需要多样性，低 Temperature 会导致输出重复、乏味
3. T = 0 时模型倾向于高频 token，可能产生"安全但无聊"的回复
4. 不同 LLM 对 Temperature 的敏感度不同，需根据具体模型微调

**Q3（实战）**：在 Coze 中调试一个客服 Bot，用户反馈回复太机械，应该怎么调参？
**回答要点**：
1. 当前问题：回复太机械 → 随机性不足
2. 调整方案：Temperature 从 0 提升到 0.4，TopP 从 0.1 提升到 0.5
3. 同时需注意：不要调太高，以免客服回复偏离标准答案
4. 验证：用 A/B 测试对比调参前后的用户满意度

**Q4（边界）**：Temperature 和 TopP 同时调高会有什么风险？
**回答要点**：
1. 两者同时调高会导致输出极度发散，模型可能生成无意义内容
2. 建议遵循"调一个固定另一个"原则
3. 极端情况（T=2, TopP=1, TopK=100）相当于近乎随机采样，输出基本不可控
