# 文本分类全流程

## 定义

文本分类是 NLP 中最基础也最实用的任务。一个完整的文本分类项目包含从**数据获取到模型部署**的完整流水线。

## 项目全流程

```
数据获取 → 数据探索(EDA) → 预处理 → 特征工程 → 模型训练 → 评估 → 部署
```

## 面试追问

**Q1（基础）**：一个完整的文本分类项目包含哪些步骤？如何根据数据量选择不同的模型方案？
**回答要点**：数据获取→EDA→预处理→特征工程→模型训练→评估→部署；<1000 样本推荐传统 ML（TF-IDF + LR/RF），1000-10000 推荐 FastText，>10000 推荐 BERT 微调；小样本不适合深度学习方法——容易过拟合，DL 需要大数据量才能发挥预训练优势。

**Q2（深挖）**：TF-IDF + 逻辑回归和 BERT 微调两种方案在特征表示和分类原理上有什么本质区别？
**回答要点**：TF-IDF 基于词袋模型，将文本转为稀疏向量（维度=词表大小），LR 做线性决策边界——可解释性强、训练快但无法捕捉词序和上下文语义；BERT 基于 Transformer 预训练，通过注意力机制学习上下文相关的稠密向量表示——语义理解强但需要 GPU 资源、推理慢。

**Q3（实战）**：案例中 FastText 在 81 万数据 40 类任务上以 94% 精度超越 BERT 的 93%，分析了哪些原因？这对实际项目选型有什么启示？
**回答要点**：FastText 利用子词 n-gram 特征捕捉形态学信息，对中文新词和变体鲁棒；81 万数据量对 FastText 已经足够饱和但 BERT 微调未必充分收敛；FastText 采用 hierarchical softmax 在类别多时训练更快；启示：重视基准模型（简单方法在充分调优后可能接近或超越复杂模型），选型需综合考量数据量、类别数、延迟要求而非一味追求"最先进"。

**Q4（边界）**：文本分类系统上线后可能遇到哪些训练阶段未见的挑战？如何应对？
**回答要点**：数据分布漂移——线上数据分布与训练集不一致导致准确率下降，需监控置信度分布并触发重训；新类别出现——需设计 OOD 检测机制（如基于预测熵或距离度量），并规划增量学习流程；长文本截断丢失关键分类特征——需根据业务定制 truncation 策略或使用长文本模型；推理延迟和吞吐量要求——需模型量化/剪枝/蒸馏，或用传统 ML 做快速预过滤再深度模型兜底。
