# 提示词工程核心原则

## 定义

提示词工程（Prompt Engineering）是通过**设计输入给 LLM 的指令**来引导模型产生期望输出的技术。它是人与 LLM 交互的核心技能。

## 六大核心原则

| 原则 | 说明 | 错误示例 | 正确示例 |
|:----|:----|:---------|:---------|
| **明确具体** | 告诉模型你想要什么，越具体越好 | "总结一下" | "用 3 句话总结，每句不超过 20 字" |
| **分步引导** | 复杂任务拆解为步骤 | "写个方案" | "1. 分析需求；2. 列出方案；3. 评估优缺点" |
| **角色设定** | 为模型设定专业角色 | "回答这个问题" | "你是资深算法工程师，请解释..." |
| **提供示例** | Few-shot 示例 | "分类这个文本" | "正面：'太棒了'；负面：'太差了'；现在请分类：'..." |
| **输出格式** | 明确指定输出结构 | "给我结果" | "以 JSON 格式输出：{'sentiment': 'positive'}" |
| **约束条件** | 设定边界和限制 | "写代码" | "用 Python 3.10+，不依赖第三方库，处理异常" |

## Few-shot Prompt（少样本提示）

```python
# Zero-shot（零样本提示）：不提供示例，直接让模型判断情感
prompt = "这个电影太精彩了！情感是正面还是负面？"

# Few-shot（少样本提示）：给出两个示例让模型类比学习情感分类任务
prompt = """
文本: 这个手机质量太差了
情感: 负面

文本: 服务态度非常好
情感: 正面

文本: 这个电影太精彩了
情感:"""  # 模型会根据前面示例的模式自动推断此处的情感

## Chain-of-Thought（思维链）

引导模型展示推理过程，而不是直接给出答案：

```python
# 标准 Prompt（可能出错）：直接提问，模型可能跳过推理步骤导致答案错误
prompt = "如果 3 个苹果 5 美元，9 个苹果多少钱？"

# CoT Prompt（思维链提示）：引导模型展示逐步推理过程，提升复杂问题的准确性
prompt = """
如果 3 个苹果 5 美元，9 个苹果多少钱？
让我们一步一步思考：
3 个苹果 5 美元，所以每个苹果 5/3 美元
9 个苹果就是 9 × 5/3 = 15 美元
答案：15 美元
"""  # 通过显式展示中间计算步骤，帮助模型遵循正确的推理路径

## 提示词模板

```python
from langchain.prompts import PromptTemplate

# 结构化模板：通过模板变量动态填充上下文和问题，实现提示词的复用
template = PromptTemplate(
    input_variables=["context", "question"],  # 定义模板中需要动态替换的变量
    template="""基于以下上下文回答问题。
如果上下文中没有足够信息，请说"信息不足"。

上下文：
{context}

问题：{question}
回答："""  # {context}和{question}会在运行时被实际内容替换
)

## ML 中的提示词工程

| 应用场景 | 提示词技巧 | 说明 |
|:--------:|:----------|:----|
| **文本分类** | Few-shot + 输出格式约束 | 给 3-5 个示例，指定输出 JSON |
| **代码生成** | 角色设定 + 约束条件 | "资深 Python 工程师，写一个函数..." |
| **数据提取** | 明确格式 + 约束 | "从以下文本中提取人名、日期，以 JSON 输出" |
| **推理任务** | CoT + 分步引导 | "让我们一步一步思考..." |
| **翻译** | 角色 + 格式 | "专业翻译，保留格式，只翻译内容" |

## 面试追问

**Q1（基础）**：提示词工程六大核心原则中，"角色设定"和"输出格式"各自解决了什么问题？请举例说明。

**回答要点**：角色设定为模型框定专业知识背景和回答风格（如"你是一个资深算法工程师"），减少回答范围的不确定性；输出格式指定模型返回数据的结构（如"JSON 格式输出"），便于下游程序解析和集成。

**Q2（深挖）**：Zero-shot、Few-shot 和 Chain-of-Thought 三种提示策略分别适用于什么任务？各自的底层原理是什么？

**回答要点**：Zero-shot 适合模型已充分训练过的简单任务，直接利用预训练知识推理；Few-shot 通过上下文示例（in-context learning）让模型类比学习任务模式，适合分类、格式转换等；CoT 引导模型展示中间推理步骤，将隐式推理过程显式化，显著提升数学和逻辑推理的准确性。

**Q3（实战）**：在构建 RAG 问答系统的提示词时，如何通过提示词设计减少 LLM 的幻觉行为？

**回答要点**：明确约束"请基于以下检索内容回答，如果信息不足请说不知道"；在提示词中限定 LLM 不要引入检索内容之外的知识；加入角色设定强化事实性要求；使用 Few-shot 示例展示"有则回答、无则拒绝"的正确回答方式；输出格式约束（如"只输出答案本身"）减少自由发挥空间。

**Q4（边界）**：提示词工程有哪些固有局限？什么情况下必须通过系统架构变更（而非优化提示词）才能解决问题？

**回答要点**：模型本身的知识截止边界和推理能力上限无法通过提示词突破；模型对措辞敏感导致同样的提示在不同模型/版本上效果不稳定；高度专业或小众领域知识提示词无法补偿——需 RAG 补充；复杂多步推理场景提示词优化边际收益递减——需 Agent 的规划+工具机制。
