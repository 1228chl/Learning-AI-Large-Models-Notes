# OCR解析与多模态文档处理

## 定义

OCR（Optical Character Recognition）是将图片、扫描件中的文字提取为可编辑文本的技术。在 RAG 系统中，OCR 用于处理无法直接提取文字的文档（扫描版 PDF、图片、截图等），将这些非结构化视觉信息转化为可检索的文本内容。

OCR 场景推荐使用多模态模型（如 **PaddleOCR-VL**），可同时提取图片中的文字、表格、公式和图表，比传统 OCR 仅提取文字的效果更全面。部署方式：通过 vLLM 加载 PaddleOCR-VL 模型提供 OpenAI 兼容 API，支持 OCR / 表格识别 / 公式识别 / 图表识别等任务类型。

## OCR 处理流程

```
原始文件（扫描件/图片）
    │
    ├─→ 格式识别（文件扩展名判断）
    │
    ├─→ 加载器分发
    │       │
    │       ├─→ PDF 扫描件 → OCRPDFLoader（逐页渲染+OCR）
    │       ├─→ Word 文档 → OCRDOCLoader（含页眉页脚清洗）
    │       ├─→ PPT 文件 → OCRPPTLoader（幻灯片提取）
    │       └─→ 图片文件 → OCRIMGLoader（端到端OCR）
    │
    ├─→ OCR 引擎处理（PaddleOCR-VL 多模态识别）
    │
    ├─→ 文档预处理（空格压缩、换行统一、页眉页脚清洗）
    │
    └─→ 输出 LangChain Document 对象列表
```

## OCR 加载器实现

```python
# OCR 加载器字典：将文件扩展名映射到对应的 OCR 加载器
ocr_loaders = {
    ".pdf": OCRPDFLoader,       # 扫描件 PDF，逐页渲染 + OCR
    ".docx": OCRDOCLoader,      # Word 文档，自动清除页眉页脚
    ".ppt": OCRPPTLoader,       # PPT 幻灯片，提取每页文字
    ".pptx": OCRPPTLoader,      # PPTX 格式
    ".jpg": OCRIMGLoader,       # JPEG 图片 OCR
    ".png": OCRIMGLoader,       # PNG 图片 OCR
}
```

把 PDF 每页渲染成图片，发给多模态 LLM（如 GPT-4o、Claude 3.5）让它描述图片内容，再把描述文字当作 chunk 存入知识库。代价：调用多模态 LLM 成本高，处理速度慢，适合对质量要求极高的场景。

## 文档预处理

| 处理类型 | 操作 | 目的 |
|:---------|:-----|:-----|
| **空格压缩** | 连续空格替换为单个空格 | 减少冗余 token，提高嵌入质量 |
| **换行压缩** | 连续 \n 替换为单个 \n | 统一段落格式，避免切分器误判 |
| **页眉页脚清洗** | 识别并移除页眉页脚 | 防止干扰信息混入正文 |
| **OCR 增强** | 对扫描件进行光学字符识别 | 图片中的文字转为可检索文本 |

## ML/DL 应用场景

| 应用场景 | OCR 策略 | 说明 |
|:--------:|:---------|:------|
| **教材扫描件建库** | OCRPDFLoader + PaddleOCR-VL | 教材多为扫描版 PDF，逐页 OCR 提取文字后建库 |
| **课件 PPT 处理** | OCRPPTLoader + 版式分析 | 每页幻灯片提取文字，保留页内标题层级 |
| **公式/图表识别** | 多模态 LLM 描述 | 将公式和图表用多模态模型描述为文本，存入知识库 |
| **历史文档数字化** | 传统 OCR + 人工校对 | 低质量扫描件先 OCR 提取，再人工校对关键段落 |

## 面试追问

**Q1（基础）**：为什么 PDF 扫描件不能直接用文本加载器处理？OCR 在 RAG 系统中扮演什么角色？
**回答要点**：
1. 扫描件本质是图片，没有可提取的文本层，必须通过 OCR 将图像转为文字
2. OCR 将非结构化的视觉信息转化为可检索的文本，扩展了 RAG 知识库的覆盖范围
3. 没有 OCR，扫描版教材、历史文档等无法进入知识库

**Q2（深挖）**：多模态模型 OCR 相比传统 OCR 有什么优势？代价是什么？
**回答要点**：
1. 多模态模型不仅能提取文字，还能理解表格结构、公式、图表的语义
2. 传统 OCR 只输出文字，丢失了版式信息和视觉语义
3. 代价：调用多模态 LLM 成本高（API 费用或 GPU 推理），处理速度慢，不适合大规模批量处理

**Q3（实战）**：OCR 处理后文档中常见的质量问题有哪些？如何预处理？
**回答要点**：
1. 连续空格/换行冗余、页眉页脚混入正文、表格/公式识别错乱
2. 预处理：空格压缩（连续空格→单个）、换行压缩（连续换行→单个）、页眉页脚识别移除
3. 对公式密集的文档使用专门的公式识别引擎（如 Mathpix），对双栏文档进行版面分析后再 OCR

**Q4（边界）**：OCR 在什么场景下效果最差？如何兜底？
**回答要点**：
1. 手写体、艺术字体、低分辨率图片 OCR 识别率极低
2. 双栏排版、表格、数学公式的 OCR 结果难以保持原始阅读顺序
3. 兜底方案：对重要文档优先使用原始电子版而非扫描件；对 OCR 置信度低的段落标记为"需人工校对"；保留原始图片路径供人工查阅
