# BM25 算法

## 定义

BM25（Best Matching 25）是一种**稀疏检索**算法，基于**词袋模型**和**TF-IDF**改进而来。它计算查询与文档之间的相关性分数，是 RAG 系统中与稠密向量检索互补的经典方法。

**核心公式**：

$$\text{Score}(Q, D) = \sum_{i=1}^n \text{IDF}(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot (1 - b + b \cdot \frac{|D|}{\text{avgdl}})}$$

其中：
- $f(q_i, D)$：词 $q_i$ 在文档 $D$ 中的频率
- $|D|$：文档长度；$\text{avgdl}$：平均文档长度
- $k_1$：控制词频饱和（默认 1.2~2.0）
- $b$：控制长度归一化（默认 0.75）

## BM25 vs TF-IDF

| 对比 | TF-IDF | BM25 |
|:----:|:------|:----|
| **词频影响** | 线性增长 | **非线性饱和**（$k_1$ 控制） |
| **文档长度** | 不考虑 | 考虑（$b$ 控制） |
| **长文档惩罚** | ❌ 不惩罚，越长 TF 越高 | ✅ 合理惩罚长文档 |
| **效果** | 基准 | **更好，业界标准** |

## Python 实现

```python
import math
from collections import Counter
import jieba

class BM25:
    def __init__(self, documents, k1=1.5, b=0.75):
        self.documents = documents
        self.k1 = k1
        self.b = b
        self.avgdl = sum(len(doc) for doc in documents) / len(documents)
        self.doc_freqs = [Counter(doc) for doc in documents]
        self.idf = self._compute_idf()

    def _compute_idf(self):
        n_docs = len(self.documents)
        idf = {}
        for doc in self.doc_freqs:
            for word in doc:
                idf[word] = idf.get(word, 0) + 1
        return {word: math.log(1 + (n_docs - freq + 0.5) / (freq + 0.5))
                for word, freq in idf.items()}

    def score(self, query, doc_idx):
        score = 0
        doc_len = len(self.documents[doc_idx])
        for q in query:
            if q in self.idf:
                f = self.doc_freqs[doc_idx].get(q, 0)
                score += self.idf[q] * (f * (self.k1 + 1)) / (
                    f + self.k1 * (1 - self.b + self.b * doc_len / self.avgdl)
                )
        return score
```

## BM25 参数调优

| 参数 | 作用 | 调高 | 调低 |
|:----:|:----|:----|:----|
| $k_1$ | 词频饱和速度 | 高估高频词重要性 | 忽略高频词 |
| $b$ | 文档长度惩罚 | 更偏向短文档 | 不惩罚长文档 |
| 默认 | $k_1 = 1.2 \sim 2.0$，$b = 0.75$ | — | — |

| 维度 | BM25（稀疏） | Embedding（稠密） |
|:----:|:-----------:|:----------------:|
| **匹配方式** | 精确关键词匹配 | 语义相似度匹配 |
| **同义词** | ❌ 不匹配 | ✅ 能匹配 |
| **罕见专业词** | ✅ 精确命中 | ⚠️ 可能丢失 |
| **适用** | 术语多、需要精确命中的场景 | 泛化语义搜索 |

> **面试追问**
>
> Q1（基础）：BM25 公式中的 k1 和 b 两个参数分别控制什么？默认值通常取多少？
> 回答要点：k1 控制词频饱和速度（默认 1.2~2.0），决定高频词对分数的贡献上限；b 控制文档长度归一化强度（默认 0.75），决定对长文档的惩罚程度；k1→0 时只考虑 IDF 忽略词频，k1→∞ 时退化为线性词频（同 TF-IDF）。
>
> Q2（深挖）：BM25 相比 TF-IDF 的三个核心改进是什么？为什么这些改进在实际检索中效果更好？
> 回答要点：词频非线性饱和——防止高频词主导分数（k1 控制）；文档长度归一化——避免长文档因词频累积天然高分（b 控制）；IDF 平滑——公式使用 `log(1+(N-df+0.5)/(df+0.5))` 避免罕见词 IDF 无穷大。这些改进使 BM25 在几乎所有标准检索基准（TREC 等）上一致优于 TF-IDF。
>
> Q3（实战）：在 RAG 系统中为什么常用 BM25 + 稠密向量的混合检索？如何设置融合权重？
> 回答要点：BM25 擅长精确关键词匹配和专业术语命中但无法理解语义，稠密向量擅长同义词和语义匹配但可能丢失精确术语——两者互补；融合方式包括加权求和（BM25:0.3~0.4 + Dense:0.6~0.7）、先独立检索再 RRF（倒数排序融合）或学习式权重。
>
> Q4（边界）：BM25 在什么场景下检索效果会显著下降？有什么替代或补充方案？
> 回答要点：查询与文档用词不一致时（同义词问题）BM25 完全无法匹配——需配合 Query Expansion 或稠密检索；极短查询（1-2 个词）缺乏区分度——可用 HyDE 生成假设答案扩展查询；文档和查询语言不同时失效——需跨语言检索或翻译方案；海量数据下内存版 BM25 性能不足——应换 ElasticSearch 或分布式搜索引擎。
