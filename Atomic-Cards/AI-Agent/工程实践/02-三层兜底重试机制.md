# 三层兜底重试机制

## 定义

**三层兜底重试机制** 是一套从"自动重试"到"Agent 降级"再到"系统兜底"的递进式容错策略，确保 LLM 系统在 API 调用失败、服务不可用等异常情况下仍能提供可用的服务。

### 三层总览

| 层级 | 触发条件 | 处理方式 |
|:----|:---------|:---------|
| **第一层：自动重试** | 网络抖动/LLM 超时等短暂故障 | 自动重试最多 2 次（间隔 1s/3s），消化偶发故障 |
| **第二层：Agent 级降级** | 重试 2 次仍失败 | 退化为简单实现：问答→跳过检索直接答，批改→标记教师复核 |
| **第三层：系统级兜底** | 连降级都失败 | 返回友好提示，保证用户始终能收到响应 |

### 直观理解

> 好比你去 ATM 取钱：第一次卡没读出来（第一层重试）→ 再试一次 → 还是不行（第二层降级）→ 去柜台人工取钱 → 柜台也排长队（第三层兜底）→ 至少给你一张"抱歉，请稍后再来"的纸条，而不是系统崩溃。

## 异常分类

```python
# 可重试异常：重试有意义
RETRYABLE_ERRORS = (
    LLMAPIError,         # 大模型 API 调用失败
    MilvusConnectionError, # 向量数据库连接失败
    TimeoutError,         # 超时
    ConnectionError,      # 网络连接错误
)

# 不可重试异常：重试无意义，直接抛出
NON_RETRYABLE_ERRORS = (
    InvalidInputError,    # 用户输入不合法
    AuthenticationError,  # 认证失败
)
```

## 装饰器实现

```python
import asyncio
from functools import wraps

def with_retry(agent_type: str, max_retries: int = 2):
    """装饰器工厂：给异步函数加上三层兜底能力"""
    def decorator(func):
        @wraps(func)
        async def wrapper(state: dict, *args, **kwargs):
            # 第一层：自动重试
            last_error = None
            for attempt in range(max_retries + 1):
                try:
                    return await asyncio.wait_for(
                        func(state, *args, **kwargs),
                        timeout=30.0  # 30秒超时
                    )
                except NON_RETRYABLE_ERRORS:
                    raise  # 不可重试，直接抛出
                except RETRYABLE_ERRORS as e:
                    last_error = e
                    if attempt < max_retries:
                        wait = 2 ** attempt * 0.5  # 指数退避：0.5s, 1s
                        await asyncio.sleep(wait)

            # 第二层：Agent 级降级
            try:
                return await _fallback(agent_type, state, last_error)
            except Exception as e:
                # 第三层：系统级兜底
                return _system_fallback_response(agent_type, str(e))

        return wrapper
    return decorator
```

## 降级函数

```python
async def _fallback(agent_type: str, state: dict, error: Exception) -> dict:
    """Agent 级降级：按 agent_type 找降级策略"""
    fallbacks = {
        "qa":        _qa_fallback,           # 跳过检索直接答
        "exam_code": _exam_code_fallback,    # 标记 needs_teacher_review
        "exam_subjective": _exam_subjective_fallback,
        "resume":    _resume_fallback,
        "interview": _interview_fallback,
    }
    fallback_func = fallbacks.get(agent_type)
    if fallback_func:
        return await fallback_func(state, error)
    raise error

def _system_fallback_response(agent_type: str, error: str) -> dict:
    """第三层：系统级兜底"""
    return {
        "error": f"服务暂时不可用，请稍后重试",
        "fallback_used": True,
        "agent_type": agent_type,
    }
```

## 使用示例

```python
@with_retry(agent_type="qa")
async def retrieve_node(state: QAState) -> dict:
    """检索节点：自动带三层兜底"""
    docs = await vector_search(state["question"])
    return {"retrieved_docs": docs}
```

## 面试追问

**Q1（基础）**：三层兜底分别是哪三层？每层的作用是什么？
**回答要点**：
1. 第一层自动重试：消化偶发故障（网络抖动、LLM 超时），最多重试 2 次
2. 第二层 Agent 降级：退化为简单实现，如标记教师复核
3. 第三层系统兜底：返回友好提示，保证用户始终能收到响应

**Q2（深挖）**：可重试异常和不可重试异常的区别是什么？为什么这样区分？
**回答要点**：
1. 可重试异常（API 错误、超时、连接错误）：通常是临时的，重试可能成功
2. 不可重试异常（输入不合法、认证失败）：重试一定会失败，重试是浪费资源
3. 区分它们避免无意义的重复尝试

**Q3（实战）**：第二层降级中，试卷批改的降级策略是什么？为什么标记为 needs_teacher_review？
**回答要点**：
1. AI 评分失败时，标记为 needs_teacher_review，让教师人工复核
2. 这比返回一个错误分数更好——至少保留人工裁决权
3. 体现了"AI 辅助，人工兜底"的设计理念

**Q4（边界）**：第三层系统兜底的目的是什么？为什么说是"最后的保底"？
**回答要点**：
1. 确保即使所有降级都失败，用户仍然能收到响应（而不是崩溃或无限等待）
2. 返回友好提示，而不是技术错误堆栈
3. 这是"优雅降级"的体现——系统不完美，但不会崩溃
