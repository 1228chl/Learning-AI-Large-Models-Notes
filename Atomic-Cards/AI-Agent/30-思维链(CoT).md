# 思维链（Chain-of-Thought, CoT）

## 定义

思维链（Chain-of-Thought, CoT）是一种通过在提示中引导模型"逐步推理"来生成中间推理步骤，从而提升最终答案准确性的提示技术。它模仿人类解决问题的过程：先分析问题、列出关键信息、逻辑推导，最后得出结论。

从概率角度，标准 prompt 直接建模条件概率 $P(a|q)$，其中 $q$ 为输入问题，$a$ 为最终答案。CoT 将其分解为中间推理步骤的链式条件概率：

$$
P(a|q) = \prod_{t=1}^{T} P(s_t | q, s_{<t})
$$

其中 $s_t$ 为第 $t$ 步的推理 token（中间推理步骤），$s_{<t} = \{s_1, s_2, \dots, s_{t-1}\}$ 为前 $t-1$ 步的推理序列。CoT 通过显式建模 $P(s_t | q, s_{<t})$ 的链式分解，将复杂推理问题转化为若干子步骤的连乘，使得每一步的预测空间从完整答案空间 $|A|$ 缩小到单步推理空间 $|S_t|$（通常 $|S_t| \ll |A|$），从而降低单步预测的复杂度。

### 核心思想

- **不直接问答案**，而是要求模型"展示思考过程"
- 利用大模型上下文学习（in-context learning）能力，在 few-shot 示例中示范"如何一步步思考"

## 三种主要类型

### 1. Zero-shot CoT

在提示后加"让我们一步一步地思考"（Let's think step by step），无需提供示例。

```python
# 标准 Prompt：直接提问，模型可能忽略安全边界直接回答
prompt = "每天喝10升水有益吗？"

# Zero-shot CoT Prompt：引导模型逐步推理，自动发现潜在风险
prompt = """
每天喝10升水有益吗？
让我们一步一步思考。
"""  # 模型会自发分解问题：正常饮水量→10升是否过量→水中毒风险→得出结论
```

### 2. Few-shot CoT

提供若干示例展示完整的推理过程，让模型模仿同样的推理模式回答新问题。

```python
# Few-shot CoT：通过示例示范推理模式
prompt = """
问题：小明有 3 个苹果，妈妈又给了他 5 个，他一共吃了 2 个，还剩几个？
推理：小明开始有 3 个苹果，妈妈给了 5 个，所以共有 3+5=8 个。
      他吃了 2 个，所以还剩 8-2=6 个。
答案：6 个

问题：商店有 20 支笔，上午卖了 8 支，下午进了 12 支，现在有多少支？
推理："""
# 模型会按示例的推理模式继续推导：20-8=12, 12+12=24, 答案：24 个
```

### 3. 多跳问答（Multi-hop QA）

需要多步推理才能回答的问题，每一步依赖前一步的结果。

```python
# 多跳问答：需要链式分解多个知识关联步骤
prompt = """
问题：谁是《哈利·波特》中赫敏·格兰杰最好的朋友的扮演者的丈夫？

链式分解：
第1跳：赫敏·格兰杰最好的朋友 → 哈利·波特
第2跳：哈利·波特的扮演者 → 丹尼尔·雷德克里夫（Daniel Radcliffe）
第3跳：丹尼尔·雷德克里夫的丈夫 → 错误！丹尼尔·雷德克里夫是男性
      需要重新推理：赫敏·格兰杰的扮演者 → 艾玛·沃特森（Emma Watson）
第4跳：艾玛·沃特森的丈夫 → 需要查询最新信息

请一步一步推理并给出最终答案。
"""  # 多跳问答需要模型具备"错误检测与回溯"能力，这在实际 CoT 应用中是一个关键挑战
```

## 适用场景

| 任务类型 | 是否适合 CoT | 原因 |
|:--------|:-----------:|:----|
| 简单事实问答 | 不必要 | 直接回答更快更准，CoT 增加 token 消耗且无收益 |
| 数学/逻辑推理 | 强烈推荐 | 需要分步计算，每一步可验证中间结果正确性 |
| 常识推理、因果推断 | 推荐 | 避免跳跃性错误，使推理过程可追溯 |
| 文本摘要、翻译 | 通常无效 | 非推理型任务，CoT 可能引入无关冗余信息 |
| 代码生成（带逻辑） | 可结合 | 先描述算法逻辑，再生成代码，降低逻辑错误率 |

## ML/DL 应用场景

| 应用场景 | CoT 策略 | 说明 |
|:--------|:--------|:----|
| **数学应用题求解** | Few-shot CoT | 提供 2-3 道题的完整解题步骤，模型按相同模式推导新题 |
| **常识推理（CommonsenseQA）** | Zero-shot CoT | 加"让我们一步一步思考"，模型自发分解问题 |
| **符号推理（Last Letter Concatenation）** | Few-shot CoT | 示例展示字母拼接的逐步操作，模型模仿执行 |
| **策略推理（Game of 24）** | CoT + Self-Consistency | 多路径推理后投票选择最一致的答案，提升可靠性 |
| **医疗诊断推理** | Multi-hop QA | 症状分析→可能病因→检查方案→诊断结论的多跳推理 |
| **法律条文分析** | CoT + 角色设定 | 设定"资深律师"角色，按法条解析→事实匹配→结论的推理链 |

## 面试追问

**Q1（基础）**：Zero-shot CoT 和 Few-shot CoT 的核心区别是什么？各在什么场景下优先使用？
**回答要点**：

1. Zero-shot CoT 不需要示例，仅在提示后追加"让我们一步一步思考"即可触发推理，适合通用推理任务，实现成本最低
2. Few-shot CoT 需要提供 2-3 个带完整推理步骤的示例，让模型通过上下文学习模仿推理模式，适合特定领域或格式要求严格的推理任务
3. 选择原则：通用推理优先 Zero-shot CoT，领域特定推理优先 Few-shot CoT；当 Zero-shot CoT 效果不稳定时，可增加 few-shot 示例提升推理质量

**Q2（深挖）**：CoT 为什么能提升大模型的推理能力？其背后的数学原理是什么？
**回答要点**：

1. CoT 将复杂推理问题分解为链式条件概率 $P(a|q) = \prod_{t=1}^{T} P(s_t | q, s_{<t})$，每一步的预测空间从完整答案空间缩小到单步推理空间，降低了单步预测的复杂度
2. 从信息论角度，CoT 通过显式生成中间推理步骤 $s_t$ 为模型提供了"计算中间变量"，相当于将隐式推理过程外部化，减少了模型需要在隐空间中维持的推理状态
3. 从训练数据角度，LLM 预训练语料中包含了大量逐步推理的文本（如数学解题过程、技术文档等），CoT 提示方式恰好激活了模型在预训练阶段学到的这种推理模式

**Q3（实战）**：在构建 RAG 问答系统时，如何结合 CoT 提升复杂问题的回答质量？
**回答要点**：

1. 对于需要多步推理的复杂问题，使用 CoT 将问题分解为子问题，每步检索对应子问题的最相关文档，而非一次性检索全部文档
2. 在 prompt 中加入 CoT 引导，让模型在阅读检索结果后先列出关键信息再给出答案，减少因跳跃推理导致的幻觉
3. 结合 Self-Consistency 策略，多次使用 CoT 生成多个推理路径，对结果投票选择最一致的答案，显著提升复杂推理的可靠性

**Q4（边界）**：CoT 有哪些固有局限？什么场景下 CoT 不仅无效反而会降低模型性能？
**回答要点**：

1. CoT 会增加 token 消耗，对于简单事实问答（如"中国首都是什么"），CoT 引入的推理步骤浪费计算资源且无性能提升
2. 对于非推理型任务（如文本摘要、翻译、情感分类），CoT 可能引入无关的中间推理步骤，反而降低输出质量
3. CoT 的推理质量高度依赖模型自身的基础推理能力，小模型（<7B 参数）即使使用 CoT 也难以完成复杂推理，需要结合外部工具（如计算器、代码解释器）才能突破模型固有的推理能力上限
