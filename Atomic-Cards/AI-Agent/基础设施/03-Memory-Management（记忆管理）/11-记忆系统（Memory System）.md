# 记忆系统（Memory System）

## 定义

记忆系统是 Agent Harness 中实现跨会话持久化知识的机制。Agent 在每个回合结束后从对话中自动提取新记忆，存储到文件系统，后续会话中通过索引文件检索相关记忆并注入到 System Prompt 中。记忆在文件数超过阈值时自动合并去重。

$$
\text{Memory System} = \text{提取（Extract）} + \text{索引（Index）} + \text{选择（Select）} + \text{合并（Merge）}
$$


## 问题描述

上下文压缩会丢失重要信息——用户的偏好设置、项目关键决策、已完成的里程碑……压缩后这些信息就消失了，下一轮对话需要重新告诉模型。跨会话更是如此：每次新会话都是“白纸一张”。

需要一种机制，从对话中提取关键信息，持久化存储，并在需要时自动注入到上下文中。让 Agent 有“长期记忆”，而不是“每次见面都重新认识”。

## 存储结构

```
.memory/
  MEMORY.md              ← 索引文件（每条记忆一行，≤200 行）
  user_profile.md        ← 用户偏好记忆（如：喜欢用 tabs 而非 spaces）
  project_facts.md       ← 项目事实记忆（如：项目使用 Python 3.12）
  feedback_tabs.md       ← 用户反馈记忆（如：上次的代码审查意见）
```

## 记忆类型对比

| 类型 | 内容 | 提取时机 | 注入方式 |
|:-----|:-----|:---------|:---------|
| user | 用户偏好（编辑器、风格、命名习惯） | 每个回合结束后 | 索引文件常驻 System Prompt |
| feedback | 用户指导意见和反馈 | 用户提供反馈时 | 完整内容按需加载 |
| project | 项目事实（技术栈、约定、架构） | 项目初始化 + 对话中补充 | 索引文件常驻 System Prompt |
| reference | 外部引用（文档链接、规范） | 用户主动提供时 | 完整内容按需加载 |

## 生命周期流程

```
每个回合结束后
  → extract_memories(messages) 提取新记忆
  → 写入文件系统（每条记忆独立文件）
  → 更新 MEMORY.md 索引（标题 + 一行描述）

下一轮/下一会话开始时
  → select_relevant_memories(current_messages) 挑选相关记忆
  → 将相关记忆内容注入 System Prompt

当文件数 ≥ 10 时
  → 触发合并：去重、合并相似内容
  → 删除已合并的单个文件
```

## 直观理解

记忆系统就像一个"个人助理"——每次对话结束后，助理会记下你提到的偏好和事实（提取），写在笔记本上（持久化），下次见面时翻看笔记本的目录（索引），找出与你当前话题相关的内容（选择），如果笔记太多就整理合并（去重）。

## Agent 工程应用场景

| 应用场景 | 记忆类型 | 说明 |
|:---------|:---------|:-----|
| 记住用户偏好 | user | "我喜欢用 tabs 而不是 spaces"→ 后续代码生成自动使用 tabs |
| 记住项目约定 | project | "项目使用 Python 3.12 + pytest"→ 后续代码生成符合规范 |
| 记住反馈意见 | feedback | 用户对代码风格的反馈，后续生成时自动修正 |
| 跨会话连续工作 | 所有类型 | 同一项目多次会话，Agent 记住之前的进展和约定 |

## 面试追问

**Q1（基础）**：记忆系统的核心流程是什么？提取、索引、选择、合并各做什么？
**回答要点**：

1. 提取：每个回合结束后，用 LLM 分析对话内容，识别用户偏好、约束或项目事实
2. 索引：每条记忆写入独立文件，`MEMORY.md` 索引文件维护所有记忆的名称和描述
3. 选择：每轮开始时，通过 LLM 或关键词匹配，从索引中挑选与当前对话相关的记忆
4. 合并：当记忆文件数达到阈值（如 10 个），触发去重合并，减少冗余

**Q2（深挖）**：为什么 MEMORY.md 索引文件常驻 System Prompt，而完整记忆按需加载？
**回答要点**：

1. 索引文件很短（≤200 行，约 1000 tokens），常驻 System Prompt 成本极低
2. 完整记忆可能很长（如项目事实文件），全部注入会浪费大量上下文空间
3. 两级设计：索引让 Agent"知道有哪些记忆存在"，需要时再通过 `select_relevant_memories` 加载具体内容
4. 这是"先做便宜的再做贵的"原则在记忆系统中的应用

**Q3（实战）**：如何实现记忆的跨会话持久化？新会话启动时怎么加载记忆？
**回答要点**：

1. 记忆以文件形式存储在 `.memory/` 目录，独立于会话的生命周期
2. 新会话启动时，读取 MEMORY.md 索引文件注入 System Prompt
3. 用 `select_relevant_memories` 根据用户第一条消息挑选相关记忆
4. 选中的记忆完整内容注入到 System Prompt 中
5. 回忆不准确时，Agent 可通过工具读取完整的记忆文件

**Q4（边界）**：记忆系统可能出现哪些错误？如何保证记忆的准确性？
**回答要点**：

1. 幻觉记忆：LLM 提取时可能"编造"用户未说过的内容——需用户确认后才写入
2. 过期记忆：项目技术栈变更后旧记忆仍被加载——需时间戳 + 自动过期机制
3. 记忆冲突：不同来源的记忆内容矛盾——需合并时检测冲突，请求用户裁决
4. 隐私泄露：敏感信息被提取为记忆，在无关会话中被加载——需分类分级 + 用户审批
