# Agent Harness（基础设施层）

## 定义

Harness 是 AI Agent 的**基础设施层**，为模型提供感知、推理和行动所需的外部支持系统。Agency（感知、推理、行动的能力）来自模型训练本身，但一个可用的 Agent 产品需要**模型（Model）**和**Harness（基础设施）**两者兼备。

$$
\text{Harness} = \text{工具} + \text{知识} + \text{观察} + \text{行动接口} + \text{权限}
$$

- **工具**：模型与外部世界交互的接口（bash、read_file、write_file 等）
- **知识**：按需注入的领域知识和上下文（技能加载、记忆系统）
- **观察**：模型感知环境状态的能力（文件系统、网络、任务看板）
- **行动接口**：工具执行和结果返回的通信机制（TOOL_HANDLERS、MCP 协议）
- **权限**：安全边界和操作控制（拒绝列表、规则匹配、用户确认）

## 直观理解

Harness 是 Agent 的"车辆"，模型是"驾驶员"——车辆提供操控装置、仪表盘和安全带，驾驶员负责判断和决策。Harness 工程师的工作是造更好的车，而非训练驾驶员。

## Agent 工程应用场景

| 应用场景 | 具体体现 | 说明 |
|:---------|:---------|:-----|
| 生产级 Agent 系统 | 完整的 Harness 实现 | 如 Claude Code、Cursor、GitHub Copilot 的底层基础设施 |
| 教学课程 | LearnClaudeCode 项目 | 20 个渐进式构建模块，从最简循环到全功能集成 |
| 多 Agent 协作 | 消息总线 + 队友管理器 | 多个 Agent 共享 Harness 但独立运行 |
| 安全合规 | 权限系统 + 审计日志 | 企业级部署中的操作审计和权限管控 |

## 面试追问

**Q1（基础）**：什么是 Agent Harness？它和模型是什么关系？
**回答要点**：

1. Harness 是 Agent 的基础设施层，包含工具、知识、观察、行动接口、权限五大组件
2. 模型负责感知、推理和决策（Agency 来自训练），Harness 负责提供执行环境
3. 两者缺一不可：没有模型的 Harness 是空壳，没有 Harness 的模型无法与外部世界交互

**Q2（深挖）**：Harness 设计的核心原则有哪些？
**回答要点**：

1. 关注点分离：每个机制独立模块（权限→Hooks→任务系统），便于理解和修改
2. 先做便宜的再做贵的：压缩管线从零 API 调用的裁剪开始，LLM 摘要作为最后手段
3. 真实状态判断：基于文件是否存在、工具是否启用等真实状态，而非关键词匹配
4. 错误是常态：所有外部调用都可能失败，需要指数退避、降级、备用模型等机制

**Q3（实战）**：如果要为一个新 Agent 系统设计 Harness，从哪些组件开始？
**回答要点**：

1. 先实现核心 Agent 循环（s01）：`while True` + LLM 调用 + 工具执行
2. 再添加工具分发（s02）：用字典映射解耦工具注册和调用
3. 然后加入权限系统（s03）：防止模型执行危险操作
4. 最后用 Hooks（s04）将扩展点从循环体中分离，使后续功能可插拔

**Q4（边界）**：Harness 和 Agent 框架（如 LangChain、AutoGPT）有什么区别？
**回答要点**：

1. Harness 是底层基础设施概念，强调"模型驱动，Harness 承载"的哲学
2. 很多框架过度抽象，将 Agency 错误地归因于编排代码而非模型本身
3. Harness 设计追求最小化依赖和最大化透明性，代码刻意保持精简
4. 框架通常提供更高层次的抽象（Chain、AgentExecutor），而 Harness 提供原始构建块
