# 评分 Rubric 设计

## 定义

**评分 Rubric（分档评分标准）** 是一种让大模型进行"有据可依"的评估打分的方法——把 0-100 分按档次分好，每档写明具体特征，让 LLM 有明确的"尺子"可依，而不是凭感觉打分。

### 核心公式

```
Rubric = 评分维度 + 分档标准(每档的行为特征描述) + 权重
```

### 直观理解

> 没有 Rubric 的评分好比"让老师凭感觉给作文打分"——今天给 85，明天可能给 75，同一篇作文不同老师可能给不同分数。有 Rubric 的评分好比"用评分表给体操打分"——每个动作的得分标准写在纸上，裁判按表打分，不同裁判的分数差异很小。

## 为什么需要 Rubric

大模型打分如果没有标尺，结果会飘忽不定、难以复现：

| 问题 | 表现 | Rubric 的解决 |
|:-----|:-----|:-------------|
| **评分漂移** | 同一份内容不同时间打分不同 | 固定标准，减少漂移 |
| **维度混淆** | 一个维度打高分，其他维度也偏高 | 每个维度独立评分，独立标准 |
| **缺乏可解释性** | 说不清为什么给这个分数 | 每档有明确特征描述 |
| **难以调试** | 不知道 LLM 评分依据 | 标准公开，可对照分析 |

## 完整示例

### 六维度评分标准

```python
SIX_DIMENSIONS = [
    {"key": "project_depth",    "name": "项目深度",   "weight": 0.30},
    {"key": "tech_match",       "name": "技术匹配度", "weight": 0.25},
    {"key": "expression",       "name": "表达规范性", "weight": 0.15},
    {"key": "structure",        "name": "简历结构",   "weight": 0.15},
    {"key": "quantification",   "name": "量化程度",   "weight": 0.10},
    {"key": "authenticity",     "name": "真实可信度", "weight": 0.05},
]
```

### Rubric 设计（项目深度示例）

```python
PROJECT_DEPTH_RUBRIC = """请评审以下简历在【项目深度】维度的表现。

评分标准（0-100分）：
- 90-100：每个项目都有量化指标、明确的技术选型理由、清晰的个人贡献和难点解决
- 70-89：大部分项目有量化数据，个人贡献基本清晰
- 50-69：项目描述偏泛，缺少量化数据，个人贡献不明确
- 30-49：项目描述流水账，看不出技术深度
- 0-29：项目描述极度简陋或与岗位完全不相关"""
```

### Rubric 设计原则

| 原则 | 说明 | 好的写法 | 坏的写法 |
|:-----|:-----|:---------|:---------|
| **行为化** | 描述具体行为特征 | "有量化数据" | "项目描述好" |
| **可区分** | 不同档次有明显区别 | "大部分/部分/没有" | 档次间模糊 |
| **可观察** | 能从输入中直接看到 | "有量化指标如'提升30%'" | "技术深度深" |
| **全覆盖** | 覆盖从 0 到 100 所有范围 | 5 档覆盖所有可能 | 只写高分档 |

### 权重设计

权重之和为 1.0，保证加权综合分落在 0-100：

```python
# 加权综合分计算
weighted_score = sum(d["score"] * d["weight"] for d in dimension_scores)
# 权重和为 1.0，结果天然落在 0-100
```

**权重设计思路**：
- 项目深度（0.30）和技术匹配度（0.25）占大头——对工程师简历最关键
- 表达规范性（0.15）和简历结构（0.15）中等重要
- 量化程度（0.10）和真实可信度（0.05）作为补充

## 代码实现

```python
async def review_one_dimension(dim: dict) -> dict:
    """单个维度评审"""
    for attempt in range(2):
        try:
            prompt = DIMENSION_REVIEW_PROMPTS[dim["key"]].format(
                focus=dim["focus"],
                structured_summary=structured_summary,
                resume_text=resume_text,
            )
            structured_llm = get_structured_llm("resume", DimensionScore)
            result = await structured_llm.ainvoke([...])

            d = result.model_dump()
            d["dimension"] = dim["name"]   # 代码层填：中文维度名
            d["weight"] = dim["weight"]    # 代码层填：权重
            return d
        except Exception:
            if attempt == 1:
                return _empty_dimension_score(dim)  # 降级为 50 分

# 六维度并行
tasks = [review_one_dimension(dim) for dim in SIX_DIMENSIONS]
dimension_scores = await asyncio.gather(*tasks)
```

## 关键设计决策

| 决策 | 做法 | 原因 |
|:-----|:-----|:-----|
| **维度名和权重由代码填** | 不交给 LLM | 确保权重准确，防止 LLM 私自修改 |
| **降级给 50 分** | 评审失败时给中性分 | 50 分是"中性"，不偏袒也不惩罚 |
| **维度独立评审** | 每个维度独立调用 LLM | 避免维度间相互影响 |
| **并行执行** | 使用 asyncio.gather | 6 个维度同时评，耗时 ≈ 最慢的一个 |

## 面试追问

**Q1（基础）**：什么是评分 Rubric 设计？为什么它在 LLM 评估类任务中如此重要？
**回答要点**：
1. Rubric 是把 0-100 分分档，每档写明具体特征的评分标准
2. 解决大模型打分漂移、维度混淆、缺乏可解释性的问题
3. 给 LLM 一把"刻度尺"，让不同内容的评分有一致的依据

**Q2（深挖）**：Rubric 设计的四个原则是什么？为什么"行为化"最重要？
**回答要点**：
1. 行为化：描述具体行为特征而非抽象评价
2. 可区分：不同档次有明显区别
3. 可观察：能从输入中直接看到
4. 全覆盖：覆盖 0 到 100 所有范围
5. 行为化最重要，因为 LLM 是根据"看到了什么"来打分的，不是根据"感觉怎么样"

**Q3（实战）**：EduAgent 中六维度评分有哪些关键设计决策？
**回答要点**：
1. 维度名和权重由代码填写，不交给 LLM
2. 降级给 50 分（中性分）
3. 每个维度独立调用 LLM，避免维度间相互影响
4. 使用 asyncio.gather 并行执行，总耗时 ≈ 一次调用

**Q4（边界）**：如果某个维度评审失败，降级给 50 分而不是 0 分，为什么这样设计？
**回答要点**：
1. 50 分是"中性分"，不偏袒也不惩罚
2. 0 分会严重拉低加权综合分，对其他维度不公平
3. 50 分表示"该维度评审失败，建议人工复核"，而不是"该维度得 0 分"
