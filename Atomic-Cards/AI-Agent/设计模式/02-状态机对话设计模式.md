# 状态机对话设计模式

## 定义

**状态机对话设计模式** 将多轮对话建模为**状态机（State Machine）**，由三个要素构成：**状态（State）**、**转移条件（Transition）**、**当前状态记录**。它将"现在到哪一步了"从对话内容里独立出来，由代码逻辑管理，而不是靠 LLM 推断。

### 核心公式

```
状态机对话 = 有限状态集合 + 状态转移规则 + 当前状态指针
```

### 直观理解

> 普通多轮对话好比"自由聊天"——每轮都在做同样的事（听→想→说）。状态机对话好比"面试流程"——热身阶段、技术阶段、项目深挖阶段各有不同的规则，不能混在一起。状态机让"现在到哪一步了"由程序管理，而不是靠 LLM 自己猜。

## 为什么需要状态机

**核心问题**：普通多轮对话每一轮做的事情完全相同（学员提问 → LLM 回应），但模拟面试天然是"分阶段"的——热身阶段不能问技术题，技术阶段不能问反问，每个阶段内部还有追问逻辑和轮数控制。

| 要素 | 交通灯类比 | 面试 Agent 对应 |
|:-----|:-----------|:----------------|
| **状态（State）** | 红/黄/绿 | WARMUP / TECH_BASE / PROJECT / CLOSING / FINISHED |
| **转移条件（Transition）** | 计时器到点 | 问够轮数 / 题库问完 / 学员说"结束" |
| **当前状态记录** | 当前亮的灯 | `current_stage` 字段 |

## 实现示例

### 状态定义

```python
from enum import Enum

class InterviewStage(str, Enum):
    WARMUP    = "warmup"     # 热身：破冰开场，自我介绍
    TECH_BASE = "tech_base"  # 技术基础：题库问答 + 追问
    PROJECT   = "project"    # 项目深挖：项目经验深入
    CLOSING   = "closing"    # 收尾：反问环节
    FINISHED  = "finished"   # 结束：生成报告
```

### 阶段推进逻辑

```python
class InterviewState(TypedDict):
    current_stage: str
    stage_rounds: dict       # 每个阶段的轮次计数
    dialogue_history: list
    evaluation: dict

def check_stage_transition(state: InterviewState) -> str:
    """检查是否需要推进到下一阶段"""
    stage = state["current_stage"]
    rounds = state["stage_rounds"].get(stage, 0)

    if stage == "warmup":
        # 最少1轮，最多4轮后推进
        if rounds >= 4 or (rounds >= 1 and "自我介绍完成" in last_msg):
            return "tech_base"
    elif stage == "tech_base":
        # 至少6轮且已问过8道题
        if rounds >= 6 and questions_asked >= 8:
            return "project"
    elif stage == "project":
        # 问完所有项目相关问题
        if all_projects_covered:
            return "closing"
    elif stage == "closing":
        # 反问环节结束
        return "finished"

    return stage  # 不推进，继续当前阶段
```

### 追问逻辑

同一个阶段内部，根据学员回答质量动态调整追问：

```python
def decide_next_action(state: InterviewState) -> str:
    """根据回答质量决定下一步"""
    last_answer_quality = state["evaluation"].get("last_answer_quality")

    if last_answer_quality == "EXCELLENT":
        # 答得好：最多追问2次深入
        if state["follow_up_count"] < 2:
            return "follow_up_deep"
        else:
            return "next_question"
    elif last_answer_quality == "WEAK":
        # 答得差：给提示后换题
        return "give_hint_and_next"
    elif last_answer_quality == "NO_ANSWER":
        # 答不出：直接换题
        return "skip_to_next"
    else:
        return "next_question"
```

## 状态图

```
WARMUP（热身）
  职责：破冰开场，邀请自我介绍
  推进条件：学员完成自我介绍（最少1轮，最多4轮）
  │
  ▼
TECH_BASE（技术基础）
  职责：考察技术知识，题库问答 + 追问
  推进条件：至少6轮 且 已问过8道题
  追问规则：EXCELLENT → 最多追问2次；WEAK/NO_ANSWER → 换题
  │
  ▼
PROJECT（项目深挖）
  职责：深入项目经验
  推进条件：所有项目问题覆盖完毕
  │
  ▼
CLOSING（收尾）
  职责：反问环节
  推进条件：反问结束
  │
  ▼
FINISHED（结束）
  职责：生成面试报告
```

## 设计要点

| 要点 | 说明 |
|:-----|:-----|
| **状态独立** | 每个阶段有自己的规则和逻辑，互不干扰 |
| **转移条件明确** | 推进条件由代码写死，不由 LLM 决定 |
| **动态调整** | 同一阶段内根据回答质量动态调整追问策略 |
| **可中断** | 每个阶段结束后可中断，等待用户继续 |
| **可追溯** | 记录完整的阶段流转历史，便于分析 |

## 面试追问

**Q1（基础）**：什么是状态机对话设计模式？三个要素是什么？
**回答要点**：
1. 将多轮对话建模为状态机，由代码逻辑管理对话阶段
2. 三个要素：状态（State）、转移条件（Transition）、当前状态记录
3. 解决了"普通多轮对话每轮都做同样的事"的问题

**Q2（深挖）**：为什么模拟面试需要状态机，而不是用 LLM 自己判断"现在到哪一步了"？
**回答要点**：
1. LLM 自己判断不可靠，可能提前进入技术阶段或遗漏关键环节
2. 代码逻辑管理转移条件更精确、可控
3. 状态机使面试流程标准化，每个学员都经历相同的完整流程

**Q3（实战）**：EduAgent 模拟面试中，回答质量如何影响后续流程？
**回答要点**：
1. EXCELLENT：追问深入，最多 2 次
2. WEAK：给提示后换题
3. NO_ANSWER：直接换题
4. 动态调整让面试更有针对性，强化学员不浪费在已掌握的内容上

**Q4（边界）**：如果学员要求"跳过当前阶段直接进入技术面"，系统如何响应？
**回答要点**：
1. 正常流程：由代码控制推进，不处理学员的跳转请求
2. 可扩展设计：可以在每个阶段加一个"强制跳转"的入口
3. 但面试完整性需要保证，建议最少完成最低轮次后再跳转
