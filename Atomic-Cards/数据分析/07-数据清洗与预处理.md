# 数据清洗与预处理

## 定义

数据清洗是将原始脏数据转换为可用数据的过程，涵盖去重、类型转换、字符串清洗、日期解析和异常值检测。数据清洗通常占据数据分析工作 60-80% 的时间，数据质量直接影响模型效果的上限。

### 核心任务

**去重**：检测并删除完全重复的样本行。`pandas` 中用 `duplicated()` 检测、`drop_duplicates()` 删除。列级去重需要指定子集，如 `subset=['id', 'timestamp']` 保留最后一次出现的记录。

**类型转换**：确保每列的数据类型正确。常见问题包括：数字以字符串形式存储（如 `"1,234"` 含逗号需先 `str.replace(',','')` 再 `astype(float)`），日期存为字符串需用 `pd.to_datetime()` 解析，分类变量用 `category` 类型节省内存。

**字符串清洗**：去除首尾空白（`str.strip()`）、统一字母大小写（`str.lower()`）、替换非标准字符（如全角符号转半角）、正则表达式提取模式（`str.extract(r'(\d+)')`）。

### 异常值检测

**IQR 规则**：$x < Q1 - 1.5 \times \text{IQR}$ 或 $x > Q3 + 1.5 \times \text{IQR}$ 标记为异常值。适用于非正态分布数据，对尾部异常值较为稳健。

**Z-score 规则**：$|z_i| = |\frac{x_i - \bar{x}}{s}| > 3$ 标记为异常值。适用于近似正态分布的数据，但极端值会拉高均值导致漏检（掩蔽效应）。

**领域规则**：基于业务知识定义异常范围，如心率 < 30 或 > 250 视为异常。这是最可靠的检测方式，但需要领域专家参与。

## ML/DL 应用场景

| 应用场景 | 清洗策略 | 说明 |
|:--------:|:--------|:------|
| **文本分类** | 去 HTML 标签、统一大小写、标点标准化 | 使用 `BeautifulSoup` 去标签，`str.lower()` 统一大小写，减少词汇表大小 |
| **时间序列预测** | 插值处理缺失、重采样到固定频率 | 用 `resample()` 统一时间间隔，异常值用前/后值替换或中位数过滤 |
| **图像分类** | 检查损坏图片、统一尺寸格式 | 用 `PIL` 或 `cv2` 检测无法解码的图片文件，丢弃或修复 |
| **推荐系统** | 去重用户交互记录、处理冷启动用户 | 删除重复点击（保留最后一次），对交互 < 5 次的用户单独处理 |

## 面试追问

**Q1（基础）**：数据清洗中常见的字符串处理问题有哪些？如何用 Pandas 高效处理？
**回答要点**：

1. 常见问题：首尾空格、不一致大小写、全角半角混用、数字中的分隔符（逗号、百分号）、编码错误
2. Pandas 处理：`str.strip()` 去空格、`str.lower()` 统一大小写、`str.replace()` 替换模式、`str.extract()` 提取内容
3. 高效技巧：使用 `str` 访问器（向量化操作）而非 `apply` lambda，大数据量时用正则表达式编译 `re.compile` 提前缓存

**Q2（深挖）**：IQR 规则和 Z-score 规则在异常值检测上各自的优缺点是什么？如何选择？
**回答要点**：

1. IQR 规则不依赖正态假设，对偏态分布更稳健，但 $1.5 \times \text{IQR}$ 是经验阈值，不同场景可能需要调整（如金融风险检测用 3 倍 IQR）
2. Z-score 规则计算简单直观，但假设数据近似正态，且极端值会造成掩蔽效应（多个极端值互相掩盖）
3. 选择：偏态分布用 IQR 规则，近正态分布用 Z-score 规则，生产环境用领域规则兜底

**Q3（实战）**：在 ML 流水线中，数据清洗操作应该在特征工程之前还是之后？为什么？
**回答要点**：

1. 先清洗后特征工程：清洗修复了数据质量问题，特征工程基于干净数据构建，避免"垃圾进垃圾出"
2. 具体顺序：去重 → 类型转换 → 字符串清洗 → 缺失值处理 → 异常值处理 → 特征工程
3. 注意：异常值检测中的统计量（均值、分位数）必须在训练集上计算，然后用同样的阈值应用到测试集，避免数据泄露

**Q4（边界）**：如何处理文本数据中的编码问题？GBK 和 UTF-8 混用的文件如何恢复？
**回答要点**：

1. 检测编码：用 `chardet` 库自动检测文件编码，或尝试常见编码依次解码
2. 统一转换：`str.encode('gbk').decode('utf-8')` 修复错误解码的文本，但无法恢复已丢失的信息
3. 最佳实践：所有数据入库前统一用 UTF-8 编码，数据库连接设置 `charset='utf8mb4'`，文件读取时指定 `encoding='utf-8'`
