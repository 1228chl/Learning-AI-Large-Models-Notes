## 第一部分：认识文本预处理

### 1.1 文本预处理的概念与作用

**概念**：文本语料在输入到模型之前，通常需要经过一系列预处理工作，使其符合模型输入的要求。这些工作包括：将文本转换为模型需要的张量格式、规范张量的尺寸、检查标签分布、清洗脏数据、分析数据长度分布等。

**作用**：

- 指导模型超参数的选择（例如根据序列长度分布确定填充或截断策略）
- 提升模型的评估指标（例如通过处理类别不平衡、去除噪声数据来提高准确率）

通俗理解：文本预处理就是准备模型需要的输入特征 $X$ 和标签 $Y$，然后将其送入模型进行训练或推理。

---

### 1.2 文本预处理的主要环节

文本预处理包含以下五个主要环节（按一般执行顺序排列）：

| 序号 | 环节 | 说明 |
|------|------|------|
| 1 | 文本语料的数据分析 | 分析标签分布（分类问题中查看是否均匀）、文本长度分布、是否存在脏数据等 |
| 2 | 文本特征处理 | 对文本进行清洗、标准化、特征选择等 |
| 3 | 文本处理的基本方法 | 分词、命名实体识别、词性标注 |
| 4 | 文本张量表示方法 | 将文本转换为张量（如 one-hot、word2vec、word embedding） |
| 5 | 数据增强方法 | 对有限数据生成变体，增加多样性 |

**常见疑问**：在数据已经存在的情况下，哪个环节一般是最先要做的？  
答案：**文本语料的数据分析**。因为只有了解数据特性（如标签是否均衡、长度分布、噪声情况），才能指导后续预处理策略的选择。

---

### 1.3 总结速查表（第一部分）

| 概念 | 核心内容 |
|------|----------|
| 文本预处理 | 将原始文本转换为模型可接受的格式 |
| 主要环节 | 数据分析 → 特征处理 → 基本方法（分词/NER/POS） → 张量表示 → 数据增强 |
| 数据分析优先 | 了解标签分布、长度分布、脏数据，指导后续超参选择 |

## 第二部分：文本处理的基本方法

文本处理的基本方法是 NLP 预处理的核心，包括**分词**、**命名实体识别（NER）**、**词性标注（POS）**。这些方法将原始自然语言文本转换为结构化、可计算的形式，为后续的文本张量表示和高阶任务（如问答、翻译）奠定基础。

### 2.1 分词（Tokenization）

#### 2.1.1 分词的定義与作用

**定义**：分词是将连续的字序列按照一定的规范重新组合成词序列的过程。在英文等以空格分隔的语言中，分词相对简单（按空格和标点切分即可）；但在中文、日文等语言中，词之间没有明显的分界符，必须通过算法进行识别。

**作用**：

- 词是语言语义理解的最小单元，是人类理解文本的基础。
- 分词是 AI 解决 NLP 高阶任务（如自动问答、机器翻译、文本生成）的重要基础环节。

**为什么中文需要分词？**  
中文句子中词与词之间没有空格分隔。例如：“我爱自然语言处理” 如果不分词，计算机难以知道“自然语言处理”是一个完整的术语。分词后得到 `['我', '爱', '自然语言处理']` 更便于语义理解。

---

#### 2.1.2 常用中文分词工具：jieba

**jieba** 是一个 Python 实现的中文分词库，因其高效、易用、可定制而广泛使用。其愿景是成为最好的 Python 中文分词组件。

**主要功能**：

- 支持多种分词模式（精确模式、全模式、搜索引擎模式）
- 支持中文繁体分词
- 支持用户自定义词典
- 支持词性标注（通过 `jieba.posseg`）

---

#### 2.1.3 jieba 三种分词模式详解

三种模式的实质是**分词颗粒度**不同。

| 模式 | 方法 | 特点 | 适用场景 |
|------|------|------|----------|
| **精确模式** | `jieba.cut(sentence, cut_all=False)` | 试图将句子最精确地切开，适合文本分析 | 默认模式，大多数任务使用 |
| **全模式** | `jieba.cut(sentence, cut_all=True)` | 把句子中所有可能的词语都扫描出来，速度快，但不能消除歧义 | 搜索引擎索引建立时提高召回率 |
| **搜索引擎模式** | `jieba.cut_for_search(sentence)` | 在精确模式的基础上，对长词再次切分，提高召回率 | 搜索引擎分词，兼顾精度和召回 |

**代码示例与效果对比**：

```python
import jieba

sentence = "传智教育是一家上市公司，旗下有黑马程序员品牌。我是在黑马这里学习人工智能"


# 1. 精确模式
words_precise = jieba.lcut(sentence, cut_all=False)
print("精确模式:", words_precise)


# 输出: ['传智', '教育', '是', '一家', '上市公司', '，', '旗下', '有', '黑马', '程序员', '品牌', '。', '我', '是', '在', '黑马', '这里', '学习', '人工智能']


# 2. 全模式
words_full = jieba.lcut(sentence, cut_all=True)
print("全模式:", words_full)


# 输出: ['传', '智', '教育', '是', '一家', '上市', '上市公司', '公司', '', '', '旗下', '下有', '黑马', '程序', '程序员', '品牌', '', '', '我', '是', '在', '黑马', '这里', '学习', '人工', '人工智能', '智能']


# 3. 搜索引擎模式
words_search = jieba.lcut_for_search(sentence)
print("搜索引擎模式:", words_search)

# 输出: ['传智', '教育', '是', '一家', '上市', '公司', '上市公司', '，', '旗下', '有', '黑马', '程序', '程序员', '品牌', '。', '我', '是', '在', '黑马', '这里', '学习', '人工', '智能', '人工智能']
```

**注意事项**：

- 全模式下，标点符号（逗号、句号）也会被当作一个独立的词。
- 全模式会将“人工智能”拆分为“人工”和“智能”，有助于提高搜索引擎的召回率。
- `jieba.lcut()` 直接返回 list，`jieba.cut()` 返回生成器（适合大数据流处理）。

#### 2.1.4 中文分词的难点与 jieba 原理

| 难点 | 说明 | jieba 解决策略 |
|------|------|----------------|
| **歧义切分** | 如“研究生命科学” → “研究/生命/科学” vs “研究生/命/科学” | 基于统计（前缀词典 + 动态规划）计算最大概率路径 |
| **未登录词（OOV）** | 新词、人名、地名等不在词库中 | 使用 HMM（隐马尔可夫模型）和 Viterbi 算法识别 |
| **词性边界** | 中文无空格，难以判断词边界 | 结合词典匹配与 HMM 状态转移 |

**jieba 分词流程图**：

1. 根据前缀词典构建有向无环图（DAG）。
2. 在 DAG 上使用动态规划求最大概率路径，得到初步切分。
3. 对未登录词，使用 HMM 模型进行标注（B、M、E、S 四状态），再合并成词。

**学习建议**：了解 HMM 的基本假设（观测序列、隐状态序列）有助于理解 jieba 的 OOV 识别能力。

#### 2.1.5 用户自定义词典

当 jieba 的默认词库无法正确切分某些专业词汇或品牌名称时，可以加载用户自定义词典。词典格式为每行一个词，格式为 `word freq word_type`（freq 和 word_type 可选）。

**示例自定义字典**（`userdict.txt` 内容）：

```python
黑马程序员 5 n
传智教育 6 n
人工智能 7 nz
```

**加载与效果对比**：

```python
import jieba

sentence = "传智教育是一家上市公司，旗下有黑马程序员品牌。我是在黑马这里学习人工智能"


# 未加载自定义词典
print("未加载自定义词典:", jieba.lcut(sentence, cut_all=False))


# 输出: ['传智', '教育', '是', '一家', '上市公司', '，', '旗下', '有', '黑马', '程序员', '品牌', '。', '我', '是', '在', '黑马', '这里', '学习', '人工智能']


# 加载自定义词典
jieba.load_userdict("./userdict.txt")
print("加载自定义词典后:", jieba.lcut(sentence, cut_all=False))


# 输出: ['传智教育', '是', '一家', '上市公司', '，', '旗下', '有', '黑马程序员', '品牌', '。', '我', '是', '在', '黑马', '这里', '学习', '人工智能']
```

**效果**：“传智教育”和“黑马程序员”被正确识别为完整词，不再拆开。

#### 2.1.7 停用词处理

**定义**：停用词（Stop Words）是指在文本中出现频率极高，但对语义贡献较小的词，如“的”、“了”、“是”、“在”等。在文本预处理中，常将其过滤掉，以减少特征维度、降低噪声。

**常用中文停用词表来源**：

- 哈工大停用词表
- 百度停用词表
- `nltk` 的中文停用词（需额外下载）

**代码示例**：

```python
import jieba

def load_stopwords(filepath):
    with open(filepath, 'r', encoding='utf-8') as f:
        return set(line.strip() for line in f)

stopwords = load_stopwords("hit_stopwords.txt")
sentence = "这是我最喜欢的电影，真的很好看。"
words = jieba.lcut(sentence)
filtered = [w for w in words if w not in stopwords and w.strip()]
print("原始:", words)
print("去停用词后:", filtered)
```

**注意事项**：

- 停用词过滤应当放在分词**之后**。
- 对于情感分析任务，某些停用词（如“不”、“没有”）可能携带重要情感信息，需谨慎删除。
- 任务不同，停用词表也应调整：如新闻分类中“报道”、“记者”可能是无用词，但在特定领域可能是关键词。

### 2.2 命名实体识别（NER）

#### 2.2.1 概念与作用

**命名实体（Named Entity）**：指人名、地名、机构名、专有名词等具有特定意义的实体。例如：“周杰伦”（人名）、“黑山县”（地名）、“孔子学院”（机构名）、“24 辊方钢矫直机”（专有名词）。

**命名实体识别（NER）**：识别出一段文本中可能存在的命名实体，并标注其类型。

**作用**：命名实体同样是人类理解文本的基础单元，是 AI 解决 NLP 高阶任务（如信息抽取、知识图谱构建、智能问答）的重要基础环节。

**示例**：

> “鲁迅，浙江绍兴人，五四新文化运动的重要参与者，代表作朝花夕拾。”  
> 识别结果：鲁迅（人名）/ 浙江绍兴（地名）/ 五四新文化运动（专有名词）/ 朝花夕拾（专有名词）

---

#### 2.2.2 NER 的常用方法

| 方法 | 原理 | 优缺点 |
|------|------|--------|
| 基于词典与规则 | 利用预定义的实体词典和模式匹配 | 简单、可解释，但覆盖率低 |
| 统计模型（HMM/CRF） | 序列标注，特征工程 | 需要特征设计，可处理未登录词 |
| 深度学习（BiLSTM+CRF） | 自动提取特征，全局序列解码 | 精度高，需标注数据 |
| 预训练模型（BERT） | 微调 token 分类任务 | SOTA 效果，计算成本较高 |

---

#### 2.2.3 jieba 对 NER 的支持

jieba 本身不直接提供完整的 NER 功能，但可通过其词性标注功能间接获得部分实体信息（如 `nr` 表示人名，`ns` 表示地名，`nt` 表示机构名）。更专业的 NER 可使用 `HanLP`、`LTP` 或 `transformers` 库。

### 2.3 词性标注（POS）

#### 2.3.1 概念与作用

**词性（Part-of-Speech）**：语言中对词的一种分类方法，以语法特征为主要依据、兼顾词汇意义对词进行划分。常见的词性有名词、动词、形容词等（通常有 14 种以上细分类别）。

**词性标注（POS Tagging）**：标注出一段文本中每个词汇的词性。

**作用**：从另一个角度理解文本语言，是 NLP 高阶任务（如句法分析、语义分析、机器翻译）的重要基础。

**示例**：

> “我爱自然语言处理”  
> 标注结果：我 / rr (人称代词), 爱 / v (动词), 自然语言 / n (名词), 处理 / vn (动名词)

---

#### 2.3.2 jieba 词性标注 API

使用 `jieba.posseg` 模块可以同时完成分词和词性标注。

**代码示例**：

```python
import jieba.posseg as pseg

sentence = "我爱北京天安门"
words_pos = pseg.lcut(sentence)
for word, flag in words_pos:
    print(f"{word}/{flag}", end=" ")


# 输出: 我/r 爱/v 北京/ns 天安门/ns
```

**返回结果**：一个列表，每个元素是一个 `pair` 对象，包含 `word` 和 `flag` 属性。

| **PER**  | 人名          | 在Paddle模式中专名类别标签，对应“nr”[](https://cpjrc.igadc.cn/lesson/jt9b78/) |
| **LOC**  | 地名          | 在Paddle模式中专名类别标签，对应“ns”[](https://cpjrc.igadc.cn/lesson/jt9b78/) |
| **ORG**  | 机构名         | 在Paddle模式中专名类别标签，对应“nt”[](https://cpjrc.igadc.cn/lesson/jt9b78/) |
| **TIME** | 时间          | 在Paddle模式中专名类别标签，对应“t”                                           |

| 任务 | 定义 | 常用工具/API | 作用 |
|------|------|---------------|------|
| **分词** | 将连续字符序列切分为词序列 | `jieba.lcut(s, cut_all=False)` | 语义理解最小单元 |
| **命名实体识别** | 识别人名、地名、机构名等专有名词 | `jieba.posseg` 或专用 NER 模型 | 信息抽取、知识图谱 |
| **词性标注** | 标注每个词的词性 | `jieba.posseg.lcut(sentence)` | 语法分析、高阶任务基础 |

**jieba 三种分词模式对比**：

| 模式   | 参数                 | 特点          | 示例输入“人工智能”输出           |
| ---- | ------------------ | ----------- | ---------------------- |
| 精确模式 | `cut_all=False`    | 最精确，适合分析    | `['人工智能']`             |
| 全模式  | `cut_all=True`     | 扫描所有可能词，速度快 | `['人工', '智能', '人工智能']` |
| 搜索模式 | `cut_for_search()` | 长词再切分，提高召回  | `['人工', '智能', '人工智能']` |

**常见问题与注意事项**：

1. **未登录词（OOV）**：默认词库不包含的词汇，可通过自定义词典解决。
2. **歧义切分**：如“研究生命科学”可能被切为“研究/生命/科学”或“研究生/命/科学”，jieba 基于统计和 HMM 模型消歧。
3. **性能**：精确模式速度中等，全模式最快，搜索模式最慢（因为额外切分）。
4. **词性标注的局限性**：jieba 的词性标注基于规则和统计，复杂句子可能存在错误，专业场景建议使用 BERT 等预训练模型。

## 第三部分：文本张量表示方法

文本张量表示是 NLP 预处理的核心环节之一。其目的是将经过分词、词性标注等处理后的文本转换为**张量（矩阵）形式**，以便计算机能够解析和计算。简单来说，就是将“词”变成“向量”。这部分将详细介绍三种主要表示方法：one-hot 编码、Word2Vec 以及 Word Embedding（词嵌入）。

---

### 3.1 文本张量表示概述

**定义**：将一段文本使用张量进行表示的过程。对于单个词，我们会得到一个**词向量**（Word Vector）；对于一句话，我们会得到一个**词向量矩阵**（每一行是一个词的向量）。

**作用**：将文本转化为数值形式，使其能够输入到计算机程序（特别是深度学习模型）中进行处理和分析。

**生活中的类比**：用一个学生的各科成绩向量来代表该学生。例如，张三的 `[90, 70, 80, 90, 70]` 代表他的数学、物理、化学、语文、英语成绩。类似地，在 NLP 中，`["人生", "该", "如何", "起头"]` 可能对应一个矩阵，其中每个词对应一个向量。

**NLP 中常用的文本张量表示方法**：

1. **One-hot 编码**（稀疏表示）
2. **Word2Vec**（稠密表示，基于神经网络）
3. **Word Embedding**（广义的稠密表示，包括 Word2Vec 以及神经网络中的嵌入层）

---

### 3.2 One-hot 编码（稀疏词向量表示）

#### 3.2.1 概念与原理

**One-hot 编码**是一种将分类变量转换为数字格式的方法。对于一个具有 $n$ 个不同类别的分类变量，将其表示为一个 $n$ 维的向量，其中**只有一个维度的值为 1**（代表该样本属于这个类别），其他所有维度的值均为 0。

在 NLP 中，将词汇表中的每个词看作一个类别，就可以用 one-hot 向量表示每个词。

**示例**：

- 词汇表：`["改变", "要", "如何", "起头"]`
- 各词的 one-hot 表示：
  - “改变” → `[1, 0, 0, 0]`
  - “要”   → `[0, 1, 0, 0]`
  - “如何” → `[0, 0, 1, 0]`
  - “起头” → `[0, 0, 0, 1]`

**数学形式**：  
设词汇表大小为 $|V|$，则每个词 $w_i$ 对应的 one-hot 向量 $\mathbf{o}_i \in \{0, 1\}^{|V|}$，且 $\mathbf{o}_i[j] = 1$ 当且仅当 $j = i$，其余为 0。

---

#### 3.2.2 优缺点

| 优点 | 缺点 |
|------|------|
| 操作简单，容易理解 | 完全割裂了词与词之间的联系（任何两个词的点积为 0） |
| 不需要训练 | 在大语料下，词汇表大，导致向量维度极高，占用大量内存 |
| 适合处理分类标签（Y） | 属于稀疏表示，信息密度低 |

---

#### 3.2.3 代码实现（使用 TensorFlow/Keras Tokenizer 和 joblib）

以下代码演示了如何生成 one-hot 编码并保存/加载映射器。

```python
import jieba
from tensorflow.keras.preprocessing.text import Tokenizer
import joblib

# 示例语料（词汇集合）
vocabs = {"周杰伦", "陈奕迅", "王力宏", "李宗盛", "鹿晗"}

# 1. 实例化 Tokenizer 并拟合
tokenizer = Tokenizer()
tokenizer.fit_on_texts(vocabs)

# 查看内部映射
print("word_index:", tokenizer.word_index)   # 词 -> 索引（从1开始）
print("index_word:", tokenizer.index_word)   # 索引 -> 词

# 2. 生成 one-hot 编码
for word in vocabs:
    # 初始化全零向量，长度为词汇表大小
    one_hot = [0] * len(vocabs)
    # 获取该词的索引（减1是因为索引从1开始）
    idx = tokenizer.word_index[word] - 1
    one_hot[idx] = 1
    print(f"{word} 的 one-hot 编码: {one_hot}")

# 3. 保存 tokenizer 以便后续使用
joblib.dump(tokenizer, "./my_tokenizer.pkl")
print("tokenizer 已保存")
```

**加载并使用已保存的 tokenizer**：

```python

# 加载 tokenizer
loaded_tokenizer = joblib.load("./my_tokenizer.pkl")

# 对一个新的词进行 one-hot 编码
word = "李宗盛"
if word in loaded_tokenizer.word_index:
    one_hot = [0] * len(loaded_tokenizer.word_index)
    idx = loaded_tokenizer.word_index[word] - 1
    one_hot[idx] = 1
    print(f"{word} 的 one-hot 编码: {one_hot}")
else:
    print(f"{word} 不在词汇表中")
```

**注意事项**：

- `Tokenizer` 的索引从 1 开始，0 通常保留给填充（padding）或未知词。
- 如果查询未在词汇表中注册的词，`word_index` 会抛出 `KeyError`，需要预先处理。
- 由于字典（`vocabs`）无序，生成的 one-hot 编码顺序可能不同，但不影响语义（只是维度顺序重排）。

---

#### 3.2.4 常见问题与改进

- **维度爆炸**：当词汇表很大（如 100k）时，one-hot 向量长度为 100k，非常稀疏且浪费。解决方法：使用**稠密向量**（Word2Vec 等）。
- **无语义相似度**：“苹果”和“香蕉”的 one-hot 点积为 0，无法反映它们都是水果。稠密向量可以通过训练让相似词在空间中接近。

---

### 3.3 Word2Vec 模型

#### 3.3.1 概念与核心思想

**Word2Vec** 是一种将单词转换为**稠密词向量**（Dense Word Vector）的技术。它利用浅层神经网络，在大规模无标注语料上以**自监督**方式学习单词之间的语义关系。其核心思想是：**语义相近的单词在上下文分布上也相似**。训练完成后，神经网络的权重参数就被用作词向量。

**两大训练方式**：

- **CBOW**（Continuous Bag of Words）：根据上下文（周围词）预测当前词（中心词）。
- **Skip-gram**：根据当前词（中心词）预测上下文（周围词）。

---

#### 3.3.2 CBOW 方式详解

**原理**：用上下文词的向量求和或平均作为输入，通过一个神经网络预测中心词。

**数学形式**：  
设上下文窗口大小为 $2m$（左右各 $m$ 个词），上下文词为 $w_{t-m}, ..., w_{t-1}, w_{t+1}, ..., w_{t+m}$。CBOW 的目标是最大化：

$$
P(w_t \mid w_{t-m}, ..., w_{t-1}, w_{t+1}, ..., w_{t+m})
$$

通常，先将上下文词的词向量（从嵌入矩阵中查找）进行平均得到 $\mathbf{h}$，然后通过 softmax 输出：

$$
\mathbf{h} = \frac{1}{2m} \sum_{j \neq 0} \mathbf{v}_{w_{t+j}}
$$

$$
P(w_t \mid \text{context}) = \frac{\exp(\mathbf{u}_{w_t}^\top \mathbf{h})}{\sum_{v \in V} \exp(\mathbf{u}_v^\top \mathbf{h})}
$$

其中 $\mathbf{v}_w$ 是输入词向量，$\mathbf{u}_w$ 是输出词向量。

**示例**：句子 `"Hope can set you free"`，窗口大小为 3（即 $m=1$）。第一个训练样本：

- 上下文词：`Hope` 和 `set`
- 中心词：`can`

---

#### 3.3.3 Skip-gram 方式详解

**原理**：与 CBOW 相反，用当前词预测其上下文词。

**数学形式**：

最大化：

$$
P(w_{t-m}, ..., w_{t-1}, w_{t+1}, ..., w_{t+m} \mid w_t) = \prod_{-m \leq j \leq m, j \neq 0} P(w_{t+j} \mid w_t)
$$

其中 $P(w_{t+j} \mid w_t) = \frac{\exp(\mathbf{u}_{w_{t+j}}^\top \mathbf{v}_{w_t})}{\sum_{v \in V} \exp(\mathbf{u}_v^\top \mathbf{v}_{w_t})}$。

**示例**：同样句子 `"Hope can set you free"`，窗口大小 3，第一个训练样本：

- 输入（中心词）：`can`
- 输出（上下文词）：`Hope` 和 `set`

---

#### 3.3.4 CBOW 与 Skip-gram 对比

| 特性 | CBOW | Skip-gram |
|------|------|------------|
| 预测方向 | 上下文 → 中心词 | 中心词 → 上下文 |
| 训练速度 | 较快（尤其在大语料上） | 较慢（每个样本产生多个预测） |
| 对低频词效果 | 较差 | 较好 |
| 常用场景 | 词向量训练效率优先 | 需要高质量词向量，尤其低频词 |
| 内存占用 | 较小 | 较大（需存储更多梯度） |

---

#### 3.3.5 Word2Vec 的训练加速技巧

##### 3.3.5.1 负采样（Negative Sampling）

传统 Softmax 计算量过大（需遍历整个词汇表），Word2Vec 实际训练时使用**负采样**（Negative Sampling）加速。其目标函数变为：

$$
\mathcal{L} = \log \sigma(\mathbf{u}_{w}^\top \mathbf{v}_c) + \sum_{i=1}^{k} \mathbb{E}_{w_i \sim P_n(w)} \log \sigma(- \mathbf{u}_{w_i}^\top \mathbf{v}_c)
$$

其中 $\sigma$ 为 sigmoid 函数， $k$ 为负样本数量（通常 5~20）， $P_n(w)$ 为噪声分布（常用词频的 3/4 次方）。

**作用**：将多分类问题转化为二分类问题（判断中心词与上下文词是否共现），大幅降低计算复杂度。

##### 3.3.5.2 子采样（Subsampling）

高频词（如“的”、“了”）对词向量贡献很小，但出现过多。Word2Vec 以概率 $P(w)$ 丢弃高频词：

$$
P(w) = 1 - \sqrt{\frac{t}{f(w)}}
$$

其中 $f(w)$ 是词的频率， $t$ 为阈值（常用 $10^{-5}$ ）。**效果**：加速训练并改善低频词的向量质量。

##### 3.3.5.3 动态窗口

训练时，对于每个中心词，实际上下文窗口大小 $m'$ 从 $[1, m]$ 中随机采样。这可以模拟不同距离的上下文，使近处的词被采样的概率略高，但总体上保持灵活性。

---

#### 3.3.6 使用 FastText 训练 Word2Vec 词向量

**FastText** 是 Facebook 开源的 NLP 工具库，不仅支持 Word2Vec 的 CBOW 和 Skip-gram，还引入了子词（subword）信息，能够生成未登录词的向量。

**安装**：

- Linux/Mac: `pip install fasttext`
- Windows: `pip install fasttext-wheel`

**数据准备**：使用维基百科语料（经过预处理后的 `fil9` 文件，每行一个句子）。

**训练 CBOW 模型**：

```python
import fasttext

def train_cbow():
    # 训练无监督词向量
    model = fasttext.train_unsupervised(
        'data/fil9',          # 训练文件路径
        model='cbow',         # 使用 CBOW 模式（默认是 skipgram）
        ws=5,                 # 上下文窗口大小
        dim=4,                # 词向量维度（为演示设小值，实际常用 100-300）
        epoch=5               # 迭代轮数
    )
    # 保存模型
    model.save_model('model/cbow_fasttext_model.bin')
    print("CBOW 模型训练完成并保存")

def test_cbow():
    model = fasttext.load_model('model/cbow_fasttext_model.bin')
    # 获取词向量
    vec = model.get_word_vector('music')
    print("music 的词向量:", vec)
    # 查找最相似的词
    neighbors = model.get_nearest_neighbors('music', k=5)
    print("与 music 最相似的词:", neighbors)

if __name__ == '__main__':
    train_cbow()
    test_cbow()
```

**训练 Skip-gram 模型**：

```python
def train_skipgram():
    model = fasttext.train_unsupervised(
        'data/fil9',
        model='skipgram',     # 明确指定 skipgram
        ws=5,
        dim=4,
        epoch=5
    )
    model.save_model('model/skipgram_fasttext_model.bin')

def test_skipgram():
    model = fasttext.load_model('model/skipgram_fasttext_model.bin')
    print("music 的词向量:", model.get_word_vector('music'))
    print("最相似的词:", model.get_nearest_neighbors('music', k=5))
```

**注意事项**：

- 实际使用时，`dim` 应设为 100~300，`epoch` 为 5~10，语料尽可能大（几百万句子）。
- `get_nearest_neighbors` 返回 `(相似度, 词)` 的列表，相似度用余弦相似度衡量。
- FastText 自动将句子中的标点符号视为词的一部分，可能需要预处理。

#### 3.3.7 Word2Vec 的常见问题

**Q1: 如何处理未在训练语料中出现的词（OOV）？**  

- 对于 FastText，由于使用了子词（n-gram 字符），可以生成 OOV 词的近似向量。
- 对于标准 Word2Vec，通常无法处理 OOV，可以将 OOV 映射为 \<UNK> 的向量，或者使用随机初始化。

**Q2: 窗口大小如何影响词向量？**  

- 小窗口（2-5）更关注句法相似性（如词性相近的词）。
- 大窗口（5-10）更关注语义相似性（如同义词）。

**Q3: Word2Vec 训练出来的向量是静态的吗？**  

- 是的。一旦训练完成，每个词对应的向量是固定的，不会随上下文变化，因此无法处理一词多义（如“bank”可以指银行或河岸）。这是静态词向量的局限性。

---

### 3.4 Word Embedding（词嵌入）

#### 3.4.1 广义与狭义概念

- **广义的 Word Embedding**：所有将词汇映射到**稠密向量空间**的方法的统称。包括 Word2Vec、GloVe、FastText，以及深度神经网络中的嵌入层。
- **狭义的 Word Embedding**：特指在深度神经网络中作为一个**可训练层**（如 `torch.nn.Embedding`）的词向量表示。该层的参数会随模型训练任务一起更新，是**动态的**。

---

#### 3.4.2 与 Word2Vec 的异同

| 维度 | Word2Vec | 狭义 Word Embedding (nn.Embedding) |
|------|----------|-------------------------------------|
| 训练方式 | 无监督（独立训练） | 有监督（作为模型的一部分，随目标任务训练） |
| 向量是否固定 | 静态（训练后不再变化） | 动态（随模型训练不断更新） |
| 使用流程 | 两步：先预训练词向量，再输入模型 | 一步：直接作为网络第一层，端到端训练 |
| 能否处理 OOV | 通常不能（FastText 除外） | 随机初始化或映射到 <UNK> |
| 典型应用 | 传统 NLP 任务、迁移学习 | 深度学习模型（CNN、RNN、Transformer） |

**示例**（PyTorch 中的嵌入层）：

```python
import torch
import torch.nn as nn

# 定义一个嵌入层：词汇表大小 20，每个词向量维度 8
embedding = nn.Embedding(num_embeddings=20, embedding_dim=8)

# 假设输入是 3 个词的索引（batch_size=1, seq_len=3）
input_indices = torch.tensor([2, 5, 12])   # 词索引
output_vectors = embedding(input_indices)  # shape: (3, 8)
print(output_vectors.shape)
print(embedding.weight.data.shape)          # (20, 8)
```

**特点**：

- 嵌入层的权重矩阵在训练过程中会通过反向传播自动更新。
- 可以与其他网络层（如 LSTM、Linear）无缝连接。

---

#### 3.4.3 为什么需要 Word Embedding？

- **语义表示**：稠密向量可以捕捉词之间的相似关系（如余弦相似度）。
- **降维**：从 one-hot 的高维稀疏（几万维）降到几十到几百维，降低计算开销。
- **可训练**：嵌入层可以针对特定任务优化，使得词向量更适配任务（如情感分析）。

---

### 3.5 其他主流词向量表示方法

| 方法 | 核心思想 | 特点 | 适用场景 |
|------|----------|------|----------|
| **GloVe** | 基于全局词共现矩阵，构造损失函数（矩阵分解） | 训练速度快，能捕捉线性关系（如 king – man + woman ≈ queen） | 中等规模语料，需要权衡统计信息与上下文 |
| **FastText** | 在 Word2Vec 基础上引入子词（n-gram 字符） | 可生成 OOV 词向量，适合形态丰富语言 | 中文、德语等，或存在大量专有名词的任务 |
| **ELMo** | 双向 LSTM 生成动态词向量（上下文相关） | 解决一词多义问题 | 复杂语义任务，但有更高计算成本 |
| **BERT 词向量** | 从预训练 Transformer 的中间层提取向量 | 动态、深度上下文表示 | 几乎所有现代 NLP 任务（但需微调） |

**补充**：笔记中已提到 FastText 的子词特性，此处强调其与标准 Word2Vec 的区别。

---

### 3.6 总结速查表（第三部分）

| 表示方法 | 类型 | 维度 | 是否稠密 | 语义相似度 | 是否可训练 | 典型应用 |
|----------|------|------|----------|------------|------------|----------|
| **One-hot** | 稀疏 | \|V\| | 否 | 无 | 否 | 分类标签（Y） |
| **Word2Vec (CBOW/Skip-gram)** | 稠密 | 100-300 | 是 | 余弦相似度 | 无监督预训练 | 静态词向量，迁移学习 |
| **Word Embedding (nn.Embedding)** | 稠密 | 可指定 | 是 | 随任务学习 | 端到端训练 | 深度学习模型第一层 |

**Word2Vec 两种训练方式对比**：

| 方式 | 输入 | 输出 | 训练速度 | 低频词效果 |
|------|------|------|----------|------------|
| CBOW | 上下文词向量平均 | 中心词 | 快 | 较差 |
| Skip-gram | 中心词向量 | 上下文词 | 慢 | 较好 |

**常见选择题知识点**：

1. One-hot 编码中，n 个类别 → n 维向量。
2. 维度爆炸通常出现在分类变量取值较多时。
3. CBOW 和 Skip-gram 的区别在于预测方向（上下文→中心词 vs 中心词→上下文）。
4. 窗口大小决定上下文范围。
5. 未见过词的处理：使用最接近的已知单词的向量（或 FastText 子词方法）。

## 第四部分：文本特征处理与数据增强方法

在完成分词、实体识别、词性标注以及文本张量表示之后，文本预处理流程还包含两个重要环节：**文本特征处理**（如 n-gram 特征、特征选择、长度规范等）和**数据增强方法**（提升模型的泛化能力和鲁棒性）。本部分基于工业界和学术界的常见实践进行补充。

---

### 4.1 文本特征处理

#### 4.1.1 特征处理的目標

将文本的原始形式（词序列、词向量序列）转换为模型更容易学习的特征表示。包括：

- 特征构建（如 n-gram、TF-IDF）
- 特征选择（卡方检验、信息增益等）
- 特征缩放与归一化（对于数值型特征）
- 序列长度规范化（padding / truncation）

---

#### 4.1.2 常用特征构建方法

| 方法 | 描述 | 适用场景 |
|------|------|----------|
| **Bag-of-Words (BoW)** | 统计每个词在文档中出现的次数，忽略词序 | 主题分类、情感分析 |
| **TF-IDF** | 词频（TF）乘以逆文档频率（IDF），降低常见词权重 | 信息检索、关键词提取 |
| **n-gram 特征** | 将连续的 n 个词作为一个特征单元，保留局部顺序 | 机器翻译、拼写纠错 |
| **词性标签特征** | 使用 POS 标签作为额外特征 | 句法分析、命名实体识别 |
| **位置特征** | 记录词在句子中的绝对或相对位置 | Transformer 位置编码、序列标注 |

**TF-IDF 数学公式**：

$$
\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \text{IDF}(t, D)
$$

其中：

- $\text{TF}(t, d) = \frac{\text{词 } t \text{ 在文档 } d \text{ 中出现的次数}}{\text{文档 } d \text{ 的总词数}}$
- $\text{IDF}(t, D) = \log \frac{\text{语料库 } D \text{ 中的文档总数}}{1 + |\{d \in D : t \in d\}|}$

**代码示例：使用 sklearn 提取 TF-IDF 特征**

```python
from sklearn.feature_extraction.text import TfidfVectorizer

corpus = [
    "我喜欢自然语言处理",
    "自然语言处理是人工智能的重要方向",
    "机器学习也是人工智能的一部分"
]

vectorizer = TfidfVectorizer(token_pattern=r"(?u)\b\w+\b")
tfidf_matrix = vectorizer.fit_transform(corpus)
print("词汇表:", vectorizer.get_feature_names_out())
print("TF-IDF 矩阵形状:", tfidf_matrix.shape)  # (3, len(vocab))
print("第一篇文章的 TF-IDF 向量:", tfidf_matrix[0].toarray())
```

---

#### 4.1.3 序列长度规范化（Padding / Truncation）

对于使用循环神经网络或 Transformer 的模型，一个批次（batch）内的所有序列需要具有相同的长度。处理策略：

- **截断（Truncation）**：将超过设定最大长度的序列截断（从左、右或中间）。
- **填充（Padding）**：将短于设定长度的序列用特殊符号（如 `<PAD>`）填充。
- **动态批处理**：每个批次内的序列按该批次的最长长度填充，减少计算浪费。

**代码示例（使用 PyTorch 和 HuggingFace Tokenizer）**：

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
sentences = ["Hello world", "This is a much longer sentence for testing"]

# 填充到该批次最大长度，并截断到 10 个 token
encoding = tokenizer(
    sentences,
    padding=True,          # 填充到批次内最长句子的长度
    truncation=True,       # 超过 max_length 则截断
    max_length=10,
    return_tensors="pt"
)
print("input_ids shape:", encoding["input_ids"].shape)   # (2, 10)
print("attention_mask:\n", encoding["attention_mask"])   # 1 表示真实 token，0 表示填充
```

---

#### 4.1.4 特征选择与降维

当特征维度很高时（如 BoW 特征可能有几万维），可以进行特征选择：

- **基于频率**：移除出现次数过少或过多的词（如停用词）。
- **基于统计检验**：卡方检验、信息增益，选择与类别标签最相关的特征。
- **嵌入方法**：使用 L1 正则化（Lasso）或树模型的特征重要性。

### 4.2 数据增强方法

数据增强旨在从有限的原始数据中生成更多变体，提升模型的泛化能力和鲁棒性，尤其在小样本或类别不平衡场景下非常有效。

---

#### 4.2.1 常见文本数据增强技术

| 方法 | 描述 | 示例 |
|------|------|------|
| **同义词替换** | 随机将句子中的某些词替换为同义词 | “这部电影很棒” → “这部电影出色” |
| **随机插入** | 在句子中随机插入一个词（常为同义词或停用词） | “今天天气好” → “今天天气真的很好” |
| **随机交换** | 随机交换句子中两个词的位置 | “我吃苹果” → “苹果吃我”（需谨慎，可能改变语义） |
| **随机删除** | 以一定概率随机删除句子中的词 | “我喜欢看电影” → “喜欢电影” |
| **回译（Back Translation）** | 将文本翻译成另一种语言，再翻译回原语言 | 中→英→中，生成语义相似但表达不同的文本 |
| **句子打乱（Shuffle）** | 对于多句文本，打乱句子顺序（适用于顺序无关任务） | 文档摘要、主题分类 |
| **生成式增强** | 使用预训练模型（如 T5、GPT）生成相似文本 | 条件生成，保留标签语义 |

---

#### 4.2.2 回译增强的代码示例（使用 HuggingFace 翻译模型）

```python
from transformers import MarianMTModel, MarianTokenizer

# 加载中文到英文的翻译模型
zh_en_model_name = "Helsinki-NLP/opus-mt-zh-en"
zh_en_tokenizer = MarianTokenizer.from_pretrained(zh_en_model_name)
zh_en_model = MarianMTModel.from_pretrained(zh_en_model_name)

# 加载英文到中文的翻译模型
en_zh_model_name = "Helsinki-NLP/opus-mt-en-zh"
en_zh_tokenizer = MarianTokenizer.from_pretrained(en_zh_model_name)
en_zh_model = MarianMTModel.from_pretrained(en_zh_model_name)

def back_translate(text, src_lang="zh", mid_lang="en"):
    # 中文 -> 英文
    inputs = zh_en_tokenizer(text, return_tensors="pt", truncation=True)
    translated = zh_en_model.generate(**inputs)
    english = zh_en_tokenizer.decode(translated[0], skip_special_tokens=True)
    
    # 英文 -> 中文
    inputs = en_zh_tokenizer(english, return_tensors="pt", truncation=True)
    back_translated = en_zh_model.generate(**inputs)
    chinese = en_zh_tokenizer.decode(back_translated[0], skip_special_tokens=True)
    return chinese

original = "这家餐厅的菜很好吃，环境也很优雅。"
augmented = back_translate(original)
print("原始:", original)
print("增强:", augmented)
```

**注意事项**：

- 回译可能会轻微改变语义，对于情感、意图等敏感任务需要人工校验。
- 翻译模型的质量直接影响增强效果，建议使用高质量的多语言模型（如 mBART、M2M-100）。

#### 4.2.3 使用 NLPAug 库快速实现多种增强

[NLPAug](https://github.com/makcedward/nlpaug) 是一个专为 NLP 设计的增强库。

```python

```

#### 4.2.4 高级数据增强技术（EDA、生成式增强、MixUp）

##### 4.2.4.1 EDA (Easy Data Augmentation)

来自论文 [EDA: Easy Data Augmentation for Boosting Performance on Text Classification Tasks](https://arxiv.org/abs/1901.11196)，包含四种操作：

- 同义词替换（SR）
- 随机插入（RI）
- 随机交换（RS）
- 随机删除（RD）

作者建议：对于短文本（n ≤ 10），修改约 10% 的词；对于长文本（n > 10），修改约 25% 的词。

##### 4.2.4.2 基于预训练生成模型的增强

使用 T5、GPT-2 等模型，以原始文本为条件生成相似但不同的文本。例如：

```python
from transformers import pipeline

generator = pipeline('text-generation', model='uer/gpt2-chinese-lyric')
text = "这家餐厅很棒"
augmented = generator(text, max_length=50, num_return_sequences=3)
```

##### 4.2.4.3 MixUp for Text

在输入嵌入空间进行线性插值： $\tilde{x} = \lambda x_i + (1-\lambda) x_j$ ，标签同样插值。适用于文本分类，需要模型支持软标签。

---

#### 4.2.5 数据增强的适用场景与注意事项

| 场景 | 是否推荐增强 | 说明 |
|------|--------------|------|
| 数据量充足（>10 万） | 可选，增益不明显 | 模型已见过足够多样性 |
| 小样本（<1000） | 强烈推荐 | 大幅提升泛化能力 |
| 类别不平衡 | 对少数类增强 | 缓解过拟合少数类 |
| 序列标注任务（NER、POS） | 需谨慎 | 词替换可能破坏标签对齐，需保持标签一致性 |
| 机器翻译 | 常用回译 | 可视为额外的平行语料 |

**关键原则**：增强后的数据不应改变原始标签或语义（对于分类任务）。例如，“我喜欢这部电影” 增强为 “我讨厌这部电影” 会错误地将正面情感变成负面。

---

### 4.3 预处理完整流程总结

回顾整个文本预处理环节，通常按以下顺序进行：

1. **文本清洗**：去除 HTML 标签、特殊字符、统一大小写、转码等。
2. **文本语料的数据分析**：统计长度分布、标签分布、词频等，为后续设置超参数（如 max_len）提供依据。
3. **分词**：使用 jieba 等工具将句子切分为词序列。
4. **特征处理**：
   - 可选：去停用词、词形还原/词干提取。
   - 长度规范：padding / truncation 到统一长度。
5. **文本张量表示**：
   - 将词映射为索引（构建词汇表）。
   - 转换为 one-hot 或嵌入向量（Word2Vec 或 nn.Embedding）。
6. **数据增强**：对训练集进行扩充（可选，尤其在数据不足时）。
7. **构建数据集**：组织成 `(input_ids, attention_mask, label)` 格式供模型使用。

| 插入/删除/交换 | `nlpaug.augmenter.word.RandomWordAug` | 轻度扰动提升鲁棒性 |

### 5.1 构建词汇表（Vocabulary Building）

词汇表是将原始文本中的词映射到唯一整数索引的映射表。构建词汇表的一般步骤：

1. **收集语料**：读取所有训练文本，进行分词。
2. **统计词频**：统计每个词在语料中出现的总次数。
3. **设定阈值**：决定保留哪些词（如只保留出现次数 ≥ 2 的词，或按频率百分比截断）。
4. **分配索引**：为每个保留的词分配一个唯一的整数编号（通常从 0 或 1 开始），并加入特殊符号：
   - `<PAD>`：填充符号，索引常为 0。
   - `<UNK>`：未知词（未登录词），索引固定（如 1）。
   - `<BOS>` / `<EOS>`：序列开始/结束符号（用于生成任务）。
   - `<SEP>`：分隔符（BERT 等模型使用）。

**代码示例：手动构建词汇表**

```python
from collections import Counter
import jieba

def build_vocab(texts, min_freq=2, special_tokens=['<PAD>', '<UNK>']):
    # 1. 分词并统计词频
    word_counter = Counter()
    for text in texts:
        words = jieba.lcut(text)
        word_counter.update(words)
    
    # 2. 过滤低频词
    vocab = {word: idx+len(special_tokens) for idx, (word, freq) in enumerate(word_counter.items()) if freq >= min_freq}
    
    # 3. 添加特殊 token
    for token in reversed(special_tokens):   # 反转使 <PAD> 索引为 0
        vocab[token] = len(vocab)
    return vocab

# 示例语料
corpus = [
    "我喜欢自然语言处理",
    "自然语言处理是人工智能的重要方向",
    "机器学习也是人工智能的一部分"
]
vocab = build_vocab(corpus, min_freq=1)
print("词汇表:", vocab)
# 输出可能为: {'<PAD>': 0, '<UNK>': 1, '自然语言处理': 2, '人工智能': 3, ...}
```


### 5.2 处理未登录词（OOV）

**未登录词**是指测试或推理时遇到的、在训练词汇表中不存在的词。

**常见解决策略**：

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| **映射到 `<UNK>` ** | 将所有 OOV 词用一个统一符号代替 | 简单、快速，但丢失语义信息 |
| **子词分词（BPE/WordPiece）** | 将 OOV 拆解为子词，如 `"playing"` → `["play", "##ing"]` | 现代预训练模型（BERT、GPT） |
| **字符级或 n-gram 回退** | 当词不在词汇表时，使用字符级嵌入或 n-gram 特征 | 形态丰富语言（阿拉伯语、土耳其语） |
| **FastText 子词向量** | 利用字符 n-gram 之和表示 OOV 词 | 需要对 OOV 给出有意义的向量 |
| **动态插入** | 在推理时动态更新词汇表（如翻译系统遇到新实体） | 特定领域应用（如医疗、法律） |

**FastText 处理 OOV 示例**：

```python
import fasttext
model = fasttext.load_model("model/cbow_fasttext_model.bin")
oov_word = "transformer"
vec = model.get_word_vector(oov_word)   # 即使 oov_word 不在训练词表中，也能得到向量
print(f"'{oov_word}' 的向量长度:", len(vec))
```

### 5.3 流式数据预处理与惰性求值

当语料非常大（超过内存）时，应使用迭代器或生成器逐个处理文本，而不是一次性将所有数据加载到内存。

**代码示例：使用生成器逐条预处理**

```python
def text_stream(file_path):
    with open(file_path, 'r', encoding='utf-8') as f:
        for line in f:
            yield line.strip()

def preprocess_stream(stream, tokenizer, max_len=128):
    for text in stream:
        # 分词、清洗等操作
        tokens = tokenizer(text, truncation=True, max_length=max_len)
        yield tokens

# 使用
stream = text_stream("large_corpus.txt")
processed = preprocess_stream(stream, tokenizer)
for i, batch in enumerate(processed):
    if i >= 10:   # 只处理前 10 条作为演示
        break
    print(batch)
```

**使用 PyTorch 的 `DataLoader` + `IterableDataset` **：

```python
from torch.utils.data import IterableDataset, DataLoader

class TextIterableDataset(IterableDataset):
    def __init__(self, file_path, tokenizer, max_len):
        self.file_path = file_path
        self.tokenizer = tokenizer
        self.max_len = max_len

    def __iter__(self):
        with open(self.file_path, 'r', encoding='utf-8') as f:
            for line in f:
                yield self.tokenizer(line.strip(), truncation=True, max_length=self.max_len)

dataset = TextIterableDataset("large_corpus.txt", tokenizer, max_len=128)
dataloader = DataLoader(dataset, batch_size=32)
for batch in dataloader:
    # 处理 batch
    break
```

```python
import joblib
```

### 5.5 预处理效果的评估

预处理过程可能出错或引入偏差，需要评估其质量：

| 评估维度 | 方法 | 目标 |
|----------|------|------|
| **分词准确率** | 人工标注小样本，计算分词与标准结果的 F1 | 确保分词工具符合任务需求 |
| **OOV 覆盖率** | 统计验证集中 OOV 词的比例 | OOV 率越低越好（< 5%） |
| **标签对齐**（用于 NER/POS） | 检查数据增强或预处理是否破坏了标签边界 | 保持标签与 token 一一对应 |
| **长度分布一致性** | 可视化训练集和验证集的长度分布 | 避免训练集与验证集分布偏移 |

**分词评估示例（使用 jieba 与人工标注对比）**：

```python
import jieba

def evaluate_segmentation(pred_words, true_words):
    # 将词序列转换为字符级别的 BIES 标签，然后计算精确率、召回率
    # 为简化，此处用集合的 Jaccard 相似度作为粗略指标
    pred_set = set(pred_words)
    true_set = set(true_words)
    jaccard = len(pred_set & true_set) / len(pred_set | true_set)
    return jaccard

true_seg = ["传智教育", "是", "一家", "上市公司"]
pred_seg = jieba.lcut("传智教育是一家上市公司", cut_all=False)
print("Jaccard:", evaluate_segmentation(pred_seg, true_seg))
```

### 5.6 完整预处理 Pipeline（PyTorch + HuggingFace 示例）

以下代码构建了一个端到端的文本预处理流水线，适用于中文文本分类任务：

```python
import torch
from torch.utils.data import Dataset, DataLoader
from transformers import AutoTokenizer
import jieba

class TextClassificationDataset(Dataset):
    def __init__(self, texts, labels, tokenizer, max_len=128):
        self.texts = texts
        self.labels = labels
        self.tokenizer = tokenizer
        self.max_len = max_len

    def __len__(self):
        return len(self.texts)

    def __getitem__(self, idx):
        text = str(self.texts[idx])
        label = self.labels[idx]
        # 使用 jieba 先分词（可选；如果 tokenizer 是基于词的，可以保留）
        # words = jieba.lcut(text)
        # text = " ".join(words)   # 对于子词 tokenizer 通常不需要预分词
        
        encoding = self.tokenizer(
            text,
            truncation=True,
            padding='max_length',
            max_length=self.max_len,
            return_tensors='pt'
        )
        return {
            'input_ids': encoding['input_ids'].flatten(),
            'attention_mask': encoding['attention_mask'].flatten(),
            'label': torch.tensor(label, dtype=torch.long)
        }

# 使用预训练中文 BERT tokenizer
tokenizer = AutoTokenizer.from_pretrained("bert-base-chinese")

# 示例数据
train_texts = ["我喜欢这部电影", "非常糟糕的体验", "绝对值得一看"]
train_labels = [1, 0, 1]   # 1: 正面, 0: 负面

dataset = TextClassificationDataset(train_texts, train_labels, tokenizer)
dataloader = DataLoader(dataset, batch_size=2)

for batch in dataloader:
    print("input_ids shape:", batch['input_ids'].shape)
    print("label:", batch['label'])
    break
```

**流水线包含的步骤**：

1. 原始文本输入。
2. （可选）使用 jieba 进行中文分词。
3. Tokenizer 将文本转换为 subword tokens，并自动完成截断、填充、生成 attention mask。
4. 组装成 PyTorch Dataset 和 DataLoader。
5. 送入模型训练。

### 5.7 常见预处理错误与调试技巧

| 错误现象 | 可能原因 | 解决方法 |
|----------|----------|----------|
| `RuntimeError: CUDA out of memory` | 序列太长或 batch 太大 | 减小 `max_len` 或 `batch_size` |
| 模型预测结果全为同一类 | 标签处理错误（如标签编码从 1 开始而非 0） | 检查 `label` 的值域，使用 `LabelEncoder` |
| 验证集损失不下降 | 预处理不一致（如训练和验证使用了不同的 tokenizer） | 确保使用同一个 tokenizer 对象 |
| 词向量找不到某些词 | OOV 未映射到 `<UNK>` | 设置 `unk_token` 或使用子词分词 |
| 分词后标点符号丢失 | tokenizer 默认忽略标点 | 设置 `tokenizer` 的 `do_lower_case=False` 或自定义预处理 |

**调试技巧**：

- 在将数据送入模型前，打印一个样本的 `input_ids` 和 `attention_mask`，人工检查是否合理。
- 使用 `tokenizer.decode(input_ids)` 查看还原后的文本，验证截断/填充是否正确。
- 对于序列标注任务，确保标签序列与 token 序列长度一致（考虑子词分词会分裂 token）。

### 5.8 预处理对模型性能影响的评估方法

| 评估方面 | 方法 | 预期效果 |
|----------|------|----------|
| **分词质量** | 对比不同分词器（jieba、HanLP、LTP）在同一下游任务上的 F1 | 更准确的分词应带来更高分数 |
| **停用词过滤** | 有/无停用词过滤的 A/B 测试 | 通常能提升分类精度，但对短文本可能有害 |
| **最大长度截断** | 绘制不同 max_len 的验证曲线 | 选择能覆盖 90% 样本的长度 |
| **数据增强** | 训练集 + 增强后 vs 仅原始数据 | 如果增强有效，验证集损失应更低且泛化更好 |

**实践中**：建议始终保留一小部分原始验证集（不参与任何增强），用于公平对比。

### 5.9 常见面试/考试题补充

**Q1：为什么 Word2Vec 需要两个词向量矩阵（输入和输出）？**  
A：训练完成后，通常只取输入矩阵作为词向量。两个矩阵的设计是为了简化梯度计算，且对称形式可使优化更稳定。

**Q2：CBOW 为什么比 Skip-gram 训练快？**  
A：CBOW 每次用一个平均向量预测一个中心词，产生一个 softmax 误差；Skip-gram 每个样本要预测 2m 个上下文词，产生 2m 个误差，反向传播次数更多。

**Q3：如何处理类别不平衡下的文本数据？**  
A：预处理阶段可采用过采样少数类（如回译增强）、欠采样多数类，或在损失函数中加入类别权重。

**Q4：BERT 的 tokenizer 与 jieba 分词有何不同？**  
A：BERT 使用 WordPiece 子词分词，不依赖词典匹配，能自动处理未登录词；jieba 是基于词典的全局分词。二者可结合（先 jieba 分词再对每个词做子词切分，但通常直接使用 BERT tokenizer 即可）。
