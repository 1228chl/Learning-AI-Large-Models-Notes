# 3. 进阶模型定义 `PhonePriceModelAdvanced`

该类继承自 `nn.Module`，构建了一个带 **批归一化** 和 **Dropout** 的全连接网络，并使用了 **Kaiming 均匀初始化**。

## 3.1 构造函数 `__init__`

```python
def __init__(self, input_dim, output_dim, hidden_dims=[128,256], dropout_rate=0.3):
    super(PhonePriceModelAdvanced, self).__init__()
    self.fc1 = nn.Linear(input_dim, hidden_dims[0])
    self.bn1 = nn.BatchNorm1d(hidden_dims[0])
    self.dropout1 = nn.Dropout(dropout_rate)

    self.fc2 = nn.Linear(hidden_dims[0], hidden_dims[1])
    self.bn2 = nn.BatchNorm1d(hidden_dims[1])
    self.dropout2 = nn.Dropout(dropout_rate)

    self.out = nn.Linear(hidden_dims[1], output_dim)

    self._initialize_weights()
```

**参数说明**：

- `input_dim`：输入特征数（数据集中为 20）。
- `output_dim`：输出类别数（本例为 4）。
- `hidden_dims`：列表，指定每一隐藏层的神经元数量，默认为 `[128, 256]`。注意：此代码只使用了前两个值（`hidden_dims[0]` 和 `hidden_dims[1]`），后面主程序中传入 `[128,256,512,128]` 却只用了前两个，**这是一个潜在的 bug**（后面会详细说明）。
- `dropout_rate`：Dropout 概率，默认为 0.3，表示随机将 30%的神经元输出置为 0。

**网络结构**：

1. **第一全连接层** `fc1`：`input_dim` → `hidden_dims[0]`（如 128）
2. **批归一化** `bn1`：对 `fc1` 的输出（batch_size, 128）进行归一化（使每批数据的每个通道均值为 0、方差为 1）
3. **ReLU 激活**（在 `forward` 中实现）
4. **Dropout** `dropout1`：随机失活，防止过拟合
5. **第二全连接层** `fc2`：`hidden_dims[0]` → `hidden_dims[1]`（如 256）
6. **批归一化** `bn2`
7. **ReLU 激活**
8. **Dropout** `dropout2`
9. **输出层** `out`：`hidden_dims[1]` → `output_dim`

**关于** `BatchNorm1d` ：

- 对于全连接层（2D 输入：`[batch_size, feature_dim]`），使用 `BatchNorm1d(feature_dim)`。
- 作用：加速收敛、允许更大的学习率、缓解梯度消失/爆炸、有一定的正则化效果。

**关于** `Dropout` ：

- 训练时随机丢弃一部分神经元的输出，强制网络学习冗余表示，避免共适应（co-adaptation），从而减轻过拟合。
- 验证/测试时 Dropout 自动关闭（通过 `model.eval()` 实现），所有神经元都参与计算，但输出会按比例缩放（PyTorch 自动处理）。

## 3.2 权重初始化 `_initialize_weights`

```python
def _initialize_weights(self):
    for m in self.modules():
        if isinstance(m, nn.Linear):
            nn.init.kaiming_uniform_(m.weight, mode='fan_in', nonlinearity='relu')
            if m.bias is not None:
                nn.init.constant_(m.bias, 0)
```

- 遍历模型的所有子模块（`self.modules()`）。
- 当遇到 `nn.Linear` 层时，使用 **Kaiming 均匀初始化**（也叫 He 初始化）初始化权重。
  - `mode='fan_in'`：保持前向传播时每层的方差大小。
  - `nonlinearity='relu'`：针对 ReLU 激活函数设计的增益因子 `sqrt(2 / fan_in)`。
- 偏置初始化为常数 0。
- 为什么需要手动初始化？PyTorch 默认的初始化在某些深层网络中可能收敛较慢，Kaiming 初始化配合 ReLU 能显著改善梯度流动。

## 3.3 前向传播 `forward`

```python
def forward(self, x):
    x = self.fc1(x)
    x = self.bn1(x)
    x = torch.relu(x)
    x = self.dropout1(x)

    x = self.fc2(x)
    x = self.bn2(x)
    x = torch.relu(x)
    x = self.dropout2(x)

    x = self.out(x)
    return x
```

- 顺序执行：线性变换 → 批归一化 → ReLU → Dropout。
- **注意**：Dropout 放在激活函数之后是常见做法（也有一些变体放在之前，但通常放在激活后）。
- 输出层没有 softmax，因为损失函数 `CrossEntropyLoss` 内部包含了 log-softmax。

# 4. 进阶训练函数 `train_model`

该函数整合了 **学习率调度**、**早停**、**最佳模型保存**、**训练曲线记录** 等功能。

## 4.1 函数签名与参数

```python
def train_model(
        model,
        train_dataset,
        test_dataset,
        batch_size=64,
        lr=0.001,
        weight_decay=1e-4,
        num_epochs=100,
        patience=10):
```

- `model`：待训练的模型实例。
- `train_dataset`, `test_dataset`：PyTorch 的 `Dataset` 对象。
- `batch_size`：批大小，默认 64（基础版为 8，更大的批次可提高训练稳定性）。
- `lr`：初始学习率，默认 0.001。
- `weight_decay`：L2 正则化系数，默认 1e-4，防止过拟合。
- `num_epochs`：最大训练轮数，默认 100。
- `patience`：早停的耐心值，即验证集准确率连续多少个 epoch 不提升就停止训练，默认 10。

## 4.2 数据加载器

```python
train_loader = DataLoader(train_dataset, batch_size=batch_size, shuffle=True)
test_loader = DataLoader(test_dataset, batch_size=batch_size, shuffle=False)
```

- 训练集打乱顺序（`shuffle=True`），测试集不打乱。

## 4.3 损失函数、优化器与调度器

```python
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=lr, weight_decay=weight_decay)
scheduler = optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode='min', factor=0.5, patience=5)
```

- **Adam 优化器**：自适应学习率方法，相比 SGD 通常收敛更快，对超参数不太敏感。
- **ReduceLROnPlateau 调度器**：
  - 当某个指标（此处为 `mode='min'` 的损失）在 `patience=5` 个 epoch 内没有改善时，将学习率乘以 `factor=0.5`。
  - 这有助于在损失平台期时减小步长，帮助模型更精细地收敛。
  - 注意：调度器在验证阶段后调用，此处监控的是 `avg_train_loss`（训练损失），通常应该监控验证损失，但代码中监控训练损失也是可行的，只是不够典型。

## 4.4 记录容器与初始化最佳模型变量

```python
best_test_acc = 0.0
best_epoch = 0
epochs_no_improve = 0

train_losses = []
test_accs = []
```

- 记录每个 epoch 的训练损失和测试准确率，用于后续绘图。
- `best_test_acc` 保存迄今最佳验证准确率。
- `best_epoch` 记录取得最佳准确率的 epoch 编号。
- `epochs_no_improve` 统计连续未提升的 epoch 数。

## 4.5 训练循环

### (1) 训练阶段

```python
model.train()
total_loss = 0.0
for x_batch, y_batch in train_loader:
    optimizer.zero_grad()
    outputs = model(x_batch)
    loss = criterion(outputs, y_batch)
    loss.backward()
    optimizer.step()
    total_loss += loss.item() * x_batch.size(0)
avg_train_loss = total_loss / len(train_dataset)
train_losses.append(avg_train_loss)
```

- `model.train()` 启用 Dropout 和 BatchNorm 的训练模式（BatchNorm 会使用当前批次的均值和方差）。
- 计算平均训练损失（加权平均，按每个批次的实际样本数）。

### (2) 验证阶段

```python
model.eval()
correct = 0
total = 0
with torch.no_grad():
    for x_batch, y_batch in test_loader:
        outputs = model(x_batch)
        _, preds = torch.max(outputs, dim=1)
        correct += (preds == y_batch).sum().item()
        total += y_batch.size(0)
test_acc = correct / total
test_accs.append(test_acc)
```

- `model.eval()` 关闭 Dropout，固定 BatchNorm 的 running 统计量（使用训练时累计的均值和方差）。
- `with torch.no_grad()` 禁用梯度计算，节省内存并加速。

### (3) 学习率调度

```python
scheduler.step(avg_train_loss)
```

- 根据当前平均训练损失调整学习率。如果连续 5 个 epoch 损失没有下降，学习率减半。

### (4) 打印进度

```python
if epoch % 10 == 0 or epoch == 1:
    print(f'Epoch [{epoch}/{num_epochs}], Loss: {avg_train_loss:.4f}, Test Acc: {test_acc:.4f}')
```

- 每 10 个 epoch 或第一个 epoch 打印一次。

### (5) 早停与保存最佳模型

```python
if test_acc > best_test_acc:
    best_test_acc = test_acc
    best_epoch = epoch
    torch.save(model.state_dict(), 'best_phone_model.pth')
    epochs_no_improve = 0
else:
    epochs_no_improve += 1
    if epochs_no_improve >= patience:
        print(f"Early stopping at epoch {epoch}, best test acc: {best_test_acc:.4f} at epoch {best_epoch}")
        break
```

- 如果当前验证准确率超过历史最佳，则保存模型参数，并重置 `epochs_no_improve`。
- 否则，`epochs_no_improve` 加 1。当连续 `patience` 个 epoch 没有提升时，停止训练（早停）。
- 早停可以有效防止过拟合，避免在验证集性能饱和后继续训练浪费资源。

## 4.6 返回结果

```python
model.load_state_dict(torch.load('best_phone_model.pth'))
return model, best_test_acc, train_losses, test_accs
```

- 训练结束后，加载之前保存的最佳模型参数，确保返回的模型是验证集上表现最好的状态。
- 返回模型、最佳准确率、损失历史、准确率历史，供后续分析或绘图使用。

# 6. 进阶技巧详解

## 6.1 批归一化（Batch Normalization）

- **作用**：对每一层的输入（通常是线性层后、激活函数前）进行归一化，使每批数据的分布稳定。
- **好处**：加速收敛（可使用更大学习率）、降低对初始化的敏感、有一定正则化效果（因为引入了噪声）。
- **训练与测试差异**：训练时使用当前批次的均值和方差；测试时使用训练时计算的全局滑动平均值（PyTorch 自动维护）。

## 6.2 Dropout

- **作用**：以概率 `p` 随机将神经元输出置为 0，使得每次迭代网络结构不同，相当于训练了多个子模型的集成。
- **效果**：显著缓解过拟合，尤其当模型参数多、训练数据相对较少时。
- **注意**：仅在训练时启用，测试时需要关闭（`model.eval()`），PyTorch 会自动处理输出缩放。

## 6.3 Kaiming 初始化

- 对于使用 ReLU 及其变体的网络，传统的正态/均匀初始化可能导致梯度爆炸或消失。Kaiming 初始化根据神经元输入数量调整权重的方差，使得激活值的方差在网络中保持稳定。
- 公式：权重从均匀分布 `U(-sqrt(6/fan_in), sqrt(6/fan_in))` 中采样（`mode='fan_in'`）。

## 6.4 学习率调度器 `ReduceLROnPlateau`

- **思想**：当模型性能不再提升时，降低学习率有助于更精细地搜索损失函数的局部最小值。
- **参数**：
  - `mode='min'`：监控的指标下降时认为是改善（此处为损失）。
  - `factor=0.5`：每次降低时将学习率乘以 0.5。
  - `patience=5`：指标连续 5 个 epoch 不改善时才触发。

## 6.5 早停（Early Stopping）

- **动机**：随着训练进行，验证集准确率通常会先上升后下降（过拟合）。早停在验证集性能不再提升时停止训练，避免过拟合，同时节省时间。
- **实现**：记录最佳验证准确率，连续 `patience` 个 epoch 未突破则终止循环。

# 7. 代码中的潜在问题（供读者注意）

1.  `hidden_dims` 未完全使用：模型只用了前两个值，而主程序传入了 4 个值。若要支持多层，需要在 `__init__` 中动态构建模块列表。正确写法示例：

   ```python
   self.layers = nn.Sequential()
   in_dim = input_dim
   for h_dim in hidden_dims:
       self.layers.append(nn.Linear(in_dim, h_dim))
       self.layers.append(nn.BatchNorm1d(h_dim))
       self.layers.append(nn.ReLU())
       self.layers.append(nn.Dropout(dropout_rate))
       in_dim = h_dim
   self.out = nn.Linear(in_dim, output_dim)
   ```

2. **调度器监控的是训练损失**：通常应该监控验证损失（或验证准确率）来决定是否降低学习率，因为训练损失持续下降不代表验证性能提升。但此处使用训练损失也可以工作，只是不如验证损失合理。

3.  `model.eval()` 位置：在循环内每个 batch 前调用 `model.eval()` 是多余的，应该在进入验证循环前调用一次即可。不过多次调用不会出错，仅稍显低效。

4. **最佳模型文件路径**：保存到当前目录 `'best_phone_model.pth'`，与基础版本的 `'model/phone.pth'` 不一致，可能造成混乱。建议统一。
