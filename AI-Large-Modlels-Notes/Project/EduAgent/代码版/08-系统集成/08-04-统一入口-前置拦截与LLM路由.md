## 一、为什么需要两层拦截？

如果没有路由拦截，所有用户输入都走 LLM 判断，浪费 Token：

| 用户输入 | 正确路由 | 拦截方式 |
|:---------|:---------|:---------|
| "你好" | 问候模板 | 规则前置拦截（零 Token） |
| "谢谢" | 感谢模板 | 规则前置拦截（零 Token） |
| "你是谁" | 身份模板 | 规则前置拦截（零 Token） |
| "Transformer 原理是什么" | QA Agent | LLM 路由 |
| "帮我看看简历" | Resume Agent | LLM 路由 |
| "我要找工作" | multi_agent | LLM 路由 |

**规则前置拦截**处理问候/感谢/道别/身份/功能五类高度确定场景，零 Token 消耗。**LLM 路由**处理需要理解语义的复杂场景。

## 二、规则前置拦截（第 75~197 行）

### 2.1 五类关键词

```python
# 精确匹配（frozenset）
_HELLO_KEYWORDS = frozenset(["你好", "您好", "hi", "hello", "在吗", ...])
_THANKS_KEYWORDS = frozenset(["谢谢", "感谢", "辛苦了", "太棒了", "明白了", ...])
_BYE_KEYWORDS = frozenset(["再见", "拜拜", "88", "bye", "下次见", ...])

# 正则匹配（re.compile）
_IDENTITY_RE = re.compile(r"(你|您)(是谁|叫什么|的名字|是什么|是.*AI|是.*机器人|是.*助手) ...", re.IGNORECASE)
_CAPABILITY_RE = re.compile(r"(你|您)(能|可以|会).{0,6}(做|帮|干) ...", re.IGNORECASE)
```

| 类别 | 匹配方式 | 示例 |
|:-----|:---------|:-----|
| 问候 | 精确匹配 `frozenset` | "你好"、"hi"、"在吗" |
| 感谢 | 精确匹配 `frozenset` | "谢谢"、"辛苦了"、"明白了" |
| 道别 | 精确匹配 `frozenset` | "再见"、"bye"、"溜了" |
| 身份询问 | 正则 `re.compile` | "你是谁"、"你叫什么" |
| 功能询问 | 正则 `re.compile` | "你能做什么"、"怎么用" |

**为什么用 `frozenset`？** `frozenset` 的 `in` 操作是 O(1) 哈希查找，`list` 是 O(n) 线性扫描。

### 2.2 `_pre_filter` 函数（第 169~197 行）

```python
def _pre_filter(text: str) -> str | None:
    t = text.strip()
    t_lower = _STRIP_TAIL_RE.sub("", t.lower())   # 去末尾标点
    if t_lower in _HELLO_KEYWORDS: return _REPLY_HELLO
    if t_lower in _THANKS_KEYWORDS: return _REPLY_THANKS
    if t_lower in _BYE_KEYWORDS: return _REPLY_BYE
    if _IDENTITY_RE.search(t): return _REPLY_IDENTITY     # 正则用原文
    if _CAPABILITY_RE.search(t): return _REPLY_CAPABILITY  # 正则用原文
    return None
```

| 行号 | 逻辑 | 说明 |
|:----:|:-----|:------|
| 174 | `t = text.strip()` | 去首尾空白 |
| 175 | `t_lower = _STRIP_TAIL_RE.sub("", t.lower())` | 转小写 + 去末尾标点 |
| 178~186 | 精确匹配三类 | 问候/感谢/道别 |
| 189~194 | 正则匹配两类 | 身份/功能（用原文） |

**`_STRIP_TAIL_RE`**：`re.compile(r"[\s!！?？。~～,.，。]+$")`——"你好！" → "你好"，"拜拜~" → "拜拜"。

## 三、LLM 路由（第 200~287 行）

### 3.1 路由提示词（第 201~214 行）

```python
_ROUTE_PROMPT = """判断用户需求应路由到哪个功能。

可选功能：
- qa          : 技术知识问答（用户直接提问，不涉及文件上传）
- exam        : 试卷/作业批改（需上传 Word 答卷）
- resume      : 简历审查（需上传 PDF 简历）
- interview   : 模拟面试（用户提到"面试""练习面试"等）
- multi_agent : 综合求职准备（用户同时提到简历 + 面试）
- clarify     : 意图不明确，无法判断，需要追问

严格按以下 JSON 格式返回，不要有其他内容：
{{"label": "功能名", "reason": "一句话说明判断依据"}}

用户输入：{message}"""
```

**6 种路由目标**：

| label | 对应 Agent | 执行模式 |
|:------|:-----------|:---------|
| `qa` | QA | SINGLE |
| `exam` | EXAM | SINGLE |
| `resume` | RESUME | SINGLE |
| `interview` | INTERVIEW | SINGLE |
| `multi_agent` | QA（占位） | PIPELINE |
| `clarify` | QA（占位） | CLARIFY |

### 3.2 label 映射表（第 217~234 行）

```python
_LABEL_TO_AGENT = {"qa": AgentType.QA, "exam": AgentType.EXAM, ...}
_LABEL_TO_MODE = {"qa": ExecutionMode.SINGLE, "multi_agent": ExecutionMode.PIPELINE, ...}
_VALID_LABELS = frozenset(_LABEL_TO_AGENT.keys())
```

**`_VALID_LABELS` 校验**：LLM 可能返回不在列表中的非法 label，校验后降级为 `qa`。

### 3.3 `_llm_route` 函数（第 249~287 行）

```python
async def _llm_route(message: str) -> _RouteResult:
    try:
        llm = get_llm("intent", temperature=0)
        resp = await llm.ainvoke([HumanMessage(content=_ROUTE_PROMPT.format(message=message))])
        raw = resp.text.strip()
        parsed = json.loads(raw)
        label = parsed.get("label", "qa").strip().lower()
        reason = parsed.get("reason", "LLM 路由判断")

        if label not in _VALID_LABELS:
            label = "qa"    # 降级
    except Exception as e:
        label = "qa"        # 降级
        reason = "路由判断异常，默认转入智能问答"

    return _RouteResult(label=label, agent_type=_LABEL_TO_AGENT[label],
                        execution_mode=_LABEL_TO_MODE[label], confidence=0.85, reason=reason)
```

| 步骤 | 行号 | 操作 | 说明 |
|:----:|:-----|:-----|:------|
| ① | 261 | `get_llm("intent", temperature=0)` | 路由专用模型，温度 0 求稳定 |
| ② | 262~264 | 调 LLM + 格式化 Prompt | 嵌入用户消息 |
| ③ | 265~266 | 解析 JSON | `resp.text` 提取 |
| ④ | 270~272 | 合法性校验 | 非法 label → 降级 qa |
| ⑤ | 276~278 | 异常降级 | 调用失败 → 降级 qa |

**`confidence=0.85` 固定值**：LLM 路由没有置信度概念，固定值仅供前端展示。

## 五、`★` 设计亮点总结

`★ Insight ─────────────────────────────────────`
**"规则前置 + LLM 路由"两层拦截，兼顾效率和灵活性**：
- 第一层：规则前置，五类场景用 `frozenset` 精确匹配 + 正则，零 Token
- 第二层：LLM 路由，复杂意图用 LLM 分类
- 问候/感谢/道别等场景高度确定，规则就能 100% 命中
- 这种"规则兜底浅层、LLM 处理模糊"的设计，在成本和准确率之间取得平衡
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**`get_llm("intent")` 路由专用模型**：
- 路由任务用 `"intent"` 配置的模型，独立于 QA 的 `"qa"` 和面试的 `"interview"`
- 不同任务可以用不同模型（如路由用更便宜的模型）
- 这是"按任务选择模型"而非"按 Agent 选择模型"的设计
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**`_VALID_LABELS` 校验 + 异常降级 = 两层安全兜底**：
- LLM 可能返回非法 label（如幻觉"xxx_agent"）→ `_VALID_LABELS` 校验降级 qa
- LLM 调用可能异常（网络超时）→ `try/except` 降级 qa
- 两层兜底确保路由永远不崩溃——最差情况是默认走 QA
`─────────────────────────────────────────────────`
