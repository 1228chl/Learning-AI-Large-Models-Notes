## 一、请求模型与 SSE 工具（第 290~297 行）

```python
class UnifiedChatRequest(BaseModel):
    session_id: str = Field(..., description="会话 ID")
    message:    str = Field(..., min_length=1, max_length=2000, description="用户输入")

def _sse(data: dict) -> dict:
    return {"data": json.dumps(data, ensure_ascii=False)}
```

- `min_length=1` 防止空字符串
- `max_length=2000` 防止超长输入
- `_sse` 把 dict 包装成 `sse_starlette` 需要的格式

## 二、`unified_chat_stream`：主端点（第 300~401 行）

```python
@router.post("/stream")
async def unified_chat_stream(req, current_user=Depends(get_current_user)):
    async def event_generator():
        # Step 0：规则前置拦截
        pre_reply = _pre_filter(req.message)
        if pre_reply is not None:
            yield _sse({"type": "token", "content": pre_reply})
            yield _sse({"type": "done"})
            return

        # Step 1：LLM 路由判断
        decision = await _llm_route(req.message)

        # Step 2：推送路由决策卡片
        yield _sse({"type": "routing_decision", "agent_type": ..., "agent_display": ..., "reason": ...})

        # Step 3：按路由结果分发处理
        label = decision.label

        # 3a：qa → 流式执行 QA Agent
        if label == "qa":
            async for event in _stream_qa_agent(req, current_user):
                yield event

        # 3b：exam/resume/interview → 引导跳转
        elif label in ("exam", "resume", "interview"):
            guidance = _GUIDANCE.get(decision.agent_type, {})
            yield _sse({"type": "guidance", "message": ..., "action_label": ..., "action_url": ...})

        # 3c：multi_agent → 求职全链路 Pipeline 计划
        elif label == "multi_agent":
            yield _sse({"type": "pipeline_plan", "title": "求职全链路", "steps": [
                {"step": 1, "agent_type": "resume", "label": "简历审查", ...},
                {"step": 2, "agent_type": "interview", "label": "模拟面试", ...},
            ]})

        # 3d：clarify → 追问提示
        else:
            yield _sse({"type": "guidance", "message": "您的问题我还不太确定..."})

        yield _sse({"type": "done"})

    return EventSourceResponse(event_generator())
```

### 2.1 四条分支路径

| 分支 | label | SSE 事件序列 |
|:-----|:------|:-------------|
| ① 规则拦截 | 命中关键词 | `token` + `done` |
| ② QA | `qa` | `routing_decision` → `progress` → `token` → `meta` → `done` |
| ③ 引导跳转 | `exam/resume/interview` | `routing_decision` → `guidance` → `done` |
| ④ Pipeline 计划 | `multi_agent` | `routing_decision` → `pipeline_plan` → `done` |
| ⑤ 追问 | `clarify` | `routing_decision` → `guidance` → `done` |

## 三、`_stream_qa_agent`：QA 流式执行（第 404~463 行）

```python
async def _stream_qa_agent(req, current_user):
    orchestrator = get_orchestrator()
    graph = orchestrator._get_agent_graph(AgentType.QA)

    thread_id = build_thread_id(current_user["user_id"], req.session_id)
    initial_state = {
        "messages": [HumanMessage(content=req.message)],
        "student_id": current_user["user_id"],
        "tenant_id": current_user["tenant_id"],
        "session_id": req.session_id,
        "course_id": None,
        "query_type": "PRECISE",
    }
    config = {"configurable": {"thread_id": thread_id}}

    answer_mode = None; confidence = 0.0; sources = []

    try:
        async for event in graph.astream_events(initial_state, config=config, version="v2"):
            evt = event["event"]
            node = event.get("metadata", {}).get("langgraph_node", "")

            # ① progress 事件
            if evt == "on_chain_start" and node in _PROGRESS_LABELS:
                yield _sse({"type": "progress", "stage": _PROGRESS_LABELS[node]})
            # ② token 事件
            elif evt == "on_chat_model_stream" and node in _GENERATE_NODES:
                chunk = event["data"].get("chunk")
                if chunk and chunk.content:
                    yield _sse({"type": "token", "content": chunk.content})
            # ③ 生成节点结束 → 回填元数据
            elif evt == "on_chain_end" and node in _GENERATE_NODES:
                output = event["data"].get("output", {})
                if output.get("answer_mode"): answer_mode = output["answer_mode"]
                if output.get("sources"): sources = output["sources"]
                confidence = (output.get("structured_output") or {}).get("confidence", confidence)
    except Exception as e:
        yield _sse({"type": "error", "message": "问答服务异常，请稍后重试"})
        return

    # ④ meta 事件
    if answer_mode:
        yield _sse({"type": "meta", "answer_mode": answer_mode, "confidence": confidence, "sources": sources})
```

### 3.1 四种 SSE 事件

| 事件类型 | 触发条件 | 内容 |
|:---------|:---------|:-----|
| `progress` | `on_chain_start` + 节点在 `_PROGRESS_LABELS` | 进度描述文本 |
| `token` | `on_chat_model_stream` + 节点在 `_GENERATE_NODES` | 逐字 token |
| `meta` | QA 生成完毕 | `answer_mode` / `sources` / `confidence` |
| `error` | 异常 | 错误信息 |

### 3.2 进度标签映射

```python
_PROGRESS_LABELS = {
    "classify_query":        "理解问题中...",
    "load_memory_and_embed": "检索知识库...",
    "retrieve":              "召回相关文档...",
    "rerank":                "精排中...",
    "hyde_generate":         "理解问题中...",
    "multi_query_rewrite":   "改写查询中...",
    "generate_general":      "思考中...",
}
_GENERATE_NODES = {"generate_rag", "generate_direct", "generate_general"}
```

**`_GENERATE_NODES`**：QA Agent 的三个生成节点，只有它们的 token 才被流式输出。其他节点只产生 `progress` 事件。

## 四、Guidance 引导消息

```python
_GUIDANCE = {
    AgentType.EXAM: {
        "message": "检测到您需要进行试卷批改。请前往「试卷批改」页面上传 Word 格式答卷...",
        "action_label": "前往试卷批改", "action_url": "/exam",
    },
    AgentType.RESUME: {
        "message": "检测到您需要进行简历审查。请前往「简历审查」页面上传 PDF 格式简历...",
        "action_label": "前往简历审查", "action_url": "/resume",
    },
    AgentType.INTERVIEW: {
        "message": "检测到您需要进行模拟面试。请前往「模拟面试」页面选择目标岗位...",
        "action_label": "前往模拟面试", "action_url": "/interview",
    },
}
```

**为什么 exam/resume/interview 不走直接执行？** 这三个 Agent 需要文件上传（试卷 Word、简历 PDF）或前置选择（目标岗位），不适合纯文本对话入口。统一入口只返回引导卡片，前端把用户导航到对应功能页。

## 五、`pipeline_plan` 与 `_run_pipeline` 的分工

| 概念 | 职责 | 执行时机 |
|:-----|:-----|:---------|
| `pipeline_plan`（SSE 事件） | 推计划给前端，让用户确认 | 路由到 `multi_agent` 时 |
| `_run_pipeline`（Orchestrator） | 实际执行多 Agent 串联 | 用户确认后，通过其他端点触发 |

**`pipeline_plan` 推计划，`_run_pipeline` 执行计划**——两者分工明确，不耦合。

## 七、`★` 设计亮点总结

`★ Insight ─────────────────────────────────────`
**`astream_events` 的精准过滤 + 4 类事件覆盖完整 QA 流程**：
- `progress`：节点级别进度提示（"检索知识库..."）
- `token`：生成节点逐字输出
- `meta`：生成完毕后的元数据（answer_mode / sources / confidence）
- 前端根据事件类型渲染不同 UI：进度条→打字机效果→引用来源
- 这种"事件驱动"的流式架构，比 WebSocket 更简单，比轮询更实时
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**`pipeline_plan` 推计划，`_run_pipeline` 执行——关注点分离**：
- 统一入口不做执行，只做路由和分发
- 多 Agent 串联的实际执行在 Orchestrator 中
- SSE 端点只推计划，用户确认后走其他路径触发执行
- 这种"路由和执行分离"的设计，让统一入口职责清晰
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**8 种 SSE 事件类型 = 前端 UI 的 8 种渲染状态**：
- `routing_decision` → 路由卡片
- `progress` → 进度条
- `token` → 打字机效果
- `guidance` → 引导卡片
- `pipeline_plan` → 步骤列表
- `meta` → 引用来源
- `done` → 关闭流式
- `error` → 错误提示
- 每个事件对应一个前端 UI 行为，前后端通过事件类型契约协作
`─────────────────────────────────────────────────`
