# BGE-M3 嵌入 — 从零理解

## 一、什么是向量嵌入？

计算机无法直接比较两段文字的"语义相似度"——它只能做数值运算。

**嵌入（Embedding）** 就是把文字转换成数值向量的过程：

```
"什么是 Spring IOC？"   →  [0.12, -0.34, 0.87, ..., 0.45]   （1024 个数字）
"IOC 容器负责管理对象"  →  [0.11, -0.31, 0.89, ..., 0.43]   （1024 个数字）
"今天天气怎么样"        →  [-0.92, 0.41, -0.13, ..., 0.07]   （1024 个数字）
```

语义相近的文字，向量方向相近（余弦相似度高）；语义无关的文字，向量方向差异大。

## 二、稠密向量 vs 稀疏向量

| 类型 | 形态 | 优点 | 盲区 |
|------|------|------|------|
| 稠密 | `[0.12, -0.34, ...]` 1024维 | 语义相似，用词不同也能匹配 | 精确关键词不敏感 |
| 稀疏 | `{token_id: weight}` 字典 | 精确匹配关键词 | 不理解语义 |

**两者互补**：

```
查询："OrderedDict 和普通 dict 有什么区别"

稠密检索命中：
  ✅ "Python 字典数据结构详解"（语义相关，但没有 OrderedDict）

稀疏检索命中：
  ✅ "OrderedDict 保持插入顺序"（关键词精准命中）

融合后排名：
  🥇 "OrderedDict 保持插入顺序"（两路都命中）
  🥈 "Python 字典数据结构详解"（稠密命中）
```

## 三、BGE-M3：一个模型输出两种向量

BGE-M3 是 BAAI 发布的多功能嵌入模型，一次推理同时输出两种向量：

| 输出 | 字段 | 维度 | 用途 |
|------|------|------|------|
| 稠密向量 | `dense_vecs` | 1024 维 | 语义相似度 |
| 稀疏向量 | `lexical_weights` | `{token_id: weight}` | 关键词匹配 |

### 4.3 批量编码

```python
def encode(self, texts, batch_size=12):
    output = self._model.encode(
        texts,
        batch_size=batch_size,
        max_length=8192,         # 最长 8192 token
        return_dense=True,        # 输出稠密向量
        return_sparse=True,       # 输出稀疏向量
        return_colbert_vecs=False # ColBERT 多向量，本项目不用
    )

    dense_vecs = output["dense_vecs"].tolist()  # numpy → Python list

    # 必须转换：numpy.float16 → Python float
    # msgpack 不支持 numpy.float16，序列化时会抛 TypeError
    sparse_vecs = [
        {int(k): float(v) for k, v in d.items()}
        for d in output["lexical_weights"]
    ]

    return dense_vecs, sparse_vecs
```

### 4.4 单条查询编码

```python
def encode_query(self, text: str) -> tuple[list[float], dict]:
    dense_list, sparse_list = self.encode([text], batch_size=1)
    return dense_list[0], sparse_list[0]
```

## 五、DocumentChunk 数据类

```python
@dataclass
class DocumentChunk:
    id:               str          # MD5 唯一 ID
    content:          str          # chunk 文本
    embedding:        list[float]  # 稠密向量
    sparse_embedding: dict         # 稀疏向量
    course_id:        str          # 所属课程
    document_id:      str          # 所属文档
    source_name:      str          # 来源标注
    chunk_type:       str          # text / code / table
    chunk_index:      int          # 在文档中的顺序
    version:          str          # 版本号
    tenant_id:        str          # 多租户隔离
    updated_at:       int          # 时间戳
```

## 六、generate_chunk_id

```python
def generate_chunk_id(content: str, document_id: str, chunk_index: int) -> str:
    raw = f"{document_id}_{chunk_index}_{content[:50]}"
    return hashlib.md5(raw.encode()).hexdigest()
```

内容+位置不变则 ID 不变，支持幂等 upsert。

## 七、总结

```
BGEMEmbedder（单例）
  ├── encode()        → 批量编码，返回 dense + sparse
  ├── encode_query()  → 单条编码
  └── get_instance()  → 获取单例

DocumentChunk（数据类）
  └── 字段与 Milvus Schema 一一对应

generate_chunk_id（工具函数）
  └── MD5 散列，幂等
```

**核心思想：BGE-M3 一次推理输出两种向量，实现混合检索。**
