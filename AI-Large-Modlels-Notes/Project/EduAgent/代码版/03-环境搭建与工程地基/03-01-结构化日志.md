# 结构化日志 — 从零理解

## 一、为什么不用 `print()`？

```python
# 假设你写了这样的代码
print(f"用户 {user_id} 登录成功")
print(f"用户 {user_id} 查询简历")
```

`print()` 的问题：

| 问题 | 说明 |
|------|------|
| 无法分级 | 怎么区分 INFO / WARNING / ERROR？ |
| 没有时间戳 | 出问题时不知道什么时候发生的 |
| 无法过滤 | 调试时想看所有，上线只想看 WARNING 以上 |
| 不可解析 | 日志收集系统（ELK/Loki）怎么解析"用户 xxx 登录成功"这种自然语言？ |

标准库 `logging` 解决了这些问题，但传统写法还是字符串拼接：

```python
import logging
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)
logger.info(f"用户 {user_id} 登录成功")  # 还是传统字符串拼接
```

## 二、结构化日志的思路

看 `backend/core/logger.py` 的核心方法 `_fmt`：

```python
def _fmt(self, event: str, **kw) -> str:
    if kw:
        return event + " | " + " ".join(f"{k}={v!r}" for k, v in kw.items())
    return event
```

**核心思想：把一条日志拆成"事件名 + 键值对"。**

```python
# 传统写法（搜日志靠字符串匹配）
logger.info(f"用户 {user_id} 登录成功，角色是 {role}")

# 结构化写法（搜日志靠事件名，键值对可解析）
logger.info("auth.login_success", user_id="u1", role="student")
# 输出: auth.login_success | user_id='u1' role='student'
```

### 好处

```
搜索：grep "auth.login_success"              ← 精确，不依赖中文措辞
解析：event="auth.login_success", user_id="u1", role="student"  ← 直接给 ELK/Loki 用
```

## 三、逐行读 logger.py

### 3.1 内部类 `_Logger`

```python
class _Logger:
    def __init__(self, name: str):
        self._log = logging.getLogger(name)  # 包装标准库 logger
```

`name` 通常是 `__name__`，比如 `backend.core.llm_factory`。这样日志里能看出是哪个模块打的。

### 3.2 格式化方法 `_fmt`

```python
def _fmt(self, event: str, **kw) -> str:
    if kw:
        return event + " | " + " ".join(f"{k}={v!r}" for k, v in kw.items())
    return event
```

注意 `{v!r}` 的 `!r` 表示用 `repr()` 显示值，字符串会带引号：

```python
>>> f"key={'hello'!r}"
"key='hello'"

>>> f"key={'hello'}"
"key=hello"    # 不带引号，区分不了类型
```

### 3.3 四个日志级别方法

以 `info` 为例：

```python
def info(self, event: str, *args, **kw):
    if args:                           # 有位置参数 → 传统写法
        self._log.info(event, *args)
    else:                              # 有关键字参数 → 结构化写法
        self._log.info(self._fmt(event, **kw))
```

**为什么同时支持 `*args` 和 `**kw`？**

```python
# 结构化写法（推荐）
logger.info("auth.login_success", user_id="u1")

# 传统写法（兼容，过渡期用）
logger.info("用户 %s 登录成功", user_id)
```

### 3.4 error 方法的特殊处理

```python
def error(self, event: str, **kw):
    exc_info = kw.pop("exc_info", False)  # 从 kw 中取出 exc_info
    self._log.error(self._fmt(event, **kw), exc_info=exc_info)
```

`exc_info=True` 会把异常堆栈也打印出来，排查问题必备：

```python
try:
    result = 1 / 0
except ZeroDivisionError as e:
    logger.error("math.division_error", exc_info=e)  # 会打印完整堆栈
```

## 四、全局配置 `configure_logging()`

```python
def configure_logging() -> None:
    settings = get_settings()
    level = getattr(logging, settings.log_level.upper(), logging.INFO)
    logging.basicConfig(
        format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
        stream=sys.stdout,
        level=level,
        force=True,           # 强制覆盖已有配置
    )
    # 压低第三方库的噪音
    logging.getLogger("sqlalchemy.engine").setLevel(logging.WARNING)
    logging.getLogger("httpx").setLevel(logging.WARNING)
```

**注意 `force=True`**：Python 的 `basicConfig` 默认只生效一次，第二次调用就没效果了。`force=True` 强制覆盖。

## 五、动手测试

```python
# 在项目根目录下跑
python -c "
from backend.core.logger import configure_logging, get_logger

configure_logging()  # 初始化（只在 main.py 启动时调用一次）

# 带错误堆栈
try:
    1/0

    logger.error('test.error', exc_info=e)
"
```

你会看到终端输出：

```

  File "<string>", line 1, in <module>

```

## 六、项目里实际怎么用

看 `backend/core/llm_factory.py` 里的实际用法：

```python
# 模块顶部
from backend.core.logger import get_logger
logger = get_logger(__name__)

# 正常信息
logger.info("llm_factory.model_initialized",
            agent_type=agent_type, model_key=model_key,
            temperature=temperature, streaming=streaming)

# 警告
logger.warning("six_dimensions.dimension_retry",
               dimension=dim["name"], error=str(e))

# 错误 + 堆栈
logger.error("resume.background_task_failed",
             review_id=review_id, error=str(exc), exc_info=exc)
```

## 七、总结

```
logger.info("auth.login_success", user_id="u1", role="student")
    │
    ▼
_fmt() 拼成 → "auth.login_success | user_id='u1' role='student'"
    │
    ▼
标准库 logging 加前缀 → "2025-01-15 [INFO] module: auth.login_success | ..."
    │
    ▼
输出到 stdout（控制台）
```

**核心思想：事件名 + 键值对，而不是自然语言字符串。这样既方便人读，也方便机器解析。**
