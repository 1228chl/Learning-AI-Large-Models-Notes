# 三层兜底重试 — 从零理解

## 一、为什么需要重试？

调用大模型 API 时，失败是常态：

```python
# 常见的失败原因
- 网络抖动（偶尔超时）
- API 限流（请求太频繁，返回 429）
- 服务端暂时不可用（返回 503）
```

**直接失败**：用户看到"服务异常"，体验差。

**无限制重试**：如果错误是"输入非法"，重试一万次也没用，浪费资源。

**正确做法：分层处理。**

## 二、三层兜底设计

```
第一层：自动重试    失败 → 等待 1s → 再试 → 等待 3s → 再试
                         ↓ 全失败
第二层：Agent 降级   → 按类型返回友好提示
                         ↓ 降级也失败
第三层：系统兜底     → 永远返回一条消息，不让用户空等
```

## 三、逐行读 retry.py

### 3.1 异常分类

```python
RETRYABLE_ERRORS = (      # 可重试：短暂故障，重试可能好
    LLMAPIError,
    MilvusConnectionError,
    TimeoutError,
    ConnectionError,
)

NON_RETRYABLE_ERRORS = (   # 不可重试：重试也没用
    InvalidInputError,
    AuthenticationError,
    AgentExecutionError,
    PipelineError,
    IntentRouteError,
    FileParseError,
)
```

### 3.2 重试配置

```python
MAX_RETRIES = 2           # 最多重试 2 次（加上首次 = 共 3 次）
RETRY_DELAYS = [1.0, 3.0] # 第 1 次重试前等 1 秒，第 2 次前等 3 秒
TIMEOUT_PER_ATTEMPT = 30.0  # 单次调用最多等 30 秒
```

### 3.3 装饰器 `@with_retry`

```python
def with_retry(agent_type: str = ""):
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            # 第一层：自动重试
            for attempt in range(MAX_RETRIES + 1):  # 0, 1, 2
                try:
                    result = await asyncio.wait_for(
                        func(*args, **kwargs), timeout=TIMEOUT_PER_ATTEMPT,
                    )
                    if attempt > 0:
                        logger.info("retry.succeeded", attempt=attempt + 1)
                    return result
                except NON_RETRYABLE_ERRORS:
                    raise  # 不可重试，立即抛出
                except Exception as e:
                    last_error = e
                    if attempt < MAX_RETRIES:
                        await asyncio.sleep(RETRY_DELAYS[attempt])
            
            # 第二层：Agent 降级
            try:
                return await AgentFallbackHandler.handle(
                    agent_type=agent_type, original_error=last_error,
                )
            except Exception:
                pass
            
            # 第三层：系统兜底
            return _system_fallback_response(agent_type)
        
        return wrapper
    return decorator
```

### 3.4 各 Agent 的降级策略

```python
class AgentFallbackHandler:
    @classmethod
    async def handle(cls, agent_type, original_error):
        fallback_map = {
            "qa":            cls._qa_fallback,
            "exam_code":     cls._exam_code_fallback,
            "exam_subjective": cls._exam_subjective_fallback,
            "resume":        cls._resume_fallback,
            "interview":     cls._interview_fallback,
        }
        handler = fallback_map.get(agent_type)
        if handler:
            return await handler()
        raise original_error
```

每种降级返回不同的友好提示：

```python
@classmethod
async def _qa_fallback(cls) -> dict:
    return {
        "fallback_used": True,
        "content": "⚠️ 知识库检索暂时不可用，请稍后重试或直接联系教师提问。",
        "structured_output": None,
    }

@classmethod
async def _exam_code_fallback(cls) -> dict:
    return {
        "fallback_used": True,
        "needs_teacher_review": True,
        "fallback_note": "代码评分服务暂时不可用，已标记为需教师人工复核。",
    }
```

### 3.5 系统兜底

```python
def _system_fallback_response(agent_type: str) -> dict:
    messages = {
        "qa":        "非常抱歉，智能问答服务暂时不可用...",
        "exam":      "非常抱歉，试卷批改服务暂时不可用...",
        "resume":    "非常抱歉，简历审查服务暂时不可用...",
        "interview": "非常抱歉，模拟面试服务暂时不可用...",
    }
    return {
        "messages": [],
        "content": messages.get(agent_type, "服务暂时不可用..."),
        "fallback_used": True,
        "system_fallback": True,   # 标记：走到了最后一层
        "structured_output": None,
    }
```

## 四、怎么用？

```python
@with_retry(agent_type="qa")
async def _invoke():
    return await graph.ainvoke(state, config=config)
```

只需加一个装饰器，三层保护自动生效。

## 五、完整流程

```
asyncio.wait_for(func(), timeout=30s)
    │
    ├─ 成功 → 返回结果
    │
    ├─ 不可重试异常 → 立即抛出
    │
    └─ 可重试异常 → 还剩重试次数？
         │
         ├─ 是 → 等 1s/3s → 重试
         │
         └─ 否 → 按 Agent 类型找降级策略
                  │
                  ├─ 降级成功 → 返回降级结果
                  │
                  └─ 降级失败 → 返回系统兜底消息
```

## 六、总结

```
第一层：自动重试      → 解决网络抖动等短暂故障
第二层：Agent 降级    → 尽量保留核心功能
第三层：系统兜底      → 永远让用户收到响应，不空等
```

**核心思想：用户永远不应该看到"服务不可用"的空白页。**
