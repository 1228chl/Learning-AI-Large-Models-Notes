# 配置中心 — 从零理解

## 一、为什么需要配置中心？

看一个没有配置中心的项目，配置会散落在各处：

```python
# database.py
DATABASE_URL = "postgresql+asyncpg://user:pass@localhost:5433/eduagent"

# auth.py
SECRET_KEY = "my-secret-key"
ALGORITHM = "HS256"

# llm.py
API_KEY = "sk-xxx"
BASE_URL = "https://api.deepseek.com/v1"
```

**问题：**

- 换环境（本地 → 测试 → 生产）要改多个文件
- 敏感信息（API Key、密钥）硬编码在代码里
- 配置项没有类型校验（端口写成字符串也不知道）

**配置中心**就是把所有配置集中到一个地方统一管理。

## 二、pydantic-settings 是什么？

`pydantic-settings` 是 Pydantic 的扩展库，能自动从环境变量 / `.env` 文件读取配置，并做类型校验。

```python
class Settings(BaseSettings):
    app_name: str = "EduAgent"  # 有默认值 → 可选
    db_password: str            # 无默认值 → 必填，缺了启动报错
    app_port: int = 8000        # 自动转成 int

    class Config:
        env_file = ".env.local"  # 从这个文件读取
```

配置的优先级：**环境变量 > `.env` 文件 > 代码默认值**。

## 三、逐行读 config.py

### 3.1 配置模型

```python
class Settings(BaseSettings):
    db_host: str = "localhost"
    db_port: int = 5433
    db_name: str = "eduagent"
    db_user: str = "eduagent_user"
    db_password: str = "123456"
```

每个属性名对应 `.env.local` 里的配置项名，大小写不敏感：

```ini
# .env.local
DB_HOST=localhost
DB_PORT=5433
DB_USER=eduagent_user
```

### 3.2 动态属性

```python
@property
def database_url(self) -> str:
    return (
        f"postgresql+asyncpg://{self.db_user}:{self.db_password}"
        f"@{self.db_host}:{self.db_port}/{self.db_name}"
    )
```

`@property` 装饰器让方法可以像属性一样访问：

```python
settings = get_settings()
print(settings.database_url)
# postgresql+asyncpg://eduagent_user:123456@localhost:5433/eduagent
```

### 3.3 单例模式

```python
@lru_cache()
def get_settings() -> Settings:
    return Settings()
```

`@lru_cache` 是 Python 标准库装饰器，缓存函数结果。第一次调用时创建 `Settings` 实例读 `.env` 文件，后续调用直接返回缓存，不再读文件。

**为什么是单例？** 每次读取 `.env` 文件都有 IO 开销，而且全局配置应该只有一个实例。

### 3.4 Config 元配置

```python
class Config:
    env_file = ".env.local"      # 从这个文件读
    env_file_encoding = "utf-8"   # 文件编码
    case_sensitive = False        # 大小写不敏感：DB_HOST 对应 db_host
    extra = "ignore"              # 多余字段忽略，不报错
```

## 四、项目里有哪些配置？

| 配置组 | 字段 | 用途 |
|--------|------|------|
| 数据库 | `db_host/port/name/user/password` | PostgreSQL 连接 |
| Milvus | `milvus_host/port` | 向量库连接 |
| DeepSeek | `deepseek_api_key/base_url/model_chat/model_coder` | 大模型 API |
| 本地模型 | `reranker_model_path/classifier_model_path/bge_m3_model_path` | 模型权重路径 |
| JWT | `jwt_secret_key/algorithm/access_token_expire_minutes` | 登录鉴权 |
| MCP | `kb_mcp_server_url/web_search_mcp_url` | MCP 工具服务 |
| 应用 | `app_env/debug/host/port/log_level` | 运行环境 |

## 五、动手测试

```python
# 在项目根目录下跑
python -c "
from backend.config import get_settings

s = get_settings()

# 配置项
print('数据库连接:', s.database_url)
print('Milvus 地址:', f'{s.milvus_host}:{s.milvus_port}')
print('日志级别:', s.log_level)

# get_settings() 是单例
s2 = get_settings()
print('两次调用同一实例:', s is s2)  # True
"
```

## 六、总结

```
config.py
    │
    ▼
pydantic-settings 从 .env.local 读取
    │
    ▼
@lru_cache 缓存实例（单例）
    │
    ▼
get_settings() 返回全局唯一配置对象
    │
    ▼
任何模块通过 from backend.config import get_settings 获取配置
```

**核心思想：配置集中管理，全局唯一，类型安全。**
