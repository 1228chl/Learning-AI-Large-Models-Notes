## 一、为什么需要分派主函数？

面试有五个阶段，每个阶段的回应生成逻辑不同。如果写在一个函数里，会非常臃肿。`generate_response_node` 作为**分派器**，根据 `current_stage` 调用对应的 `_respond_*` 子函数。

```
generate_response_node (分派器)
  ├─ current_stage == WARMUP     → _respond_warmup
  ├─ current_stage == TECH_BASE  → _respond_tech_base
  ├─ current_stage == PROJECT    → _respond_project（7.8）
  ├─ current_stage == CLOSING    → _respond_closing（7.8）
  └─ 其他（FINISHED）             → 固定提示语
```

## 二、`generate_response_node`：分派主函数（第 375~407 行）

```python
# nodes.py 第 375~407 行
async def generate_response_node(state: InterviewState) -> dict:
    current_stage = state.get("current_stage", InterviewStage.WARMUP.value)
    stage_turns   = state.get("stage_turn_count", 0)
    messages      = state.get("messages", [])

    transition_prefix = ""
    if stage_turns == 1 and current_stage not in (
        InterviewStage.WARMUP.value, InterviewStage.TECH_BASE.value
    ):
        transition_prefix = STAGE_TRANSITION_PROMPTS.get(current_stage, "")

    if current_stage == InterviewStage.WARMUP.value:
        response_text, updates = await _respond_warmup(state)
    elif current_stage == InterviewStage.TECH_BASE.value:
        response_text, updates = await _respond_tech_base(state)
    elif current_stage == InterviewStage.PROJECT.value:
        response_text, updates = await _respond_project(state)
    elif current_stage == InterviewStage.CLOSING.value:
        response_text, updates = await _respond_closing(state)
    else:
        response_text = "感谢您参加本次模拟面试，请稍等，正在生成评估报告..."
        updates = {}

    if transition_prefix:
        response_text = transition_prefix + "\n\n" + response_text

    updates["messages"]         = [AIMessage(content=response_text)]
    updates["should_summarize"] = should_trigger_summary(messages)

    return updates
```

| 行号 | 逻辑 | 说明 |
|:----:|:-----|:------|
| 382~385 | 阶段过渡语拼接 | 进入新阶段的第一轮，在回应前拼接过渡语 |
| 387~388 | WARMUP | 调用 `_respond_warmup` |
| 389~390 | TECH_BASE | 调用 `_respond_tech_base` |
| 391~392 | PROJECT | 调用 `_respond_project` |
| 393~394 | CLOSING | 调用 `_respond_closing` |
| 395~397 | 其他（FINISHED） | 固定提示语，等待报告生成 |
| 402~403 | 统一更新 | `messages` 追加 AIMessage，`should_summarize` 判断摘要 |

**过渡语拼接时机**：`stage_turns == 1` 且当前阶段不是 WARMUP 或 TECH_BASE。WARMUP 不需要过渡语（它就是开场），TECH_BASE 的过渡语由 `INTRO_EVAL_TECH_FIRST_PROMPT` 内部处理。

**`should_trigger_summary(messages)`**：每 10 轮触发一次摘要压缩（来自 `backend/core/memory.py`）。

## 四、`_build_messages`（第 419~426 行）

```python
# nodes.py 第 419~426 行
def _build_messages(system: str, history: list, current_prompt: str, window: int = 10) -> list:
    result = [SystemMessage(content=system)]
    windowed = trim_messages_to_window(history[:-1], window_size=window)
    for msg in windowed:
        if not isinstance(msg, SystemMessage):
            result.append(msg)
    result.append(HumanMessage(content=current_prompt))
    return result
```

| 行号 | 代码 | 说明 |
|:----:|:-----|:-----|
| 420 | `result = [SystemMessage(content=system)]` | System 消息始终在最前 |
| 421 | `windowed = trim_messages_to_window(history[:-1], window_size=window)` | 滑窗裁剪：去掉最后一条（当前问题），保留历史 |
| 422~424 | 过滤 System 消息 | 防止重复添加 System 消息 |
| 425 | `result.append(HumanMessage(content=current_prompt))` | 追加当前 Prompt 作为 Human 消息 |

**`history[:-1]` 去掉最后一条**：当前消息已由 `evaluate_answer_node` 处理了，不需要再作为历史传给 LLM。当前 Prompt 替代了这条消息的位置。

## 五、`_respond_warmup`（第 429~437 行）

```python
# nodes.py 第 429~437 行
async def _respond_warmup(state: InterviewState) -> tuple[str, dict]:
    messages = state.get("messages", [])
    position = state.get("target_position", "软件工程师")
    system   = _build_system_with_summary(state)

    prompt = WARMUP_PROMPT["opening"].format(position=position)
    llm = get_llm("interview", temperature=0.7)
    response = await llm.ainvoke(_build_messages(system, messages, prompt, window=4))
    return _msg_text(response).strip(), {}
```

| 行号 | 代码 | 说明 |
|:----:|:-----|:-----|
| 433 | `prompt = WARMUP_PROMPT["opening"].format(position=position)` | 开场白提示词 |
| 434 | `get_llm("interview", temperature=0.7)` | 最高温度，开场白需自然多变 |
| 435 | `_build_messages(system, messages, prompt, window=4)` | 窗口=4（仅保留最近 2 轮） |
| 436 | `return _msg_text(response).strip(), {}` | 返回回应文本，无额外更新 |

**`temperature=0.7`**：开场白是面试的第一印象，较高的温度让 LLM 每次生成略有不同的开场方式，避免千篇一律。

## 八、`★` 设计亮点总结

`★ Insight ─────────────────────────────────────`
**`generate_response_node` 是"分派器"而非"执行器"**：
- 它不直接生成回应，而是根据 `current_stage` 分派给子函数
- 每个子函数独立维护自己的逻辑
- 新增一个面试阶段只需：① 加枚举值 ② 写 `_respond_xxx` ③ 加一个分派分支
- 其他节点（`check_stage`、`evaluate_answer`）完全不需要修改——"开闭原则"的体现
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**`_build_messages` 的窗口裁剪 + 去重设计**：
- `trim_messages_to_window(history[:-1], window)` 只保留最近 N 轮
- System 消息始终保留在最前，不受窗口限制
- 循环中过滤掉重复的 System 消息，防止重复添加
- 这种"裁剪 + 去重"保证了 LLM 上下文窗口不被历史消息撑爆
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**追问门槛 `EXCELLENT` 是"质量驱动的教学策略"**：
- 只有回答 EXCELLENT 才追问，WEAK/NO_ANSWER 直接换题
- 追问是为"学有余力"的学员深化知识点，不浪费在基础薄弱处
- 这体现了"因材施教"——面试官根据回答质量动态调整考察深度
`─────────────────────────────────────────────────`
