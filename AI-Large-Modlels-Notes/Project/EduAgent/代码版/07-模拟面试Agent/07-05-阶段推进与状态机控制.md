## 一、为什么需要阶段推进？

面试 Agent 是**五阶段状态机**，不是每轮都做同样的事：

```
WARMUP(1~4轮) → TECH_BASE(6~12轮) → PROJECT(2~14轮) → CLOSING(2~4轮) → FINISHED
```

`check_stage_node` 是状态机的"心脏"——它判断当前阶段是否应该推进、是否强制结束。它的输出决定了图的走向（`_route_after_check_stage` 读取 `current_stage` 决定走正常对话还是结束收尾）。

## 二、阶段轮次常量（第 31~46 行）

```python
# nodes.py 第 35~46 行
STAGE_MIN_TURNS = {
    InterviewStage.WARMUP.value:    1,   # 热身至少 1 轮
    InterviewStage.TECH_BASE.value: 6,   # 技术环节至少 6 轮
    InterviewStage.PROJECT.value:   2,   # 项目环节至少 2 轮
    InterviewStage.CLOSING.value:   2,   # 反问环节至少 2 轮
}
STAGE_MAX_TURNS = {
    InterviewStage.WARMUP.value:    4,   # 热身最多 4 轮
    InterviewStage.TECH_BASE.value: 12,  # 技术环节最多 12 轮
    InterviewStage.PROJECT.value:   14,  # 项目环节最多 14 轮
    InterviewStage.CLOSING.value:   4,   # 反问环节最多 4 轮
}
```

| 阶段 | 最少轮数 | 最多轮数 | 说明 |
|:-----|:---------|:---------|:-----|
| WARMUP | 1 | 4 | 自我介绍完即可推进 |
| TECH_BASE | 6 | 12 | 技术环节至少 6 道题，最多 12 道 |
| PROJECT | 2 | 14 | 项目深挖至少 2 个问题 |
| CLOSING | 2 | 4 | 反问环节至少 2 轮 |

**`max_turns` 总上限 40**：全局兜底，防止某阶段卡住导致无限对话。

### 3.3 阶段推进逻辑（第 230~253 行）

```python
# nodes.py 第 236~253 行
stage_min = STAGE_MIN_TURNS.get(current_stage, 2)
stage_max = STAGE_MAX_TURNS.get(current_stage, 10)

should_advance = False
if stage_turns >= stage_max:
    should_advance = True
elif stage_turns >= stage_min:
    should_advance = _check_advance_condition(current_stage, state, latest_student_msg)

if should_advance:
    next_stage = _next_stage(current_stage)
    return {
        "current_stage": next_stage,
        "stage_turn_count": 0,
        "followup_count": 0,
        "current_question": None,
    }
```

| 步骤 | 行号 | 逻辑 | 说明 |
|:----:|:-----|:-----|:------|
| ① | 236~237 | 读取轮数范围 | 如 TECH_BASE 最少 6 轮，最多 12 轮 |
| ② | 239~243 | 判断是否推进 | 超过上限→强制推进；超过下限→检查内容条件 |

## 四、`_check_advance_condition`：推进条件（第 258~275 行）

```python
# nodes.py 第 258~275 行
def _check_advance_condition(stage: str, state: InterviewState, latest_msg: str) -> bool:
    if stage == InterviewStage.WARMUP.value:
        return True
    if stage == InterviewStage.TECH_BASE.value:
        bank = state.get("question_bank", [])
        asked_count = sum(1 for q in bank if q.get("asked", False))
        return asked_count >= min(8, len(bank))
    if stage == InterviewStage.PROJECT.value:
        projects = state.get("resume_projects", [])
        projects_asked = state.get("projects_asked", [])
        if not projects:
            return True
        return len(projects_asked) >= len(projects)
    return False
```

| 阶段 | 推进条件 | 说明 |
|:-----|:---------|:-----|
| WARMUP | 总是 True | 自我介绍完即可推进 |
| TECH_BASE | 已问 ≥ 8 题 | `min(8, len(bank))` 防止题库不足 8 题时永远达不到 |
| PROJECT | 所有项目已深挖 | 无简历时直接推进 |

**`min(8, len(bank))`**：如果题库不足 8 题（如 LLM 出题失败，DB 也只有 3 道），直接取全部题目数，避免推进条件永远达不到。

## 五、`_next_stage`：下一阶段（第 278~290 行）

```python
# nodes.py 第 278~290 行
def _next_stage(current: str) -> str:
    order = [
        InterviewStage.WARMUP.value, InterviewStage.TECH_BASE.value,
        InterviewStage.PROJECT.value, InterviewStage.CLOSING.value,
        InterviewStage.FINISHED.value,
    ]
    try:
        idx = order.index(current)
        return order[idx + 1] if idx + 1 < len(order) else InterviewStage.FINISHED.value
    except ValueError:
        return InterviewStage.CLOSING.value
```

| 行号 | 代码 | 说明 |
|:----:|:-----|:-----|
| 279 | `order = [...]` | 定义五阶段顺序 |
| 286~287 | `idx = order.index(current)` | 找当前阶段索引 |
| 288 | `return order[idx + 1]` | 返回下一阶段 |
| 289~290 | `except ValueError` | 当前阶段不在顺序中时，默认推进到 CLOSING |

## 八、`★` 设计亮点总结

`★ Insight ─────────────────────────────────────`
**`check_stage_node` 是"纯逻辑节点"，不调 LLM**：
- 阶段推进判断完全基于轮数计数 + 关键词匹配，不依赖 LLM
- 这意味着即使 LLM 完全不可用，面试也能正常推进到结束
- 对比 QA Agent 的 `classify_query` 节点依赖 LLM 分类
- 这是"关键路径最小化 LLM 依赖"的设计原则——越靠近状态机核心的节点，越应该用纯逻辑实现
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**min/max 双阈值设计 = 轮数弹性 + 内容兜底**：
- 低于 `min` 轮：强制不推进（保证每个阶段有足够轮数）
- 超过 `max` 轮：强制推进（防止卡死）
- 介于 `min` 和 `max` 之间：检查内容条件（如问了多少题、深挖了多少项目）
- 这种"弹性窗口"比固定轮数更合理——既不会因为学员回答慢而卡住，也不会因为回答快而草草跳过
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**`force_end_keywords` 是"学员主权"的体现**：
- 学员说"不想继续"、"结束面试"等关键词，系统立即结束
- 这是"人机交互"中的关键设计——用户应该随时能退出，而不是被系统绑架
- 配合 `max_turns` 兜底，形成"双重退出机制"：学员主动退出 + 系统自动退出
`─────────────────────────────────────────────────`
