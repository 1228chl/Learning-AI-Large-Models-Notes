## 一、为什么需要报告生成？

面试结束时，`check_stage_node` 把 `current_stage` 设为 `FINISHED`，图的条件路由检测到 `FINISHED` 后，绕过 `evaluate_answer → generate_response`，直接进入报告路径：

```
check_stage(FINISHED) → generate_report → save_report → save_memory → END
```

`generate_report_node` 是这条报告路径的起点，负责从对话历史生成完整的五维度评估报告。

## 二、双层输入策略（第 602~613 行）

```python
# nodes.py 第 602~613 行
recent_messages = [msg for msg in messages[-40:] if isinstance(msg, (HumanMessage, AIMessage))]
conversation_text = "\n".join([
    f"{'面试官' if isinstance(m, AIMessage) else '学员'}：{_msg_text(m)}"
    for m in recent_messages
])

prompt = GENERATE_REPORT_PROMPT.format(
    position=position,
    history_summary=summary or "（无历史摘要）",
    conversation=conversation_text[:4000],
    total_turns=state.get("total_turn_count", 0),
)
```

| 行号 | 代码 | 说明 |
|:----:|:-----|:-----|
| 602 | `messages[-40:]` | 取最近 40 条消息 |
| 603~606 | 格式化为可读文本 | `"面试官/学员：xxx"` |
| 608~613 | 拼接 Prompt | 岗位、历史摘要、对话文本、总轮数 |

**双层输入**：`existing_summary`（历史摘要，早期对话压缩） + `conversation`（近期完整对话，截断 4000 字）。摘要提供全局视角，对话提供细节。如果只传摘要，LLM 看不到具体对话细节；如果只传对话，可能超出上下文窗口。

## 三、结构化输出（第 615~634 行）

```python
# nodes.py 第 615~634 行
struct_llm = get_structured_llm("interview", InterviewReport)

report_dict = None
for attempt in range(2):
    try:
        result: InterviewReport = await struct_llm.ainvoke([
            SystemMessage(content=SYSTEM_PROMPT.format(position=position)),
            HumanMessage(content=prompt),
        ])
        if result is None:
            raise ValueError("structured output returned None")
        report_dict = result.model_dump()
        break
    except Exception as e:
        if attempt == 0:
            logger.warning("generate_report.retry", error=str(e))
            await asyncio.sleep(1)
        else:
            logger.warning("generate_report.failed", error=str(e))
```

| 步骤 | 行号 | 操作 | 说明 |
|:----:|:-----|:-----|:------|
| ① | 615~616 | 获取结构化 LLM | 绑定 `InterviewReport` schema |
| ② | 619~634 | 调用 LLM（最多 2 次重试） | 失败后等 1 秒重试 |
| ③ | 625~626 | `result is None` 检查 | 结构化输出可能返回 None（格式不匹配时） |
| ④ | 629~631 | 第 1 次失败 | 只记录警告，sleep 1 秒后重试 |
| ⑤ | 632~634 | 第 2 次失败 | 记录错误，`report_dict` 保持 None |

## 七、`★` 设计亮点总结

`★ Insight ─────────────────────────────────────`
**双层输入策略 = 历史摘要 + 近期对话**：
- 一场 40 轮的面试对话远超 LLM 上下文窗口
- 解决方案：`existing_summary`（早期对话压缩摘要） + `conversation[:4000]`（近期对话截断）
- 摘要提供"全局视角"，对话提供"细节补充"
- 这是"分层记忆"的典型应用——粗粒度用摘要，细粒度用原文
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**两层降级保障报告生成不崩溃**：
- 第 1 层：重试 1 次，sleep 1 秒（应对临时性 LLM 异常）
- 第 2 层：兜底报告（60 分 + 通用评语）
- 即使 LLM 完全不可用，面试也能正常结束，学员能看到一个基础版本的评价
- 这是"最后的防线"——兜底报告虽然不精准，但比报错强
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**`result.model_dump()` 在 nodes.py 中，而非 state.py 中**：
- `InterviewReport` 是 Pydantic 模型，`model_dump()` 转 dict 存入 State
- State 是 TypedDict，不能存 BaseModel 对象
- 结构化输出在 `generate_report_node` 中解析，`report` 字段以 dict 形式存入 State
- `save_report_node` 读 dict 后用 `json.dumps` 写入 DB
- 这是"Pydantic 校验 → dict 存 State → JSON 存 DB"的三层转换
`─────────────────────────────────────────────────`
