## 一、为什么需要这节？

面试 Agent 每一轮对话从 `load_context_node` 开始。它需要处理两个场景：

- **首轮**：`total_turn_count == 0`，需要完整初始化（加载题库、简历、设置初始字段）
- **非首轮**：`total_turn_count > 0`，只需要从 DB 恢复历史摘要

首轮需要做三件事：① 从 DB 加载简历项目 ② 从 DB 拉取预置题库 ③ 用 LLM 动态生成岗位题目。这三件事互不依赖，可以并行执行。

## 二、`_msg_text`：安全提取消息文本（第 49~57 行）

```python
# nodes.py 第 49~57 行
def _msg_text(msg: BaseMessage) -> str:
    """安全提取消息文本，兼容 str 和 list（多模态）content。"""
    content = msg.content
    if isinstance(content, list):
        return "".join(
            p.get("text", "") if isinstance(p, dict) else str(p)
            for p in content
        )
    return str(content)
```

| 行号 | 代码 | 说明 |
|:----:|:-----|:-----|
| 49 | `def _msg_text(msg: BaseMessage) -> str:` | 接收 BaseMessage，返回纯文本 |
| 52 | `if isinstance(content, list):` | 多模态消息的 content 是 list |
| 53~56 | `"".join(...)` | 从每个 dict 块中提取 text 字段 |
| 57 | `return str(content)` | 普通文本直接返回 |

**为什么需要兼容 list？** LangChain 的 `AIMessage` 在流式输出时，`content` 可能是 `list[dict]` 格式（每个 dict 有 `type` 和 `text` 字段）。`_msg_text` 统一提取文本，避免 `str(msg.content)` 返回非人类可读的字符串。

## 三、`_generate_questions_by_llm`：LLM 出题（第 60~94 行）

```python
# nodes.py 第 60~94 行
async def _generate_questions_by_llm(target_position: str, count: int = 8) -> list:
    try:
        llm = get_llm("interview", temperature=0.3)
        prompt = TECH_BASE_GENERATE_PROMPT.format(position=target_position, count=count)
        response = await llm.ainvoke([HumanMessage(content=prompt)])
        text = _msg_text(response).strip()

        if "```" in text:                     # 代码块解析
            parts = text.split("```")
            for part in parts:
                stripped = part.strip()
                if stripped.startswith("json"):
                    stripped = stripped[4:].strip()
                if stripped.startswith("["):
                    text = stripped; break

        questions_raw = json.loads(text)
        result = []
        for i, q in enumerate(questions_raw):
            if not isinstance(q, dict) or not q.get("content"):
                continue
            result.append({
                "id": f"llm_{i}", "content": q["content"],
                "difficulty": q.get("difficulty", "medium"),
                "tags": q.get("tags", []), "asked": False,
            })
        return result
    except Exception as e:
        logger.warning("generate_questions_llm.failed", error=str(e))
        return []
```

| 行号 | 代码 | 说明 |
|:----:|:-----|:-----|
| 63 | `get_llm("interview", temperature=0.3)` | 低温度保证出题稳定 |
| 64 | 拼接出题提示词 | 填入 `{position}` 和 `{count}` |
| 68~76 | 代码块解析 | LLM 可能把 JSON 放 ```json...``` 代码块中，需提取 |
| 78 | `json.loads(text)` | 解析 JSON |
| 79~89 | 结果格式化 | 每项添加 `id`、`asked` 字段，过滤无效项 |
| 92~94 | 失败兜底 | 返回空列表，DB 题库补充 |

**代码块解析逻辑**（第 68~77 行）：LLM 有时把 JSON 输出包裹在 markdown 代码块中。代码先检测 `"```"` 标记，找到以 `[` 开头的代码块内容，提取纯 JSON 字符串。

### 4.3 首轮初始化流程（第 119~196 行）

```python
# nodes.py 第 167~173 行 — 三重并发加载
resume_projects, resume_skills = await load_resume()
db_bank_task = asyncio.create_task(load_questions_from_db())
llm_bank_task = asyncio.create_task(
    _generate_questions_by_llm(state.get("target_position", ""), count=8)
)
db_bank = await db_bank_task
llm_bank = await llm_bank_task
```

| 步骤 | 行号 | 操作 | 说明 |
|:----:|:-----|:-----|:------|
| ① | 120~139 | `load_resume()` | 异步加载简历项目和技能 |
| ② | 141~164 | `load_questions_from_db()` | 从 `interview_questions` 表随机取 20 道 |
| ③ | 169~170 | `_generate_questions_by_llm(...)` | LLM 动态生成 8 道题 |
| ④ | 175 | `question_bank = llm_bank + db_bank` | 合并题库（LLM 题在前，DB 题在后） |
| ⑤ | 179~196 | 返回初始化结果 | 设置 15 个初始字段 |

**`asyncio.create_task` 实现并行**：简历加载和两个出题任务互不依赖，`create_task` 提交后立即返回，`await` 时等待结果。三个任务并行执行，总耗时约等于最慢的一个（通常是 LLM 出题）。

## 六、`★` 设计亮点总结

`★ Insight ─────────────────────────────────────`
**首轮判断依据 `total_turn_count == 0` 的精妙之处**：
- 首轮时 `total_turn_count` 还未被 `evaluate_answer_node` 更新，值为 0
- 非首轮时 `total_turn_count` 已经 ≥ 1
- 不需要额外的 `is_first_round` 布尔字段，直接复用已有的轮数计数器
- 这是"状态驱动"的设计——节点行为由 State 中的已有字段决定，而非引入新字段
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**`asyncio.create_task` 实现"发起-等待"分离**：
- `create_task` 提交任务到事件循环，不阻塞当前执行
- 后续 `await` 时才等待结果，期间可以并发执行其他操作
- 三个任务（简历加载 + DB 出题 + LLM 出题）并行执行，比串行快 3 倍
- 这是异步编程中"先发后等"（fire-and-await）的标准模式
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
**LLM 出题失败不阻断初始化**：
- `_generate_questions_by_llm` 失败时返回空列表
- `load_questions_from_db` 从 DB 拉取预置题目作为补充
- `question_bank = llm_bank + db_bank`——LLM 题为空时，DB 题仍能正常使用
- 这是"尽力而为"的设计哲学——LLM 出题是可选项，不是必选项
`─────────────────────────────────────────────────`
