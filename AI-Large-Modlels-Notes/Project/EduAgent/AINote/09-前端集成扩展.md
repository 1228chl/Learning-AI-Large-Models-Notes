## 9.1 前端集成全景

### 9.1.1 本章定位

前8章完成了后端的全部功能：四大Agent、系统集成、环境与基础设施。第9章是**扩展环节**，目标不是深入讲解Vue3，而是把前端这层"外壳"接上后端，让你看到一个完整运行的带UI的AI系统。

前端代码已经写好，存放在 `frontend/` 目录，只需要理解它是如何与后端通信的，然后把两者都跑起来。

### 9.1.2 前端技术栈一览

| 层次 | 技术 | 作用 |
|------|------|------|
| 框架 | Vue 3 + Composition API | 响应式UI |
| UI组件库 | Element Plus | 表单、弹窗、布局 |
| HTTP客户端 | Axios | 封装所有非流式API请求 |
| 状态管理 | Pinia | 全局存储登录状态（token、user） |
| 路由 | Vue Router 4 | SPA页面切换 + 鉴权守卫 |
| 构建工具 | Vite 5 | 开发服务器(:3000) + 反向代理 |
| Markdown渲染 | markdown-it + highlight.js | 渲染AI回复中的代码块 |

### 9.1.4 前端-后端数据流全景

整个EduAgent系统的数据流从用户浏览器到后端基础设施，经过三层中转：

```
用户浏览器 (:3000)
    │
    ├── 普通请求（非流式）── 经过 Vite Proxy ──→ FastAPI 后端 (:8000)
    │   （登录、上传文件、查询历史、轮询状态等）
    │
    ├── SSE 流式请求 ── 直连后端（绕过Vite Proxy）──→ FastAPI 后端 (:8000)
    │   （QA流式回答、面试对话流）
    │
    └── 静态资源 ── Vite 直接提供
```

**关键连接点有三个**：Vite proxy转发普通请求、fetch直连处理SSE流式、JWT由Axios拦截器自动注入。

### 9.1.5 Vite代理：前端如何找到后端

前端运行在 `:3000`，后端在 `:8000`。开发时直接从 `:3000` 发请求到 `:8000` 会触发浏览器跨域限制。`vite.config.ts` 用代理规则绕开：

```typescript
// vite.config.ts
server: {
  port: 3000,
  proxy: {
    '/api': {
      target: 'http://localhost:8000',
      changeOrigin: true,
    },
  },
},
```

所有以 `/api` 开头的请求，Vite开发服务器会透明转发给 `:8000`。Axios的 `baseURL` 配置成 `/api/v1`，发出的请求路径就是 `/api/v1/qa/chat`，经代理后变成 `http://localhost:8000/api/v1/qa/chat`。

### 9.1.6 SSE流式输出为什么绕过代理

Vite proxy基于Node.js HTTP，默认会在内存里缓冲整个响应体再转发，导致SSE的 `data:` 事件帧被批量堆积，前端无法实时看到token流。

**解决方案**：SSE请求直连后端 `:8000`，不经过Vite proxy。这由 `.env.local` 里的 `VITE_API_BASE_URL` 控制：

```bash
# frontend/.env.local
VITE_API_BASE_URL=http://localhost:8000
```

`QAChatView.vue` 和 `api/interview.ts` 里的流式方法都用 `fetch` 直接请求 `${VITE_API_BASE_URL}/api/v1/...`，不走Axios。

### 9.1.7 JWT鉴权流程

```
用户登录
  → POST /api/v1/auth/login → 返回 access_token
  → auth.login() 写入 Pinia store + localStorage

后续每个请求
  → Axios 请求拦截器读取 localStorage 中的 token
  → 在 Header 附加 Authorization: Bearer <token>

Token 过期（后端返回 401）
  → Axios 响应拦截器捕获
  → 调用 auth.logout()，清除 store + localStorage
  → 跳转到 /login
```

这套流程全部封装在 `src/api/client.ts` 中，业务代码无需处理鉴权细节。

## 9.2 四大功能页面解读

### 9.2.1 登录页（LoginView.vue）

**对应后端API**：`POST /api/v1/auth/login`

**操作流程**：
1. 用户输入用户名和密码，点击「登录」
2. 前端调用 `authApi.login({ username, password })`
3. 后端验证成功后返回 `access_token`、`user_id`、`role`
4. `auth.login()` 将token写入localStorage，并存储用户信息到Pinia store
5. 路由守卫检测到已登录，跳转到 `/dashboard`

登录成功后，之后所有请求Header里都会自动携带 `Authorization: Bearer <token>`，不需要每个页面单独处理。

**测试账号**（由 `seed_data.py` 写入）：

| 用户名 | 密码 | 角色 |
|--------|------|------|
| student01 | Student@123456 | 学生 |
| teacher01 | Teacher@123456 | 教师 |
| admin | Admin@123456 | 管理员 |

### 9.2.2 Dashboard（DashboardView.vue）

登录后的首页，展示五个功能入口卡片：

- 点击「AI助手」→ `/chat`（UnifiedChatView，调用 `POST /api/v1/chat`，由Orchestrator自动路由到合适的Agent）
- 点击「智能问答」→ `/qa`
- 点击「试卷批改」→ `/exam`
- 点击「简历审查」→ `/resume`
- 点击「模拟面试」→ `/interview`

教师/管理员角色登录后，侧边栏还会出现「教师端」入口，包含批改确认和知识库管理功能。

### 9.2.3 智能问答页面（QAChatView.vue）

**对应后端API**：
- `POST /api/v1/qa/chat/stream`（SSE流式，主要路径）
- `GET /api/v1/qa/sessions/:id/history`（加载历史消息）

**页面结构**：
- 左侧：会话列表，可新建多个会话、切换历史
- 右侧：聊天气泡区 + 输入框

**SSE流式工作流**：
1. 用户按Enter发送消息
2. 前端用 `fetch` 直连 `http://localhost:8000/api/v1/qa/chat/stream`（绕过Vite proxy）
3. 逐帧读取 `data: {"type":"token","content":"..."}` 事件，实时渲染token
4. 收到 `data: {"type":"done",...}` 后标记流结束，显示来源文档

右上角有「Web Search」开关：开启后，当RAG置信度低于阈值时，QA Agent会先调用MCP Web Search工具再回答。

**SSE事件类型在前端的处理**：

| 事件类型 | 前端处理逻辑 |
|----------|-------------|
| token | 追加到当前回答气泡的文本内容，实时渲染 |
| progress | 在输入框上方显示进度条或"检索知识库中..."提示 |
| meta | 渲染完成后附上来源文档引用列表 |
| done | 标记流结束，停止loading状态，允许用户继续输入 |
| error | 显示错误提示气泡 |

### 9.2.4 试卷批改页面

**学生端——提交页（ExamSubmitView.vue）**

对应后端API：
- `POST /api/v1/exam/submit`（上传答题文件）
- `GET /api/v1/exam/my-submissions`（历史提交列表）

操作步骤：
1. 输入教师提供的「试卷ID」（`exam_id`，格式为UUID）
2. 上传 `.docx` 格式答题文件
3. 点击「提交批改」，系统返回 `submission_id`
4. 批改完成后（状态变为 `pending_review` 或 `reviewed`），点击「查看结果」

**学生端——结果页（ExamResultView.vue）**

路由：`/exam/:submissionId`，调用 `GET /api/v1/exam/my-submissions/:id`

展示：逐题AI反馈（客观题对错标红/标绿、简答题评分与评语、代码题评估）、总分、知识薄弱点分析（按知识点维度聚合的得分率雷达图）。

**教师端——批改确认页（ExamReviewView.vue）**

路由：`/teacher/exam-review`，仅 teacher/admin 角色可见。

对应API：
- `GET /api/v1/exam/pending-reviews`（待确认列表）
- `GET /api/v1/exam/submissions/:id/review`（查看批改详情）
- `POST /api/v1/exam/submissions/:id/confirm`（确认/修改后发布）

教师在抽屉里查看每道题的AI预评分，可以直接「批准」或「修改分数+评语」后发布。这是Human-in-the-Loop（HitL）流程的前端体现。

### 9.2.5 简历审查页面

**上传页（ResumeUploadView.vue）**

对应API：`POST /api/v1/resume/upload`（上传PDF）

操作：点击「选择PDF文件」→「开始审查」，后端异步处理，返回 `review_id`。

**报告页（ResumeReportView.vue）**

路由：`/resume/:reviewId`，轮询 `GET /api/v1/resume/reviews/:id` 直至状态变为 `done`。

展示内容：
- **六维度雷达图**（内容质量、格式规范、项目描述、技能匹配、量化成果、语言表达）
- **加权综合评分**（总分+各维度分数）
- **逐条问题清单**，带原文定位和修改建议
- **核心亮点与改进建议汇总**

六维度雷达图使用ECharts或类似库绘制，前端将后端返回的六个维度的分数绘制成五边形/六边形雷达图，直观展示简历在各维度的表现差异。

### 9.2.6 模拟面试页面

**配置页（InterviewSetupView.vue）**

对应API：`POST /api/v1/interview/sessions`

填写目标岗位（必填）、可选关联已审查的简历，点击「开始面试」，后端创建session并返回 `session_id`，自动跳转到对话页。

**对话页（InterviewChatView.vue）**

路由：`/interview/:sessionId`

对应API（SSE流式）：`POST /api/v1/interview/sessions/:id/chat/stream`

面试分三个阶段：
1. **opening**：开场介绍，AI确认面试计划
2. **technical**：技术原理追问（双轨：知识广度+代码/原理深度）
3. **project**：项目经历深挖（需要关联简历提取项目信息）

面试结束（`is_finished: true`）后自动跳出对话，生成结构化评估报告（`GET /api/v1/interview/sessions/:id/report`），展示五维度评分和改进建议。

**面试对话页的SSE处理**：与QA流式类似，但额外处理 `stage` 事件（阶段切换时前端显示阶段提示条）和 `question_type` 元数据（标注当前问题是技术广度还是深度追问）。

### 9.2.7 角色权限在UI上的体现

学生和教师看到的是同一套前端，通过JWT里的 `role` 字段控制页面权限：

- **学生角色**：侧边栏显示「智能问答」「试卷批改」「简历审查」「模拟面试」
- **教师角色**：额外显示「教师端→批改确认」「教师端→知识库管理」
- **管理员角色**：额外显示所有管理功能

路由守卫 `router/index.ts` 中的 `beforeEach` 导航守卫检查 `auth.role`，无权访问的页面自动跳转回Dashboard。

## 9.3 完整系统启动与联调验证

### 9.3.1 前提条件

在启动前端之前，确认后端基础设施已就绪：

```bash
# 检查基础服务运行状态
docker-compose --env-file .env.local ps
# 应看到 postgres、redis、minio、milvus 状态为 Up

# 检查后端能否正常启动
conda activate edu_agent
uvicorn backend.main:app --reload --port 8000
# 浏览器打开 http://localhost:8000/docs，能看到 Swagger 文档说明后端正常
```

### 9.3.2 安装前端依赖

进入 `frontend/` 目录，安装Node.js依赖（只需做一次）：

```bash
cd frontend
npm install
```

> Node.js版本要求：**18+**。可用 `node --version` 检查，低于18请先升级。

### 9.3.3 配置前端环境变量

```bash
# 在 frontend/ 目录下，复制模板
cp .env.example .env.local
```

`.env.local` 内容只有一行，保持默认即可（本机开发）：

```bash
VITE_API_BASE_URL=http://localhost:8000
```

这个变量告诉前端SSE流式请求的目标地址。如果后端运行在其他机器上，把 `localhost` 改成对应IP。

### 9.3.4 启动前端开发服务器

```bash
# 在 frontend/ 目录下
npm run dev
```

控制台输出类似：
```
  VITE v5.x.x  ready in 800 ms

  > Local:   http://localhost:3000/
  > Network: use --host to expose
```

### 9.3.5 两个终端同时运行

正常开发时需要**两个终端**分别维持：

| 终端 | 命令 | 端口 |
|------|------|------|
| 终端A | `uvicorn backend.main:app --reload --port 8000` | :8000 后端 |
| 终端B | `cd frontend && npm run dev` | :3000 前端 |

两者都在运行时，浏览器访问 `:3000` 即是完整系统。

### 9.3.9 异常场景处理

**场景一：后端中途重启**
- 前端页面会卡在当前状态，刷新页面后重新登录即可
- SSE流式连接会断开，需要重新发送问题

**场景二：DeepSeek API限流**
- QA Agent回答变慢或返回错误
- 后端日志显示 `rate_limit_exceeded`
- 解决方案：等待一段时间后重试，或切换API Key

**场景三：Milvus连接超时**

- 检查 `docker-compose ps` 确认Milvus状态
- 重启Milvus容器：`docker-compose restart milvus`

## 核心设计决策总结

### 1. Vite Proxy + SSE直连双通道
**决策**：普通请求走Vite proxy，SSE流式请求直连后端。
**理由**：Vite proxy基于Node.js会缓冲响应体，导致SSE流式事件帧被批量堆积。直连后端确保逐帧实时推送。
**核心文件**：`frontend/vite.config.ts`、`frontend/.env.local`

### 2. JWT鉴权自动注入
**决策**：Axios请求拦截器自动从localStorage读取token并注入Header，响应拦截器捕获401后自动跳转登录。
**理由**：业务代码无需处理鉴权细节，统一在 `client.ts` 中封装。Token过期后自动清除状态并跳转。
**核心文件**：`frontend/src/api/client.ts`、`frontend/src/stores/auth.ts`

### 3. 角色权限路由守卫
**决策**：Vue Router的 `beforeEach` 导航守卫检查 `auth.role`，控制页面可见性。
**理由**：SPA的鉴权在前端做第一层过滤，后端API层做第二层校验。学生和教师看到不同菜单。
**核心文件**：`frontend/src/router/index.ts`

### 4. SSE流式逐帧渲染
**决策**：QA和面试对话使用 `fetch` 原生API读取SSE流，逐帧解析JSON事件，按 `type` 分发渲染。
**理由**：8种事件类型分别对应不同UI组件（token→气泡、progress→进度条、meta→来源引用、guidance→引导卡片等），按事件类型分别渲染。
**核心文件**：`frontend/src/views/qa/QAChatView.vue`、`frontend/src/views/interview/InterviewChatView.vue`

### 5. 轮询 vs WebSocket
**决策**：简历审查结果和试卷批改状态使用轮询（`setInterval` 定时请求），而非WebSocket。
**理由**：这些场景是"一次性等待完成"而非"持续双向通信"，轮询实现简单且足够。Agent处理时间在10-30秒，轮询间隔3秒即可。
**核心文件**：`frontend/src/views/resume/ResumeReportView.vue`

### 6. 前端只是展示层
**决策**：所有业务逻辑（Agent执行、路由判断、知识检索、评分计算）都在后端，前端只负责展示和交互。
**理由**：保持前后端分离的清晰边界。前端不存储任何业务状态，所有数据都从后端API获取。更换前端框架不影响核心业务。
**核心文件**：`frontend/src/views/*`、`frontend/src/api/*`

### 7. 环境变量分离
**决策**：使用 `.env.local` 管理前端环境变量，`VITE_API_BASE_URL` 控制SSE直连目标地址。
**理由**：`.env.local` 被 `.gitignore` 忽略，不会污染版本控制。不同环境（开发/测试/生产）只需修改此文件。
**核心文件**：`frontend/.env.example`、`frontend/.env.local`
