## 第一梯队：系统定位

---

### ① 四大痛点与 EduAgent 定位

#### 学习目标

- IT 教育培训机构的四大痛点是什么？各自对应哪个 Agent？
- 通用大模型不够用的三个原因？
- EduAgent 的定位是什么？融合了哪三大核心能力？

#### 核心知识点

**四大痛点与对应 Agent**

| 痛点 | 核心矛盾 | 对应 Agent |
|------|---------|-----------|
| 学员答疑 | 老师精力有限 vs 重复问题多 | QA（智能问答） |
| 试卷批改 | 工作量大 vs 评分一致性要求高 | Exam（试卷批改） |
| 简历审查 | 简历数量多 vs 没时间逐份精读 | Resume（简历审查） |
| 模拟面试 | 需要专业陪练 vs 缺少面试官资源 | Interview（模拟面试） |

**通用大模型不够用的三个原因**

1. **缺少企业私有知识** → 幻觉：模型不知道机构的课程大纲、教材案例、常见错误
2. **缺少业务流程** → 多步骤有状态：试卷批改需要多步流转，模拟面试是分阶段状态机
3. **缺少工程化可靠性** → 无重试/降级/超时/熔断机制

**EduAgent 定位**：AI 原生教学辅助系统，融合三大核心能力：

- **私有知识融合**：RAG 技术注入机构私有知识，根本上解决幻觉问题
- **内置业务流程**：LangGraph 图模型将教学流程建模为状态图，每一步有明确的输入输出和状态管理
- **容错机制**：内置重试、降级、超时、熔断等工程化保障

> **核心目标**：掌握一套可迁移到任何企业业务场景的多 Agent 系统开发方法论

### ② 四大 Agent 对比

#### 学习目标

- 四个 Agent 分别用什么技术方案？各自教你什么技术？
- 各自的状态管理方式是什么？

#### 核心知识点

| 维度 | QA | Exam | Resume | Interview |
|------|-----|------|--------|-----------|
| 技术方案 | RAG 检索增强生成 | 三轨并行批改 + HitL | 结构化抽取 + 多维并行评分 | 状态机多阶段对话 + 流式输出 |
| 核心教你 | RAG 管线/向量检索/嵌入模型 | 并行任务编排/HitL | 信息抽取/并行评分聚合 | 状态机设计/流式/对话管理 |
| 状态管理 | 无状态 | 有状态（批改进度） | 有状态（评估进度） | 复杂状态机 |
| 复杂度 | 中等 | 高 | 中等 | 很高 |

### ③ 技术栈

#### 学习目标

- EduAgent 用了哪些核心组件？各自的用途是什么？
- 进程内部署模式有什么特点？

#### 核心知识点

| 组件 | 用途 |
|------|------|
| Python 3.11 + 全异步 | 全异步编程（FastAPI→asyncpg→httpx 全链路异步） |
| FastAPI | Web 框架，REST API + SSE 流式接口 |
| LangChain 1.2.10 | LLM 应用框架（版本严格锁定） |
| LangGraph 1.0.9 | Agent 编排框架（图模型） |
| DeepSeek-V3 | 大语言模型（API 调用） |
| Milvus | 向量数据库 |
| PostgreSQL | 关系数据库 |
| BGE-M3 | 嵌入模型（dense+sparse 双输出，进程内） |
| BGE-Reranker | 重排序模型（进程内） |
| MiniLM | 意图分类模型（进程内） |

**进程内部署**：模型与主应用同进程，函数调用无网络开销，部署简化但无法独立扩缩容。

## 第二梯队：架构设计

---

### ④ 六层分层架构

#### 学习目标

- EduAgent 的六层架构从底到顶是什么？
- 各层之间的调用关系？

#### 核心知识点

```
API层（FastAPI REST/SSE）
  → 编排层（Orchestrator 意图识别 + 路由）
    → Agent层（QA/Exam/Resume/Interview）
      → 公共层（嵌入/重排序/分类）
        → MCP层（统一LLM接口 + 重试降级）
          → 数据层（Milvus/PostgreSQL/文件/缓存）
```

---

### ⑤ Agent 五大能力与四种形态

#### 学习目标

- Agent 的五大能力是什么？
- Agent 的四种形态分别是什么？EduAgent 选用了哪种？

#### 核心知识点

**Agent 五大能力**：感知（接收输入）→ 记忆（短期/长期/工作记忆）→ 决策（LLM/规则/混合）→ 行动（调用 LLM/工具/其他 Agent）→ 可循环/可中断

> **Agent = 大模型 + 记忆 + 工具 + 自主循环**

**Agent 四种形态**

| 形态 | 特点 | 适用场景 |
|------|------|---------|
| 单次 LLM 调用 | 无状态无工具无循环 | 简单翻译/摘要 |
| 固定工作流（Chain） | 步骤固定顺序执行 | RAG 问答（检索→重排序→生成） |
| 单 Agent 自主循环 | 灵活决策，可循环 | 代码生成/数据分析 |
| 多 Agent 协作 | 职责清晰，可扩展 | 复杂企业业务系统 |

**EduAgent 选择**：每个 Agent 内部用固定工作流（可控可预测），系统层面用多 Agent 协作（灵活编排）。

## 第三梯队：核心概念

---

### ⑥ LangGraph 图模型四要素

#### 学习目标

- LangGraph 图的四要素是什么？分别如何理解？
- 实现一个 Agent 的五步套路？

#### 核心知识点

| 要素 | 说明 | 类比 |
|------|------|------|
| **State** | TypedDict 定义，所有节点共享的数据结构 | 贯穿全程的「工单」 |
| **Node** | 处理单元，函数接收 State 返回"要更新的字段"字典 | 工位上的工人 |
| **Edge** | 固定边（无条件）和条件边（根据条件路由） | 传送带或分拣口 |
| **Checkpointer** | 持久化 State，实现中断恢复和记忆 | 存档点 |

**实现五步套路**：定义 State → 写节点函数 → 连接边 → 绑定 Checkpointer → 编译运行

---

### ⑦ Orchestrator 职责

#### 学习目标

- Orchestrator 的两个层次分别做什么？

#### 核心知识点

- **层次一**：意图识别 + 单 Agent 路由（MiniLM 分类，置信度 < 0.7 请求确认）
- **层次二**：多 Agent 串联 Pipeline（通过 context 字典传递数据）
