### ① Python 异步编程 (2.1)

#### 学习目标（学完要能回答）

- 同步与异步的区别？为什么 I/O 密集型场景用异步？
- 协程、`async/await`、`asyncio.run` 的关系？
- 如何用 `asyncio.gather` 实现并发？
- `run_in_executor` 解决什么问题？怎么用？
- 后台任务为什么会被 GC 回收？如何防御？
- `@asynccontextmanager` 的 yield 前后分别在什么时候执行？

#### 核心知识点

**1. 同步 vs 异步**

| 维度 | 同步 | 异步 |
|------|------|------|
| 执行方式 | 一个一个等，串行 | 一起下单，一起等 |
| 耗时 | 多个等待累加 | ≈ 最慢的那个 |
| 适用场景 | CPU 密集型 | I/O 密集型（API 调用、数据库查询、向量检索） |
| 生活类比 | 一杯一杯排队点咖啡 | 三杯一起下单，谁好了拿谁 |

**2. 协程三件套**

```python
async def fetch():          # ① async def 定义协程（调用后不执行，返回协程对象）
    await asyncio.sleep(1)  # ② await 等待结果（只能写在 async def 内部）
    return "done"

asyncio.run(fetch())        # ③ asyncio.run 是总入口（整个程序通常只有一个）
```

**3. `asyncio.gather` — 并发**

```python
results = await asyncio.gather(
    fetch("A", 2), fetch("B", 2), fetch("C", 2),
)
# 总耗时 ≈ 2 秒，不是 6 秒；按传入顺序收集返回值
```

> **EduAgent 应用**：启动时并行预热 3 个本地模型、简历六维度并行评分、试卷多题并行批改

**4. `run_in_executor` — 同步阻塞代码的安全写法**

```python
loop = asyncio.get_running_loop()
result = await loop.run_in_executor(None, sync_func, arg1, arg2)
```

> **核心原则**：协程里绝对不能直接调 `time.sleep`、`requests.get` 等同步阻塞函数，会卡死事件循环

> **EduAgent 应用**：所有本地模型推理（BGE-M3/Reranker/MiniLM）、PDF/Word 解析、密码校验

**5. `create_task` — 后台任务 + GC 保护**

```python
_background_tasks: set[asyncio.Task] = set()  # 模块级集合

task = asyncio.create_task(background_job())
_background_tasks.add(task)                     # ① 强引用，防GC回收
task.add_done_callback(_background_tasks.discard)  # ② 完成自动移除
```

**6. `@asynccontextmanager` — 异步上下文管理器**

```python
@asynccontextmanager
async def lifespan():
    print("【启动】加载模型、建立连接")   # yield 之前 = 启动逻辑
    yield
    print("【关闭】释放资源、清理缓存")   # yield 之后 = 关闭逻辑
```

> **EduAgent 应用**：`main.py` 的 lifespan 函数，启动时迁移 DB + 预热模型，关闭时清理缓存

**7. 三个常见坑**

| 坑 | 错误写法 | 正确写法 |
|----|---------|---------|
| 忘记 await | `result = get_value()` → 拿到协程对象 | `result = await get_value()` |
| 事件循环里再调 run | `asyncio.run(...)` 在 FastAPI 接口里 | 直接 `async def` 接口，框架已启动 |
| 协程里写阻塞调用 | `time.sleep(5)` | `await asyncio.sleep(5)` 或 `run_in_executor` |

### ② Pydantic (2.2)

#### 学习目标

- Pydantic 解决了什么问题？两大用途是什么？
- `Field` 的 `description` 为什么是大模型结构化输出的关键？
- `default` 和 `default_factory` 的区别？
- 嵌套模型如何工作？字典如何自动转成子模型对象？
- `model_dump()` 的作用？
- `Enum` 和 `BaseSettings` 的典型用法？

#### 核心知识点

**1. 核心价值**

自动校验 + 合理类型转换，替代手动 `isinstance` 检查：

```python
class Student(BaseModel):
    name: str          # 自动校验类型
    age: int           # "18" 自动转成 18

Student(name="小刚", age="十八")  # → ValidationError
```

**两大用途**：① 让大模型输出结构化数据（最重要） ② 读取配置与接口参数

**2. `Field` 的 `description` — 大模型的填空指令**

```python
class PersonInfo(BaseModel):
    name: str = Field(description="姓名")
    age:  int = Field(description="年龄（整数）")
```

> ⭐ **核心心法**：写 Pydantic 模型 = 设计大模型输出格式 = 写提示词的一部分。`description` 写得越清楚，大模型填得越准。

**必填 vs 可选**：没写 `default` 的字段是必填，写了 `default` 的是可选。

**3. `default_factory=list` — 可变默认值**

```python
tags: list[str] = Field(default_factory=list, description="标签列表")
# 禁止写 default=[]，会共享同一个列表，污染其他实例
```

**4. 嵌套模型**

```python
class EducationItem(BaseModel):
    school: str = Field(description="学校名称")
    major:  str = Field(description="专业名称")

class Resume(BaseModel):
    education: list[EducationItem] = Field(default_factory=list)

# 字典自动转成子模型对象
resume = Resume(education=[{"school": "清华大学", "major": "计算机"}])
print(resume.education[0].school)  # 清华大学（已经是 EducationItem 对象）
```

**5. 模型 ↔ 字典转换**

```python
d = student.model_dump()          # 模型 → 字典（存库、返回 JSON）
s = Student(**data_dict)          # 字典 → 模型（自动校验）
```

**6. `Enum` + `BaseSettings`**

```python
class InterviewStage(str, Enum):  # 固定取值
    WARMUP = "warmup"
    TECH_BASE = "tech_base"

class Settings(BaseSettings):     # 从 .env 文件读配置
    db_host: str = "localhost"
    db_port: int = 5433
```

**2. 创建模型 — 1.x 新写法**

llm = init_chat_model(
    model="deepseek-chat",           # ❌ 不能写成 "deepseek/deepseek-chat"
    model_provider="openai",         # 走 OpenAI 兼容协议
    api_key="sk-xxx",

**3. 消息体系**

```python
SystemMessage(content="你是一位严谨的简历评审专家")  # 人设规则
HumanMessage(content="这段代码报错了")                # 用户输入
AIMessage(content="我来帮你排查")                     # 模型回复
```

**EduAgent 风格**：直接用 f-string 拼提示词，不用 `ChatPromptTemplate`，一目了然好调试。

**4. 调用模型**

```python
response = await llm.ainvoke(messages)   # 异步调用，返回 AIMessage
print(response.text)                      # 取文本（属性，不加括号！）
```

> ⭐ **强制规范**：`response.text` 是属性，**不是方法**，禁止写成 `response.text()`

**5. `with_structured_output` ⭐ — 核心招式**

```python
structured_llm = llm.with_structured_output(PersonInfo, method="function_calling")
result: PersonInfo = await structured_llm.ainvoke(messages)
print(result.name)  # 直接访问，不需要解析 JSON
```

> ⭐ **强制规范**：`method="function_calling"` **必须写**（DeepSeek 不支持 `json_schema` 模式）

**6. 流式输出**

```python
async for chunk in llm.astream(messages):
    print(chunk.text, end="", flush=True)  # 打字机效果
```

**7. 禁用/必用对照表**

| 用途 | 禁用（旧写法） | 必用（新写法） |
|------|---------------|---------------|
| 创建模型 | `ChatOpenAI(...)` | `init_chat_model(...)` |
| 串联调用 | `LLMChain` / `AgentExecutor` | LangGraph 状态图 |

### ④ LangGraph (2.4)

#### 学习目标

- Agent 四要素是什么？分别如何理解？
- 实现一个 Agent 的五步套路？
- 条件边如何工作？路由函数的作用？
- `MemorySaver` + `thread_id` 如何实现多轮记忆？
- `add_messages` 的作用？

#### 核心知识点

**1. 四要素心智模型**

| 要素 | 说明 | 类比 |
|------|------|------|
| **State** | 所有节点共享的数据，`TypedDict` 定义 | 贯穿全程的「工单」 |
| **Node** | 处理单元，读 State，返回要更新的字段 | 工位上的工人 |
| **Edge** | 固定边或条件边，决定流向 | 传送带或分拣口 |
| **Checkpointer** | 持久化 State，实现记忆和恢复 | 存档点 |

**2. 实现五步**

```python
# ① 定义 State
class HelperState(TypedDict):
    question: str
    category: str
    answer: str

# ② 写节点函数（接收 State，返回要更新的字段字典，不直接修改 State）
def classify_node(state: HelperState) -> dict:
    return {"category": "concept"}   # 只返回要更新的字段

# ③ 搭图
builder = StateGraph(HelperState)
builder.add_node("classify", classify_node)
builder.add_edge(START, "classify")    # ✅ 入口用 START，禁 set_entry_point
builder.add_edge("classify", END)      # ✅ 出口用 END，禁 set_finish_point

# ④ 编译
graph = builder.compile()

# ⑤ 运行
result = graph.invoke({"question": "什么是装饰器", "category": "", "answer": ""})
```

**3. 条件边 — 分支路由**

```python
def route_by_category(state: HelperState) -> str:
    return state["category"]  # 返回 "concept" / "code" / "chat"

builder.add_conditional_edges(
    "classify",                # 从哪个节点出发
    route_by_category,         # 路由函数
    {"concept": "concept", "code": "code", "chat": "chat"},  # 路标→目标
)
```

**4. 多轮记忆 — `MemorySaver` + `thread_id`**

```python
# State 定义
class ChatState(TypedDict):
    messages: Annotated[list, add_messages]  # 追加而非覆盖

# 编译时绑定 Checkpointer
graph = builder.compile(checkpointer=MemorySaver())

# 调用时传入同一 thread_id
config = {"configurable": {"thread_id": "user-1"}}
graph.invoke({"messages": [HumanMessage(content="你好")]}, config)
graph.invoke({"messages": [HumanMessage(content="还记得我吗")]}, config)  # 有记忆
```

**`add_messages` 的三个功能**：追加、自动包装字符串为 `HumanMessage`、相同 ID 去重替换

**5. `interrupt` / `Command` — 人在环中**

```python
interrupt("等待老师确认")           # 暂停图
Command(resume={"approved": True})  # 恢复执行
```

> **EduAgent 应用**：试卷批改 Agent 用此实现「AI 批改完 → 暂停 → 等老师确认 → 继续发布」流程

#### 学习目标

- SSE 流式响应如何实现？

#### 核心知识点

**1. 核心角色**：系统对外的 API 大门，接收请求 → 调用业务逻辑 → 返回结果

**两大招牌优势**：基于类型注解自动校验 + 全异步（与 `async def` 无缝配合）

**2. 路由 + Pydantic 请求体**

```python
@app.post("/login", response_model=TokenResponse)
async def login(req: LoginRequest, db: AsyncSession = Depends(get_db)):
    # req 已自动校验，直接用 req.username
    return TokenResponse(access_token="...", role="student")
```

**3. 依赖注入 `Depends` ⭐ — 复用通用逻辑**

**最重要的两个依赖：**

```python
# 依赖一：get_db — 数据库会话（yield 型）
async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:
        try:
            yield session            # yield 前 = 准备连接
            await session.commit()   # 接口正常结束 → 提交
        except Exception:
            await session.rollback() # 异常 → 回滚
            raise

# 依赖二：get_current_user — JWT 鉴权
async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme),
) -> dict:
    user = verify_jwt(credentials.credentials)
    if not user:
        raise HTTPException(status_code=401, detail="无效的认证凭证")
    return {"user_id": user["id"], "role": user["role"]}
```

**接口中使用：**

```python
@app.get("/my-reviews")
async def my_reviews(
    db = Depends(get_db),                       # 自动注入数据库会话
    current_user: dict = Depends(get_current_user),  # 自动鉴权
):
    return {"user": current_user["user_id"]}
```

**4. 文件上传**

```python
@app.post("/upload", status_code=202)  # 202 = 已接受，后台处理
async def upload(file: UploadFile = File(...)):
    content = await file.read()
    return {"filename": file.filename, "size": len(content)}
```

**5. SSE 流式响应 — 打字机效果**

### ⑥ PostgreSQL 实操 (2.6)

#### 学习目标

- PostgreSQL 与 MySQL 的关键差异（6 个方面）？
- 命令行连接方式？反斜杠元命令？
- UUID 主键、JSONB、`RETURNING`、`ON CONFLICT`、`CHECK`、触发器分别怎么用？
- 字符串和布尔值在 PG 中要注意什么？

#### 核心知识点

**1. PG vs MySQL 速查表**

| 特性 | MySQL | PostgreSQL |
|------|-------|-----------|
| 命令行 | `mysql -u root -p` | `psql -U 用户 -d 库` |
| 列出库 | `SHOW DATABASES;` | `\l` |
| 切库 | `USE 库名;` | `\c 库名` |
| 列出表 | `SHOW TABLES;` | `\dt` |
| 查看表结构 | `DESC 表名;` | `\d 表名` |
| 主键自增 | `INT AUTO_INCREMENT` | `UUID DEFAULT uuid_generate_v4()` |
| 布尔类型 | `TINYINT(1)`（0/1） | `BOOLEAN`（`true` / `false`） |
| JSON 类型 | `JSON` | `JSONB`（二进制，更快可索引） |
| 自动更新时间 | `ON UPDATE CURRENT_TIMESTAMP` | `TIMESTAMPTZ` + 触发器 |
| upsert | `INSERT ... ON DUPLICATE KEY UPDATE` | `INSERT ... ON CONFLICT ... DO UPDATE` |
| 插入后拿回主键 | `LAST_INSERT_ID()` | `RETURNING id` |
| CHECK 约束 | 8.0.16 之前被忽略 | 一直严格生效 |

**两个关键注意点**：
- 字符串一律用**单引号** `'student'`，双引号给标识符用
- 布尔值直接写 `true` / `false`，不是 `1` / `0`

**2. UUID 主键**

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";  -- 启用一次
id UUID PRIMARY KEY DEFAULT uuid_generate_v4()
```

**3. `RETURNING` — 插入后直接拿回数据**

```sql
INSERT INTO users (username, role) VALUES ('alice', 'student')
RETURNING id, username;  -- 一步到位，不需要再查一次
```

**4. `JSONB` — 查询操作符**

```sql
profile ->> 'city'   -- 取文本（"上海"）
profile -> 'tags'    -- 取 JSON（["java","spring"]）
WHERE profile ->> 'city' = '上海'  -- 按 JSON 内部字段过滤
```

**5. `ON CONFLICT` — upsert**

```sql
INSERT INTO users (username, role) VALUES ('alice', 'teacher')
ON CONFLICT (username) DO UPDATE
    SET role = EXCLUDED.role  -- EXCLUDED 指「本次要插入的新数据」
RETURNING username, role;
```

**6. `CHECK` 约束**

```sql
score INTEGER NOT NULL CHECK (score >= 0 AND score <= 100)
-- PG 严格生效，插 200 直接报错
```

**7. 触发器维护 `updated_at`**

```sql
-- ① 创建触发器函数
CREATE OR REPLACE FUNCTION touch_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- ② 挂到表上
CREATE TRIGGER trg_updated_at
BEFORE UPDATE ON users
FOR EACH ROW EXECUTE FUNCTION touch_updated_at();
```

### ⑦ SQLAlchemy 异步操作 (2.7)

#### 学习目标

- 异步三件套是什么？换数据库改什么？
- 为什么必须用参数化查询？写法是什么？
- 读取结果有哪几种方式？推荐哪种？
- 事务管理如何实现？

#### 核心知识点

**1. 异步三件套**

```python
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

DATABASE_URL = "postgresql+asyncpg://eduagent_user:密码@localhost:5433/eduagent"

engine = create_async_engine(DATABASE_URL)                              # ① 引擎+连接池
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)  # ② 会话工厂
# ③ AsyncSession → 执行 SQL 和管理事务
```

**换数据库**：只需改 `DATABASE_URL`，如 `mysql+aiomysql://...`

**2. 参数化查询 — 防 SQL 注入**

```python
result = await db.execute(
    text("SELECT * FROM users WHERE username = :name AND role = :role"),
    {"name": "小明", "role": "student"}  # 用字典传值，自动转义
)
```

> ⭐ **禁止**使用 f-string 拼接 SQL，存在注入风险

**3. 读取结果**

```python
row = result.mappings().fetchone()    # 推荐：返回 {"id": ..., "username": ...}
rows = result.mappings().fetchall()   # 推荐：返回字典列表
row = result.fetchone()               # 返回 Row 对象
rows = result.fetchall()              # 返回 Row 列表
```

**4. 完整 CRUD 示例**

```python
async with AsyncSessionLocal() as db:
    # 建表
    await db.execute(text("CREATE TABLE ..."))
    await db.commit()

    # 插入
    await db.execute(text("INSERT INTO users (name) VALUES (:name)"), {"name": "小明"})
    await db.commit()

    # 查询
    result = await db.execute(text("SELECT * FROM users"))
    for row in result.mappings():
        print(row["name"])

    # 更新 / 删除
    await db.execute(text("UPDATE users SET score = :s WHERE name = :n"), {"s": 90, "n": "小明"})
    await db.commit()
```

### ⑧ Reducer 状态合并 (2.8 — 选读)

#### 学习目标

- LangGraph 默认的状态合并规则是什么？
- 列表字段使用默认规则会有什么问题？
- `add_messages` 比 `operator.add` 多了哪些功能？
- 如何自定义 Reducer？

#### 核心知识点

**1. 默认规则：覆盖式合并**

节点返回 `{"score": 90}` → 直接覆盖 State 中 `score` 的值。没返回的字段保持原样。

**2. 列表字段的问题**

多个节点向 `messages` 添加内容，后一个会覆盖前一个 → 数据丢失。

**3. `Annotated[类型, 合并函数]` 解决方案**

```python
# operator.add：列表拼接
messages: Annotated[list, add]

# add_messages：消息专用（更智能）
messages: Annotated[list, add_messages]
# 功能：追加、自动包装字符串、相同 ID 去重替换
```

**4. 自定义 Reducer**

```python
def accumulate_total(current: int, update: int) -> int:
    return current + update

class StatsState(TypedDict):
    total: Annotated[int, accumulate_total]
```
