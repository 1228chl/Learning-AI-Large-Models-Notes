### ② 双通道通信

#### 学习目标

- 前端和后端分别运行在什么端口？
- 普通请求和 SSE 请求分别走什么通道？
- 为什么 SSE 要绕过 Vite proxy？

#### 核心知识点

**双通道设计**

```
用户浏览器 (:3000)
  ├── 普通请求（登录/上传/查询/轮询）
  │   → 走 Vite proxy（/api → localhost:8000）
  │   → Axios 自动注入 JWT
  │
  └── SSE 流式请求（QA 流式回答/面试对话）
      → fetch 直连后端 http://localhost:8000
      → 绕过 Vite proxy
```

**为什么 SSE 绕过 Vite proxy**：Vite proxy 基于 Node.js HTTP，默认会在内存里缓冲整个响应体再转发，导致 SSE 的 `data:` 事件帧被批量堆积，前端无法实时看到 token 流。

**解决方案**：`.env.local` 里的 `VITE_API_BASE_URL=http://localhost:8000`，SSE 请求用 `fetch` 直接请求这个地址，不走 Axios。

### ③ JWT 鉴权流程

#### 学习目标

- JWT 鉴权的完整流程？
- Axios 请求拦截器和响应拦截器分别做什么？

#### 核心知识点

```
用户登录
  → POST /api/v1/auth/login → 返回 access_token
  → auth.login() 写入 Pinia store + localStorage

后续每个请求
  → Axios 请求拦截器读取 localStorage 中的 token
  → 在 Header 附加 Authorization: Bearer <token>

Token 过期（后端返回 401）
  → Axios 响应拦截器捕获
  → 调用 auth.logout()，清除 store + localStorage
  → 跳转到 /login
```

**业务代码无需处理鉴权细节**，全封装在 `src/api/client.ts` 中。

### ⑥ 关键设计决策

#### 学习目标

- 为什么 Vite Proxy + SSE 直连双通道？
- 轮询 vs WebSocket 的选择？
- 角色权限如何实现？

#### 核心知识点

| 决策 | 方案 | 原因 |
|------|------|------|
| 通信通道 | Vite Proxy + SSE 直连双通道 | Proxy 处理普通请求，SSE 直连避免帧堆积 |
| 状态查询 | 轮询（setInterval，3 秒间隔） | 一次性等待完成场景，实现简单，无需 WebSocket |
| 角色权限 | JWT role + 前端路由守卫 + 后端 API 层校验 | 前端控制可见性，后端做第二层安全校验 |
