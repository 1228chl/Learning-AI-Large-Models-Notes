### ② 数据库设计（11 张表）

#### 学习目标

- 三大贯穿性设计是什么？
- 11 张表的核心用途和关键字段？
- 多租户 `tenant_id` 设计原理？
- 关键约束和索引策略？

#### 核心知识点

**三大贯穿性设计**

1. **UUID 主键**：`UUID DEFAULT gen_random_uuid()`，全局唯一不怕冲突，前端不暴露自增 ID
2. **多租户 `tenant_id`**：所有业务表含此字段，按租户逻辑隔离数据，默认值 `tenant_default`
3. **时间戳 + 触发器**：`created_at` + `updated_at`（`TIMESTAMPTZ`），触发器函数自动维护 `updated_at`

```sql
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**11 张表核心用途**

| 表名 | 用途 |
|------|------|
| `users` | 用户信息（含 `role`/`password_hash`，bcrypt 加密） |
| `knowledge_pending_queue` | 知识库待补充问题队列 |
| `exams` | 试卷基本信息 |
| `questions` | 试题（含题型/正确答案/分值/知识点标签） |
| `scoring_points` | 主观题评分要点 |
| `exam_submissions` | 学生答卷提交（状态流转：`submitted→ai_processing→pending_review→reviewed→published`） |
| `exam_reviews` | 逐题批改详情（含 AI 分/教师分/最终分） |
| `resume_reviews` | 简历审查结果（含 JSONB 字段） |
| `interview_questions` | 面试题库 |
| `interview_sessions` | 面试会话（含 `thread_id`/`report`/`status`） |
| `qa_sessions` | 问答会话 |

**关键约束**：
- `exam_submissions` 有 `UNIQUE (exam_id, student_id)` — 一人一卷只能提交一次
- `exam_reviews` 冗余存储 `question_type` 和 `knowledge_tag` — 避免频繁 JOIN
- 所有表的外键使用 `ON DELETE CASCADE` 级联删除

### ③ 配置、日志与异常体系

#### 学习目标

- `config.py` 的核心设计是什么？`@lru_cache()` 的作用？
- 结构化日志的写法？为什么要压制第三方库日志？
- 异常体系有哪些子类？哪些可重试？

#### 核心知识点

**`config.py` — 配置中心**

```python
class Settings(BaseSettings):
    db_host: str = "localhost"
    db_port: int = 5433
    db_user: str
    db_password: str                     # 无默认值 => 必填项
    deepseek_api_key: str                # 三个必填之一
    jwt_secret_key: str                  # 三个必填之一

    @property
    def database_url(self) -> str:
        return f"postgresql+asyncpg://{self.db_user}:{self.db_password}@{self.db_host}:{self.db_port}/eduagent"

    class Config:
        env_file = ".env.local"
        extra = "ignore"                 # .env.local 多出的字段自动忽略

@lru_cache()                             # 全局单例：只读一次文件
def get_settings() -> Settings:
    return Settings()
```

> ⭐ **核心设计**：`@lru_cache()` 保证全局单例——只创建一次 Settings、只读一次文件。`@property` 动态拼接 `database_url`，避免在 `.env.local` 存一长串。

**`logger.py` — 结构化日志**

```python
logger.info("Agent 开始执行", agent_type="resume", review_id=review_id)
logger.info("六维度评分完成", scores=dimension_scores, total=weighted_score)
```

- 支持 `logger.info("事件", key=value)` 写法
- 压制第三方库噪音：`sqlalchemy`/`httpx`/`httpcore` 提到 WARNING

**`exceptions.py` — 统一异常体系**

```python
class EduAgentBaseError(Exception):
    def __init__(self, message, agent_type="unknown", details=None):
        self.agent_type = agent_type
        self.details = details or {}
        super().__init__(message)

class LLMAPIError(EduAgentBaseError): pass    # 可重试
class MilvusConnectionError(EduAgentBaseError): pass  # 可重试
class InvalidInputError(EduAgentBaseError): pass  # 不可重试
```

| 异常类 | 是否可重试 | 说明 |
|--------|-----------|------|
| `LLMAPIError` | 是 | 大模型 API 调用失败 |
| `MilvusConnectionError` | 是 | Milvus 连接失败 |
| `AgentExecutionError` | 视情况 | Agent 业务逻辑执行失败 |
| `FileParseError` | 否 | 文件解析失败 |
| `InvalidInputError` | 否 | 用户输入不合法 |
| `AuthenticationError` | 否 | 认证失败 |

> **EduAgent 应用**：异常 `agent_type` 字段帮助定位是哪个 Agent 出错的，`details` 字典携带调试信息。

### ④ LLM Factory

#### 学习目标

- 为什么需要 LLM Factory？直接在各 Agent 里调 `init_chat_model` 有什么问题？
- 两个核心入口 `get_llm` 和 `get_structured_llm` 的区别？
- 为什么设置 `trust_env=False` 和 `max_retries=0`？

#### 核心知识点

**为什么需要**：避免各 Agent 重复配置 `model_provider`/`base_url`/`api_key`/`temperature`；统一管控超时、重试、代理。

**两个核心入口**

```python
def get_llm(agent_type: str, temperature=0, streaming=False):
    cache_key = f"deepseek-chat_{temperature}_{streaming}"
    if cache_key in _llm_cache:
        return _llm_cache[cache_key]

    http_client = httpx.AsyncClient(trust_env=False)   # 绕过系统代理
    llm = init_chat_model(
        model="deepseek-chat",
        model_provider="openai",
        temperature=temperature,
        max_retries=0,                                   # 重试统一由 retry.py 管理
        http_client=http_client,
    )
    _llm_cache[cache_key] = llm
    return llm

def get_structured_llm(agent_type: str, output_schema: type[BaseModel]):
    llm = get_llm(agent_type, temperature=0)
    return llm.with_structured_model(output_schema, method="function_calling")
```

**关键设计**：
- `trust_env=False`：绕过 Windows 系统代理（否则 DeepSeek 请求失败）
- 缓存键 `cache_key = f"{model}_{temperature}_{streaming}"`，相同参数只创建一次
- `max_retries=0`：模型层不重试，统一由 `retry.py` 管理
- 所有 Agent 当前全部使用 `deepseek-chat`，扩展性好

> **项目规定**：所有 Agent 必须通过工厂获取模型，**禁止直接调用 `init_chat_model`**。

### ⑤ 三层兜底与重试机制

#### 学习目标

- 三层兜底分别是什么？每层的触发条件和处理方式？
- 可重试异常和不可重试异常的区别？
- 降级函数为什么统一返回字典？

#### 核心知识点

```python
@with_retry(agent_type="qa")
async def qa_agent(query: str) -> dict:
    # 正常的 QA 逻辑
    ...
```

**三层兜底**

| 层级 | 触发条件 | 处理方式 |
|------|---------|---------|
| **第一层：自动重试** | 网络抖动/LLM 超时 | 最多重试 2 次（间隔 1s/3s），30s 超时保护 |
| **第二层：Agent 级降级** | 重试仍失败 | 退化为简单实现：QA→跳过检索直接答，批改→标记教师复核 |
| **第三层：系统级兜底** | 降级也失败 | 返回友好提示，保证用户始终能收到响应 |

**异常分类**
```python
RETRYABLE_ERRORS = (LLMAPIError, MilvusConnectionError, TimeoutError, ConnectionError)
NON_RETRYABLE_ERRORS = (InvalidInputError, AuthenticationError)
```

**降级函数示例**
```python
def _qa_fallback(state: dict) -> dict:
    return {
        "answer": "知识库暂时不可用，请您稍后再试，或直接联系老师。",
        "fallback_used": True,
    }
```

> **EduAgent 应用**：`@with_retry` 装饰器覆盖所有 Agent 的 LLM 调用，确保网络抖动时系统自动恢复，用户无感知。

### ⑥ 认证与依赖注入

#### 学习目标

- JWT 认证的完整流程？
- `bcrypt` 密码校验为什么要用 `run_in_executor`？
- `dependencies.py` 提供的两个 FastAPI 依赖？

#### 核心知识点

**JWT 认证流程**

```python
# ① 用户登录
@app.post("/login")
async def login(req: LoginRequest, db=Depends(get_db)):
    # ② 查用户+bcrypt校验密码
    user = await db.fetchrow(text("SELECT * FROM users WHERE username = :name"), {"name": req.username})
    if not user or not verify_password(req.password, user["password_hash"]):
        raise HTTPException(401)
    # ③ 签发 JWT Token
    token = jwt.encode({"user_id": user["id"], "role": user["role"]}, SECRET_KEY, algorithm="HS256")
    return {"access_token": token, "role": user["role"]}

# ④ 后续请求自动鉴权
@app.get("/me")
async def me(current_user=Depends(get_current_user)):
    return current_user
```

**`bcrypt` 密码安全**：
- 单向不可逆、自带盐值
- 密码校验是 CPU 密集型（~100ms），必须在异步接口里用 `run_in_executor` 丢到线程池

> **EduAgent 应用**：密码校验在 `login` 接口中通过 `run_in_executor` 执行，避免阻塞事件循环。

**`dependencies.py` 两个依赖**

```python
# 依赖一：get_db — 数据库会话
async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:
        try:
            yield session
            await session.commit()      # 正常结束 → 提交
        except Exception:
            await session.rollback()    # 异常 → 回滚
            raise

# 依赖二：get_current_user — JWT 鉴权
async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme),
) -> dict:
    user = verify_jwt(credentials.credentials)
    if not user:
        raise HTTPException(status_code=401, detail="无效的认证凭证")
    return {"user_id": user["id"], "role": user["role"]}
```
