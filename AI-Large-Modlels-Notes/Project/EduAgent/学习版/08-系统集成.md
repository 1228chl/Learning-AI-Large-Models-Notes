### ③ Schema 与单 Agent 直达

#### 学习目标

#### 核心知识点

**三个统一 Schema**

```python
class AgentRequest(BaseModel):
    agent_type: AgentType        # 路由到的 Agent 类型
    user_message: str            # 用户输入
    context: dict = {}           # 附加上下文
    pipeline_mode: bool = False  # 是否走串联 Pipeline

    @property
    def thread_id(self) -> str:
        return f"student_{self.student_id}_session_{self.session_id}"

class AgentResponse(BaseModel):
    success: bool                # 是否成功
    agent_type: AgentType        # 哪个 Agent 返回的
    content: str                 # 文本响应
    structured: dict | None      # 结构化数据（评分/报告）
    fallback_used: bool = False  # 是否触发降级
    error_msg: str | None        # 错误信息

class PipelineResult(BaseModel):
    steps: list[AgentResponse]   # 各步 AgentResponse 列表
    combined: dict               # 聚合后的最终数据
```

**图懒加载**

```python
class Orchestrator:
    _agent_graphs: dict = {}     # 图缓存
    _pipelines: dict = {}        # Pipeline 定义

    def _get_agent_graph(self, agent_type: AgentType):
        if agent_type not in self._agent_graphs:
            # 内部 import，推迟到真正需要时
            if agent_type == AgentType.QA:
                from backend.agents.qa.graph import build_qa_graph
                self._agent_graphs[agent_type] = build_qa_graph()
            elif agent_type == AgentType.RESUME:
                from backend.agents.resume.graph import build_resume_graph
                self._agent_graphs[agent_type] = build_resume_graph()
            # ...
        return self._agent_graphs[agent_type]
```

**为什么需要懒加载**：四个 Agent 图各自有不小的初始化成本（QA 图要连 Milvus、装载 reranker），全量加载拖慢启动且没用到的 Agent 也白占资源。

```python
_pipelines = {
    "job_preparation": [AgentType.RESUME, AgentType.INTERVIEW],
}

async def _run_pipeline(self, request: AgentRequest) -> PipelineResult:
    context = {}
    for i, agent_type in enumerate(self._pipelines[request.pipeline_mode]):
        # 每个 step 加独立 session_id 后缀，防检查点串台
        step_request = AgentRequest(
            agent_type=agent_type,
            context=context,
            session_id=f"{request.session_id}_step{i}",
        )
        # 前序 structured_output 注入后序 context
        response = await self._run_single_agent(step_request)
        if response.structured:
            context[f"{agent_type.value}_result"] = response.structured
        # 某步失败时 break，保留已完成步骤结果
        if not response.success:
            return PipelineResult(steps=..., combined=...)
    return PipelineResult(steps=..., combined=...)
```

#### 核心知识点

```python
async def handle(self, request: AgentRequest) -> AgentResponse:
    try:
        if request.pipeline_mode:
            return await self._run_pipeline(request)
        return await self._run_single_agent(request)
    except Exception as e:
        # 最外层保险：无论怎么炸，都返回合法响应
```

### ⑥ 前置拦截与 LLM 路由

#### 学习目标

- 前置拦截的五类场景？为什么能零 Token？
- 六类意图映射分别是什么？
- 为什么路由用 LLM 不用本地分类模型？失败如何处理？

#### 核心知识点

**前置拦截五类**：HELLO（你好/嗨）、THANKS（谢谢）、GOODBYE（再见）、WHO_ARE_YOU（你是谁）、CAPABILITIES（你能做什么）。精确匹配 + 正则匹配，**零 Token 模板回复**。

```python
_PRE_FILTERS = {
    "hello": re.compile(r"^(你好|嗨|hi|hello|hey)\s*$", re.I),
    "thanks": re.compile(r"^(谢谢|感谢|thanks|thank you)\s*$", re.I),
    # ...
}

def _pre_filter(message: str) -> str | None:
    for key, pattern in _PRE_FILTERS.items():
        if pattern.match(message.strip()):
            return TEMPLATES[key]  # 零 Token 模板回复
    return None
```

**六类意图映射**

| 意图 | 含义 | 执行方式 |
|------|------|---------|
| qa | 技术问答 | 单 Agent 流式 |
| exam | 试卷批改 | 引导跳转 |
| resume | 简历审查 | 引导跳转 |
| interview | 模拟面试 | 引导跳转 |
| multi_agent | 求职全链路 | Pipeline 计划 |
| clarify | 意图不明 | 追问澄清 |

**为什么路由用 LLM 不用本地分类模型**：调用频率低（仅统一入口一处），省一个本地模型，改 Prompt 即可新增意图。失败时降级回 qa。

```python
async def _stream_by_label(label, request, event_generator):
    if label == "qa":
```
