## 第一梯队：全景理解

---

### ① 系统集成全景

#### 学习目标

- 前四章造了什么？第八章做什么？
- 两个核心角色分别是什么？一句话职责？

#### 核心知识点

**前四章成果**

| Agent | 范式 | 章节 |
|-------|------|------|
| 简历审查 | 并行评审（六维度 fan-out/fan-in） | 第 4 章 |
| 智能问答 | RAG（检索增强 + 记忆） | 第 5 章 |
| 试卷批改 | Human-in-the-Loop（interrupt/resume） | 第 6 章 |
| 模拟面试 | 状态机 + SSE（多轮对话） | 第 7 章 |

**第八章核心任务**：在四个 Agent 前面架一个统一入口，用户只说一句话，系统自动判断路由到哪个 Agent。

**两个核心角色**

| 文件 | 角色 | 一句话职责 |
|------|------|-----------|
| unified_chat.py | **统一入口（接待员）** | 收一句话→判断意图→SSE 流式返回 |
| orchestrator.py | **编排器（调度台）** | 拿到明确 agent_type→直调对应 Agent 图，或按序串联多个 Agent |

**关键认知**：本章几乎不造新轮子，所有 Agent 图、异常体系、重试降级、LLM 工厂、MCP 工具、本地模型全部在前面章节已经实现。本章的工作是**装配**。

#### 学习目标

- 用户一句话的完整流程？

#### 核心知识点

```
用户一句话
```

## 第二梯队：Orchestrator

---

### ③ Schema 与单 Agent 直达

#### 学习目标

- 三个统一 Schema 分别是什么？
- 图懒加载为什么重要？
- 懒加载如何在代码层面实现？

#### 核心知识点

**三个统一 Schema**

| Schema | 用途 | 关键字段 |
|--------|------|---------|
| AgentRequest | 统一入参 | agent_type, user_message, context, pipeline_mode |
| AgentResponse | 统一出参 | success, content, structured, fallback_used |
| PipelineResult | 串联结果 | steps（各步 AgentResponse）, combined |

**图懒加载**：`_get_agent_graph` 首次用到某 Agent 才 build 图并缓存。`get_orchestrator()` 单例让图缓存全程复用。在 `_get_agent_graph` 内部 import 而不是文件顶部 import，也是懒加载的一部分。

**为什么需要懒加载**：四个 Agent 图各自有不小的初始化成本（QA 图要连 Milvus、装载 reranker），全量加载拖慢启动且没用到的 Agent 也白占资源。

---

### ④ 多 Agent 串联 Pipeline

#### 学习目标

- Pipeline 的顺序是什么？上下文如何传递？
- 如何防止检查点串台？

#### 核心知识点

**求职全链路 Pipeline**：简历审查 → 模拟面试。前序 structured_output 以 `{agent}_result` 为 key 注入 context，后序通过 `**request.context` 平铺进自己的 State。

**关键设计**：
- 独立 session_id（加 `_step{idx}` 后缀）防检查点串台
- 某步失败时 break 保留已完成步骤结果

### ⑤ handle 两层兜底

#### 核心知识点

- **`_run_single_agent` 内部**：用 `@with_retry`（第 3.5 章三层兜底）处理"Agent 执行中"的失败
- **handle 最外层**：`try/except` 保证无论怎么炸都返回合法 `AgentResponse(success=False, content=友好文案)`，绝不把异常抛到 API 层

## 第三梯队：统一入口

---

### ⑥ 前置拦截与 LLM 路由

#### 学习目标

- 前置拦截的五类场景？为什么能零 Token？
- 六类意图映射分别是什么？
- 为什么路由用 LLM 不用本地分类模型？失败如何处理？

#### 核心知识点

**前置拦截五类**：HELLO（你好/嗨）、THANKS（谢谢）、GOODBYE（再见）、WHO_ARE_YOU（你是谁）、CAPABILITIES（你能做什么）。精确匹配 + 正则匹配，**零 Token 模板回复**。

**六类意图映射**

| 意图 | 含义 | 执行方式 |
|------|------|---------|
| qa | 技术问答 | 单 Agent 流式 |
| exam | 试卷批改 | 引导跳转 |
| resume | 简历审查 | 引导跳转 |
| interview | 模拟面试 | 引导跳转 |
| multi_agent | 求职全链路 | Pipeline 计划 |
| clarify | 意图不明 | 追问澄清 |

**为什么路由用 LLM 不用本地分类模型**：
- 调用频率低（仅统一入口一处），一次 LLM 调用开销完全可接受
- 省一个本地模型，部署更轻
- 改 Prompt 即可新增意图，不用重训模型

**异常兜底**：LLM 路由失败降级回 qa，不阻断 SSE 流。

### ⑦ SSE 分发

#### 学习目标

- 8 种事件类型分别是什么？前端表现？
- 四分支分发逻辑？

#### 核心知识点

| 事件类型 | 何时推送 | 前端表现 |
|----------|---------|----------|
| routing_decision | LLM 路由判完 | 顶部"已为你转接到【智能问答】"卡片 |
| progress | QA 各节点开始 | "检索知识库中..."进度条 |
| token | QA 生成时逐字 | 答案气泡逐字打出 |
| meta | QA 答完 | 答案模式/引用来源 |
| guidance | exam/resume/interview/clarify | 引导卡片（含"前往 XX"按钮） |
| pipeline_plan | multi_agent | 多步骤计划卡片 |
| done | 流结束 | 结束信号 |
| error | 异常 | 错误提示 |

**四分支分发**：
- **qa 分支**：通过 `astream_events` 逐 token 推送，同时推 progress 和 meta 事件
- **exam/resume/interview 分支**：推 guidance 引导卡片（含跳转链接 action_url）
- **multi_agent 分支**：推 pipeline_plan 多步骤计划卡片
- **clarify 分支**：推 guidance 提示用户补充信息

---

### ⑧ 路由聚合与 main 集成

#### 学习目标

- router.py 聚合了哪些路由？
- lifespan 启动时做哪三件事？

#### 核心知识点

**router.py**：6 个 APIRouter 聚合（auth/chat/qa/exam/resume/interview），统一前缀 `/api/v1`。

**lifespan 启动三件事**：
1. DB 迁移（`run_migrations`）
2. 并行预热三个本地模型（`asyncio.gather` + `run_in_executor`）
3. MCP 子应用生命周期管理

**Windows conda 兼容**：文件头将 base 环境 Library/bin 加入 DLL 搜索路径。
