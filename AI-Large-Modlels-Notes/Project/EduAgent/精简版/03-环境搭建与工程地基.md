# 第 3 章 环境搭建与工程地基

## 3.1 环境与基础设施

**基础设施**：PostgreSQL（业务数据）+ Milvus（向量数据）。etcd 和 MinIO 是 Milvus 内部依赖，应用不直接连。

**端口隔离**：PostgreSQL 5433、Milvus 19531、FastAPI 8000，从.env.local 读取，代码不写死。

**Python 环境**：Python 3.11 严格锁定，conda 创建。

**requirements.txt 关键锁定**：`langchain==1.2.10`、`langgraph==1.0.9`、`bcrypt==4.0.1`（新版与 passlib 不兼容）。

**docker-compose**：启动 5 个服务(postgres/etcd/minio/milvus/attu)。

**.env.local 三个必填项**：`DB_PASSWORD`、`DEEPSEEK_API_KEY`、`JWT_SECRET_KEY`。必须加入.gitignore。

## 3.2 数据库设计（11 张表）

**三大贯穿设计**：

1. **UUID 主键**：`UUID DEFAULT gen_random_uuid()`，全局唯一不怕冲突
2. **多租户 tenant_id**：所有业务表含此字段，按租户逻辑隔离数据
3. **时间戳+触发器**：`created_at` + `updated_at`，触发器自动维护 updated_at

**11 张表核心用途**：

| 表名 | 用途 |
|------|------|
| users | 用户信息（含角色 role/password_hash） |
| knowledge_pending_queue | 知识库待补充问题队列 |
| exams | 试卷基本信息 |
| questions | 试题（含题型/正确答案/分值/知识点标签） |
| scoring_points | 主观题评分要点 |
| exam_submissions | 学生答卷提交（状态流转：submitted→ai_processing→pending_review→reviewed→published） |
| exam_reviews | 逐题批改详情（含 AI 分/教师分/最终分） |
| resume_reviews | 简历审查结果（含 JSONB 字段：structured_data/scores/issues） |
| interview_questions | 面试题库 |
| interview_sessions | 面试会话（含 thread_id/report/status） |
| qa_sessions | 问答会话 |

**关键约束**：`exam_submissions` 有 `UNIQUE (exam_id, student_id)` 一人一卷只能提交一次；`exam_reviews` 冗余存储 `question_type` 和 `knowledge_tag` 避免频繁JOIN。

## 3.3 配置、日志与异常体系

**config.py**：继承 `BaseSettings`，自动从.env.local 读取。`@lru_cache()` 保证全局单例。`@property` 动态拼接 database_url。

**logger.py**：包装标准库 logging，支持 `logger.info("event", key=value)` 结构化写法。`configure_logging()` 压制第三方库噪音（sqlalchemy/httpx 等提到 WARNING）。

**exceptions.py**：基类 `EduAgentBaseError(Exception)` 带 `agent_type` 和 `details`。7个子类：

- **可重试**：LLMAPIError、MilvusConnectionError
- **视情况**：AgentExecutionError、PipelineError、IntentRouteError
- **不可重试**：FileParseError、InvalidInputError、AuthenticationError

## 3.4 LLM Factory

**为什么需要**：避免各 Agent 重复配置 model_provider/base_url/api_key/temperature；统一管控超时、重试、代理。

**两个核心入口**：

- `get_llm(agent_type, temperature=0, streaming=False)`：普通模型
- `get_structured_llm(agent_type, output_schema)`：绑定 Pydantic 结构的模型

**关键设计**：

- 自定义 httpx 客户端 `trust_env=False` 绕过系统代理（Windows 代理导致 DeepSeek 请求失败）
- 按组合缓存实例：`cache_key = f"{model}_{temperature}_{streaming}"`
- `max_retries=0`：模型层不重试，统一由 retry.py 管理
- Agent 类型路由表：qa/exam_subjective/exam_code/resume/interview/intent/summarize 全部用 deepseek-chat

## 3.5 三层兜底与重试机制

| 层级 | 触发条件 | 处理方式 |
|------|---------|---------|
| 第一层：自动重试 | 网络抖动/LLM 超时 | 最多重试 2 次（间隔 1s/3s），30s 超时保护 |
| 第二层：Agent 级降级 | 重试仍失败 | 退化为简单实现（QA 跳过检索直接答，批改标记教师复核） |
| 第三层：系统级兜底 | 降级也失败 | 返回友好提示，保证用户始终能收到响应 |

**装饰器**：`@with_retry(agent_type="qa")`，三层嵌套函数（最外层接收参数→中间层接收函数→最内层执行逻辑）。

**降级函数**：统一返回字典（对接 LangGraph 节点约定），包括 `_qa_fallback`、`_exam_code_fallback`、`_exam_subjective_fallback`、`_resume_fallback`、`_interview_fallback`。

## 3.6 认证与依赖注入

**JWT 认证流程**：用户登录→bcrypt 校验密码→签发 JWT（含 user_id/role/tenant_id）→后续请求携带 Bearer Token→get_current_user 解码验证。

**bcrypt**：单向不可逆、自带盐值。校验是 CPU 密集型操作（~100ms），必须用 `run_in_executor` 丢线程池。

**dependencies.py 两个依赖**：

- `get_db`：yield 型依赖，自动提交/回滚事务
- `get_current_user`：`HTTPBearer` 自动解析 Authorization 头，`jwt.decode()` 验证，失败抛 401

**seed_data.py**：灌入测试账号（student01/teacher01/admin），密码 bcrypt 哈希存储。
