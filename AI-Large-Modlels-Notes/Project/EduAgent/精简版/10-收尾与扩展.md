# 第 10 章 收尾与扩展

## 10.1 系统总览

**三层架构**：

```python
集成层（unified_chat统一入口 + orchestrator编排器 + main装配）
  ↓ 调度
Agent层（4种LangGraph范式：并行评审/RAG/HitL/状态机+SSE）
  ↓ 复用
地基层（config/logger/exceptions/retry/llm_factory/认证/记忆/MCP/本地模型）
```

**一条请求的完整生命周期**（以"什么是 RAG"为例）：

```python
[unified_chat] 前置拦截未命中→LLM路由判为qa→推routing_decision
[orchestrator] 懒加载QA图→@with_retry包裹调用
[load_memory] 读MemorySaver历史+摘要
[classify] 意图分类
[retrieve] BGE-M3嵌入→Milvus检索
[rerank] BGE-Reranker精排
[generate] 增强生成→流式token
[unified_chat] 透传progress+token+meta事件→SSE返回
```

## 10.2 迁移方法论（四步拆解）

**第一步：找"角色"**——每个专业角色对应一个 Agent。

**第二步：定范式**——看工作性质套四种范式：

| 工作性质 | 范式 | EduAgent 出处 |
|---------|------|-------------|
| 一个输入多维度评估 | 并行评审 | 简历六维 |
| 基于私有知识回答 | RAG | QA |
| 关键决策需人把关 | HitL | 试卷批改 |
| 有明确阶段的多轮交互 | 状态机+多轮 | 模拟面试 |

**第三步：定编排方式**——互斥→路由分发，有先后依赖→串联 Pipeline，同时进行→并行。

**第四步：补地基**——get_llm 取模型、MemorySaver+thread_id 记忆、with_retry 三层兜底、统一入口路由+SSE。

## 10.3 常见面试题要点

**Agent 协作**：Orchestrator 统一入口 handle(request)，按 pipeline_mode 分单 Agent 直达(_run_single_agent)或多 Agent 串联(_run_pipeline)。选择标准：互斥用路由，依赖用 Pipeline，并行用 fan-out。

**上下文传递**：Pipeline 中前序 agent 的 structured_output 以 `{agent}_result` 为 key 注入 current_context，后序通过 `**request.context` 平铺进 State。

**路由失败处理**：LLM 路由异常降级回 qa，不阻断 SSE 流；意图不明返回 clarify 分支推追问引导。

**Token 成本控制**：①规则前置拦截零 Token 模板回复 ②本地 MiniLM 判通用/专项 ③LLM 实例缓存复用连接。

**长对话处理**：`trim_messages_to_window` 滑动窗口 + `should_trigger_summary` 增量摘要压缩。

**RAG 检索不准**：BGE-M3 稠密+稀疏双向量召回 → BGE-Reranker 精排。可加 HyDE/多查询改写/混合检索。

**防幻觉**：检索结果带 sources 一起返回（meta 事件），答案可溯源；检索不可用时降级不硬答。

## 10.4 Langfuse 监控（扩展）

**核心功能**：Trace（每次请求完整调用链，定位 RAG 答错/路由失败/高延迟根因）、Cost Tracking（按模型/功能/用户分组统计 Token 成本）、Dataset+Evaluation（评测集批量运行，Prompt 改动前后对比）。

**三种接入方式**：LangChain 回调（最快，改动最少）、手动 SDK（最灵活，精确控制每步 span）、LangGraph 集成（节点级可见）。
