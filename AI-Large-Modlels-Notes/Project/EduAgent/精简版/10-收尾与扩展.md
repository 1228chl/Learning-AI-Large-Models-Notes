# 第10章 收尾与扩展

## 10.1 系统总览

**三层架构**：
```
集成层（unified_chat统一入口 + orchestrator编排器 + main装配）
  ↓ 调度
Agent层（4种LangGraph范式：并行评审/RAG/HitL/状态机+SSE）
  ↓ 复用
地基层（config/logger/exceptions/retry/llm_factory/认证/记忆/MCP/本地模型）
```

**一条请求的完整生命周期**（以"什么是RAG"为例）：
```
[unified_chat] 前置拦截未命中→LLM路由判为qa→推routing_decision
[orchestrator] 懒加载QA图→@with_retry包裹调用
[load_memory] 读MemorySaver历史+摘要
[classify] 意图分类
[retrieve] BGE-M3嵌入→Milvus检索
[rerank] BGE-Reranker精排
[generate] 增强生成→流式token
[unified_chat] 透传progress+token+meta事件→SSE返回
```

## 10.2 迁移方法论（四步拆解）

**第一步：找"角色"**——每个专业角色对应一个Agent。
**第二步：定范式**——看工作性质套四种范式：
| 工作性质 | 范式 | EduAgent出处 |
|---------|------|-------------|
| 一个输入多维度评估 | 并行评审 | 简历六维 |
| 基于私有知识回答 | RAG | QA |
| 关键决策需人把关 | HitL | 试卷批改 |
| 有明确阶段的多轮交互 | 状态机+多轮 | 模拟面试 |

**第三步：定编排方式**——互斥→路由分发，有先后依赖→串联Pipeline，同时进行→并行。
**第四步：补地基**——get_llm取模型、MemorySaver+thread_id记忆、with_retry三层兜底、统一入口路由+SSE。

## 10.3 常见面试题要点

**Agent协作**：Orchestrator统一入口handle(request)，按pipeline_mode分单Agent直达(_run_single_agent)或多Agent串联(_run_pipeline)。选择标准：互斥用路由，依赖用Pipeline，并行用fan-out。

**上下文传递**：Pipeline中前序agent的structured_output以`{agent}_result`为key注入current_context，后序通过`**request.context`平铺进State。

**路由失败处理**：LLM路由异常降级回qa，不阻断SSE流；意图不明返回clarify分支推追问引导。

**Token成本控制**：①规则前置拦截零Token模板回复 ②本地MiniLM判通用/专项 ③LLM实例缓存复用连接。

**长对话处理**：`trim_messages_to_window`滑动窗口 + `should_trigger_summary`增量摘要压缩。

**RAG检索不准**：BGE-M3稠密+稀疏双向量召回 → BGE-Reranker精排。可加HyDE/多查询改写/混合检索。

**防幻觉**：检索结果带sources一起返回（meta事件），答案可溯源；检索不可用时降级不硬答。

## 10.4 Langfuse监控（扩展）

**核心功能**：Trace（每次请求完整调用链，定位RAG答错/路由失败/高延迟根因）、Cost Tracking（按模型/功能/用户分组统计Token成本）、Dataset+Evaluation（评测集批量运行，Prompt改动前后对比）。

**三种接入方式**：LangChain回调（最快，改动最少）、手动SDK（最灵活，精确控制每步span）、LangGraph集成（节点级可见）。
