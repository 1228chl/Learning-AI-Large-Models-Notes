# 第1章 项目简介 — EduAgent 多Agent教学辅助系统

## 1. 四大痛点与EduAgent定位

| 痛点 | 核心矛盾 | 对应Agent |
|------|---------|-----------|
| 学员答疑 | 老师精力有限 vs 重复问题多 | QA（智能问答） |
| 试卷批改 | 工作量大 vs 评分一致性要求高 | Exam（试卷批改） |
| 简历审查 | 简历数量多 vs 没时间逐份精读 | Resume（简历审查） |
| 模拟面试 | 需要专业陪练 vs 缺少面试官资源 | Interview（模拟面试） |

**通用大模型不够用的三个原因**：①缺少企业私有知识（幻觉）②缺少业务流程（多步骤有状态）③缺少工程化可靠性（重试/降级）

**EduAgent定位**：AI原生教学辅助系统，融合三大核心能力：
- **私有知识融合**：RAG技术注入机构私有知识
- **内置业务流程**：LangGraph图模型建模为状态图
- **容错机制**：重试/降级/超时/熔断

## 2. 四大Agent对比

| 维度 | QA | Exam | Resume | Interview |
|------|-----|------|--------|-----------|
| 技术方案 | RAG检索增强生成 | 三轨并行批改+HitL | 结构化抽取+多维并行评分 | 状态机多阶段对话+流式输出 |
| 核心教你 | RAG管线/向量检索/嵌入模型 | 并行任务编排/HitL | 信息抽取/并行评分聚合 | 状态机设计/流式/对话管理 |
| 状态管理 | 无状态 | 有状态 | 有状态 | 复杂状态机 |

## 3. 技术栈

| 组件 | 用途 |
|------|------|
| Python 3.11 + 全异步 | 全异步编程（FastAPI→asyncpg→httpx全链路异步） |
| FastAPI | Web框架，REST API + SSE流式接口 |
| LangChain 1.2.10 | LLM应用框架（版本严格锁定） |
| LangGraph 1.0.9 | Agent编排框架（图模型） |
| DeepSeek-V3 | 大语言模型（API调用） |
| Milvus | 向量数据库 |
| PostgreSQL | 关系数据库 |
| BGE-M3 | 嵌入模型（dense+sparse双输出，进程内） |
| BGE-Reranker | 重排序模型（进程内） |
| MiniLM | 意图分类模型（进程内） |

**进程内部署**：模型与主应用同进程，函数调用无网络开销，部署简化但无法独立扩缩容

## 4. 六层分层架构

```
API层（FastAPI REST/SSE）→ 编排层（Orchestrator意图识别+路由）
→ Agent层（QA/Exam/Resume/Interview）→ 公共层（嵌入/重排序/分类）
→ MCP层（统一LLM接口+重试降级）→ 数据层（Milvus/PostgreSQL/文件/缓存）
```

## 5. Agent五大能力

1. **感知**：接收用户输入、读取系统状态、获取外部数据
2. **记忆**：短期记忆（对话上下文）+ 长期记忆（跨会话）+ 工作记忆（中间结果），LangGraph通过State+Checkpointer实现
3. **决策**：LLM决策/规则决策/混合决策
4. **行动**：调用LLM/工具/其他Agent
5. **可循环/可中断**：感知-决策-行动循环，中断后恢复

**Agent = 大模型 + 记忆 + 工具 + 自主循环**

## 6. Agent四种形态

| 形态 | 特点 | 适用场景 |
|------|------|---------|
| 单次LLM调用 | 无状态无工具无循环 | 简单翻译/摘要 |
| 固定工作流（Chain） | 步骤固定顺序执行 | RAG问答（检索→重排序→生成） |
| 单Agent自主循环 | 灵活决策，可循环 | 代码生成/数据分析 |
| 多Agent协作 | 职责清晰，可扩展 | 复杂企业业务系统 |

**EduAgent选择**：每个Agent内部用固定工作流（可控可预测），系统层面用多Agent协作（灵活编排）

## 7. LangGraph图模型四要素

1. **State**：TypedDict定义，所有节点共享的数据结构
2. **Node**：处理单元，函数接收State返回"要更新的字段"字典
3. **Edge**：固定边（无条件）和条件边（根据条件路由）
4. **Checkpointer**：持久化State，实现中断恢复和记忆

**实现五步套路**：定义State → 写节点函数 → 连接边 → 绑定Checkpointer → 编译运行

## 8. Orchestrator职责

- **层次一**：意图识别 + 单Agent路由（MiniLM分类，置信度<0.7请求确认）
- **层次二**：多Agent串联Pipeline（通过context字典传递数据）
