# 第 8 章 系统集成

## 8.1 全景

**核心任务**：在四个 Agent 前面架一个统一入口，用户只说一句话，系统自动判断路由到哪个 Agent。

**两个核心角色**：

- `unified_chat.py`（统一入口/接待员）：收一句话→判断意图→SSE 流式返回
- `orchestrator.py`（编排器/调度台）：拿到明确 agent_type→直调对应 Agent 图，或按序串联多个 Agent

**统一请求生命周期**：

```python
用户一句话 → 规则前置拦截（五类社交场景零Token模板回复）
→ LLM路由判6类意图 → 推送routing_decision事件
→ 按label分发：qa流式执行/exam等引导跳转/multi_agent计划/clarify追问
```

**为什么路由用 LLM 不用本地分类模型**：调用频率低（仅统一入口一处），省一个本地模型，改 Prompt 即可新增意图。失败时降级回 qa。

## 8.2 Orchestrator

**三个统一 Schema**：`AgentRequest`（统一入参，含 agent_type/context/pipeline_mode）、`AgentResponse`（统一出参，含 success/content/structured/fallback_used）、`PipelineResult`（串联结果，含 steps+combined）。

**图懒加载**：`_get_agent_graph` 首次用到某 Agent 才 build 图并缓存。`get_orchestrator()` 单例让图缓存全程复用。

**handle 两层兜底**：`_run_single_agent` 内部用 `@with_retry` 处理 Agent 执行中的失败；handle 最外层 try/except 保证无论怎么炸都返回合法 AgentResponse。

## 8.3 多 Agent 串联 Pipeline

**求职全链路 Pipeline**：简历审查→模拟面试。前序 structured_output 以 `{agent}_result` 为 key 注入 context，后序通过 `**request.context` 平铺进自己的 State。

**关键设计**：独立 session_id（加 `_step{idx}` 后缀）防检查点串台；某步失败时 break 保留已完成步骤结果。

## 8.4 统一入口

**前置拦截五类**：HELLO/THANKS/GOODBYE/WHO_ARE_YOU/CAPABILITIES，精确匹配+正则匹配，零 Token 模板回复。

**六类意图映射**：qa(单 Agent)、exam(单 Agent)、resume(单 Agent)、interview(单 Agent)、multi_agent(Pipeline)、clarify(澄清)。

## 8.5 SSE 分发

**8 种事件类型**：routing_decision(路由卡片)、progress(进度)、token(逐字)、meta(来源)、guidance(引导跳转)、pipeline_plan(多步骤计划)、done(结束)、error(错误)。

**qa 分支**：通过 `astream_events` 逐 token 推送，同时推 progress 和 meta 事件。

**exam/resume/interview 分支**：推 guidance 引导卡片（含跳转链接 action_url）。

**multi_agent 分支**：推 pipeline_plan 多步骤计划卡片。注意：pipeline_plan 是推计划让前端引导用户，不是程序化跑完所有 Agent。

**clarify 分支**：推 guidance 提示用户补充信息。

## 8.6 路由聚合与 main 集成

**router.py**：6 个 APIRouter 聚合（auth/chat/qa/exam/resume/interview），统一前缀 `/api/v1`。

**lifespan 启动三件事**：DB 迁移→并行预热三个本地模型（asyncio.gather）→MCP 子应用生命周期管理。

**Windows conda 兼容**：文件头将 base 环境 Library/bin 加入 DLL 搜索路径。

## 第 9 章 前端集成（精简）

**技术栈**：Vue3 + Composition API + Element Plus + Axios + Pinia + Vue Router 4 + Vite 5。

**双通道通信**：普通请求走 Vite proxy（`/api` → `localhost:8000`），SSE 流式请求 fetch 直连后端（绕过 Vite proxy，proxy 缓冲响应体导致 SSE 帧被堆积）。

**JWT 鉴权自动注入**：Axios 请求拦截器从 localStorage 读 token 注入 Header，响应拦截器捕获 401 后自动跳转登录。

**四大功能页面**：

- 智能问答：QAChatView，SSE 流式逐 token 渲染
- 试卷批改：学生提交页+结果页，教师批改确认页（HitL 前端体现）
- 简历审查：上传页+报告页（六维度雷达图+问题清单），轮询查结果
- 模拟面试：配置页+对话页（SSE 流式+阶段提示条）+报告页

**角色权限**：JWT role 字段控制页面可见性，路由守卫 beforeEach 检查。

## 第 10 章 收尾与扩展（精简）

**三层架构**：地基层(config/logger/exceptions/retry/llm_factory/认证/记忆/MCP) → Agent 层(4 种 LangGraph 范式) → 集成层(统一入口+编排器+main)。

**四种 LangGraph 范式**：并行评审(简历)、RAG(问答)、HitL(试卷批改)、状态机+SSE(面试)。

**迁移方法论四步**：①找角色（每个专业角色对应一个 Agent）②定范式（看工作性质套四种范式）③定编排方式（互斥→路由/有依赖→Pipeline/同时→并行）④补地基（get_llm/MemorySaver/with_retry/统一入口）。

**Langfuse 监控**：Trace（每次请求完整调用链，定位 RAG 答错/路由失败/高延迟）、Cost Tracking（按模型/功能/用户分组统计 Token 成本）、Dataset+Evaluation（评测集批量运行，Prompt 改动前后对比）。
