# 第8章 系统集成

## 8.1 全景

**核心任务**：在四个Agent前面架一个统一入口，用户只说一句话，系统自动判断路由到哪个Agent。

**两个核心角色**：
- `unified_chat.py`（统一入口/接待员）：收一句话→判断意图→SSE流式返回
- `orchestrator.py`（编排器/调度台）：拿到明确agent_type→直调对应Agent图，或按序串联多个Agent

**统一请求生命周期**：
```
用户一句话 → 规则前置拦截（五类社交场景零Token模板回复）
→ LLM路由判6类意图 → 推送routing_decision事件
→ 按label分发：qa流式执行/exam等引导跳转/multi_agent计划/clarify追问
```

**为什么路由用LLM不用本地分类模型**：调用频率低（仅统一入口一处），省一个本地模型，改Prompt即可新增意图。失败时降级回qa。

## 8.2 Orchestrator

**三个统一Schema**：`AgentRequest`（统一入参，含agent_type/context/pipeline_mode）、`AgentResponse`（统一出参，含success/content/structured/fallback_used）、`PipelineResult`（串联结果，含steps+combined）。

**图懒加载**：`_get_agent_graph`首次用到某Agent才build图并缓存。`get_orchestrator()`单例让图缓存全程复用。

**handle两层兜底**：`_run_single_agent`内部用`@with_retry`处理Agent执行中的失败；handle最外层try/except保证无论怎么炸都返回合法AgentResponse。

## 8.3 多Agent串联Pipeline

**求职全链路Pipeline**：简历审查→模拟面试。前序structured_output以`{agent}_result`为key注入context，后序通过`**request.context`平铺进自己的State。

**关键设计**：独立session_id（加`_step{idx}`后缀）防检查点串台；某步失败时break保留已完成步骤结果。

## 8.4 统一入口

**前置拦截五类**：HELLO/THANKS/GOODBYE/WHO_ARE_YOU/CAPABILITIES，精确匹配+正则匹配，零Token模板回复。

**六类意图映射**：qa(单Agent)、exam(单Agent)、resume(单Agent)、interview(单Agent)、multi_agent(Pipeline)、clarify(澄清)。

## 8.5 SSE分发

**8种事件类型**：routing_decision(路由卡片)、progress(进度)、token(逐字)、meta(来源)、guidance(引导跳转)、pipeline_plan(多步骤计划)、done(结束)、error(错误)。

**qa分支**：通过`astream_events`逐token推送，同时推progress和meta事件。
**exam/resume/interview分支**：推guidance引导卡片（含跳转链接action_url）。
**multi_agent分支**：推pipeline_plan多步骤计划卡片。注意：pipeline_plan是推计划让前端引导用户，不是程序化跑完所有Agent。
**clarify分支**：推guidance提示用户补充信息。

## 8.6 路由聚合与main集成

**router.py**：6个APIRouter聚合（auth/chat/qa/exam/resume/interview），统一前缀`/api/v1`。

**lifespan启动三件事**：DB迁移→并行预热三个本地模型（asyncio.gather）→MCP子应用生命周期管理。
**Windows conda兼容**：文件头将base环境Library/bin加入DLL搜索路径。

## 第9章 前端集成（精简）

**技术栈**：Vue3 + Composition API + Element Plus + Axios + Pinia + Vue Router 4 + Vite 5。

**双通道通信**：普通请求走Vite proxy（`/api`→`localhost:8000`），SSE流式请求fetch直连后端（绕过Vite proxy，proxy缓冲响应体导致SSE帧被堆积）。

**JWT鉴权自动注入**：Axios请求拦截器从localStorage读token注入Header，响应拦截器捕获401后自动跳转登录。

**四大功能页面**：
- 智能问答：QAChatView，SSE流式逐token渲染
- 试卷批改：学生提交页+结果页，教师批改确认页（HitL前端体现）
- 简历审查：上传页+报告页（六维度雷达图+问题清单），轮询查结果
- 模拟面试：配置页+对话页（SSE流式+阶段提示条）+报告页

**角色权限**：JWT role字段控制页面可见性，路由守卫beforeEach检查。

## 第10章 收尾与扩展（精简）

**三层架构**：地基层(config/logger/exceptions/retry/llm_factory/认证/记忆/MCP) → Agent层(4种LangGraph范式) → 集成层(统一入口+编排器+main)。

**四种LangGraph范式**：并行评审(简历)、RAG(问答)、HitL(试卷批改)、状态机+SSE(面试)。

**迁移方法论四步**：①找角色（每个专业角色对应一个Agent）②定范式（看工作性质套四种范式）③定编排方式（互斥→路由/有依赖→Pipeline/同时→并行）④补地基（get_llm/MemorySaver/with_retry/统一入口）。

**Langfuse监控**：Trace（每次请求完整调用链，定位RAG答错/路由失败/高延迟）、Cost Tracking（按模型/功能/用户分组统计Token成本）、Dataset+Evaluation（评测集批量运行，Prompt改动前后对比）。
