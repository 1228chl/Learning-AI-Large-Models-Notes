# 学习总结与项目要点 - 详细学习笔记

## 一、学习内容总结

### 1.1 LangChain框架

**核心概念**：
- LangChain是LLM应用开发框架，提供通用接口和组件
- 自身不开发LLMs，而是整合各种LLMs

**六大组件**：
| 组件 | 作用 | 关键类/函数 |
|------|------|------------|
| **Models** | 模型集成 | ChatOpenAI, DashScopeEmbeddings |
| **Prompts** | 提示词管理 | PromptTemplate, FewShotPromptTemplate |
| **Memory** | 记忆 | ChatMessageHistory, InMemorySaver |
| **Indexes** | 索引 | TextLoader, Chroma, Retriever |
| **Chains** | 链 | prompt \| llm \| parser |
| **Agents** | 代理 | create_agent, @tool |

**实际应用**：
```python
# LangChain核心代码模式
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 1. 初始化模型
llm = ChatOpenAI(model="qwen-max")

# 2. 创建提示模板
prompt = PromptTemplate.from_template("问题：{query}")

# 3. 构建链
chain = prompt | llm | StrOutputParser()

# 4. 调用
result = chain.invoke({"query": "什么是Python？"})
```

### 1.2 RAG系统架构

**核心原理**：
```
索引阶段：文档加载 → 切片 → 向量化 → 存入向量数据库
检索阶段：查询向量化 → 相似度匹配 → 检索相关文档
生成阶段：上下文组装 → LLM生成答案
```

**解决的问题**：
1. **知识截止日期**：LLM训练数据有截止时间，RAG可检索最新文档
2. **幻觉问题**：LLM可能编造不存在的信息，RAG提供真实文档约束答案

**EduRAG双系统架构**：
| 系统 | 技术栈 | 适用场景 | 特点 |
|------|--------|----------|------|
| MySQL FAQ | BM25 + MySQL + Redis | 有标准答案的高频问题 | 速度快、答案可控 |
| Milvus RAG | 向量检索 + Milvus + LLM | 复杂/开放性知识问题 | 灵活、语义理解 |

### 1.3 向量数据库与距离计算

**向量数据库**：
- 专门存储和查询向量数据
- 支持相似性搜索
- 常用：Chroma（开发）、Milvus（生产）

**距离计算**：
| 距离类型 | 公式 | 取值范围 | 特点 |
|----------|------|----------|------|
| 欧式距离 | $\sqrt{\sum(x_i-y_i)^2}$ | [0, +∞) | 距离越小越相似 |
| 内积 | $\sum x_i y_i$ | R | 值越大越相似 |
| 余弦相似度 | $\frac{\sum x_i y_i}{\|x\|\|y\|}$ | [-1, 1] | 最常用，只考虑方向 |

### 1.4 BM25算法

**核心思想**：
- 词频饱和：避免高频词过度影响
- 文档长度归一化：公平比较不同长度文档
- IDF：罕见词权重高，常见词权重低

**公式**：
$$
score(D, Q) = \sum_{i=1}^{n} IDF(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot (1 - b + b \cdot \frac{|D|}{avgdl})}
$$

**应用场景**：FAQ匹配、信息检索

### 1.5 Docker部署

**核心概念**：
- 镜像（Image）：只读模板
- 容器（Container）：镜像运行实例
- Dockerfile：构建镜像的脚本
- docker-compose：多容器编排

**部署流程**：
```bash
# 1. 构建镜像
docker-compose build

# 2. 启动服务
docker-compose up -d

# 3. 健康检查
curl http://localhost:8003/health
```

## 二、EduRAG项目要点

### 2.1 项目架构

```
用户请求
    ↓
┌─────────────────────────────────────┐
│           FastAPI应用               │
│  ┌─────────────┐  ┌─────────────┐  │
│  │  MySQL FAQ  │  │  Milvus RAG │  │
│  │  (BM25检索) │  │ (向量检索)  │  │
│  └─────────────┘  └─────────────┘  │
└─────────────────────────────────────┘
    ↓           ↓
┌─────────┐ ┌─────────┐
│  MySQL  │ │ Milvus  │
└─────────┘ └─────────┘
```

### 2.2 技术栈

| 层 | 技术 | 作用 |
|----|------|------|
| **LLM框架** | LangChain | 整合各种LLM组件 |
| **向量数据库** | Milvus | 存储和检索文本向量 |
| **关系型数据库** | MySQL | 存储FAQ问答对 |
| **缓存** | Redis | 缓存会话历史、常见答案 |
| **API框架** | FastAPI | 提供RESTful API接口 |
| **部署** | Docker | 容器化部署 |

### 2.3 API接口

| 接口 | 方法 | 作用 |
|------|------|------|
| `/health` | GET | 健康检查 |
| `/api/create_session` | POST | 创建会话 |
| `/api/history/{session_id}` | GET | 获取会话历史 |
| `/api/history/{session_id}` | DELETE | 清除会话历史 |
| `/api/query` | POST | 非流式查询 |
| `/api/stream` | WS | 流式查询（WebSocket） |
| `/api/sources` | GET | 获取学科类别 |

### 2.4 工作流程

**非流式查询**：
```
用户提问 → 接收请求 → 判断问题类型
    ├─ 日常问候 → 返回预设回复
    ├─ 简单问题 → BM25检索MySQL FAQ
    └─ 复杂问题 → 提示使用流式接口
→ 返回完整答案
```

**流式查询**：
```
用户提问 → 建立WebSocket连接 → 发送开始消息
→ RAG处理（查询向量化 → Milvus检索 → 组装Prompt → LLM生成）
→ 逐个发送token消息 → 发送结束消息
```

## 七、常见面试题

### Q1: 什么是RAG？它解决了LLM的什么问题？

**答案**：
RAG（检索增强生成）在LLM生成答案前先从外部知识库检索相关文档作为上下文。

**解决的问题**：
1. **知识截止日期**：LLM训练数据有截止时间，RAG可以检索最新文档
2. **幻觉问题**：LLM可能编造不存在的信息，RAG提供真实文档约束答案

### Q2: LangChain的六大组件是什么？

**答案**：
1. **Models**：模型集成，统一调用各种大模型
2. **Prompts**：提示词管理，设计和优化提示词
3. **Memory**：记忆，保存对话历史
4. **Indexes**：索引，处理文档，支持检索
5. **Chains**：链，把多个组件串联起来
6. **Agents**：代理，让模型自动选择工具

### Q3: 为什么采用MySQL + Milvus双系统架构？

**答案**：
1. **MySQL FAQ**：负责结构化FAQ问答，有标准答案的问题通过BM25匹配返回，速度快且答案可控
2. **Milvus RAG**：负责复杂/开放性知识问题，通过向量检索+LLM生成答案
3. **优势**：缓解RAG系统压力，提高整体响应速度

### Q4: 余弦相似度为什么最常用？

**答案**：
1. **只考虑方向**：不受向量长度影响，适合文本相似度
2. **取值范围固定**：[-1, 1]，便于比较
3. **语义理解**：语义相似的文本，向量方向相近

### Q5: Docker部署有什么优势？

**答案**：
1. **环境一致性**：开发、测试、生产环境完全一致
2. **快速部署**：秒级启动，无需复杂配置
3. **资源隔离**：每个容器独立运行，互不影响
4. **易于扩展**：支持水平扩展和负载均衡
