## 一、BGE-M3嵌入模型

### 1.1 什么是BGE-M3？

BGE-M3（BAAI General Embedding - Multi-Lingual, Multi-Functionality, Multi-Granularity）是由智源研究院（BAAI）开发的多语言嵌入模型。

**三大特性**：
1. **多语言**：支持100+种语言，包括中文
2. **多功能**：同时生成稠密向量和稀疏向量
3. **多粒度**：支持不同长度的文本输入

### 1.2 稠密向量 vs 稀疏向量

| 类型 | 说明 | 优势 | 劣势 |
|------|------|------|------|
| **稠密向量** | 低维连续向量（1024维） | 捕捉语义信息 | 可能丢失关键词 |
| **稀疏向量** | 高维稀疏向量（词表大小） | 精确匹配关键词 | 无法捕捉语义 |

**示例**：
```
查询："Python编程语言"
- 稠密向量：[0.23, -0.15, 0.67, ...]  # 语义表示
- 稀疏向量：{1024: 0.5, 5123: 0.3, ...}  # 关键词匹配
```

### 1.3 项目中的使用

```python
from milvus_model.hybrid import BGEM3EmbeddingFunction

# 初始化BGE-M3
embedding_function = BGEM3EmbeddingFunction(
    model_name_or_path="models/bge-m3",
    use_fp16=(device == 'cuda'),
    device=device
)

# 获取向量维度
dense_dim = embedding_function.dim["dense"]  # 1024

# 生成嵌入
embeddings = embedding_function(["Python是一种编程语言"])
# embeddings["dense"]  → 稠密向量
# embeddings["sparse"] → 稀疏向量
```

## 二、父子块策略（Parent-Child Chunking）

### 2.1 为什么需要父子块？

传统问题：
- 子块太小 → 丢失上下文，检索结果不完整
- 子块太大 → 检索精度下降，噪声多

父子块策略：
- **检索时**：用子块（小而精），提高检索精度
- **返回时**：用父块（大而全），保留完整上下文

### 2.2 实现原理

```
原始文档
    ↓ 父块分割 (1200字符)
┌──────────────────────────────────────────┐
│ 父块 A (1200字符)                        │
│ ┌─────────────┐ ┌─────────────┐         │
│ │ 子块 A1     │ │ 子块 A2     │ ...     │
│ │ (300字符)   │ │ (300字符)   │         │
│ └─────────────┘ └─────────────┘         │
└──────────────────────────────────────────┘

存储到Milvus时：
- 每个子块存储：子块内容 + 父块ID + 父块内容
- 检索时：返回子块，但用父块内容作为上下文
```

### 2.3 代码实现

```python
# document_processor.py
from langchain_text_splitters import RecursiveCharacterTextSplitter

def process_documents(directory_path):
    """处理文档：加载 → 父块分割 → 子块分割"""
    
    # 1. 加载文档
    documents = load_documents_from_directory(directory_path)
    
    # 2. 父块分割
    parent_splitter = RecursiveCharacterTextSplitter(
        chunk_size=1200,
        chunk_overlap=50
    )
    parent_chunks = parent_splitter.split_documents(documents)
    
    # 3. 子块分割
    child_splitter = RecursiveCharacterTextSplitter(
        chunk_size=300,
        chunk_overlap=50
    )
    
    all_chunks = []
    for parent_chunk in parent_chunks:
        child_chunks = child_splitter.split_documents([parent_chunk])
        for child_chunk in child_chunks:
            # 为每个子块添加父块信息
            child_chunk.metadata["parent_id"] = hashlib.md5(
                parent_chunk.page_content.encode()
            ).hexdigest()
            child_chunk.metadata["parent_content"] = parent_chunk.page_content
            all_chunks.append(child_chunk)
    
    return all_chunks
```

### 2.4 Milvus中的存储结构

```
字段说明：
├── id: 子块的唯一ID（MD5哈希）
├── text: 子块内容
├── dense_vector: 稠密向量（1024维）
├── sparse_vector: 稀疏向量
├── parent_id: 父块ID
├── parent_content: 父块内容
├── source: 学科类别（ai/java/test等）
└── timestamp: 时间戳
```

## 三、混合检索（Hybrid Search）

### 3.1 什么是混合检索？

同时使用稠密向量和稀疏向量进行检索，然后融合结果。

**优势**：
- 稠密向量：捕捉语义相似性
- 稀疏向量：精确匹配关键词
- 混合：兼顾语义和关键词

### 3.2 Milvus混合检索实现

```python
from pymilvus import AnnSearchRequest, WeightedRanker

def hybrid_search_with_rerank(self, query, k=5):
    # 1. 生成查询嵌入
    query_embeddings = self.embedding_function([query])
    
    # 2. 创建稠密向量搜索请求
    dense_request = AnnSearchRequest(
        data=[query_embeddings["dense"][0]],
        anns_field="dense_vector",
        param={"metric_type": "IP", "params": {"nprobe": 10}},
        limit=k
    )
    
    # 3. 创建稀疏向量搜索请求
    sparse_request = AnnSearchRequest(
        data=[query_embeddings["sparse"][0]],
        anns_field="sparse_vector",
        param={"metric_type": "IP"},
        limit=k
    )
    
    # 4. 加权排序
    # 稀疏向量权重0.7，稠密向量权重0.3
    ranker = WeightedRanker(0.7, 0.3)
    
    # 5. 执行混合搜索
    results = self.client.hybrid_search(
        collection_name=self.collection_name,
        reqs=[dense_request, sparse_request],
        ranker=ranker,
        limit=k
    )[0]
    
    return results
```

### 3.3 权重选择

```python
# 权重配置
ranker = WeightedRanker(0.7, 0.3)
#         稀疏向量  稠密向量
#         (关键词)  (语义)
```

**为什么稀疏向量权重更高？**
- 教育领域问答，关键词匹配很重要
- "学费"、"课程大纲"等关键词需要精确匹配
- 语义理解作为补充

## 四、重排序（Reranking）

### 4.1 什么是重排序？

混合检索后，使用更精确的模型对结果重新排序。

### 4.2 BGE-Reranker

```python
from sentence_transformers import CrossEncoder

# 初始化Reranker
reranker = CrossEncoder("models/bge-reranker-v2-m3", device=device)

# 重排序
pairs = [[query, doc.page_content] for doc in parent_docs]
scores = reranker.predict(pairs)

# 按得分排序
ranked_docs = [doc for _, doc in sorted(zip(scores, parent_docs), reverse=True)]
```

### 4.3 重排序流程

```
混合检索结果 (top-k子块)
    ↓ 提取父块（去重）
父文档列表
    ↓ 构建(query, document)对
配对列表
    ↓ Reranker打分
得分列表
    ↓ 按得分排序
重排序后的文档列表
    ↓ 取前M个
最终结果
```

## 五、四种检索策略详解

### 5.1 直接检索

```python
def direct_retrieval(query):
    """直接用原始query检索"""
    return vector_store.hybrid_search_with_rerank(query, k=5)
```

**适用场景**：查询意图明确，如"Python学费是多少？"

### 5.2 HyDE（Hypothetical Document Embeddings）

```python
def hyde_retrieval(query):
    """先生成假设答案，再用假设答案检索"""
    # 1. 用LLM生成假设答案
    hypo_prompt = "假设你是用户，想了解以下问题，请生成一个简短的假设答案：问题: {query}"
    hypo_answer = llm(hypo_prompt.format(query=query))
    
    # 2. 用假设答案检索
    return vector_store.hybrid_search_with_rerank(hypo_answer, k=5)
```

**适用场景**：查询抽象，如"人工智能在教育领域的应用有哪些？"

**原理**：假设答案与真实文档更接近，检索效果更好。

### 5.3 子查询检索

```python
def subquery_retrieval(query):
    """将复杂查询拆分为多个子查询"""
    # 1. 用LLM生成子查询
    subquery_prompt = "将以下复杂查询分解为多个简单子查询，每行一个：查询: {query}"
    subqueries_text = llm(subquery_prompt.format(query=query))
    subqueries = [q.strip() for q in subqueries_text.split("\n") if q.strip()]
    
    # 2. 每个子查询都检索
    all_docs = []
    for sub_q in subqueries:
        docs = vector_store.hybrid_search_with_rerank(sub_q, k=5)
        all_docs.extend(docs)
    
    # 3. 去重
    unique_docs = list({doc.page_content: doc for doc in all_docs}.values())
    return unique_docs
```

**适用场景**：查询涉及多个实体，如"比较Milvus和Zilliz Cloud的优缺点"

### 5.4 回溯问题检索

```python
def backtracking_retrieval(query):
    """将复杂查询简化为更基础的问题"""
    # 1. 用LLM生成简化问题
    backtrack_prompt = "将以下复杂查询简化为一个更简单的问题：查询: {query}"
    simplified_query = llm(backtrack_prompt.format(query=query))
    
    # 2. 用简化问题检索
    return vector_store.hybrid_search_with_rerank(simplified_query, k=5)
```

**适用场景**：查询复杂，如"我有一个100亿条记录的数据集，想存储到Milvus中进行查询"

### 5.5 策略选择器实现

```python
class StrategySelector:
    def __init__(self):
        self.client = OpenAI(api_key=..., base_url=...)
        self.strategy_prompt_template = self._get_strategy_prompt()
    
    def select_strategy(self, query):
        """使用LLM自动选择策略"""
        strategy = self.call_dashscope(
            self.strategy_prompt_template.format(query=query)
        ).strip()
        logger.info(f"为查询 '{query}' 选择的检索策略：{strategy}")
        return strategy
    
    def _get_strategy_prompt(self):
        return PromptTemplate(
            template="""
            你是一个智能助手，负责分析用户查询 {query}，并从以下四种检索增强策略中选择一个最适合的策略，直接返回策略名称。

            1. 直接检索：查询意图明确，需要从知识库中检索特定信息
            2. 假设问题检索（HyDE）：查询较为抽象，直接检索效果不佳
            3. 子查询检索：查询涉及多个实体或方面
            4. 回溯问题检索：查询较为复杂，需要简化后才能有效检索

            根据用户查询 {query}，直接返回最适合的策略名称。
            """,
            input_variables=["query"],
        )
```
