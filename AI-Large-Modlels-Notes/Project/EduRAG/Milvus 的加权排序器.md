# Milvus 的加权排序器笔记

我们更深入地探讨一下 Milvus 的加权排序器（WeightedRanker）。

它的核心可以概括为：**在多路向量搜索（混合搜索）后，通过“分数归一化”和“加权平均”两步，将不同搜索路径的结果整合成一个最终的综合排序列表**。

## 详细工作机制拆解

加权排序器的工作可以拆解为以下四个步骤：

1.  **收集原始分数**：首先，Milvus 会同时执行你指定的多个向量搜索请求（例如，一个基于图片向量，一个基于文本向量）。每个请求都会返回一组结果，并附带各自的**原始相似度分数**。

2.  **分数归一化（关键步骤）**：这是加权排序器最核心也最巧妙的一步。
    *   **为什么要做？** 因为不同的向量搜索可能使用不同的**相似度度量类型**。比如，使用**内积（IP）** 的分数范围是 `[-∞, +∞]`，而使用**欧氏距离（L2）** 的分数范围是 `[0, +∞]`。这些分数范围不同，含义也不同（有的是越大越相似，有的是越小越相似），无法直接进行数学运算。
    *   **怎么做？** Milvus 使用 **`arctan`（反正切）函数**，将所有搜索路径的原始分数统一映射到一个**标准的 [0, 1] 区间内**。映射后的分数含义统一为：**数值越接近 1，代表相似度越高**。这样就为后续的加权计算提供了公平可比的基础。

3.  **分配权重**：现在，你可以为每个归一化后的搜索路径分配一个权重值 (`wi`)，范围在 **[0, 1]** 之间。这个权重完全由你定义，代表了该搜索维度在你业务场景中的重要程度。权重值越**接近 1**，表示该路径越重要。

4.  **合并分数并重排**：最后，计算所有路径的**加权平均值**作为最终得分。
    *   `最终得分 = w1 * 归一化分数_1 + w2 * 归一化分数_2 + ...`
    *   系统会根据计算出的**最终得分**，对所有候选结果进行**从高到低排序**，生成一个全新的、综合考虑了所有搜索维度的 Top-K 结果列表。

## 权重设置与调优

权重的设置直接决定了排序结果，以下是一些指导原则：

*   **业务知识优先**：权重应直接反映你的业务逻辑。例如，在电商搜索中，如果用户更关注“视觉相似性”，那么“图片向量”的权重就应该更高。
*   **数据质量与可靠性**：如果你的某个向量字段的数据质量更高、更稳定，可以为它分配更高的权重。
*   **实验与迭代**：最佳的权重配置通常需要**通过 A/B 测试或离线评估来实验确定**。可以从 `[0.5, 0.5]` 这样均等的权重开始，然后根据实际效果微调。
*   **权重总和不必为 1**：权重值各自独立，系统只负责加权求和，不要求总和为 1。

## 再谈加权排序器 vs. RRFRanker

理解两者的区别，是选择正确策略的关键。

| 特性 | 加权排序器 (WeightedRanker) | 互易排名融合 (RRFRanker) |
| :--- | :--- | :--- |
| **核心逻辑** | 基于**归一化分数**的**加权平均** | 基于**原始排名**的**倒数融合** |
| **是否依赖分数** | **是**。分数本身的质量和归一化过程会影响结果。 | **否**。只依赖每个搜索返回的排名顺序，不关心具体分数。 |
| **是否需要权重** | **需要**，且必须为每个搜索路径明确指定。 | **不需要**，算法自动平衡各路径影响。 |
| **控制粒度** | **精细控制**。可以明确突出某个特定维度的重要性。 | **粗粒度平衡**。追求的是各路径间的“公平”，倾向于提升在多个路径中排名都靠前的结果。 |
| **适用场景** | 对不同搜索维度的重要性有**明确的业务偏好**时。 | 对各维度重要性**不确定**、希望**平等对待**或追求**稳健性**时。 |
| **优点** | 控制精确，可定制化程度高。 | 简单稳健，无需调参，能自动处理分数尺度不一的问题。 |
| **缺点** | 权重需要人工设定和调优，过程可能复杂。 | 无法显式突出某个特定维度，可能埋没在某一路径中极度相关的结果。 |

## 如何使用？

使用 `WeightedRanker` 非常简单。核心是确保你传入的**权重数量**与你发起的 **`AnnSearchRequest` 搜索请求数量**完全一致。

**代码示例 (PyMilvus)**：

```python
from pymilvus import WeightedRanker

# 假设你有两个向量搜索路径：一个用于图片，一个用于文本
# 为它们分别设置权重，总和不必为1，例如这里图片更重要
rerank = WeightedRanker(0.8, 0.6) 

# 在 hybrid_search 方法中使用这个排序器
# results = collection.hybrid_search(
#     reqs=[search_req_img, search_req_text],  # 两个搜索请求
#     rerank=rerank,  # 使用加权排序器
#     limit=10
# )
```

## 总结与最佳实践

1.  **明确场景**：当你有明确的业务优先级，需要强调某一个或几个搜索维度时，`WeightedRanker` 是首选。
2.  **理解归一化**：它的存在使得不同度量类型的分数可以公平比较，这也是它相对于简单加权平均的核心优势。
3.  **权重是“方向标”**：权重值不是绝对的数学比例，而是你表达“重视程度”的工具。
4.  **测试与验证**：在生产环境中大规模使用前，务必通过离线测试或小流量 A/B 测试来验证你设定的权重是否符合预期。
5.  **考虑备选**：如果你的场景不需要精细控制，或者对各个维度的相对重要性没有把握，可以优先考虑更稳健的 `RRFRanker`。
