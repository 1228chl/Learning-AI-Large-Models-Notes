# BGE-M3 与 BGE-Reranker 模型原理详解笔记

## 一、BGE-M3 模型概述

BGE-M3（M3-Embedding）是智源研究院（BAAI）推出的新一代文本嵌入模型，其名称中的“M3”代表三大核心特性：

| 特性 | 说明 |
|------|------|
| **Multi-Functionality（多功能）** | 可同时执行稠密检索、稀疏检索和多向量检索三种功能 |
| **Multi-Linguality（多语言）** | 支持超过100种工作语言 |
| **Multi-Granularity（多粒度）** | 可处理从短句到长达8192个token的长文档 |

BGE-M3 基于 BERT 架构，参数量为 5.69 亿（569M）。其核心创新在于：**一个模型在单次前向传播中，可以同时输出三种不同类型的向量表示**。

---

## 二、稠密向量（Dense Vector）的生成原理

### 2.1 什么是稠密向量

稠密向量是指**维度较低、每个维度上基本都有非零数值**的向量，通常也叫做低维稠密向量。BGE-M3 生成的稠密向量默认长度为 **1024 维**。

稠密向量的特点是：

- **语义压缩**：将文本的深层语义压缩到固定维度
- **连续表示**：向量空间中语义相似的概念距离较近
- **擅长语义理解**：能捕捉"苹果"与"水果"的关联

### 2.2 生成原理

BGE-M3 生成稠密向量的方式与 BGE v1/v1.5 系列类似：

1. 将查询（Query）或文档（Passage）输入 BGE-M3 编码器，得到隐藏状态序列 **H**
2. 使用特殊标记 **`[CLS]`** 位置的隐藏状态作为整个句子的全局语义向量
3. 对该向量进行 **归一化（Normalization）** 处理，得到最终的稠密向量

数学表达为：

$$
e_q = norm(H_q[0])
$$

其中 $H_q[0]$ 即 `[CLS]` 标记对应的隐藏状态。

### 2.3 相似度计算

查询向量 $e_q$ 与文档向量 $e_p$ 之间的相关性分数通过相似度函数计算：

$$
s_{dense} = f_{sim}(e_q, e_p)
$$

常用的相似度函数包括：**余弦距离、内积、L2距离**等。

## 三、稀疏向量（Sparse Vector）的生成原理

### 3.1 什么是稀疏向量

稀疏向量是指**维度很高（通常等于词表大小），但大多数维度上的数值为0**，只保留非零的数值和位置。每个非零维度对应词汇表中的一个词，值为该词在上下文中的重要程度。

BGE-M3 生成的稀疏向量属于 **“学习到的”（Learned）稀疏向量**，它结合了传统稀疏向量（如 BM25）的精确性与稠密向量的丰富语义：

- **传统稀疏向量**（如 BM25）：基于词频统计，缺乏语义理解
- **学习型稀疏向量**（如 BGE-M3）：融入上下文信息，能理解词在语境中的重要性

### 3.2 生成原理

BGE-M3 通过在编码器的隐藏状态之后**添加一个线性层（Linear Layer）和 ReLU 激活函数**来生成稀疏向量。

对于输入查询中的**每个 token i**，模型计算其重要性权重：

$$
w_{qt} = ReLU(W^T_{lex} \cdot H_q[i])
$$

其中：

- $H_q[i]$ 是 token i 对应的隐藏状态
- $W_{lex} \in \mathbb{R}^{d \times 1}$ 是一个**可学习的线性变换矩阵**（d 是隐藏状态的维度）
- ReLU 激活函数确保所有权重**非负**，且大部分权重为 0（实现稀疏性）

> **核心思想**：模型为每个 token 学习一个“重要性分数”，这个分数是基于**整个句子的上下文信息**计算出来的，而不是简单的词频统计。

### 3.3 相似度计算

查询与文档的稀疏向量相关性分数，通过**计算两者共同出现的 token 的权重乘积之和**来获得：

$$
s_{lex} = \sum_{t \in q \cap p} (w_{qt} \cdot w_{pt})
$$

也就是说，只有**同时出现在查询和文档中的 token** 才会对分数有贡献，这与 BM25 的关键词匹配思想一致，但权重是由神经网络学习得到的。

## 四、多向量（Multi-Vector）检索原理

### 4.1 什么是多向量检索

多向量检索方法**不使用单一的 `[CLS]` 向量**，而是利用**模型输出的全部 token 的 Embedding** 来表示查询和文档。这借鉴了 **ColBERT** 的思想。

### 4.2 生成原理

查询和文档的每一个 token 都通过一个可学习的线性变换矩阵 $W_{mul} \in \mathbb{R}^{d \times d}$ 进行投影，然后归一化：

$$
E_q = norm(W^T_{mul} \cdot H_q)
$$

$$
E_p = norm(W^T_{mul} \cdot H_p)
$$

其中 $E_q$ 和 $E_p$ 分别是查询和文档的 **token 级别的向量矩阵**。

### 4.3 相似度计算（延迟交互 / Late-Interaction）

多向量检索采用 **延迟交互（Late-Interaction）** 策略：

$$
s_{mul} = \frac{1}{N} \sum_{i=1}^{N} \max_{j=1}^{M} (E_q[i] \cdot E_p^T[j])
$$

**计算逻辑**：

1. 对查询中的**每个 token 向量** $E_q[i]$，计算它与文档中**所有 token 向量** $E_p[j]$ 的点积
2. 取其中的**最大值**（即找到文档中最相关的 token 进行匹配）
3. 对所有查询 token 的结果**取平均**

> **优势**：这种方法能进行**细粒度的 token 级别匹配**，比单一的 `[CLS]` 向量能捕捉更丰富的信息。但由于计算量大，通常只用于**重排序（Rerank）阶段**，而非初始检索阶段。

---

## 五、三种检索方式的对比总结

| 检索方式 | 向量类型 | 维度 | 优势 | 劣势 |
|----------|----------|------|------|------|
| **稠密检索** | 1个1024维向量 | 低 | 语义理解强，跨语言检索好 | 精确关键词匹配较弱 |
| **稀疏检索** | 词表大小维（高维稀疏） | 高 | 精确匹配强，可解释性好 | 缺乏深层语义理解 |
| **多向量检索** | N个向量（N=token数） | 高 | 细粒度匹配，精度最高 | 计算成本高，速度慢 |

BGE-M3 的**混合检索（Hybrid Ranking）** 策略通常为：

1. 使用**稠密或稀疏检索**快速召回 Top-K 候选文档
2. 使用**多向量方法**对候选文档进行精细重排序

## 六、BGE-Reranker 模型原理

### 6.1 Reranker 与 Embedding 模型的本质区别

| | **Embedding 模型** | **Reranker 模型（交叉编码器）** |
|--|--|--|
| **输入** | 单个文本 | **查询 + 文档** 配对 |
| **输出** | 向量（Embedding） | **相关性分数**（一个数值） |
| **计算方式** | 双塔（Bi-Encoder），可离线预处理 | 交叉编码器（Cross-Encoder），必须实时计算 |
| **速度** | 快（可预先计算文档向量） | 慢（每对都要完整计算） |
| **精度** | 相对较低 | **更高**（能联合理解查询和文档） |

### 6.2 交叉编码器（Cross-Encoder）的工作原理

Reranker 的核心是**交叉编码器（Cross-Encoder）** 架构：

1. 将**查询（Query）和文档（Passage）拼接**成一个序列：`[CLS] 查询 [SEP] 文档 [SEP]`
2. 将拼接后的序列输入 Transformer 模型
3. 模型通过 **Self-Attention 机制**让查询和文档的 token 之间**充分交互**，联合理解两者的语义关系
4. 使用 `[CLS]` 位置的输出经过一个分类层，直接输出一个**相关性分数**

> **关键洞察**：Embedding 模型是“分别编码、后计算相似度”，而 Reranker 是“一起编码、直接判分”。后者能让模型捕捉到**查询和文档之间的细粒度交互信号**，因此精度更高。

### 6.3 BGE-Reranker 模型家族

BGE-Reranker 系列包含多个版本：

| 模型 | 参数量 | 基础模型 | 特点 |
|------|--------|----------|------|
| **bge-reranker-base** | 278M | XLM-RoBERTa-Base | 轻量级，速度快 |
| **bge-reranker-large** | 560M | XLM-RoBERTa-Large | 精度更高 |
| **bge-reranker-v2-m3** | 568M | BGE-M3 | 多语言能力强，轻量易部署 |
| **bge-reranker-v2-minicpm** | 2.72B | MiniCPM-2B | 支持选择不同层输出以加速推理 |
| **bge-reranker-v2-gemma** | 2.51B | Gemma2-2B | 多语言场景表现优异 |
| **bge-reranker-v2-gemma-9B** | 9.24B | Gemma2-9B | 性能最强 |

### 6.4 BGE-Reranker v2.0 的技术亮点

BGE Re-Ranker v2.0 引入了**分层自蒸馏（Layer-wise Self-Distillation）** 策略：

- **原理**：模型的**最终排序得分**被用作“教师信号”（Teacher Signal）
- **方法**：通过知识蒸馏，让模型的**各中间层**也学习排序能力
- **效果**：用户可以根据算力条件**灵活选择使用模型的多少层**来输出排序分数，在精度和速度之间取得平衡

### 6.5 在 RAG 流程中的位置

Reranker 在 RAG（检索增强生成）系统中扮演**“第二道关卡”** 的角色：

```python
用户查询 → Embedding模型检索（召回Top-100）→ Reranker重排序（输出Top-3）→ LLM生成回答
```

1. **第一阶段（召回）** ：使用高效的 Embedding 模型（如 BGE-M3）从海量文档中快速召回 Top-K（如 Top-100）候选文档
2. **第二阶段（重排序）** ：使用 Reranker 对这 100 个文档逐一计算相关性分数，按分数重新排序，输出最终的 Top-N（如 Top-3）

> **为什么要两步？** 如果直接用 Reranker 对所有文档打分，计算成本太高（每对都要完整计算）。先用 Embedding 快速召回，再用 Reranker 精细排序，是**精度与效率的最佳平衡**。

## 七、核心公式汇总

| 公式                                                                            | 含义                       |
| ----------------------------------------------------------------------------- | ------------------------ |
| $e_q = norm(H_q[0])$                                                          | 稠密向量：取 `[CLS]` 的隐藏状态并归一化 |
| $s_{dense} = f_{sim}(e_q, e_p)$                                               | 稠密检索相似度                  |
| $w_{qt} = ReLU(W^T_{lex} \cdot H_q[i])$                                       | 稀疏向量：每个 token 的重要性权重     |
| $s_{lex} = \sum_{t \in q \cap p} (w_{qt} \cdot w_{pt})$                       | 稀疏检索相似度                  |
| $E_q = norm(W^T_{mul} \cdot H_q)$                                             | 多向量：所有 token 的向量矩阵       |
| $s_{mul} = \frac{1}{N} \sum_{i=1}^{N} \max_{j=1}^{M} (E_q[i] \cdot E_p^T[j])$ | 多向量检索相似度（延迟交互）           |
