# AI 大模型开发岗位面试逐字稿准备指南

> **资料索引**：请先阅读 `00_使用说明_先看这个.md`  
> **本文件类型**：阅读材料（逐字稿怎么写、怎么练到脱稿）  
> **下一步**：用 `10` 生成个人逐字稿；时间紧可先读 `01` 再跳到 `04`

> 适用对象：刚步入社会、面试经验较少、准备应聘 AI 大模型应用开发、RAG、Agent、Python 后端相关岗位的同学  
> 核心目标：让每位同学都能做到“有内容可讲、有结构可循、有问题可答、有追问可接”

---

## 一、为什么一定要写面试逐字稿

很多同学不是没有能力，而是面试时容易出现以下问题：

- 知道这个技术，但说不完整；
- 做过项目，但讲不清项目价值；
- 能看懂代码，但无法口头说明实现过程；
- 面试官一追问，就不知道从哪里回答；
- 自我介绍太散，项目讲解太长；
- 紧张后大脑空白，准备过的内容也说不出来；
- 回答只讲“用了什么”，没有讲“为什么这样做”。

因此，面试前必须先准备一套完整逐字稿。

逐字稿不是让大家在面试现场逐句背诵，而是帮助大家提前完成四件事：

1. 把自己的经历和项目梳理清楚；
2. 把零散知识组织成完整表达；
3. 提前发现自己讲不清、经不起追问的部分；
4. 在紧张时仍然能够沿着主线回答。
5. 结合ai进行简历及面试的模拟和优化

正确训练过程：

```text
写完整逐字稿
→ 修改成自然口语
→ 提炼关键词提纲
→ 对着提纲讲
→ 脱稿讲
→ 接受追问
→ 根据反馈继续修改
```

# 二、整套逐字稿的五大框架

每位同学都需要按照以下五个部分准备：

1. 自我介绍
2. 个人工作履历
3. 项目讲解
4. 技术讲解
5. 项目优化

这五部分要形成一条连贯主线：

```text
我是谁
→ 我以前做过什么
→ 我现在能做什么
→ 我做过哪些项目
→ 我是否真正理解核心技术
→ 我能不能发现问题并继续优化
```

建议整套主线控制在 **15～20 分钟**。

| 模块 | 建议时长 | 主要目标 |
|---|---:|---|
| 自我介绍 | 1～2 分钟 | 快速建立岗位形象 |
| 个人工作履历 | 2～3 分钟 | 解释经历与转型逻辑 |
| 项目讲解 | 7～10 分钟 | 证明项目能力 |
| 技术讲解 | 3～5 分钟 | 证明理解原理和应用 |
| 项目优化 | 2～4 分钟 | 体现工程思维和成长潜力 |

# 三、写逐字稿之前，先准备基础材料

不要一上来就直接写稿。先把下面的信息整理出来。

## 1. 个人信息

- 姓名；
- 学历和专业；
- 毕业时间；
- 原有工作经历；
- 原有技术基础；
- 当前求职方向；
- 目标岗位；
- 目标城市。

## 2. 项目信息

每个项目至少整理：

- 项目名称；
- 项目解决什么问题；
- 项目服务什么用户；
- 项目整体架构；
- 自己负责什么模块；
- 使用了哪些核心技术；
- 一个完整业务流程；
- 三个以上问题与解决方案；
- 项目如何测试；
- 项目还可以如何优化。

## 3. 技术信息

把简历中出现的每个技术都列出来，例如：

- Python；
- FastAPI；
- MySQL；
- Redis；
- LangChain；
- LangGraph；
- RAG；
- Embedding；
- Milvus；
- Qdrant；
- Hybrid 检索；
- Reranker；
- Agent；
- Prompt；
- SSE；
- Docker；
- vLLM。

每个技术至少准备五个问题：

```text
它是什么？
为什么使用？
核心原理是什么？
项目中怎么使用？
有什么缺点或替代方案？
```

# 四、自我介绍逐字稿

## 1. 自我介绍的真正作用

自我介绍不是把简历从头到尾念一遍。

它的作用是让面试官在 1～2 分钟内知道：

- 你的基本背景；
- 你应聘什么岗位；
- 你有哪些相关能力；
- 你做过什么项目；
- 接下来应该重点问你什么。

自我介绍要主动把面试官引向自己准备最充分的项目和技术。

---

## 2. 自我介绍推荐结构

```text
基本背景
→ 原有经验或技术基础
→ 当前 AI 方向
→ 两个核心项目
→ 核心能力
→ 应聘目标
```

---

## 3. 自我介绍逐字稿模板

```text
面试官您好，我叫________，毕业于________院校的________专业，
目前主要应聘 AI 大模型应用开发、RAG 或 Agent 相关岗位。

我之前主要从事/学习过________，在________、________和________方面有一定基础。
后来因为________，我开始系统学习 AI 大模型应用开发，
重点掌握了 Python 后端、FastAPI、RAG、Agent、LangGraph、
向量数据库以及大模型接口调用等技术。

在项目方面，我主要完成了两个项目。
第一个项目是________，主要解决________问题，
我重点负责________、________和________模块。

第二个项目是________，主要面向________场景，
我重点负责________和________。

我目前比较擅长的是把业务需求拆解成具体的 AI 应用流程，
包括知识库构建、检索优化、Agent 工作流、接口开发和问题排查。

希望能够从事 AI 大模型应用开发相关工作，
在实际项目中继续积累 RAG、Agent 和 AI 工程化能力。

我的自我介绍完毕，谢谢面试官。
```

---

## 4. 自我介绍三个版本

每位同学都要准备三个版本。

### 30 秒版本

适合面试官说：“简单介绍一下自己。”

结构：

```text
背景 + 岗位方向 + 核心项目 + 核心能力
```

### 1 分钟版本

适合普通技术面试开场。

结构：

```text
背景 + 原有能力 + AI 学习方向 + 两个项目 + 求职目标
```

### 2 分钟版本

适合面试官愿意完整听介绍，或者个人经历较复杂时。

结构：

```text
背景 + 工作履历 + 转型逻辑 + 项目职责 + 技术优势 + 岗位目标
```

---

## 5. 自我介绍检查标准

写完后检查：

- 是否控制在规定时间内；
- 是否出现大量无关内容；
- 是否自然引出核心项目；
- 是否突出与岗位相关的能力；
- 是否存在自己解释不了的术语；
- 是否像正常交流，而不是朗读作文。

# 五、个人工作履历逐字稿

## 1. 工作履历不能只念时间线

错误方式：

```text
2022 年我在某公司工作，
2023 年去了另一家公司，
2024 年开始学习 AI。
```

这种表达只有时间，没有能力主线。

正确方式应该讲清楚：

```text
做过什么
→ 负责什么
→ 学到了什么
→ 为什么转向 AI
→ 原有能力如何迁移
```

---

## 2. 每段经历的五句话

每一段工作或学习经历都按照下面五句话准备：

1. 我在哪里、担任什么角色；
2. 我主要负责什么；
3. 我完成过什么具体工作；
4. 我积累了什么能力；
5. 这些能力对现在的 AI 岗位有什么帮助。

---

## 3. 有工作经验的同学模板

```text
我上一段工作是在________公司，岗位是________。

我主要负责________业务，具体工作包括________、________和________。

在这段经历中，我比较重要的收获是________，
例如需求分析、接口开发、数据库处理、数据分析、问题排查或团队协作。

可能会涉及到离职原因

后来我接触到________场景，
发现大模型能够解决________问题，
因此开始系统转向 AI 大模型应用开发。

过去的________经验也可以迁移到现在的工作中，
例如我可以将________能力应用到 RAG、Agent 或 AI 后端项目中。
```

---

## 5. 跨行业转型同学模板

```text
我之前主要从事________行业，负责________工作。

这段经历让我积累了________能力，
例如业务理解、客户沟通、流程管理、数据处理或项目协作。

后来在接触________业务时，
我发现大模型可以解决________问题，
因此开始系统学习 AI 大模型应用开发。

转型后，我重点学习了 Python 后端、RAG、Agent 和大模型调用，
并通过________项目把原来的业务理解与新的技术能力结合起来。
```

---

## 6. 空窗期如何准备逐字稿

不要长篇解释，也不要表现得过度紧张。

推荐结构：

```text
简要说明原因
→ 这段时间做了什么
→ 现在已经准备到什么程度
```

模板：

```text
这段时间我主要在完成职业方向调整，
系统学习了 AI 大模型应用开发相关技术，
并完成了________和________两个完整项目。

除了学习基础知识，我也重点补充了项目架构、
业务实现、问题排查和面试准备。

目前我的目标方向已经比较明确，
希望尽快进入 AI 大模型应用开发岗位，
在实际工作中继续积累经验。
```

# 六、项目讲解逐字稿

项目讲解是整个面试中最重要的部分。

每个同学至少准备两个项目：

- 一个主项目：准备 8～10 分钟；
- 一个辅助项目：准备 3～5 分钟。

主项目必须能够经受连续追问。

---

## 1. 项目讲解完整结构

每个项目按照以下顺序准备：

```text
1. 项目背景
2. 为什么要做
3. 项目目标
4. 整体架构
5. 我的职责
6. 一个具体业务实现
7. 至少三个问题与解决方案
8. 项目结果
9. 项目不足
10. 后续优化
```

---

## 2. 项目背景逐字稿

先讲业务，不要先讲技术栈。

模板：

```text
这个项目主要面向________场景，
服务的用户是________。

原来的业务处理方式是________，
存在几个比较明显的问题：

第一，________；
第二，________；
第三，________。

因此，我们希望通过________技术，
实现________功能，
最终提高________，降低________。
```

---

## 3. “为什么做这个项目”逐字稿

不能只说“为了学习 RAG”或“为了练习 Agent”。

应该回答三个问题：

- 业务中原来有什么问题；
- 为什么普通方式解决不好；
- 为什么需要大模型、RAG 或 Agent。

模板：

```text
我们做这个项目的主要原因是________。

传统方式通常通过________完成，
但它在________情况下效果不好。

例如，________。

大模型比较擅长________，
但是如果直接调用大模型，又会出现________问题。

所以我们最终采用________方案，
让系统既能________，又能________。
```

---

## 4. 项目架构逐字稿

项目架构要按“数据如何流动”讲，不要只念框架名称。

### RAG 项目推荐顺序

```text
文档上传
→ 文档解析
→ 文本清洗
→ 文本切块
→ Embedding
→ 向量数据库
→ 用户提问
→ Query 分类
→ Query 改写
→ 混合检索
→ Reranker
→ Prompt 拼接
→ 大模型生成
→ SSE 返回
→ 会话记忆
```

### RAG 项目架构模板

```text
整个项目主要分为离线知识库构建和在线问答两部分。

离线阶段，用户上传 PDF、Word 或 Markdown 文档后，
系统先进行文档解析和文本清洗，
之后根据________策略进行切块。

切块完成后，通过________模型生成向量，
并将向量、原始文本和文档元数据一起存入________数据库。

在线阶段，用户问题首先经过________，
判断是否需要查询知识库。

需要检索的问题会先进行________，
再执行________和________两路检索。

两路结果经过________融合后，
再交给________进行精排，
选出最终的 Top-K 内容。

最后，系统将用户问题和检索结果组装成 Prompt，
调用________大模型生成答案，
并通过________方式返回给前端。

多轮对话部分通过________保存会话状态，
并使用________隔离不同用户的会话。
```

---

## 5. 个人职责逐字稿

不能只说“我负责整个项目”，也不能一直使用“我们”。

模板：

```text
在这个项目中，我重点负责三部分。

第一部分是________，主要完成了________。

第二部分是________，主要完成了________。

第三部分是________，主要负责________。

另外，我也参与了接口联调、日志排查和测试数据构建。
```

面试官继续追问时，要能区分：

- 哪部分是自己重点完成；
- 哪部分是团队协作；
- 哪部分只是了解；
- 哪部分自己可以深入讲解。

# 七、具体业务实现逐字稿

每个项目至少选择一个核心业务模块，准备 3～5 分钟完整讲解。

推荐模块：

- 文档上传与知识库构建；
- 文本切块；
- Query 分类；
- Query 改写；
- Hybrid 检索；
- Reranker 精排；
- Agent 工具调用；
- 多轮记忆；
- SSE 流式输出；
- 人在环审核；
- Bad Case 收集与优化。

---

## 1. 业务实现统一结构

```text
业务目标
→ 输入是什么
→ 经过哪些步骤
→ 每一步为什么这样做
→ 输出是什么
→ 异常怎么处理
→ 如何测试
```

---

## 2. 业务实现逐字稿模板

```text
我重点讲一下项目中的________模块。

这个模块主要解决________问题。

它的输入是________，
输出是________。

整个处理过程分为________步。

第一步是________，
主要作用是________。

第二步是________，
这样设计是因为________。

第三步是________，
主要负责________。

如果过程中出现________异常，
系统会通过________进行处理。

这个模块完成后，
我通过________方式进行了测试，
重点验证了________、________和________。
```

---

## 3. Hybrid 检索示例

```text
我重点讲一下项目中的混合检索模块。

这个模块的输入是用户问题，
输出是一批与问题最相关的候选文本。

项目初期只使用稠密向量检索。
它比较擅长理解语义和同义表达，
但面对错误码、API 名称、类名和产品型号时，
检索效果不够稳定。

因此，我们又增加了稀疏检索。

稠密检索主要负责语义匹配，
稀疏检索主要负责关键词和专业术语匹配。

两路检索分别返回候选结果后，
通过 WeightedRanker 进行加权融合，
再将 Top-N 结果交给 Reranker 精排。

这样做的目的是先保证召回范围，
再提高最终排序精度。
```

# 八、项目中遇到的问题及解决方案

每个项目至少准备三个问题，而且三个问题要来自不同层面。

建议包括：

1. 一个效果问题；
2. 一个性能问题；
3. 一个工程问题。

---

## 1. 问题回答统一结构

```text
问题现象
→ 如何发现
→ 如何定位
→ 原因是什么
→ 采取了什么方案
→ 为什么这样解决
→ 如何验证
→ 最终结果
```

---

## 2. 问题逐字稿模板

```text
项目中遇到的第一个问题是________。

当时的现象是________。

我们通过________发现了这个问题。

一开始我们怀疑是________，
后来通过查看日志、对比输入输出、构造测试数据，
最终定位到问题主要是________导致的。

针对这个问题，我主要做了三项调整：

第一，________；
第二，________；
第三，________。

修改完成后，我通过________重新测试，
重点观察________指标或现象。

最终结果是________。

这个问题让我意识到，
在实际项目中除了功能能运行，
还需要重视________。
```

---

## 3. 可准备的问题方向

### 效果类问题

- 文档中有答案，但检索不到；
- 检索到了错误内容；
- Chunk 内容不完整；
- 专业术语匹配不准；
- 大模型没有根据资料回答；
- Query 分类错误；
- Agent 选择了错误工具；
- 结构化输出格式不稳定。

### 性能类问题

- 接口响应时间过长；
- 首 Token 时间过长；
- 多路检索串行执行；
- 重复问题反复调用模型；
- 文档入库速度慢；
- 上下文过长；
- 数据库连接不足；
- 并发时资源占用过高。

### 工程类问题

- 多用户会话串话；
- 文档重复入库；
- Prompt 修改后效果回退；
- 开发环境和生产环境配置混乱；
- Agent 节点异常导致流程中断；
- 日志信息不足，无法定位问题；
- 知识库文档更新后旧版本未删除；
- 接口异常没有统一返回。

---

## 4. 三个问题准备标准

每个问题都必须能够回答：

- 是怎么发现的；
- 是怎么定位的；
- 为什么会发生；
- 改了哪些代码或配置；
- 为什么选择这个方案；
- 修改后如何验证；
- 是否还有其他方案。

---

# 九、技术讲解逐字稿

技术讲解不是背定义，而是证明自己：

- 理解这个技术；
- 知道它解决什么问题；
- 知道项目中怎么使用；
- 知道它的优点和限制；
- 能够进行方案选择。

---

## 1. 技术回答六步法

```text
它是什么
→ 解决什么问题
→ 核心原理
→ 项目中怎么用
→ 为什么这样选
→ 有什么限制或替代方案
```

---

## 2. 通用逐字稿模板

```text
________是一种________技术，
主要用于解决________问题。

它的核心原理是________。

在我的项目中，
它主要用在________环节。

具体实现流程是________。

当时选择它的原因是________，
相比________方案，它更适合当前项目的________需求。

不过它也存在________问题，
如果业务规模或场景发生变化，
还可以考虑使用________方案。
```

---

## 3. RAG 示例

```text
RAG 是检索增强生成，
主要用于解决大模型缺少私有知识、
知识更新不及时和直接回答容易产生幻觉的问题。

它的核心思路是，
在大模型回答之前，
先根据用户问题从知识库中检索相关资料，
再把资料和问题一起交给大模型生成答案。

在我的项目中，
RAG 主要包括文档解析、切块、Embedding、
向量存储、混合检索、Reranker 精排和答案生成。

选择 RAG 而不是直接微调模型，
主要是因为知识更新比较频繁，
RAG 更新知识库的成本更低，
而且能够返回引用来源。

不过 RAG 也不能完全消除幻觉，
如果检索结果本身错误，
最终答案仍然可能不准确。
```

---

## 4. Agent 示例

```text
Agent 可以理解为能够根据目标自主选择步骤和工具的大模型应用。

普通大模型调用通常是输入一个问题、返回一个答案，
而 Agent 会根据当前任务，
决定是否调用搜索、数据库、计算、知识库或其他工具。

在我的项目中，
Agent 主要用于________场景。

整个流程通过 LangGraph 组织，
State 保存上下文，
Node 执行具体任务，
Edge 决定后续流转。

Agent 的优点是灵活，
但也容易出现工具选择错误、流程不稳定和调用成本高的问题，
因此需要增加条件限制、状态检查和异常兜底。
```

---

# 十、项目优化逐字稿

项目优化不是随便说“换一个更大模型”。

要回答：

- 现在的问题是什么；
- 为什么先优化这个问题；
- 准备怎么改；
- 如何验证；
- 会增加什么成本；
- 是否需要分阶段上线。

---

## 1. 项目优化四个方向

### 效果优化

- 优化文本切块；
- 增加 Query 改写；
- 增加 Hybrid 检索；
- 增加 Reranker；
- 调整 Top-K；
- 增加引用来源；
- 优化 Prompt；
- 增加置信度和兜底机制。

### 性能优化

- 异步调用；
- 并行执行；
- 增加缓存；
- 减少重复模型调用；
- 使用流式输出；
- 控制上下文长度；
- 批量生成 Embedding；
- 增加限流和超时机制。

### 工程优化

- 增加日志和链路追踪；
- 增加统一异常处理；
- 增加 Prompt 版本管理；
- 增加知识库版本管理；
- 区分开发、测试、生产环境；
- 增加自动化测试；
- 增加接口鉴权；
- 增加监控和告警。

### 业务优化

- 收集用户反馈；
- 建立 Bad Case 闭环；
- 增加人工审核；
- 增加角色权限；
- 根据场景设置不同阈值；
- 增加答案引用；
- 增加无答案提示和人工转接。

---

## 2. 项目优化逐字稿模板

```text
如果继续优化这个项目，
我会优先从效果、性能和工程化三个方面进行。

第一，在效果方面，
目前项目还存在________问题。

我计划通过________进行优化，
并构建固定测试集，
使用________指标进行前后对比。

第二，在性能方面，
目前________环节耗时较长。

我计划将________改为异步或并行执行，
同时增加________缓存，
减少重复调用。

第三，在工程化方面，
目前日志、监控和版本管理还不够完善。

后续会增加请求 ID、链路日志、
Prompt 版本、知识库版本和异常告警。

这些优化不会一次性全部上线，
而是先在测试环境进行验证，
确认效果后再逐步发布。
```

---

# 十一、项目追问准备

面试官通常不会只听完整讲解，而是会随时打断追问。

因此，每个项目至少准备 20 个追问。

## 1. 业务类追问

- 这个项目服务谁？
- 为什么要做这个项目？
- 原来的业务方式是什么？
- 项目解决了什么实际问题？
- 为什么一定要使用大模型？
- 不使用大模型能不能做？

## 2. 架构类追问

- 为什么这样设计架构？
- 数据从哪里来？
- 文档如何更新？
- 多用户如何隔离？
- 项目如何部署？
- 模型服务异常怎么办？
- 如何保证系统可用性？

## 3. 技术类追问

- 为什么使用这个 Embedding 模型？
- 为什么使用 Milvus/Qdrant？
- 为什么要做 Hybrid 检索？
- Top-K 如何设置？
- Chunk Size 如何设置？
- 为什么需要 Reranker？
- LangGraph 和普通函数有什么区别？
- Redis 在项目中做什么？
- SSE 和 WebSocket 有什么区别？

## 4. 效果类追问

- 如何评估 RAG 效果？
- 如何判断检索结果好不好？
- 如何降低幻觉？
- 如何处理无答案问题？
- 如何收集 Bad Case？
- 优化前后如何对比？

## 5. 个人职责类追问

- 你具体负责哪部分？
- 最难的问题是什么？
- 哪段代码是你写的？
- 如果重新做一次，你会改什么？
- 项目中你和其他成员如何分工？
- 哪个模块你最熟悉？

---

# 十二、逐字稿的正确写法

## 1. 先写完整，不要一开始追求简短

第一版的目标是“不漏内容”。

先把所有经历、项目和技术写出来，再逐步删减。

---

## 2. 必须改成口语

错误表达：

```text
本系统旨在通过先进的大语言模型技术，
实现企业内部知识的智能化检索与问答。
```

修改为：

```text
这个项目主要解决企业内部资料不好查的问题。
员工可以直接提问，
系统从内部文档中找到相关内容，
再让大模型根据资料回答。
```

---

## 3. 一句话只表达一个重点

不要一句话塞入五个技术名词。

错误：

```text
项目使用 LangGraph、Milvus、BGE-M3、Redis、FastAPI
完成多轮对话、混合检索和流式输出。
```

修改为：

```text
项目后端使用 FastAPI。

知识库使用 Milvus 存储稠密向量和稀疏向量。

检索部分使用 BGE-M3 完成向量化，
再通过混合检索和 Reranker 提高结果准确度。

工作流使用 LangGraph 组织，
Redis 主要保存缓存和部分会话数据。
```

---

## 4. 每一个技术名词后面都要能继续解释

只要写进逐字稿或简历，就必须准备：

```text
为什么用？
怎么用？
参数如何设置？
有什么问题？
有什么替代方案？
```

---

## 5. 不要写无法证明的结果

不要随便写：

```text
准确率提高 40%
响应速度提升 60%
支持万人并发
```

除非真的有测试过程。

可以改成：

```text
在构建的测试问题中，
专业术语类问题的漏检情况明显减少。

通过并行执行多路检索，
接口整体等待时间有所下降。

目前完成了基础并发测试，
后续还需要进一步进行生产级压测。
```

---

# 十三、逐字稿训练流程

## 第一阶段：写完整稿

要求：

- 五个模块全部写完；
- 每个项目不少于三个问题；
- 每个技术都能解释；
- 不遗漏个人职责；
- 不遗漏项目优化。

---

## 第二阶段：教师或同学审核

重点检查：

- 项目逻辑是否完整；
- 技术是否正确；
- 是否有明显漏洞；
- 是否有无法解释的技术名词；
- 是否缺少业务背景；
- 是否缺少问题定位过程；
- 是否说得太像课程汇报。

---

## 第三阶段：修改成口语

要求：

- 删除书面化表达；
- 删除过长句子；
- 增加自然停顿；
- 每段只表达一个重点；
- 控制整体时间。

---

## 第四阶段：提炼关键词提纲

例如项目架构只保留：

```text
业务背景
离线建库
在线问答
Query 分类
Hybrid 检索
Reranker
LLM
SSE
Memory
```

看到这些词就能完整讲出来。

---

## 第五阶段：录音训练

至少录制三遍。

检查：

- 是否频繁说“然后、就是、那个”；
- 是否语速过快；
- 是否有长时间停顿；
- 是否像背书；
- 是否超过时间；
- 是否漏掉个人职责；
- 是否只讲技术，不讲业务。

---

## 第六阶段：模拟面试

两人一组：

- 一人讲项目；
- 一人随机打断；
- 一人连续追问“为什么”；
- 一人检查是否前后矛盾。

模拟面试时，不允许完整背完后再提问。

真实面试中，面试官通常会随时打断。

---

## 第七阶段：脱稿表达

最终不能依赖完整逐字稿。

只看关键词提纲，完成：

- 1 分钟自我介绍；
- 3 分钟项目简述；
- 8 分钟项目详述；
- 3 个问题解决；
- 3 个项目优化；
- 10 个随机追问。

---

## 5. 练习材料

# 十五、教师验收标准

## 1. 自我介绍

- 1～2 分钟内完成；
- 岗位方向明确；
- 能自然引出项目；
- 表达流畅；
- 没有无关内容。

## 2. 工作履历

- 时间线基本清楚；
- 转型逻辑合理；
- 原有能力能够迁移；
- 空窗期解释简洁；
- 不出现前后矛盾。

## 3. 项目讲解

- 能说清业务背景；
- 能说清整体架构；
- 能说清个人职责；
- 能完整讲一个业务实现；
- 至少准备三个问题；
- 每个问题都有定位和验证；
- 能回答连续追问。

## 4. 技术讲解

- 不只背定义；
- 能结合项目；
- 能说明原理；
- 能说明选型原因；
- 能说明优缺点。

## 5. 项目优化

- 能发现当前不足；
- 优化方案具体；
- 有验证方法；
- 考虑成本和风险；
- 有测试环境和上线意识。

---

# 十六、同学们最容易犯的错误

## 1. 自我介绍讲太久

自我介绍不是个人成长故事，控制在 1～2 分钟。

## 2. 项目只讲技术栈

必须先讲业务问题，再讲技术方案。

## 3. 一直使用“我们”

要明确自己负责的部分。

## 4. 只说解决方案，不说定位过程

面试官更关心你是怎么发现问题、定位问题的。

## 5. 只背概念，不结合项目

每个核心技术都要准备项目中的实际用法。

## 6. 项目优化只说“换大模型”

优化应该包括效果、性能、工程和业务。

## 7. 把逐字稿背成课文

逐字稿最终要转成关键词提纲，做到自然表达。

## 8. 被打断后无法继续

练习时必须加入随机追问和打断。

---

# 十七、最终目标

准备逐字稿不是为了让同学们背出一段完美答案。

真正目标是让每位同学做到：

```text
知道自己要讲什么
→ 知道先讲什么、后讲什么
→ 知道面试官可能追问什么
→ 知道哪些问题自己最熟悉
→ 被打断后仍能继续回答
→ 遇到不会的问题也能有条理地表达
```

面试前，至少要达到以下状态：

- 自我介绍不用看稿；
- 项目架构能够手画；
- 一个业务模块可以讲 3～5 分钟；
- 三个项目问题能够完整说明；
- 十个核心技术能够结合项目回答；
- 面对连续追问不会立刻失去思路；
- 每次模拟面试后都能继续修改逐字稿。

> 逐字稿不是最终答案，而是同学们从“会做”走向“会讲”，从“会讲”走向“能应对真实面试”的第一步。
