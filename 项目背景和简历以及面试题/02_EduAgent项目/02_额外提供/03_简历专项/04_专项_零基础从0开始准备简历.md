# 一团空白的同学，怎么用 AI 从 0 开始准备大模型简历？

> **资料索引**：请先阅读 `00_使用说明_先看这个.md`  
> **本文件类型**：专项指南（适合「没项目、没亮点、没思路」的同学）  
> **用法**：按文中步骤让 AI 帮你挖素材、设计小项目，再用 `06` 写简历

有些同学准备简历时会很慌，觉得自己“没有项目、没有实习、没有亮点、没有思路”。这种情况不能一上来就让 AI 写简历。因为没有真实素材时，AI 很容易写出一份看起来很高级、但本人完全讲不出来的简历。

正确做法是：

> 先让 AI 帮你挖素材，再帮你选方向，再帮你设计一个能做出来的小项目，最后再写简历。

AI 不是用来“编经历”的，而是用来帮你把混乱的信息整理成可执行计划。

## 一、先判断：同学到底是哪种“空白”

“空白”一般分四类，不同类型用 AI 的方式不一样。

### 第一类：真的没有项目

这类同学可能只学了语法、框架、课堂案例，没有完整做过项目。

这种情况不要硬写大项目，而是用 AI 帮他设计一个 **小而完整的个人项目**。

目标不是做一个“企业级平台”，而是做一个：

> 能跑、能演示、能讲清楚、有代码、有截图、有 README 的小项目。

例如：

- 个人知识库 RAG 问答系统；
- 简历智能分析助手；
- 课程资料问答助手；
- 面试题生成与评估助手；
- 客服工单分类助手；
- 新闻摘要与标签分析工具；
- PDF 文档问答系统。

这些项目不一定大，但只要流程完整，就能写进简历。

### 第二类：做过课程项目，但不知道怎么写

这类同学不是没做过，而是只会说：

> 老师带着做了一个项目。

这时 AI 的作用是帮他拆项目：

- 项目解决什么问题？
- 哪些模块是自己写的？
- 哪些功能自己理解？
- 哪些地方可以二次改造？
- 可以换成什么业务场景？
- 可以补哪些指标？
- 面试官会怎么问？

注意：课程项目不能原封不动写。AI 要帮助同学做 **个人化改造**。

例如课程里学过 EduAgent，不建议简历直接写 EduAgent。可以改造成：

- 企业制度知识库问答系统；
- 招聘简历智能评估系统；
- Python 课程智能答疑助手；
- 面试陪练 Agent；
- 安全日志分析 Agent；
- 合同条款问答助手。

核心是：**同学要在课程基础上做自己的版本。**

### 第三类：有经历，但不知道和 AI 岗位有什么关系

有些同学可能做过普通 Python、MySQL、爬虫、数据分析、Web 后端项目，但不知道这些和大模型岗位有什么关系。

AI 可以帮他做“迁移分析”。

比如：

- 做过 Python 后端，可以转成 AI 应用接口能力；
- 做过 MySQL，可以转成业务数据存储能力；
- 做过爬虫，可以转成知识库数据采集能力；
- 做过数据清洗，可以转成 RAG 文档预处理能力；
- 做过前端页面，可以转成 AI Demo 展示能力；
- 做过用户登录，可以转成 AI 系统权限管理能力。

很多同学不是没有基础，而是不知道怎么把基础能力和大模型应用连接起来。

### 第四类：基础弱，不知道从哪学起

这类同学不应该直接追求“高大上项目”，而是先用 AI 制定最小学习路径。

比如先做一个最小闭环：

> 用户提问 → 调用大模型 API → 返回答案 → 保存历史记录 → 页面展示

再逐步加：

> 文档上传 → 文档切分 → 向量化 → 检索 → RAG 回答 → 流式输出

不要一上来就写 LangGraph、多 Agent、MCP、Reranker、vLLM。基础弱的同学先做通一个简单 RAG，就已经比空写“熟悉大模型”强很多。

## 二、AI 帮空白同学的正确流程

### 第一步：用 AI 做“个人素材访谈”

同学先不要让 AI 写简历，而是让 AI 问自己问题。

推荐提示词：

> 你现在是一名大模型应用工程师就业指导老师。 我现在准备 AI 大模型工程师简历，但我感觉自己没什么项目和亮点。 请你像老师访谈学生一样，一次问我一个问题，帮我挖掘我学过的技术、做过的练习、课程项目、实习经历、兴趣方向、能独立完成的功能。 不要直接帮我编简历，先帮我整理真实素材。

AI 可以连续问：

- 你学过哪些编程语言？
- 你做过哪些课堂案例？
- 你是否写过接口？
- 是否用过数据库？
- 是否调过大模型 API？
- 是否做过文件上传？
- 是否做过登录？
- 是否用过向量数据库？
- 是否写过爬虫？
- 是否做过数据清洗？
- 是否有行业背景？
- 是否有感兴趣的业务场景？
- 是否愿意补做一个项目？

这样能把学生脑子里散乱的东西挖出来。

### 第二步：让 AI 生成“素材清单”

访谈完以后，让 AI 输出一张表。

推荐提示词：

> 请根据刚才我的回答，帮我整理一份求职素材清单。 表格包含：已有技能、可证明证据、能写进简历的程度、需要补强的地方、是否适合 AI 大模型岗位。 请不要夸大，如果我没有证据，请标注“需要补证据”。

输出形式：

素材当前情况能否写进简历需要补什么Python学过基础和函数可以写基础掌握需要项目证明FastAPI跟课写过接口可以写使用过需要独立接口 DemoMySQL会增删改查可以写基础操作需要表设计案例大模型 API调用过一次可以写了解需要完整问答项目RAG听过概念暂不建议写熟悉需要补项目

这一步很关键。它能把“我什么都没有”变成“我有一些基础，但缺项目证据”。

### 第三步：让 AI 帮学生选一个最适合的项目方向

空白同学最怕项目太大，最后做不出来。所以 AI 要帮他选“最小可完成项目”。

推荐提示词：

> 根据我的基础情况，请给我推荐 5 个适合大模型应用工程师简历的小项目。 要求：
>
> 1. 适合学生独立完成；
> 2. 不要太大；
> 3. 能体现 RAG、Agent、FastAPI、数据库中的至少两个能力；
> 4. 每个项目给出核心功能、技术栈、开发难度、预计产出、面试可讲点；
> 5. 不要设计虚假的企业级项目。

推荐项目可以分成三个难度。

## 三、适合空白同学的三个项目难度

### 难度一：最小 AI 问答系统

适合基础弱的同学。

项目名称可以是：

> 基于 FastAPI 的个人 AI 问答助手

核心功能：

- 用户输入问题；
- 后端调用大模型 API；
- 返回回答；
- 保存问答历史；
- 支持按用户查看历史记录；
- 简单前端页面或接口测试。

技术栈：

- Python
- FastAPI
- 大模型 API
- MySQL / SQLite
- Pydantic
- HTTP 接口

能写进简历的点：

> 实现基于 FastAPI 的 AI 问答接口，完成请求参数校验、大模型 API 调用、异常处理和问答历史持久化，具备基础 AI 应用后端开发能力。

这个项目不高级，但很真实，适合从 0 起步。

### 难度二：PDF 文档 RAG 问答系统

适合大多数同学。

项目名称可以是：

> 基于 RAG 的课程资料智能问答系统

核心功能：

- 上传 PDF / Markdown 文档；
- 文本解析和清洗；
- 文本分块；
- 生成 Embedding；
- 存入向量库；
- 用户提问；
- 检索相关片段；
- 拼接 Prompt；
- 大模型生成答案；
- 返回引用片段。

技术栈：

- Python
- FastAPI
- LangChain / LlamaIndex
- FAISS / Milvus
- Embedding 模型
- 大模型 API
- SQLite / MySQL

能写进简历的点：

> 独立实现 RAG 问答系统，完成文档解析、文本分块、向量化、Top-K 检索、Prompt 组装和答案生成流程，支持基于私有课程资料的智能问答。

这是最推荐空白同学做的项目。因为它贴合大模型应用岗位，也容易讲清楚。

### 难度三：简历智能评估助手

适合想和就业场景结合的同学。

项目名称可以是：

> 面向 AI 岗位的简历智能评估系统

核心功能：

- 上传简历；
- 解析 PDF / Word；
- 提取基本信息、技能、项目、实习；
- 输入目标岗位 JD；
- 分析岗位匹配度；
- 输出亮点、缺点、修改建议；
- 生成改进计划；
- 保存评估报告。

技术栈：

- Python
- FastAPI
- 大模型 API
- Pydantic
- MySQL / PostgreSQL
- PDF 解析工具
- Prompt Engineering

能写进简历的点：

> 基于大模型和结构化输出能力实现简历评估系统，支持简历文本解析、岗位 JD 匹配、六维度评估和优化建议生成，并通过 Pydantic 约束输出格式，提升结果稳定性。

这个项目非常适合准备 AI 应用岗，但前提是学生必须真正做出来，而不是只写描述。

## 四、AI 可以帮学生把“练习”升级成“项目”

很多学生觉得自己没有项目，是因为他把自己做过的东西都当成“练习”。

比如：

- 写过登录注册；
- 写过数据库 CRUD；
- 写过文件上传；
- 写过调用大模型 API；
- 写过一个页面；
- 写过一个爬虫；
- 写过文本清洗；
- 写过简单分类。

这些单独看是练习，但组合起来就可以变成项目。

例如：

### 原始练习

- FastAPI 接口；
- MySQL 存储；
- 大模型 API 调用；
- PDF 解析；
- 简单页面。

### AI 帮助组合成项目

> PDF 简历智能分析系统

功能链路：

> 上传简历 → 解析文本 → 调用大模型分析 → 结构化输出 → 存入数据库 → 页面查看报告

这就是一个能写进简历的小项目。

推荐提示词：

> 我做过以下练习：FastAPI 接口、MySQL 增删改查、文件上传、大模型 API 调用、PDF 文本解析。 请帮我把这些练习组合成 3 个适合简历的小项目。 每个项目要包含项目名称、业务场景、核心功能、技术栈、开发步骤、简历写法和面试追问点。 不要夸大，不要写我没做过的高级技术。

## 五、AI 帮学生从 0 设计项目时，必须遵守的规则

### 规则一：项目要小，不要虚大

空白同学不要写：

> 企业级多智能体协同平台 千万级知识库问答系统 全自动智能办公中台 大规模模型训练平台

这些项目太大，不可信。

应该写：

> 课程资料 RAG 问答系统 简历智能评估助手 PDF 文档问答系统 客服问题分类助手 面试题生成与评估工具

学生项目越具体，越可信。

### 规则二：先做完整闭环，再加高级功能

不要一开始就追求功能很多。

正确顺序：

第一版：

> 用户输入问题 → 调大模型 → 返回答案

第二版：

> 加数据库 → 保存历史记录

第三版：

> 加文档上传 → 文本解析

第四版：

> 加 Embedding → 向量检索

第五版：

> 加 RAG → 基于资料回答

第六版：

> 加 SSE → 流式输出

第七版：

> 加 Rerank / 查询改写 / 低置信度兜底

这样项目会越来越扎实。

错误顺序是：

> 第一天就写 LangGraph + MCP + 多 Agent + Reranker + 流式输出 + 权限系统 + Docker 部署

结果通常是做不完，也讲不清。

### 规则三：AI 生成代码后，学生必须自己跑通

AI 可以帮你写代码，但不能保证代码一定适合你的环境。

学生必须做到：

- 自己能启动项目；
- 自己知道入口文件在哪；
- 自己知道接口怎么调用；
- 自己知道数据库表怎么建；
- 自己知道大模型 API 怎么配置；
- 自己知道报错怎么排查；
- 自己知道核心函数干什么。

否则这个项目不能写进简历。

### 规则四：简历只写自己能解释的部分

比如 AI 帮你设计了：

- RAG；
- Agent；
- MCP；
- LangGraph；
- Reranker；
- 多轮记忆；
- SSE；
- Docker；
- Redis；
- 权限系统。

但你只真正做了 RAG 和 FastAPI，那简历就只写 RAG 和 FastAPI。

没有做的不要写。

## 六、给空白同学的标准 AI 提示词

### 提示词一：从空白开始访谈

> 你现在是一名 AI 大模型工程师就业导师。 我是一个准备找工作的学生，目前感觉自己没有项目、没有亮点、没有简历思路。 请你不要直接帮我写简历，而是像老师一样一步一步访谈我。 你每次只问一个问题，帮我挖掘我学过的技术、做过的练习、能独立完成的功能、感兴趣的方向。 最后帮我整理成：已有素材、可写进简历的内容、需要补强的内容、适合做的项目方向。

### 提示词二：把练习变成项目

> 我做过这些练习：【填写自己做过的练习】。 请你帮我判断这些练习能不能组合成一个适合 AI 大模型应用工程师简历的小项目。 要求项目真实、规模适合学生独立完成、不要夸大。 请输出项目名称、业务背景、核心功能、技术栈、开发步骤、简历写法、面试追问点。

### 提示词三：为基础弱的同学设计 7 天项目计划

> 我基础比较弱，只会 Python 基础、FastAPI 简单接口、MySQL 基础操作，刚开始学习大模型 API。 请帮我设计一个 7 天可以完成的 AI 应用小项目。 每天给出学习目标、开发任务、最终产出。 项目要能写进简历，但不能虚假夸大。 最终项目必须有代码、README、接口说明、演示截图和项目讲解稿。

### 提示词四：项目做完后生成简历描述

> 下面是我真实完成的项目内容：【粘贴项目说明】。 请帮我改写成简历项目经历。 要求按照“项目背景、技术方案、个人职责、项目结果”组织。 不能新增我没做过的功能，不能编造指标。 如果缺少信息，请用【待补充】标出来。

### 提示词五：模拟面试追问

> 你现在是北京大模型应用工程师面试官。 请根据我的项目描述进行面试追问，重点检查项目真实性、个人贡献、技术理解和代码实现。 每次只问一个问题，我回答后你继续追问。 如果我回答模糊，请继续追问细节。

## 七、空白同学的 14 天补救计划

### 第 1-2 天：素材盘点

目标：

- 用 AI 访谈自己；
- 整理技能清单；
- 整理练习清单；
- 确定目标岗位。

产出：

- 个人素材表；
- 技能掌握程度表；
- 目标岗位分析表。

### 第 3-4 天：确定项目方向

目标：

- 选择一个小项目；
- 明确项目功能；
- 画出流程图；
- 明确技术栈。

建议项目：

- PDF 文档问答系统；
- 课程资料 RAG 助手；
- 简历智能评估系统；
- 客服问题分类助手。

产出：

- 项目设计文档；
- 功能清单；
- 数据库表草图；
- 接口草图。

### 第 5-9 天：完成最小可运行版本

目标：

- 项目能跑；
- 接口能调；
- 页面或 Postman 能演示；
- 数据能保存；
- 大模型能返回结果。

产出：

- 代码；
- 启动说明；
- 接口截图；
- 运行截图。

### 第 10-11 天：补项目文档

目标：

- 写 README；
- 整理项目结构；
- 写接口说明；
- 整理核心流程；
- 准备演示数据。

产出：

- README.md；
- 接口文档；
- 项目流程图；
- 演示截图。

### 第 12 天：写简历项目

目标：

- 用 AI 优化项目表达；
- 标出个人职责；
- 删除虚大内容；
- 增加真实结果。

产出：

- 简历项目经历；
- 技能模块；
- 自我介绍。

### 第 13 天：AI 模拟面试

目标：

- 让 AI 追问项目；
- 找出答不上来的问题；
- 回头补代码和理解。

产出：

- 20 个面试问题；
- 自己的回答；
- 待补强清单。

### 第 14 天：最终修改

目标：

- 修改简历；
- 修改项目文档；
- 准备 2 分钟项目讲解；
- 准备投递版本。

产出：

- 最终简历；
- 项目证据包；
- 项目讲解稿。

## 八、这类同学时要求

对于一团空白的同学，不要只要求他交简历。因为他会很容易用 AI 瞎写。

建议要求他交五样东西：

1. **AI 访谈记录** 证明他做过素材盘点。
2. **项目设计文档** 证明项目不是凭空写的。
3. **项目代码或 Demo** 证明项目能运行。
4. **项目 README 和截图** 证明项目能展示。
5. **AI 模拟面试记录** 证明他能讲清楚项目。

这样可以防止“AI 生成简历，但本人不会”的问题。

## 九、最关键的一句话

对于完全没思路的同学，AI 最大的价值不是帮他“写出一份漂亮简历”，而是帮他：

> 从零散练习里找素材，从岗位要求里定方向，从课程基础上做个人项目，从项目复盘里提炼简历内容。

空白不可怕，乱写才可怕。

没有项目，就用 AI 辅助做一个小而真实的项目；

 不会表达，就用 AI 帮你复盘和优化；

 不会面试，就用 AI 模拟追问；

 但没有做过的东西，不要让 AI 帮你写进简历。

简历可以被 AI 优化，但项目必须真实存在，能力必须自己讲得出来。
